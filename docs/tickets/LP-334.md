# LP-334 — Live calibration of the AI tags (the first real measurement)

Calibration was KEYLESS until now — labels replayed, trivially perfect, a plumbing check. **No AI tag had
ever been scored against real content.** This ticket builds a source-agnostic live calibration harness and
takes the first measurement. It MEASURES; it does not tune prompts or activate rules (evaluate-don't-fix).

## What it is

A harness (`app/verification/eval/live_calibration.py`) that runs the REAL AI producer over LABELED
content and scores predicted-vs-golden per tag — unknown-rate + accuracy-when-concrete (reusing LP-317's
`DimensionCalibration` unchanged) + the per-case DETAIL (predicted / golden / confidence / reasoning) that
makes a wrong tag inspectable. The content source is a swappable seam; keyless CI is unchanged.

## D1 — the content source (a decision-to-be-made; flags a PRIVACY call for Geet)

**A code finding reframes the trade-off:** the AI tag-reasoners consume EXTRACTED FIELDS, not raw scans
(`subjects.py::_doc_context` sends `document.fields`). So "messy real scans" is an **extraction**-stage
risk, upstream of the tag reasoner — clean-field content measures the fields→tags reasoning *faithfully*.

| Option | Measures | Does NOT measure | Needs |
|---|---|---|---|
| **(a) synthetic / labeled fields** (this ticket; mortgageboss-synthetic exists at `../mortgageboss-synthetic`) | the fields→tags reasoning; obvious failures + systematic biases | garbled fields from bad scans; real PII edge cases; true fuzzy-tag accuracy | nothing (safe, no key for content) |
| **(b) local Qwen over real files** | real messiness, no PII leaves the machine | the PRODUCTION model (measures Qwen) | the Qwen/Bedrock migration eval |
| **(c) de-identified real → Anthropic** | real messiness AND the production model | — (but LF-6T3N is a *tagged* snapshot with NO golden labels; needs hand-labeling) | **Geet's privacy approval** + auditable de-identification |

**Recommendation: a HYBRID** — synthetic labeled fields now (breadth + regression + this ticket's numbers)
+ a small **hand-labeled de-identified real set** for truth, **pending Geet's privacy approval**
(privacy-first: local models for real PII, cloud for non-PII). The harness's `LabeledDoc` seam swaps the
source with no harness change. **This decision is Geet's; it is flagged, not taken.**

**WHAT THIS SOURCE CAN AND CANNOT TELL US (loudly).**
- **CAN:** the tag reasoner's accuracy on CLEAN extracted fields — plumbing, obvious failures, and
  systematic biases (it caught FINDING-1). The **enum-tag numbers are trustworthy**.
- **CANNOT:** real-scan/garbled-field messiness (extraction-stage, upstream); real-PII edge cases; the
  TRUE accuracy of fuzzy free-text tags (string comparison under-measures — FINDING-2); and it is
  **tiny-n** (2–4 obs/tag — not statistically robust). These require the D1 hybrid (Geet's approval) + a
  larger labeled set (n≥20/tag).

## THE FAILING CASES (the actionable part) → reported as fix tickets

**FINDING-1 (HIGH — a live-rule bias). `id.current_address_type` defaults a driver's-license address to
`prior`.** Predicted `prior`, golden `residence`; reasoning: *"Driver's licenses often contain addresses
that are not current."* ID-4's residence filter then EXCLUDES the DL address → fewer residence sources →
couldnt_check (or a missed discrepancy). → **Fix ticket:** refine the `id_address` prompt to treat a DL's
stated address as the CURRENT residence unless the document indicates otherwise. Do NOT tune here.

**FINDING-2 (a measurement limit, not an AI failure). Fuzzy free-text tags can't be scored by string
comparison.** `id.name_normalized` "failures" were `Maria Garcia-Lopez` (a valid rendering of golden
`Maria Garcia Lopez` — a hyphen-vs-space artifact) and a dropped generational suffix (`Wm. O'Brien III` →
`William O'Brien`). A normalized-name/address tag has MANY valid renderings — the raw 33% under-measures
it (this is exactly why ID-1 uses an AI FUZZY leg to compare names). → **Follow-on:** score fuzzy-string
tags by human review of the failing-case detail (the harness records it) or an AI-judge comparison, NOT a
raw % from string match. The enum-tag numbers stand.

**FINDING-3 (LOW). Dropped generational suffix** (`III`) — benign for name CONSISTENCY (ID-1 treats
suffix drift as benign) but a structuring inconsistency worth a note.

## Cost / runtime

~4s + ~270 tokens per document per group (claude-sonnet-4-5); the 13-doc run took ~53s. A robust
calibration (n≥20/tag × ~10 tags ≈ 200 calls) ≈ ~15 min and a few dollars — cheap, one-off, opt-in. **CI is
never charged:** the live seam is gated on an explicit `LP334_LIVE=1` env flag (never the mere presence of
a key); the keyless plumbing tests + the family keyless suites run free and unchanged.

## What a real-content run still needs

1. **Geet's privacy approval** for D1 option (c) — de-identified real content → Anthropic — with auditable
   de-identification; OR the local-Qwen path (option b), which measures Qwen not production.
2. **Hand-labeled golden values** for a real set — LF-6T3N is a de-identified *tagged* snapshot with no
   ground-truth tag labels; it cannot be scored without labeling.
3. **A larger labeled set** (n≥20/tag) for statistical robustness — the 2–4 obs/tag here find biases, not
   precise rates.
4. **Priya's activation bars** (D2) before any inert rule activates or any live rule is re-evaluated.
