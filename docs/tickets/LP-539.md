# LP-539 — DT-7 reports factor (viii) documented on a file with no credit report

Deferred by the user on 2026-08-18. Not started.

## The defect

On LF-WCHG, `dti.atr_factors_documented` returned **`complete` at 95% confidence**. Its
reasoning for factor (viii):

> "while **no standalone credit report document is labeled**, the liability data with
> account holders, balances, and payment amounts indicates credit information was
> obtained and is present in the file data structure."

There is no credit report on the file. The document inventory (read-only staging query,
2026-08-18):

```
drivers_license 3 | w2 3 | pay_stub 2 | bank_statement 2 | homeowners_insurance 2
property_tax_bill 1 | mortgage_statement 1 | uscis_notice_of_action 1
lender_dashboard_screenshot 1 | form_1098 1 | closing_disclosure 1
```

The liability data it reasoned from is MISMO — the borrower's **self-reported** debts off
the 1003. Self-reported liabilities are not verified credit history, which is what
Reg Z 1026.43(c)(2)(viii) is about.

The same file already knows this. **CR-6 (x4), CR-13 and CR-8 all abstain precisely
because there is no credit report** — CR-6's fix says "Upload the tri-merge credit report."
DT-7 called that factor documented while three sibling rules were abstaining over the
missing document.

This is the exact failure DT-7's own activation bar names:

> FN ("all ATR factors are documented" on a file that is missing one — **the worst false
> all-clear in this cohort**) >> FP (a processor re-checks a folder that was in fact complete).

## Second defect in the same reasoning: absence read as satisfaction

Factor (iv): *"no evidence of a simultaneous loan in the file, **factor satisfied by
absence**."* Absence is not confirmation. Under the §8 contract this is `unknown`, not
satisfied — the same inference the rest of the engine refuses to make.

## Why neither AI layer caught it

DT-7 is an AI judgment rule reading a single AI tag. The judgment tag
(`dti.atr_documentation_adequate`, `yes`, 95%) restates its input:

> "**The structured tag explicitly documents that** all eight … **The tag's 'complete'
> status with 0.95 confidence** … supports a determination …"

It cites the input tag's own confidence as grounds for agreeing with it, and never
examines factor (viii). The judgment layer adds no independent check — worth deciding
whether it earns its place at all, or whether DT-7 should read the tag directly.

The human ratification is the only remaining control, which is why it exists and why
LP-537 surfaced the evidence: this was invisible while the finding printed
"Every ability-to-repay factor has a supporting document in the file."

## Scope

1. The `atr_documentation` tag prompt must require an actual credit report for factor
   (viii). Self-reported MISMO liabilities cannot satisfy it. Name the distinction
   explicitly — the model reasoned its way to the wrong answer from real data, so a
   general instruction to be careful will not do it.
2. Factor (iv) — absence of a simultaneous loan is `unknown` for that factor, not
   satisfied. Decide whether one unknown factor makes the whole tag `unknown` or whether
   the tag needs per-factor output.
3. Decide whether the judgment layer stays.

## Constraint

Changing the prompt **invalidates DT-7's measured self-consistency** (1.0000 over 4
constructed cases, model `us.anthropic.claude-sonnet-4-5-20250929-v1:0`, 2026-08-13) and
it must be re-measured against the activation bar. A rule that says "complete" on a file
with no credit report has not earned that 1.0000 — the four constructed cases did not
include a file with liabilities but no report, which is the case that broke it.
