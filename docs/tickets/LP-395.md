### AS-7 — the orphan, resolved (the contradiction the ticket flagged)

`txn.is_nsf_or_overdraft` is in the **vocabulary** (`fact_tags.csv`, mode=AI, `AS-7`) and is **read** by the
derived recipe (`derived.py:558`, which *abstains* when the tag is on no transaction), but it is **produced by
no path**:
- **NOT** in `tag_production.yaml` (the declared producer layer) — `"txn.is_nsf_or_overdraft" not in
  load_declarations()`.
- **NOT** in Stage-B — `tag_correlation` (`app/ai/` + `app/services/`) emits only `txn.has_identified_source`
  and `txn.source_strength`. (The check that matters, per LP-390-2: a Stage-B tag like `has_identified_source`
  is *also* absent from the declared layer yet IS produced — so declared-absence alone isn't proof. The proof
  is that no path at all emits `is_nsf_or_overdraft`.)

**AS-7's real blocker is a MISSING PRODUCER, not calibration** — confirming LP-390-2's orphan finding. The AS-7
bar even hedged ("verify the derived chain when calibrating"); the chain is broken at the leaf. **Census
correction: AS-7 `needs-calibration → needs-producer`.**

### IN-8 / IN-9 / IN-13 — produce, but no discriminating scenario at n≥6

- **IN-8 `voe_present`** materializes, but the worksheet's capacity model labels it only on VOE / offer-letter
  document types → **3 rows** on the scenario fixture (the 3 VOEs), **< 6**. No fixture reaches 6 VOE docs
  (scenario 3, lf6t3n 0, lf6t3n_plus 2). *Secondary finding:* the producer runs `voe_present` on ALL documents
  (`applies_to: all`), but the worksheet labels only VOE/offer-letter types — so the precision direction (does
  the AI wrongly tag a W-2 as a VOE) isn't even in the labelable set. Both point the same way: **more VOE (and
  non-VOE income) scenarios needed.**
- **IN-9 `offer_letter_present`** can only be `yes` on an offer-letter document, and **none exists in any
  fixture** — its positive class is empty (one-sided, the AS-5 gift-n=0 shape). Not measurable until a scenario
  carries an offer letter.
- **IN-13 `continuance_3yr`** produces 13 rows — enough by count — but every borrower carries only EMPLOYMENT
  income, where continuance is honestly `unknown`; the tag is about OTHER income (pension / child support /
  alimony — B3-3.1-09), and no such borrower exists (LP-393-1 already reached n=1 meaningful). Its second input
  `income.type` is also thin (n=2, all `base`) — though `income.type` is reasoned-over context, not the binding
  load-bearing tag, so the blocker is continuance's no-signal, not a second-tag trap.

## Phase 1 — the worksheet (none) + the fixture gaps

No worksheet is generated — nothing is calibratable, and the discipline is *do not calibrate a tag thin*. The
fixture gaps to unblock these rules (each its own ticket, the LP-393-1 pattern — **NOT invented here**):

1. **A VOE + offer-letter scenario** — ≥3 more `voe` documents (to lift `voe_present` to n≥6) and at least one
   `employment_offer_letter` document (to give `offer_letter_present` a positive class). Unblocks IN-8, IN-9.
2. **An other-income scenario** — borrowers whose income is pension / child support / alimony / an award, so
   `continuance_3yr` is a real yes/no rather than `unknown`. Unblocks IN-13.
3. **A producer for `txn.is_nsf_or_overdraft`** — a Stage-B or statement AI classifier that tags NSF/overdraft
   transactions, feeding the existing derived `stmt.nsf_count`. Unblocks AS-7 (then it becomes calibratable).
