## Phase 0 — eligibility, and the gate of record vs the ticket

The ticket's AS-5 premise was **wrong against the gate of record**, in two ways — reported, not patched over:

1. **AS-5 is already `validated: false`** (committed in LP-390-5a, bec1d24) — there is no stray `true` to fix.
2. **The loader already rejects the stray-flag scenario.** `parse_bar` raises *"only a calibratable-now rule
   may be validated"* on any non-calibratable rule (LP-380). So a `validated:true` on AS-5 (null threshold,
   not-calibratable) is ALREADY a load error — the requested hardening exists. No loader change was needed.

So the AS-5 work is a **proof**, not a fix: a test asserts AS-5 stays held and that the stray flag fails loud.

  **15 satisfied + 2 needs_review** on the 17 money-in deposits; **33 couldnt_check** on the money-out

  **34 couldnt_check** (33 outflows + 1 money-in whose apparent_category read unclear). Every verdict is

## The loan_proceeds n=0 caveat AS-2 ships with

AS-2 fires on `apparent_category == loan_proceeds` — a value with **zero examples on LF-6T3N**. Its specific
trigger is therefore UNTESTED. `apparent_category` is measured broadly (100% concrete across
payroll/interest/transfer_own/third_party) and `measured_accuracy` is recorded as the weaker MEASURED gate
(`has_identified_source` 0.938), NOT `apparent_category`'s 1.0 — the number does not over-read the untested
trigger. Priya signed off knowing this; the Phase-2 run confirms AS-2 does not false-fire on a file with no
loan-proceeds deposit. **A file carrying a loan-proceeds deposit would validate the trigger directly.**
