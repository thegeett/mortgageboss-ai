# LP-342 — Fuzzy scoring for free-text tags (LP-334 FINDING-2)

## WHAT THIS IS

A ruler for free text. Calibration scored a tag by STRING EQUALITY — correct for enums, **structurally
wrong for free text.** LP-334 measured `id.name_normalized` at 33% where the "failures" were
`Maria Garcia-Lopez` vs the golden `Maria Garcia Lopez`, a valid rendering. **The model was right; the ruler
was wrong.** ID-1 itself uses an AI FUZZY leg to compare names because string equality does not work — and
then the harness used string equality to score names. This ticket makes the four free-text tags measurable
by declaring a scoring METHOD per tag.

## ACCEPTANCE CRITERIA (all met)

- The MATCH set scores equal; **the MISMATCH set scores WRONG** (a ruler that fails nothing is worthless).
- A not-inert guard: a wrong-by-construction distribution fires the fabrication flag.
- **Declared, not hardcoded** — a new free-text tag needs one `_SCORING_MODE` line, no scorer code, no
  tag-id branch (asserted).
- The enum/number path is **byte-identical** (`txn.is_money_in`, `income.documented_monthly`,
  `id.current_address_type`).
- The per-case detail survives (a near-miss is inspectable, not just counted).
- Keyless + free; no rule/tag/engine/spec behaviour changed; `ACTIVE_RULE_IDS` unchanged. `mypy app/` clean;
  full suite **757 passed, 5 skipped**.

## THE METHOD ARGUMENT (options weighed; the code corrected the ticket)

The ticket leaned option (a): reuse the consuming rule's declared normalizer chain, assuming `drop_punct`
would make the hyphen case equal. **Empirically it does NOT** — `drop_punct` DELETES the hyphen without a
space, so ID-1's own chain scores the FINDING-2 headline wrong:

| pair | ID-1 chain (`casefold,drop_punct,collapse_ws,strip`) |
|---|---|
| `Maria Garcia-Lopez` / `Maria Garcia Lopez` | `maria garcialopez` ≠ `maria garcia lopez` → **DIFFER** |

So reusing the exact chain does not fix FINDING-2. The fix is to treat **punctuation as a WORD BOUNDARY**,
not noise to delete. Options:
- **(a) normalized comparison — CHOSEN, corrected.** Reuse the registry's philosophy (casefold + collapse)
  but map every run of non-word characters to ONE space (a word boundary). Deterministic, free, no AI. Fixes
  the hyphen headline; the MISMATCH set survives unequal.
- **(b) AI-judge** — rejected: it puts a second, uncalibrated AI *inside* the measurement of an AI (who
  calibrates the judge?) and costs a call per instance.
- **(c) distance threshold** — rejected: an unvalidated threshold is exactly the number this project refuses
  to guess.
- **(d) human review** — kept for the residue (see below) and for tags with no defensible golden.
- **Hybrid (a + d) — the shape shipped:** deterministic normalized score for names/addresses; human-review
  for the free-form provenance tags and for the abbreviation residue the rule's AI judge would decide.

## WHAT WAS BUILT

A tag DECLARES its scoring method (`calibration.py`, beside `_ABSTAINING_DIMENSIONS`); the comparator
dispatches by METHOD, never by tag-id:

| method | tags | behaviour |
|---|---|---|
| `exact` (default) | every enum/number tag | UNCHANGED — numeric Decimal tolerance + `_norm` string equality |
| `normalized` | `id.name_normalized` (ID-1, LIVE), `id.address_normalized` (ID-4, LIVE) | casefold + non-word→space + strip, then equality |
| `human_review` | `txn.counterparty` (AS-2/5/12), `txn.source_reference` (AS-1/5) | recorded with per-case detail, NEVER %-scored |

`DimensionCalibration` gained a `review` count (default 0 → the enum path is byte-identical). A
`human_review` tag's answerable cases land in `review`, claim no accuracy, and are listed under
`review_cases` (not `failing_cases`).

## KEY DECISIONS / ASSUMPTIONS

- **What the `normalized` score MEANS (over-read guard):** *"the tag matches the golden as the consuming
  rule's DETERMINISTIC bookend would see it"* — **NOT** *"the tag is objectively correct."* It does NOT
  reproduce the rule's AI fuzzy judge, so abbreviation/initial/generational variance (`Ave`↔`Avenue`,
  `M`↔`Marie`, `Jr`↔`III`) is NOT collapsed. That residue is (1) surfaced in the per-case detail for human
  review, and (2) resolved at SOURCE by LP-340's convention (expand abbreviations; report the name of record)
  + consistent golden labeling. This ticket does not invent a synonym/abbreviation dictionary (tunable).
- **The leniency boundary:** `Acme Logistics` vs `Sterling Retail`, `Jordan A Rivera` vs `Taylor M Nguyen`,
  a right street with the wrong number — all WRONG. Proven by a MISMATCH set chosen INDEPENDENTLY of any tag
  result (never iterated against the numbers — the LP-335 discipline applied to the scorer itself).
- **LP-340 interaction (no hidden leniency):** the name/address scorer must NOT strip entity suffixes —
  `drop_entity_suffix` is IN-5's RULE-declared normalizer, deliberately scoped there. `Acme Inc` vs
  `Acme LLC` scores WRONG under the name scorer (asserted `test_scorer_does_not_strip_entity_suffixes`), so
  the scorer never hides a difference LP-340's convention decides elsewhere — keeping the convention testable.
- **Which tags stay human-review-only, and why:** `txn.counterparty` / `txn.source_reference` are free-form
  provenance strings (a bank wire memo) with no canonical golden — forcing a % would be a fiction.
- **One documented residual:** the single normalization rule (non-word run → boundary) renders an
  apostrophe-internal name with a space (`O'Brien` → `o brien`), so `O'Brien` vs `OBrien` scores different.
  Accepted deliberately — one clean rule beats per-character heuristics; a mixed apostrophe rendering is
  itself a labeling inconsistency, and the per-case detail surfaces it.

## THE MATCH / MISMATCH PROOF (the ruler fails things)

- **MATCH (must be equal):** hyphen-vs-space (the FINDING-2 headline), period, collapsed whitespace, case,
  comma — all score equal.
- **MISMATCH (must be wrong):** different person, different name, different address, right street/wrong
  number, a one-letter difference — all score wrong.
- **not-inert guard:** a wrong-by-construction distribution → accuracy 0 → `under_abstaining` fires.
- **enum byte-identical:** `txn.is_money_in` exact; `income.documented_monthly` numeric tolerance;
  `id.current_address_type` enum not normalized-collapsed.

## THE HONEST RISK NOTE

All four tags feed verdicts a human ALREADY ratifies (`id.name_normalized`→ID-1, `id.address_normalized`→ID-4
are fuzzy-consistency → ratification-pending; the txn tags are inert). A wrong fuzzy tag here is therefore
LOWER-risk than a wrong enum feeding an auto-shipping deterministic verdict (LP-334's D2 inventory). **This
ticket makes them MEASURABLE; it does not imply they are the urgent risk.**

## NO RE-SCORE HERE — and a better number later ≠ a better tag

Per LP-335 (measure once, never iterate the ruler against the measurement), the live calibration was NOT
re-run. The re-run happens with Priya's judgment rows (LP-341) so the whole picture is measured at once with
a settled method. **Read the eventual improvement correctly:** a better `id.name_normalized` number under
this scorer means **the RULER now matches what the system cares about — NOT that the tag got better.** The
tag's behaviour is unchanged; only the measuring instrument was fixed.

## NEW GAP (reported, not patched)

The abbreviation/initial/generational residue (`Ave`↔`Avenue`, `M`↔`Marie`) is not deterministically
collapsible without a synonym dictionary or an AI judge. It is handled today by LP-340's convention at source
+ human review of the per-case detail. If a future need arises for a % over that residue, an AI-judge scorer
(option b) is the path — but it needs its own calibration (who calibrates the judge?), a separate ticket.
