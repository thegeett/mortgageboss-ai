# LP-949 — Lender on the file

- **Ticket:** LP-949 · Phase 4.5 Stage 3 follow-ups, batch 4 (the staging trial)
- **Source:** [`phase4.5-staging-trial-2026-09-30.md`](../phases/phase4.5-staging-trial-2026-09-30.md)
  items 1 and 10b; the product owner's batch-4 list (2026-09-30):
  - "At import, if the file has no lender, detect it from the sheet (the reader used, the header, the
    mortgagee clause) and ASK her to confirm. Never set it silently."
  - "When a file's lender is set or changed, re-apply the code map to untyped conditions only, then read
    the ones still unplanned."
  - "Show a warning on the Conditions tab while there is no lender."
  - "For codes with no code-map entry, the AI may PROPOSE a library type. It goes to the lender settings
    'Lender codes to review' table and is used only after she confirms it there (saved to that lender's
    map). Write an ADR for this."
- **ADR:** [ADR-417](../../decisions.md)

## Design

**Why.** A condition gets its library type only from its lender's code map, at import
(`condition_import._apply_code_defaults`). LF-DH8V had no lender, so all six conditions were untyped,
read as generic items, and lost everything a type carries. Staging also had **no lenders at all**
(measured: `readonly.lenders` 0 rows, `readonly.lender_condition_codes` 0 rows), so a confirm has to be
able to create the lender.

**Detection** (`app/conditions/lender_detect.py`, pure). `detect_lender(sheet_format, header)` returns
`DetectedLender(key, name, source)` or None:
1. `reader`: `UWM_APPROVAL_LETTER` → `uwm`, `CHAMPIONS_CERTIFICATE` → `champions`;
2. `mortgagee_clause`: the header's clause names exactly one shipped lender's `lender_label`;
3. `header`: any other header string does.
Matching is case- and spacing-insensitive on the full printed label; two lenders named, or none, is None.
`lender_label(key)` is new in `lender_codes/loader.py`.

**Service** (`app/services/condition_lender.py`).
- `lender_suggestion(loan_file)`: while the file has no lender, the newest DRAFT or IMPORTED round whose
  sheet names a lender, unless she declined it (`round_lender_declined` on that round; a decline on the
  newest round also stops an older one being offered).
- `set_file_lender(loan_file, lender_key | lender_id)`: exactly one. A `lender_id` must be her company's.
  A key resolves to her company's lender with that `canonical_lender_key`, else one with the same printed
  name (the key is **not** attached: the seed's "never guessed at" rule), else a new lender named by the
  label, with the key, seeded at once (`seed_lender`, new in `seed_lender_codes.py`). Goes through
  `update_loan_file_with_activity`, so the activity log records it as it records an Overview edit.
- `on_file_lender_changed`, called from `loan_files.update_loan_file` (every lender change, including
  Overview's PATCH): rounds with no lender (or the previous one) take the new lender; untyped conditions
  with no lender (or the previous one) take it, then their type from its code map (`_apply_type`: type,
  `info_only` raised, owner hint only where the sheet gave none, exactly import's three). One
  `condition_typed` event per typed condition (`by: lender_set`). Unknown codes are recorded
  `observed_unmapped`, as import records them. A typed condition is never re-typed.
- `unread_round_to_read`: the newest imported round when the file has unread conditions. The routes queue
  `read_condition_round` with it **after** commit. A condition already read is not read again.
- `record_proposals`: copies each untyped condition's `reading.proposed_type_id` onto its code row while
  the row is `observed_unmapped` and has no proposal yet. Called at the end of `read_round` and from
  `on_file_lender_changed`.
- `type_conditions_for_code`: after an admin maps a code, the lender's untyped conditions with that code
  take the type (`by: code_confirmed`); the route queues the reading for the files it touched.

**The AI's proposal.** Reading prompt `read_v2.txt` (`READING_VERSION = "read_v2"`): when any condition in
the call has no type, the request carries `library` (every type's id and name) and the model may answer
`library_type` for an untyped condition. `compose_reading` keeps it as `reading.proposed_type_id` only
when it names a real type and the condition has no type and no confirmed reading. Nothing reads it except
`record_proposals`.

**Data.** Migration `7b2d9e4c1a58`: `lender_condition_codes.proposed_type_id` (exposed in the rebuilt
`readonly.lender_condition_codes`, re-granted in the same step); event kinds `condition_typed` and
`round_lender_declined` (33 kinds; the downgrade refuses while either exists).

**Routes** (`app/api/conditions.py`, tenant-scoped by `ScopedLoanFileById`):
- `GET /loan-files/{id}/conditions/lender` → `FileLenderPublic {lender, suggestion}`;
- `PUT /loan-files/{id}/conditions/lender` `{lender_key} | {lender_id}` → 409 with a sentence on refusal;
- `POST /loan-files/{id}/conditions/lender/decline` `{round_id}`.
- `PATCH /loan-files/{id}` with `lender_id` now also queues the reading; `PUT /lenders/{id}/codes/{code}`
  now types the matching untyped conditions and queues their reading.
- `GET /lenders/{id}/codes-to-review` rows carry `proposed_type_id` and `proposed_type_label` (shown only
  while the code has no type).
- History: `condition_typed` projects `typed_as`, the library's label (closed vocabulary).

**Frontend.**
- `FileLenderBanner` above the review screen and the list: the suggestion with **Set … as the lender** /
  **Not this lender**; with no suggestion, "This file has no lender" and a link to Overview; for a lender
  with no code map, a line saying so. Nothing renders once the lender has a code map.
- Lender settings, "Lender codes to review": "AI suggests <type>" with **Use it** under the select. The
  select is not pre-filled; nothing is mapped until she clicks.
- History lines: "Matched to the library: <type>"; "The lender the sheet named was marked not this file's".

**Reuses.** `update_loan_file` (the one door for lender changes), `create_lender`, the seed's `_upsert`,
`codes_to_review` / `map_code`, `_enqueue_reading`, `read_round`, `build_plan`.

**Fixtures.** None new: the tests import the shipped UWM round-1 sheet (`render_uwm_pdf(UWM_ROUND_1)`),
which carries LF-DH8V's six codes, onto a file with no lender.

## Readings taken (not STOP AND ASK; the owner's words decide them)

- **A file read while untyped keeps its generic reading** after its lender is set: "read the ones still
  unplanned" plus LP-952's "never re-read a read or confirmed condition". So LF-DH8V itself does not
  improve by setting its lender; a new import onto a file with a lender does. Re-reading such a file is
  left to LP-952's route.
- **A same-named lender without the key** is used as the file's lender, but its key is not set.
- **Confirming may create a lender.** Staging has none, and a suggestion she cannot accept would be no
  suggestion. Created with the label as its name and the key, then seeded.

## Tests

`backend/tests/conditions/test_lp949_lender_on_the_file.py`, 20 tests:
- detection: reader, mortgagee clause, header, none, two lenders named;
- the suggestion is offered from the sheet, and nothing is set until she confirms;
- confirming creates the lender with its key and seeded map, types the five mapped codes (0006 IV-01,
  0007 IV-03, 1228 PA-03, 1947 TI-03, 6378 TI-04), sets the round's lender, writes `condition_typed`;
- her company's lender is reused, another company's is refused, both-at-once is refused;
- a same-named lender without the key is used and the key is not guessed;
- decline: recorded, hides the suggestion, a wrong round is refused;
- a typed condition keeps its type;
- unread conditions are read with their types and **0007 waits on 1228** (item 10b), with the positive
  control: without the lender, 0007 waits on nothing;
- a condition already read is not read again;
- the proposal: kept only for an untyped condition and a real type; the library goes to the model only
  when a condition is untyped; it reaches review and is used only once she maps the code; it never lands
  on a seeded code;
- routes: offer, set, 409 on both-at-once, reading queued; another company's file is 404 on all three;
  decline route and a PATCH of the lender both type and queue.

Mutations, each restored from a copy afterwards:
- stop applying the type in `_apply_type`: 4 tests fail;
- drop BOTH "untyped only" guards (the query filter and `_apply_type`'s check): 1 fails. Dropping only
  `_apply_type`'s check passes, because the query already filters; the behaviour is pinned at the query;
- keep a proposal without checking the library: 1 fails;
- remove the migration's `GRANT SELECT` from `upgrade()`: the readonly regrant guard fails. (Its first
  version passed that mutation because a comment held the words; the comment was reworded.)

Frontend: `file-lender-banner.test.tsx` (4), `lender-condition-settings.test.tsx` (+2), `history.test.ts`
(the two kinds in the exhaustive list, +1).
