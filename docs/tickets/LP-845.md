# LP-845 — The communication page notices what another tab did

Status: spec. Build order: fourth of four, independent of the other three.

## The report

> "I have to refresh the communication page, after requesting document if communication page is
> opened in different tab of the browser. Can we make it auto appear on change?"

## Why it happens

`frontend/lib/query-client.ts:10-12`:

    staleTime: 60 * 1000,
    refetchOnWindowFocus: false,

Tab A requests a document and invalidates its own cache (LP-840 made sure of that). Tab B is a
different React tree with a different QueryClient and was told nothing, so it serves its cached
timeline for a minute, and `refetchOnWindowFocus: false` means even switching to it does not
recheck.

## The options, and what each actually reaches

| Approach | Reach | Cost |
|---|---|---|
| `refetchOnWindowFocus` on the timeline query | Same browser, refreshes when the tab is looked at | one line |
| `BroadcastChannel` | Same browser, instant, no server | ~30 lines, no infra |
| `refetchInterval` polling | Any device or browser | a request per interval per open tab |
| SSE / WebSocket | Any device, any user, true push | ALB, Fargate, auth — real infra |

## The change

**The first two together.** Focus-refetch covers "I switched to that tab"; BroadcastChannel covers
"both tabs are visible at once" and fires immediately. Neither needs a server change.

Polling is the established house pattern for a DIFFERENT problem — `lib/api/documents.ts:79` and
`needs.ts:60` both use a *function* `refetchInterval` that polls only while work is in flight and
idles otherwise. That shape suits a job that finishes. A draft changing is an event, not a job, and
polling every open tab forever to catch it is the wrong trade.

SSE is deliberately not built. It is the only option that reaches a second processor on a second
machine, and until two people work one file at once it buys nothing the first two do not.

## Scope note

`BroadcastChannel` is same-origin and same-browser. It will not reach a second device, a second
browser, or another user — and it must not be described in the UI as though it does.
