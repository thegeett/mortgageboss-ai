# LP-118.6 — The fact namespace: assembled per-run typed fact snapshot (foundation)

**Type:** Story · **Epic:** Phase 3.5 / Epic B · **Depends:** LP-115, LP-116, fact-namespace-foundation, ADR-239
**Status:** complete · **Date:** 2026-07-07

## What this ticket is

The engine's deepest foundation: ONE assembled, typed, immutable fact object per verification run —
the **fact namespace** — holding everything a rule might read about a loan file, gathered from its
scattered homes (enum columns, stated-entity rows, extraction JSON, on-demand calculators) into one
**entity-addressable** structure, computed once, and persisted as a per-run snapshot. Downstream:
LP-119 (applicability), LP-120 (evaluators), and LP-140 (trust surface) all read it.

**Explicitly NOT this ticket** (scope held): the applicability filter (LP-119), evaluators / any rule
execution (LP-120), borrower↔document linking (LP-118.8 — `borrowers[].documents[]` is *shaped* but
empty), the store-everything columns (LP-118.7 — current-address/county are read as **absent**), and
runner wiring (LP-121). **Nothing executes a rule; the live verification path is byte-for-byte
unchanged** (the legacy `build_cross_source_facts` and cross-source task were not touched).

## Acceptance criteria — and how each was met

- [x] **An immutable, typed, entity-addressable fact object matching the ACTUAL model shape.** →
  `app/verification/fact_namespace/snapshot.py`: frozen Pydantic models. Per-borrower income/
  employers/identity; **file-level** liabilities/assets/documents; **single** property; materialized
  `transactions[]`; a compute-once `computed` block. `None` is first-class.
- [x] **A fact-builder assembles it from the three sources, wiring the full field set.** →
  `builder.py::assemble_fact_namespace`: (a) ENUM facts from typed columns; (b) STATED rows via the
  reused cross-source loading pattern (`selectinload`+`only_active`+ordering); (c) MATERIALIZED
  facts — bank-statement `transactions[]` and documented employers lifted out of the extraction JSON
  (the LP-116 fact-wiring gap), plus per-document typed fields on each `DocumentRef`.
- [x] **Absent facts marked ABSENT, distinct from empty.** → the generic `Fact[T]` tri-state
  (present / empty / absent). Marked absent: credit tradelines (`ABSENT_NO_SCHEMA`), documented loan
  amount, occupancy evidence, borrower current address + property county (`ABSENT_NOT_PERSISTED`),
  and any uncomputable calculator (`ABSENT_UNCOMPUTABLE`). Empty (source exists, no rows) is a value
  of `None`/`[]` with `absent=False`. Tested distinct.
- [x] **A general canonicalization mechanism (map → AI-fallback-for-misses → learn) at build time,
  frozen into the snapshot; unknowns never silently ignored; documented seam if AI unwired.** →
  `canonicalize.py` + the version-controlled `canonicalization_map.json`. Map hit → `CANONICAL_MAP`;
  a miss goes to the `CanonicalizationFallback` seam (`CANONICAL_AI` + confidence, learned back
  in-run); the default `NoFallback` records the miss as `UNMAPPED` (**no faked AI**). Applied to
  `income_type`/`asset_type`/`liability_type`; add a vocabulary to extend. Runs at build time — rule
  eval reads the frozen value.
- [x] **LTV/DTI/MI/reserves computed ONCE into the snapshot; uncomputable → absent, not zero.** →
  `_build_computed` calls the existing `build_ltv_calculation` / `build_dti_calculation` /
  `compute_loan_mi` / `build_reserves_view` once; `None` ratios → `ABSENT_UNCOMPUTABLE`. Tested (a
  property-less file → LTV absent, not 0).
- [x] **Persisted as an immutable per-run JSON snapshot (not a live KV/EAV table).** → a nullable
  `verifications.fact_snapshot` JSON column (migration `c8e1a4f9d2b7`) + `save_fact_snapshot` /
  `load_fact_snapshot` (typed round-trip: Decimal→string→Decimal, date→ISO→date, enums→value). One
  frozen record per run, aligned with the LP-140 trust-surface direction.
- [x] **CrossSourceFacts re-expressed as a projection; the 5 live rules behave identically
  (LF-6T3N regression).** → `projection.py::project_cross_source_facts` reproduces the legacy
  `build_cross_source_facts` **byte-for-byte** (same 11 fields; every other CrossSourceFacts field
  left at default so no dormant rule gains inputs). A regression test asserts
  `project_cross_source_facts(ns) == build_cross_source_facts(context)`.
- [x] **SCOPE HELD; live behavior unchanged; tests execute no rule.** → new package + additive column
  only; no live-path file touched; 7 tests assert assembly/round-trip/projection, none run a rule.
- [x] **`docs/tickets/LP-118.6.md` written** (this file).

## Assumptions and decisions

- **The live path was intentionally left on the legacy builder this ticket.** The AC wants
  CrossSourceFacts "re-expressed as a projection" so the 5 live rules are identical; the *safest* way
  to guarantee identical output AND honor "live path unchanged / no runner wiring" is to provide the
  projection and **prove** it byte-equal (a regression test), while leaving the cross-source task on
  the legacy `build_cross_source_facts`. So there is zero change to live findings, cost, or latency
  this ticket. LP-121 flips the runner to the projection. This is the "if feeding from a projection
  would change output, STOP and flag" instruction resolved conservatively.
- **The projection is deliberately NARROW.** The namespace is rich (documented income, transactions,
  …), but the projection populates only the 11 fields the legacy builder did and leaves every other
  CrossSourceFacts field empty — otherwise a currently-**dormant** rule (income-variance, undisclosed
  debt, …) would gain inputs and start firing, which this ticket must not do.
- **ABSENT vs EMPTY** is modelled by the `Fact[T]` wrapper (`absent` flag + a `FactSource` reason:
  `ABSENT_NO_SCHEMA` / `ABSENT_NOT_PERSISTED` / `ABSENT_UNCOMPUTABLE`). Empty = value `None`/`[]` with
  `absent=False`. Zero is never used to mean missing.
- **PII: SSN is stored MASKED (last-4) only.** The snapshot is a persisted record; full SSN stays in
  its encrypted column and is never written into the namespace. (The `ssn_consistency` rule is
  dormant; LP-120 decides how it compares.)
- **Canonicalization fallback is a documented seam, not faked AI.** No live AI call is wired here; the
  default `NoFallback` records misses as `UNMAPPED` so unknown strings are surfaced (never silently
  ignored). `learn` is in-run (deterministic within a run); persistent cross-run learning (write back
  to the map / a learned table) is a seam LP-120 owns. It's a cousin of the LP-120 DET-FUZZY matching,
  kept distinct (category canonicalization vs. fuzzy entity matching).
- **Reserves months** is reused from the public `build_reserves_view` (parsed from its formatted
  headline) rather than re-deriving the reserves inputs — reuse over a parallel calc. `"—"`
  (uncomputable) → absent.
- **Frozen Pydantic (not dataclasses)** for the models: keeps the immutability discipline AND gives
  the typed JSON round-trip the snapshot needs. Uses PEP 695 generics (`Fact[T]`).
- **Uneven entity addressing respected:** liabilities/assets/documents are file-level (not nested
  under borrowers); property is single (`uselist=False`); transactions are a materialized
  sub-collection. `borrowers[].documents[]` is shaped but empty (LP-118.8).
- **Snapshot home:** a JSON column on `verifications` (the per-run record). LP-140 can add a sibling
  results column so the fact snapshot + three-state results live together per run.
