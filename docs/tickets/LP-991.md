# LP-991 — Company mail domain and file address

Step 2 (Send), first ticket. No AWS or Terraform changes. The Send button still does not transmit
(LP-994).

## What and why

Every loan file's email address is now built from its file code on its company's own mail domain:

```
lf-<display_id lowercase>@<company's active domain>      e.g. lf-y36e@mail.staging.mortgageboss.ai
```

A company with **no active domain gets no address**. Nothing shows one and no template mentions one
(loan-email.md §3, "No active subdomain"). The alternative, showing some fallback address, would
tell a borrower to send documents somewhere that does not receive them.

That is exactly what happened before this ticket. `LoanFile.get_inbox_address()` returned
`lf-<inbox_token>@<INBOX_DOMAIN>`. That domain has never received mail, yet the document-request
templates told borrowers to "send them to" it.

The address no longer carries the token and is not a secret. The defence is the authenticated-sender
gate (DMARC pass plus a known contact on the file), not keeping the address hidden (ADR-397,
amended).

## What changed

**Table and model.** `company_mail_domains` (`app/models/company_mail_domain.py`), migration
`6e1f6b5aa190` (hand-written, with a working downgrade; up/down/up checked on the dev DB):

| Column | |
|---|---|
| `company_id` | FK to `companies`, unique (one domain per company), `ON DELETE CASCADE` |
| `domain` | string, unique, stored lowercase, no leading `@` or dot |
| `status` | `active` / `inactive` (VARCHAR + CHECK, like every enum here). Step 3 adds onboarding states and the zone, nameserver and SES identity columns to this same table |
| `created_at`, `updated_at` | |

It has a `readonly.company_mail_domains` view with every column (a domain names a company's
subdomain, not a person), so LP-998 can read the link back with `./scripts/deploy staging query`.

**Address function.** `app/services/mail_domain.py`:

- `active_mail_domain(db, company_id) -> str | None`
- `file_address(db, loan_file) -> str | None`: `f"{display_id.lower()}@{domain}"`. `display_id`
  already starts with `LF-`, so there is one `lf-`, not two (tested).
- `set_company_mail_domain(...)`: create or update the company's row; refuses a domain another
  company has. Used by the script and the dev seed.
- `normalise_domain`: lowercase, strips a leading `@`/dot and a trailing dot, refuses anything that
  is not a hostname.

**Callers.** `get_inbox_address()` is deleted, and its production-domain guard (LP-836) with it.
`PRODUCTION_INBOX_DOMAIN` and `settings.inbox_domain` stay: the config default and the inbound
resolver still use them.

| Caller | Now |
|---|---|
| `services/email_send.build_outbound` | sync, so takes `address: str \| None`. None → `reply_to` and `suggested_bcc` are None; the body is unchanged. Async callers (`send_draft`, `open_draft_preview`, `api/communications` draft endpoint, `services/message_detail`) look it up |
| `services/email_draft.render_draft_body` | takes `address`; renders `$file_address_phrase` |
| `api/timeline.py` | `inbox_address: str \| None` |
| `OutboundDraftPublic.reply_to/suggested_bcc`, `MessageDetail(Public).suggested_bcc` | nullable |
| `scripts/seed_dev_data.py` | links the dev company; its fake inbound mail now composes the token address itself, because the resolver still routes on it |

Comments that named the deleted method were corrected: `.env.example`, `core/config.py`,
`models/loan_file.py`, `models/mailbox_connection.py`, `scripts/visual-check/run.sh`, and one
comment line in `services/inbound_routing.py` (no code change there).

**Templates.** New versions; the old files are byte-for-byte unchanged and still pinned by hash
(`test_every_pinned_version_still_resolves_to_the_words_it_names`). `$inbox_address` became
`$file_address_phrase`, which renders the whole phrase or nothing. The template keeps the full stop,
so both cases end cleanly.

`initial_documentation_request` v4 → v5. Before (v4, lines 11–15):

```
You can reply to this message with them attached, or send them to:

  $inbox_address

Anything sent to that address reaches your loan file directly, so it does not get lost even when we are away from our desks.
```

After (v5, line 11):

```
You can reply to this message with them attached$file_address_phrase.
```

Renders as, with an address:

```
You can reply to this message with them attached, or send them to lf-y36e@mb-mail.localhost. Anything sent to that address reaches your loan file directly, so it does not get lost even when we are away from our desks.
```

and without one:

```
You can reply to this message with them attached.
```

The address is no longer on its own indented line; the reassurance sentence is kept, and goes with
the address.

`reminder_follow_up` v2 → v3 and `condition_response_request` v2 → v3, line 9 in both. Before:

```
You can reply with them attached, or send them to $inbox_address.
```

After:

```
You can reply with them attached$file_address_phrase.
```

Renders as `You can reply with them attached, or send them to lf-y36e@mb-mail.localhost.` or
`You can reply with them attached.` Neither template is rendered by any code path today.

**Existing drafts.** An unsent plain-text draft re-renders when its template version moves on
(`refresh_if_stale`, LP-848), so open v4 drafts pick up v5, with or without an address, the next
time they are read. Authored (HTML) drafts are skipped by that function, and sent messages are never
touched (they are the record of what went out).

**Frontend.** No new UI.
- Timeline panel: the "This file's address" line is hidden when `inbox_address` is null.
- Conditions empty state: the "Forward the lender's email" card is hidden when the address is null.
  Its text is "Forward it to this file's address", so it cannot stand without one. While loading
  (`undefined`) it shows as before.
- Mailto links (draft panel, message dialog): no `bcc` when `suggested_bcc` is null, instead of the
  literal `bcc=null`.
- Types: `inbox_address`, `reply_to` and `suggested_bcc` are `string | null`.

**Script.** `app/scripts/set_company_mail_domain.py`:

```
uv run python -m app.scripts.set_company_mail_domain <company id or exact name> <domain> [--inactive]
```

Creates or updates the row and prints `Name (id): domain [status]`. Refuses an unknown company, a
name shared by several live companies, a malformed domain, and a domain another company has (exit 1).

**Dev seed.** Links "Summit Mortgage Processing" to `mb-mail.localhost` through
`set_company_mail_domain`. A reset removes the row with the company (cascade).

**ADR-397.** A dated amendment: the new address form; the defence is the authenticated-sender gate,
not secrecy; no grace period; the resolver moves to `display_id` in step 4.

## What did NOT change

- The inbound resolver (`services/inbound_routing.py`) and Route B (`services/mailbox_connections.py`)
  still read `settings.inbox_domain` and route `lf-<inbox_token>@…`. Step 4 moves the resolver to
  `display_id`. Until then the address shown on a file is not the one the resolver accepts. That is
  harmless while no file address receives mail.
- The `inbox_domain` setting, `PRODUCTION_INBOX_DOMAIN` and the `INBOX_DOMAIN` env stay (removed in
  step 4).
- No AWS, no Terraform, nothing run in staging.
- Third-party and employer templates still carry no address (LP-843). That is now a product choice,
  not a secrecy one.

## Staging command for LP-998

Needs an image built from this tree deployed, and migration `6e1f6b5aa190` applied
(`./scripts/deploy staging deploy`). Both run `aws` with the `mbai-staging-admin` profile
(`aws sso login --sso-session mbai` first).

**Which company.** I could not tell from the repo. No seed or fixture creates a staging company,
and provisioning records (`C5-bootstrap-admin-result.md`, `LP-960.md`) do not name one. The SSO
session had expired, so I could not query. Find it first, read-only:

```bash
./scripts/deploy staging query -c "select id, name, slug, is_active, deleted_at is null as live from readonly.companies order by created_at"
```

If no test company exists, create one with `./scripts/deploy staging add-company` (LP-960). Keep it
separate from the pilot company (loan-email.md §3, "Pilot environment").

**Link it** as a one-off ECS task, the same way the deploy script runs its one-off tasks
(the migrate task definition, the API service's subnets and security groups, no public IP):

```bash
export AWS_PROFILE=mbai-staging-admin
COMPANY_ID=<id from the query above>
cd infra/envs/staging
CLUSTER=$(terraform output -raw ecs_cluster_name)
TASKDEF=$(terraform output -json ecs_task_definition_arns | jq -r .migrate)
API_SVC=$(terraform output -json ecs_service_names | jq -r .api)
cd -
CONTAINER=$(aws ecs describe-task-definition --task-definition "$TASKDEF" \
  --query 'taskDefinition.containerDefinitions[0].name' --output text)
read -r SUBNETS SGS < <(aws ecs describe-services --cluster "$CLUSTER" --services "$API_SVC" \
  --query 'services[0].networkConfiguration.awsvpcConfiguration.[join(`,`,subnets),join(`,`,securityGroups)]' \
  --output text)

aws ecs run-task --cluster "$CLUSTER" --task-definition "$TASKDEF" --launch-type FARGATE \
  --network-configuration "awsvpcConfiguration={subnets=[$SUBNETS],securityGroups=[$SGS],assignPublicIp=DISABLED}" \
  --overrides "$(jq -nc --arg c "$CONTAINER" --arg id "$COMPANY_ID" \
    '{containerOverrides:[{name:$c,command:["uv","run","python","-m","app.scripts.set_company_mail_domain",$id,"mail.staging.mortgageboss.ai"]}]}')"
```

`uv run`, not bare `python`: the image's `python` is not the app's virtualenv (LP-989 run notes).
The task prints `Name (id): mail.staging.mortgageboss.ai [active]` to `/ecs/mbai-staging/migrate`
(or the log group the migrate task definition names). Then confirm:

```bash
./scripts/deploy staging query -c "select company_id, domain, status from readonly.company_mail_domains"
```

## Open points

- No grace period for token addresses, per `loan-email.md` §3 (changed 2026-10-26) and ADR-397's
  amendment.
- Authored (HTML) drafts are not re-rendered by `refresh_if_stale`. One composed from v4 before this
  ticket could still contain an `imbox…` address. The dev DB has none. Staging was not checked.
  `readonly.communications` has no body column, but it can count the drafts at risk:
  `select count(*) from readonly.communications where status = 'draft' and body_format = 'html' and deleted_at is null and template_key = 'initial_documentation_request' and template_version in ('v1','v2','v3','v4')`.
