# LP-469 — Add the `form_1098` catalog type (Mortgage Interest Statement)

A full type addition — the LP-467 diagnostic confirmed `1098` is absent under both namings, with no spec and
no extractor. Two corpus documents (243, 244). The smallest real schema in the missing-extractor set, and the
most standardized shape there is (a fixed-box IRS form, like the W-2). Same four-piece mechanism as LP-465→468.

### A2 — the indicator (quoted)

> *an IRS Form 1098 "Mortgage Interest Statement" — the ANNUAL TAX form a mortgage servicer/lender furnishes
> for a calendar year, reporting mortgage interest received (Box 1), outstanding principal (Box 2), points,
> and often real-estate taxes in the free-text Box 10. It prints "Form 1098", "Mortgage Interest Statement",
> "Copy B For Payer/Borrower", and OMB No. 1545-1380. NOT form_1099 (a different IRS information return —
> reports income, not mortgage interest). NOT mortgage_statement (a MONTHLY servicer bill with an "amount due
> by" date — the 1098 is an ANNUAL tax form for a calendar year, "keep for your records"). NOT
> property_tax_bill (a taxing authority's bill — the 1098 only mentions taxes as free text in Box 10).*

Uses the form's own printed separators (the LP-465/468 approach): "Form 1098", "Mortgage Interest Statement",
"Copy B For Payer/Borrower", the OMB number.

### A3 — category and tier

**`form_1098` → PROPERTY, Tier 1.** Although it is an IRS information return (like `form_1099`, which is
INCOME_EMPLOYMENT), a 1098 reports a **mortgage on a property** — interest, principal, the property address,
and property taxes — not income. Its subject and its rule tie (DT-6, housing expense on a retained property)
and its nearest analogs (`mortgage_statement`, `property_tax_bill`, `payoff_statement` — all PROPERTY) place
it in **PROPERTY**. Tier 1 with a spec (the LP-441 invariant holds).

### A4 — PII registrations and the digit guard

Guard is `\b\d{9,}\b` (9+ contiguous digits). Against 243/244:
- **`borrower_tin_masked`** — shown **pre-masked** on the form (\*\*\*\*\*7007). Register **`(SSN, True)`**
  (pre_masked → last-4 display, no hash) — NEW registration. The prompt captures the last-4 as printed.
- **`account_number`** — `2016222628`, 10 digits → trips the guard → masked via the **existing** `(ACCOUNT,
  False)` registration (reused; no new entry). from_raw → masked display + a value-hash join key.
- **`lender_tin` — do NOT mask.** It is an **EIN** (`26-1193089`), a business identifier, not personal PII
  (LP-457: masking/blanking the employer EIN broke IN-5's equivalent — an EIN must stay readable). And the
  hyphenated EIN format (`XX-XXXXXXX`) has **no 9-contiguous-digit run**, so it does **not** trip the at-rest
  guard — it is safe to store unmasked. **No `_PII_FIELDS` entry for `lender_tin`.** (Note: the older
  `employer_ein`/`payer_tin` entries *are* masked — a prior choice I am not changing here; the ticket's rule
  governs this new field.)
- `lender_phone` (877-426-8805, dashed), ZIPs (5-digit), all Box amounts (< 9 digits) → safe, unmasked.

**Net new PII registration: `borrower_tin_masked` only.** No free-text scrub backstop needed (Box 10's
"Real Estate Taxes Paid $N" and Box 8's address carry no bare 9+-digit run; the account number is a typed
field, not free text).

### A5 — existing-naming check + generator acceptance

- **No `1098` / `form_1098` / `mortgage_interest` type exists** under any naming — confirmed absent from
  `catalog.py`, `classification_prompt.py`, `docs/schema-specs/`, and `app/ai/extraction/`. No duplicate
  concept; this is a clean addition.
- **`form_1098` is accepted by the generator.** The generator rejects a leading-digit `document_type`
  (`emitters.py:92`, `isidentifier()` → GenerationError, citing "1099" as the known case). `"form_1098"
  .isidentifier()` is `True`, and `form_1099` is the existing `form_*` precedent (module `form_1099.py`). So
  the name works from the start (the LP-441 lesson applied preemptively).

### FLAG — anything inexpressible

- Nothing blocks the build. This is a clean, standardized fixed-box form — the least ambiguous type in the set.
- One honesty note: `account_number` on a 1098 **is** the servicer's loan number (same value as the cover
  "Loan Number"); captured once as `account_number`, its value-hash joins to a `loan_number` on other docs.
