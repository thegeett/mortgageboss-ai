# LP-1002 — Remove the `.failed()` factory test from every extractor

Part of trimming the backend suite. Tests only, plus the generator's test template. No production
behaviour changes.

## What and why

Each of the 118 extractor test files (`tests/ai/test_*_extraction.py`) carried a copy of
`test_failed_factory`. It builds `<Type>ExtractionResult.failed("nope")` and checks that the status is
`FAILED` and the data is empty. That checks a five-line classmethod, and the same classmethod already
runs in every failure-path test in the same file (`test_extract_ai_failure_returns_failed`,
`test_all_null_core_is_failed`, and the unsupported/empty-input tests where present). All 118 copies
had the same body. Four of them added assertions (`confidence == 0.0`, one field `is None`, one list
`== []`) that `data == <Type>Extraction()` already implies, apart from `confidence`.

## What changed

- Removed `test_failed_factory` from all 118 files: −118 tests. Ruff removed the 232 imports that
  only that test used.
- Removed the test from the generator's template (`emit_test` in
  `app/ai/extraction/generator/emitters.py`), along with its two imports and the now-unused
  `prefix`/`extraction`/`result` locals. Without this, every newly generated extractor would bring the
  test back.
- Reworded the docstring in the 100 generated test files (and in the template) that said the factory
  "holds". Leaving it would have described a test that no longer exists.

## What is no longer checked

One thing is lost. No remaining test asserts that `.failed()` sets `confidence == 0.0`, or that its
data is completely empty: the failure-path tests check only `status`. If that matters, a single
parametrized test over `EXTRACTORS` covers it for every type. LP-1003, which moves the extractors onto
one shared implementation, makes that a single test.

## Verification

- `pytest tests/ai/generator tests/ai/test_*_extraction.py`: 1127 passed. The generator tests
  include `test_generated_passes_ruff[test]`, which runs ruff on the emitted test file.
- `ruff check app tests/ai`, `ruff format --check`, `mypy app`: clean.
- Full suite not run. These tests use no database fixture, and another session's pytest was using
  the shared test DB.
