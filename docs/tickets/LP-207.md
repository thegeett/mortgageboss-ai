# LP-207 — Calculations section assembler

## Summary

The third Stage-1 assembler: CALLS the four existing calculators (DTI, LTV, MI,
reserves) and maps their returned breakdowns into the snapshot's `calculations`
section (LP-204's `CalculationEntry`/`CalcBreakdownLine`). It **computes nothing**
itself and touches no other section.

Architectural decisions recorded in **ADR-244** (`decisions.md`).

## Acceptance criteria

- [x] `build_calculations_section(db, loan_file)` → `CalculationsSection`, invoking
      the four calculators.
- [x] Each result → `CalculationEntry {value, breakdown}`; **no breakdown line
      dropped**.
- [x] Per-line source tags passed through verbatim (not re-derived), incl.
      `override`.
- [x] Not-computed → `None` (DTI no income, LTV no value basis, reserves no PITI);
      never a fabricated 0.0. MI always present.
- [x] Money stringified (no silent float; LP-204 guard).
- [x] DTI income line tagged `stated` (transparency; no reconciliation here).
- [x] Cash-to-close is OUT (not a field).
- [x] No calculation math reimplemented (invoke-not-reimplement, asserted).
- [x] Unit + DB-backed tests; real-file smoke script.
- [x] ADR added (ADR-244) and referenced here.
- [x] CI green: ruff, mypy, snapshot suite.

## Phase 0 findings (incl. contradictions flagged)

- **Model names differ from the ticket:** the committed LP-204 has
  `CalculationEntry {value: dict, breakdown: list[CalcBreakdownLine]}` and
  `CalcBreakdownLine {key, label, amount: str|None, source: str, overridden}` —
  **`source` is a free string, not a `CalcSource` enum**. Reused as-is; the free
  string carries the calculator's `override` tag (a 5th value) losslessly.
- **Calculators:** `build_dti_calculation(db, *, loan_file, confidence_cutoff)` →
  `DtiCalculation`; `build_ltv_calculation(...)` → `LtvCalculation`; `compute_loan_mi(...)`
  → `MiComputation` (`.result`, `.inputs`); `build_reserves_view(db, *, loan_file,
  cutoff)` → `CalculatorView`. Line items = `{key, label, amount: Decimal, source,
  overridden}`; source vocab `stated/computed/extracted/manual/override`.
- **Not-computed signals:** DTI `back_end_dti is None`; LTV `ltv is None`; MI never
  (always determines `required`); reserves headline `"—"` (`months_available` None).
- **Reserves value** is the formatted `CalculatorView.headline` (raw months not
  exposed).
- **Real-file smoke blocked on dev DB:** DTI reads extractions; the dev DB lacks
  LP-201's `extractions.confidence` columns.

## Assumptions & decisions

- **Invoke-and-map (ADR-244):** the calculators are the source of truth; no math
  duplicated.
- **Source tags verbatim:** never re-derived; `override` survives (free-string
  `source`).
- **Not-computed = None:** honest; MI always present ("not required" is computed).
- **DTI uses stated income:** surfaced with `source=stated`; stated-vs-extracted
  reconciliation is a downstream finding, not here.
- **Money stringified;** reserves value is the calculator's formatted headline.

## Post-review hardening (code review, 2026-07-10)

The review flagged the reserves not-computed detection as fragile — it string-matched
the view's display placeholder (`headline == "—"`) with no shared constant and no real
test. See the [ADR-244](../../decisions.md) amendment.

- **[fragility] Structured not-computed signal.** `CalculatorView` gains
  `computed: bool` (default True); `build_reserves_view` sets it from
  `months_available is not None`. `map_reserves` branches on `not view.computed`, so a
  placeholder/format change can't fabricate a present reserves entry, and a `None`
  headline no longer slips through.
- **[typing] `map_reserves(view: CalculatorView)`** replaces `view: object` + getattr +
  `# type: ignore` (mypy was blind to the reserves mapping; the other three are typed).
- **[test] Real coverage** — a DB-backed test drives the actual `build_reserves_view`
  for a no-PITI loan and asserts `section.reserves is None` (the coupling was untested).
- **[cleanup] `_CalcLineItem` → `Protocol`** (drops the 3-schema union import);
  `_seed_loan_file` gains its return annotation.

Deferred: the calculators transitively recompute each other (LTV ×5, MI ×3, DTI ×2 per
snapshot — a calculator-layer coupling, fixed by threading precomputed inputs, not the
assembler); `map_dti` drops the visible housing/debt obligations when there's no income
(a design choice per ADR-244); `_money` is a 5th copy of the Decimal→str helper; and the
hand-listed `value` dicts can drift from the calculator schemas.
