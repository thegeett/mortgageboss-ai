# LP-608 — Five rules that cannot run and do not say what to do about it

## Found by audit, not by luck

The question was whether IN-3's problem — a fix text that asks for something already in the file —
occurs elsewhere. It is auditable: a rule needing **two or more** document kinds whose fix text names
fewer. Running that over the 78 active rules turned up something different and worse.

**Five rules declare no `couldnt_check_fix` at all**, while each needing two to four document kinds:

| rule | document kinds needed |
|---|---|
| `DT-7` | 4 — credit report, pay stub/W-2, bank statement, closing disclosure |
| `AS-4` | 2 — bank statement, retirement/brokerage |
| `ID-5` | 2 — government ID, closing disclosure |
| `PC-7` | 2 — purchase agreement, closing disclosure |
| `PR-2` | 2 — appraisal, purchase agreement |

With nothing to anchor to, the composer invents an action from the problem text. LF-3CVT shows it:

> **DT-7:** "Add the missing ability-to-repay documentation."

Four document kinds, none named. It restates the verdict instead of instructing.

That is worse than IN-3's fault. IN-3 asks for the wrong thing; DT-7 asks for nothing in particular.

## DT-7 needed a different fix from the other four

Judgment rules have **no `couldnt_check_fix` field** — checked, not assumed. DT-7's action comes from
`guidance.action`, and its live finding was `needs_review` rather than `couldnt_check` anyway, so that
field would not have applied even if it existed. Its action now names the documents, and the
`incomplete` case's fix maps each factor to the document that supports it, rather than saying "the
missing document for each unsupported factor" and leaving the reader to work out which.

## The other two categories

- **IH-3's class** — a fix naming fewer documents than the rule needs: the audit found **none left**.
  IH-3 was the only one and was fixed earlier today. (A first pass flagged CL-1 and CR-6; both were
  false hits from wording variance — CL-1 says "rate-lock confirmation" where the audit searched for
  "rate lock agreement".)
- **IN-3's class** — **not detectable by audit**, and worth stating plainly. Its spec looks correct:
  one document (`pay_stub`), one gated input (`income.ytd_annualized_shortfall_pct`), and a fix that
  names the document. The real blocker lives *inside* that derived tag's own dependencies, invisible
  at the spec level. The only way it surfaced was reading live findings on a real file.

That is the argument for the separate change of telling the composer which document types are
present: it works from what is on the file rather than from what the spec declares, so it also covers
the cases no audit can predict.

## A pinned test caught the fix

LP-530 forbids user-facing text that describes the software, and the first draft of all four new fix
texts said "The check compares...". The test named all four files. Reworded to describe the loan file:
"An unexpired ID with no closing date to compare it against leaves the question open."

## Tests

10, and the audit itself is kept as one — a new multi-document rule cannot join the five quietly.
Mutation-checked: removing the fix texts, and restoring DT-7's vague action, each fail.

Full suite: **5489 passed**.
