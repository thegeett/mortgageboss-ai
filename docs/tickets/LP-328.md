# LP-328 — Typed operands (GAP-A) + a hand-editable vocabulary (GAP-E)

## What it is

Two gaps blocking the waves:
- **GAP-A** (LP-323-ID-B): `deterministic.py` coerced EVERY operand to `Decimal`, so a date inequality
  between two fact-tags was inexpressible — blocking ID-5 AND every date rule (IN-2, PR-6, CL-1, CR-6, CR-13).
- **GAP-E** (LP-326 / LP-327): the vocabulary (`fact_tags.csv`) is GENERATED from a binary xlsx, so a wave
  could not add a tag in a reviewed PR. It blocked twice.

## Acceptance criteria

- [x] An operand DECLARES a `type` (default `decimal`, new `date`); a REGISTRY resolves it to a coercer;
  ONE type-agnostic comparator serves every type. No `if type == "date"` special-case (asserted).
- [x] **EQUIVALENCE:** AS-1 + ID-3 + ID-6 produce IDENTICAL results; their suites + the frozen LF-6T3N
  trace pass UNCHANGED. `decimal` is the default so no existing spec is edited.
- [x] Coercion failure / absent operand → couldnt_check, never a fabricated value; an unparseable date →
  couldnt_check (no silent epoch/0); ONE shared date parser (`coerce_date`).
- [x] ID-5 authored as data on the typed evaluator; the `>=` default + Priya note.
- [x] **GAP-E:** a NEW tag added by editing a version-controlled YAML overlay ONLY → projects (+ its
  allowed-values materializes); the generator/xlsx never overwrite it; a duplicate tag_id fails loud.
- [x] No rule-id/family branch; ruff + mypy + full suite green (**2060 passed, 1 xfailed**); the fact-tag
  generator stays green (xlsx untouched).

## Assumptions & decisions

- **TYPED operands, not a date special-case.** The spec declares the type; a registry resolves it. This
  is the pattern that held FOUR times (enumerators, normalizers, production modes, rule kinds). Adding
  `string`/`enum`-ordering later is one registry entry — `string` is nearly free (the comparator is
  generic; `str` is the coercer), `enum`-ordering needs a declared order (a future type).
- **`decimal` is the default → equivalence.** Every existing operand declares no type → `decimal` →
  `coerce_decimal`, and `compare_values(op, dec, dec)` is byte-identical to the former
  `satisfies(Condition(op, right), left)`. AS-1/ID-3/ID-6 + the frozen trace are the proof.
- **Never guess a date; absent ≠ empty.** An absent operand tag → couldnt_check with that reason (ID-5's
  non-expiring-state-ID edge — no expiration ≠ expired). An unparseable/ambiguous date → the coercer
  returns None → couldnt_check — never a silent epoch/0. The `date` coercer is the SHARED `coerce_date`
  (the same parser the consistency `date` normalizer uses — one parser, they can't disagree).
- **GAP-E: a hand-editable overlay** (`vocabulary_extra.yaml`), NOT the full inversion. `fact_tags.csv`
  stays the xlsx-generated bulk vocabulary; new (wave-added) tags go in the overlay — a PR-reviewed YAML
  the generator never touches, so it cannot overwrite a hand-added tag. Small, additive, zero-risk. **The
  fuller inversion** (all of `fact_tags.csv` hand-editable + retire the xlsx as a generated view) is a
  larger migration — recommended as its own ticket; the overlay meets the requirement now.

## Which rules activated vs waiting + why

- **ID-5 — authored, NOT activated.** It needs both date tags under ONE subject, but LP-326 keys
  `id.id_expiration` + `contract.closing_date` under DOCUMENT subjects (a deterministic loan rule reads
  one subject's tag map). Co-locating them under the loan subject (with a single-ID caveat) is a
  materialization follow-on. ID-5 evaluates correctly on a fixture (proven); it stays out of
  `ACTIVE_RULE_IDS` until its tags materialize under the loan subject (the LP-325/326 restraint).

## New generalization gap surfaced (reported, NOT patched)

- **Cross-subject operands.** A deterministic operand reads from the subject's own tag map only. ID-5's
  natural shape is per-borrower/per-ID-document expiration vs the LOAN's closing date — a cross-subject
  read the evaluator doesn't support. This is why ID-5 is authored loan-level (not per-borrower) and is
  the same family as ID-8's blocker. A cross-subject operand primitive is a separate ticket.

## What -C must cover for ID-5

The full matrix: expiration < closing → fired; == closing → the `>=` default (name the Priya assumption);
rate-lock-extension slippage (valid at application, expired at closing); a non-expiring state ID (absent
expiration → couldnt_check); date-format normalization on the expiration.
