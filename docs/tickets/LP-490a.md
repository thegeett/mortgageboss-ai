# LP-490a — Ratify-pending activation with model self-assessment

## What this ticket is

A fourth branch on the activation gate — **`ratify-pending`** — that activates a rule on a
**self-consistency rate** instead of a measured accuracy, with **ratification** as the safety substitute.
⚠️ This **inverts the gate's stated principle** (*"activation never trusts what it hasn't measured"*), a
deliberate product decision recorded in **ADR-378**.

## ⚠️ The outcome: the mechanism shipped, and NO rule activated

**`ACTIVE_RULE_IDS` stays 47.** The target was ~60. Every candidate failed a precondition the ticket
itself set — and the reasons are the ticket's real finding, so they are listed before anything else.

| rule | why it did not activate |
|---|---|
| **CR-8** | ⚠️ **Scored 1.0000 over 35 cases — and the rate is an artifact.** See below. |
| **CR-5** | 1 inquiry row across all three reports — nothing to derive twice. `null`. |
| **CR-6** | **0** derogatory events in the corpus. `null`. |

## ⚠️ The finding that matters most: CR-8's 1.0 is an artifact of a broken input

CR-8's four tags scored **1.0000 over 35 real tradelines, zero disagreements**. Under a field called
`self_assessed_accuracy` that reads as a perfect rule. It is not:

```
liab.is_mortgage                      derivation 1: {'unknown': 35}   derivation 2: {'unknown': 35}
liab.structured_history_confident     derivation 1: {'unknown': 35}   derivation 2: {'unknown': 35}
```

**Every value was `unknown`.** The cause is in the context builder, not the model:

```
payment_history_24mo   '[redacted]'
```

`_scrub_list_value` applies `_DESC_REDACT` — a **9+-digit** PII scrub — to every list value at the
context boundary. A `payment_history_24mo` string is a **long run of digits**, so the universal PII
backstop **eats the exact field CR-8 exists to read**. The model was handed the literal string
`[redacted]` and asked whether it could interpret the payment history. **`unknown` was the correct
answer.** The rule is structurally incapable of working today.

⚠️ **This is an ADR-286/289-class defect** — a tag that can never be right because the producer never
sees the data — and it was invisible until a real derivation ran. It also **vindicates the field
naming**: a `self_assessed_accuracy` of 1.0 would have activated a rule that cannot function.

**Not fixed here.** The scrub is a genuine PII backstop protecting every list field on every document;
narrowing it for one field is a change to a safety layer and needs its own ticket with its own reasoning
about what else a digit-run exemption would expose.

## What shipped

**The gate** — a fourth branch requiring `input_resolves` **and** a `self_consistency_rate` **and**
`measured_accuracy is None`. That last clause is load-bearing: it is what stops a consistency rate
overriding a measurement that already failed, which is exactly AS-4's case.

**The loader** — rejects a bar carrying **both** numbers, a `ratify-pending` bar with no rate, a rate
with **no case count**, and a rate over **zero cases**.

**The ratification wiring** — ⚠️ `deterministic.py` **never set `ratification_pending`**. Every
`ai_fuzzy_match` rule routes through that path, so a `ratify-pending` CR-1 or OC-1 would have shipped an
unmeasured AI judgment as an **auto** verdict with no human in the loop. Now enforced where the verdict
is built.

---

## The method, and the cost

**Fresh-context re-derivation**, as specified: call 1 produces the tag through the normal production
path; call 2 produces it again from the same source data in a **fresh context**, never shown the first
answer; the two independent answers are compared. **Not** same-context grading — the v2 bench measured
misclassifications at 0.75–0.99 confidence, so a model shown its own reasoning agrees with itself.

**Provider: AWS Bedrock** (`us.anthropic.claude-sonnet-4-5`, profile `mbai-dev`), 5 rpm.
**Cost: ~$0.30**, against a $0.50–$1.50 estimate reported before the first call. **The 303-document bench
was not re-run** — its already-extracted records were read in place.

⚠️ **Real borrower PII**: the harness lives in the scratchpad, reads the bench records in place, and
prints only aggregate rates and field-shape descriptions. No borrower content entered the repo.

## Assumptions and decisions

1. **AS-4's exclusion is structural, not a deny-list.** Its bar records 0/5 in prose but leaves
   `measured_accuracy: null`, so a naive "activate everything unmeasured" would have swept it in. The
   gate requires `measured_accuracy is None` **and** the loader rejects both-populated — so the honest
   fix is to populate AS-4's `measured_accuracy: 0.0`, which is a data change left for its own ticket.
2. **Nothing was activated on a vacuous rate.** Where the corpus has no instances of a trigger, the rate
   is `null` and the rule stays held — the ticket's own rule, applied even though it cost the target.
3. **Nothing added to `_BASE_ACTIVE`.**

## What this changes downstream

- **The mechanism is proven but unused.** The first rule to use it must replace
  `test_ratify_pending_wires_ratification_through_evaluation` with a per-rule proof through a real rule
  evaluation — the test fails deliberately when a rule appears on the status, so this cannot be skipped.
- **CR-8 is blocked on a PII-scrub fix**, not on calibration. That is a different ticket and a different
  kind of work.
- **The corpus is the binding constraint**, not the code. Four of the six credit rules have no instances
  of their trigger anywhere. No gate change fixes that.

## ADR

**ADR-378** — the inverted principle, what a self-consistency rate is and is not worth, the accepted cost
and its dependence on the ratification wiring, and the exit through processor confirmations as real
labels.
