# LP-389-A — Fix ID-5's subject mismatch: check every borrower's ID expiration

## What this ticket is

LP-389 found ID-5 **structurally dead**: its inputs (`id.id_expiration`, `contract.closing_date`) materialize on
the **document** subject, but ID-5 read them at the **loan** subject — so it couldnt_checked on every file, and
its tests passed only because they hand-placed the tags at `"loan"` (a fixture asserting a fiction — the
AS-1/ID-2/OC-2/LP-321a class, a **fifth** instance). Priya's call: **ID-5 checks EVERY borrower's ID**
(per-borrower, one verdict each). This ticket implements that by reusing LP-385's per-borrower shape, then
activates ID-5 (13 → 14).

## Acceptance criteria

- ID-5 enumerates **per borrower** and reads that borrower's **`belongs_to`-attributed** driver's-licence
  expiration against the loan's single closing date — through the REAL materialization path.
- Fail-closed: a borrower with no attributable DL → couldnt_check **with a reason**, never a guessed pass.
- Per-borrower isolation: one borrower's DL never satisfies another's check.
- The fiction-asserting tests are rewritten to the true path.
- `id.id_expiration` stays a document fact; `contract.closing_date`'s scope is not changed; no per-rule branch.
- ID-5 passes the eligibility gate and activates (13 → 14); full suite (ruff + mypy + pytest) green.

## Phase 0 — the argument (premise verified, one correction)

**The bug (verified).** ID-5's spec read `tags.by_subject["loan"]["id.id_expiration"]` and
`[...]["contract.closing_date"]`; both are declared `subject: document` (tag_production.yaml) and materialize on
`dl1`/`dl2`/`pa1`. They never reach `"loan"` → ID-5 couldnt_checks on every file. Its tests hand-placed the tags
at `"loan"`.

**D1 — how a per-borrower rule reads a document-subject tag.** The `_per_borrower` enumerator's tag map is
`{**loan_tags, **by_subject[borrower_id]}` — it does **not** include document-attributed tags. LP-385's answer
(reused here): a **derived per-borrower producer** promotes the document fact under `by_subject[borrower_id]` via
`belongs_to` attribution (exactly `_borrower_documented_monthly`). No per-rule branch.

**D2 — what changes: the read path, not the tag's subject.** `id.id_expiration` STAYS `subject: document` (a
DL's expiration *is* a document fact). New derived **borrower**-subject tag `id.borrower_id_expiration` promotes
it (recipe `_borrower_id_expiration`); ID-5 re-scopes to `per_borrower`. The income and ID recipes now share one
extracted `_borrower_attributed_documents` primitive — one attribution mechanism, not two.

**D3 — the closing date. GATE-OF-RECORD CORRECTION:** the ticket assumed `contract.closing_date` is loan-level.
It is `subject: document` (materializes on `pa1`). To honor the intent (one loan-level closing date) *and* "do
not change `contract.closing_date`," a new derived **loan**-subject tag `contract.loan_closing_date` promotes it
(mirroring `housing.insurance_monthly`); ID-5 reads it via a `loan_tag` operand. `contract.closing_date` itself
is untouched. (CL-1/PC-7 also reference `contract.closing_date` in rule_tags.csv but have **no spec files** —
they are unimplemented placeholders, so ID-5 was its only real consumer.)

**D4 — the fiction tests.** `test_typed_operands` and `test_identity_family_eval` placed ID-5's tags at `"loan"`;
both are rewritten to the true subjects (borrower + loan) with a `belongs_to` document so the enumerator yields
the borrower. A new `test_id5_per_borrower_lp389a` pins the full documents → `materialize_tags` → per-borrower
path.

**Two reported gaps.** (1) `id.id_expiration` is not doc-type-scoped (`homeowners_insurance` also emits
`expiration_date`) — the recipe scopes to `drivers_license`, so a policy's expiry never leaks into an ID check.
(2) A borrower with ZERO attributed documents isn't enumerated (inherent to the document-driven per-borrower
shape) → no ID-5 verdict; a borrower with any document but no DL IS checked (couldnt_check). Closing the
zero-document gap needs a MISMO-borrower-driven enumerator — a separate change.

## Phase 1 — re-scope ID-5 per-borrower

- **New derived tags** (`vocabulary_extra.yaml`, `tag_production.yaml`, recipes in `derived.py`):
  `id.borrower_id_expiration` (borrower, date) ← the borrower's `belongs_to`-attributed **driver's-licence**
  `id.id_expiration`; `contract.loan_closing_date` (loan, date) ← the file's `contract.closing_date` promoted.
  Both fail-closed to `unknown` with a reason; conflicting values → `unknown` (ambiguous), never a picked value.
- **Shared primitive** `_borrower_attributed_documents` extracted and reused by the income + ID recipes.
- **ID-5 spec**: `subject_enumeration: per_borrower`; operands `id_expiration = tag id.borrower_id_expiration`
  (date), `closing_date = loan_tag contract.loan_closing_date` (date); both gated; the `>=` outcome logic
  unchanged.
- **Reason labels** for the two new tags (ID-5 is now a live rule).

## Assumptions & decisions

- **`contract.loan_closing_date` is a new loan tag, not a change to `contract.closing_date`** — honors the
  SCOPE-OUT and the document-fact→loan-promotion pattern; `contract.closing_date` (document) is untouched.
- **`id.id_expiration` stays a document fact** — the DL's expiration is a document fact; only ID-5's consumption
  moved per-borrower.
- **`rule_tags.csv` (generated from the vocabulary xlsx) is unchanged** — its `ID-5 → id.id_expiration` edge is
  still transitively valid (id.id_expiration is the document source the borrower promotion reads); the
  informational edge is not used for gating (that is `spec.gated_tags`). Adding the two new tags to the xlsx is a
  documentation follow-up, not required for behavior.
- **No per-rule branch; one shared attribution primitive** (`_borrower_attributed_documents`).
- **Reported limitation:** the zero-document borrower gap (above) — its own ticket.

## ADR

ADR-307 — the fifth structural-dead instance; Priya's per-borrower decision; the reused LP-385 shape (tag stays
document-subject, consumption becomes per-borrower; the closing date promoted to loan level); the fiction-
asserting tests rewritten to the true path.
