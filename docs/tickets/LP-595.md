# LP-595 — Findings were nearly all filed under "assets"

## What was wrong

`_RULE_CATEGORY` had nine entries and `reconcile_run` took
`default_category=FindingCategory.ASSETS`. There are **78 active rules**. So the other sixty-nine —
every income rule, both appraisal rules, the rate-lock rule, the mortgage-insurance rules — were filed
as `assets`.

On LF-3CVT that was twenty-eight of thirty findings in one category. Grouping or filtering by category
was not merely incomplete; it was confidently wrong, which is worse, because it looks authoritative.

It survived because a misfiled finding is **silent**. Nothing errors, no test failed, and the only way
to notice is to read a category column on a real run and find PR-6 (appraisal) sitting under assets.

## What was built

Resolution is now per-rule, then per-family, with no silent fallback.

**`_FAMILY_CATEGORY`** — derived from what each family *asks*, read out of the spec titles rather than
guessed from the prefix letters. That distinction did real work:

- `CO` is condo-project documentation → property
- `IH` is hazard insurance **on the property** → property
- `RE-1` is an undisclosed **mortgage** — a debt, not a property fact → credit
- `LO-2` is letter-of-explanation completeness → documentation
- `AU`, `CL`, `MI`, `PE` are all program/compliance obligations → regulatory

**`_RULE_CATEGORY`** now holds only overrides, which win over the family. Two exist: the `ID` family
splits (1/2/3/4 compare a fact *across sources*; 6/7/9 are about a document), and `DT-7` is ATR — a
Dodd-Frank obligation, not a reading of the borrower's debts.

**`category_for_rule()` returns `None` rather than guessing**, and the call site resolves every active
rule up front. The fallback in `rule_findings.py` now logs `finding_category_unresolved` when it fires,
so the failure that hid sixty-nine misfiled rules can no longer happen quietly.

## Tests

`tests/services/test_finding_category_lp595.py` — five, and the load-bearing one is
`test_every_active_rule_has_a_category`: a new rule whose family is not in the table now **fails CI**
instead of landing in assets on a processor's screen.

`test_the_assets_category_is_no_longer_a_dumping_ground` pins the regression directly — no non-`AS-`
rule may resolve to assets, and assets must stay under a quarter of the engine.
`test_overrides_are_not_restating_their_family` catches a future edit that changes a family and leaves
a now-redundant override reading as a decision.

Mutation-checked: removing a family, and inverting override precedence, each fail. All 54 tests across
the four suites that touch categories still pass.

## Not done here

The category vocabulary itself is unchanged (seven values, no "other"). Several assignments are
defensible rather than obvious — `CL-1` as regulatory over documentation, `PC-7` (closing-date
realism) inheriting property from its family — and are worth a pass with the domain expert. The
structure now makes changing one a one-line edit with a test behind it.
