# LP-113 — Relax truncated finding descriptions to a useful multi-line preview (Details for full text)

- **Ticket:** LP-113
- **Status:** Completed
- **Date:** 2026-07-04
- **Scope:** Frontend-only

## The bug

On the verification findings list, a finding card's DESCRIPTION/reasoning preview was clamped to a
SINGLE line and cut off mid-word — e.g. "A bank statement fragment references 'KASHS BANK …6684' but
provides no account holder name, account type, balances, or statement period, making it impossible to
veri…". A one-line mid-word cut reads as broken, not as an intentional preview, and gives the
processor no useful context without clicking Details. This is the SAME one-line-clamp bug LP-104
fixed for NEED titles — now on the finding card's description.

## The mechanism (confirmed, independent — not a shared component)

An inline **one-line CSS clamp**, in `components/file/verification/finding-card.tsx`:

```tsx
<p className="mt-0.5 line-clamp-1 text-xs text-gray-500">{collapsedWhat}</p>
```

`collapsedWhat` is the collapsed preview of the finding's specifics; the FULL text (`whatWeFound`)
already renders in the **Details** expansion ("What we found"). So only the preview was clipped.

The clamp is **independent**, not a shared truncation component: LP-104 fixed the need-title version
by removing an inline `truncate` in `need-card.tsx`; this one is an inline `line-clamp-1` in
`finding-card.tsx`. Each card clamps with its own Tailwind utility — there is no shared text-clamp
component to fix centrally.

## The fix

`finding-card.tsx` — the description preview only: `line-clamp-1` → **`line-clamp-3`**. A useful
~3-line preview (chosen over 2 because these descriptions are long — 2 lines still cut most of them
short), keeping the list scannable while readable. The full text stays in the Details expansion. The
TITLE (already wrapping), the metadata line (type · confidence · AI·novel pill · Details · source
p.N), the action buttons, and the Details expansion are all untouched.

## Shared-pattern check (this was the 2nd instance — is there a 3rd?)

Surveyed every `line-clamp` / description-`truncate` in the frontend:

- **No other `line-clamp`** anywhere (finding-card was the only one).
- `truncate` elsewhere is on **labels / filenames / values**, where a single line is intentional:
  calculator line-item labels, overview field values, document filenames in the drawer. Not
  long-description previews.
- **One candidate to flag (NOT fixed here):** `components/file/documents/document-list.tsx` truncates
  `document.summary` to one line in a **compact list row**. That summary is a **"short gist" by design
  (LP-65)**, and the row is a dense list (no Details expansion), so one line is likely intentional
  rather than the same broken-mid-word-cut-of-a-long-description bug. Reported as a possible
  consistency follow-up if the summary ever reads as cut — deliberately left out of this ticket's
  scope (finding-card description only).

No third instance of the actual bug is left lurking.

## Verification

- Finding descriptions show a useful ~3-line preview (`line-clamp-3`), not a one-line mid-word cut;
  Details still expands to the full text.
- Not unclamped to unlimited (3-line balance — scannable + readable).
- Title / metadata / actions / AI·novel pill / source link / Details expansion unaffected; the card
  grows gracefully when the description wraps.
- Independent clamp confirmed (no shared component); other cards surveyed and reported.
- biome / tsc / build pass; 51 verification component tests pass.

_(No ADR — a small, self-contained UI clamp relaxation; the LP-104 precedent already recorded the
pattern.)_
