# LP-993 — Build and send the email

Step 2 of the email work (`loan-email.md` §15a). Code, tests, a dev check and one email to the SES
mailbox simulator. No AWS or Terraform changes.

## What and why

Two pieces that LP-994 will connect to the Send button. **Nothing is wired to Send in this ticket**:
no existing code path calls either of them.

1. **`build_mime(...)`** makes the complete email from plain values: From, To, Cc, Reply-To, subject,
   body, threading. It touches no database and decides nothing about whether to send.
2. **A mail sender**, `send(message) -> provider message id`, in two versions: Amazon SES (staging)
   and SMTP to MailHog (dev). The `MAIL_TRANSPORT` setting picks one; unset means nothing transmits
   and the processor keeps copying the message out herself.

## What changed

**`app/services/outbound_mime.py`: `build_mime`.** Keyword-only inputs: `from_name`,
`from_address`, `to` (one address or a list), `cc` (optional), `reply_to` (the file address, or None
when the file has none), `subject`, `body`, `html`, `in_reply_to` and `references` (optional),
`headers` (optional, for automated mail later). Output: an `EmailMessage` with

- `From: "Priya Thaker, ABC Mortgage" <lf-…@domain>`, built with `email.headerregistry.Address`, so a
  comma in the display name is quoted and a non-ASCII name is encoded;
- `To`, `Cc` (only when given), `Reply-To` (only when given), `Subject`, `Date`;
- our own `Message-ID` on the from-address domain (`make_msgid(domain=…)`). SES may replace it;
  LP-998 records which one arrives;
- `In-Reply-To` and `References` only when given;
- body: `html=False` → one `text/plain` part, UTF-8. `html=True` → `multipart/alternative`,
  `text/plain` first, then `text/html`;
- the SMTP policy, so `as_bytes()` is the wire form (CRLF) that SES and SMTP both take.

It refuses (`ValueError`) a CR or LF in any header value (subject, names, addresses, threading ids,
extra headers), an empty `to`, an address without a local part and a domain, and an extra header that
names one it manages (`Bcc`, `From`, `Message-ID`, …) or is not a valid header name. It never sets
`Bcc`, and it has no attachment parameter (GLBA, as `OutboundEnvelope` says).

**The plain-text part of an HTML email.** No backend HTML-to-text helper existed, deliberately:
`communications/sanitise.py` says the only plain-text derivation is the frontend's `from-html.ts`
(used for `mailto:`, and it must round-trip), and a second one would be two answers to one question
(A22). The brief allowed a minimal one, so `outbound_mime.html_to_text` is one: paragraphs and `<br>`
become line breaks, `<li>` becomes `- `, tags go, entities are decoded, scripts are dropped, and a
link keeps its address (`Upload securely (https://…)`), because a text-only reader cannot click.
**This is a second derivation**, for a different reader (a text-only mail client, never the
processor's screen) and it never converts back. It can differ from `from-html.ts` in small ways
(spacing, bullet marks). `sanitise.py`'s docstring now says so. Worth a decision if that is not
acceptable: the alternative is for LP-994 to send the plain text the frontend already derives.

**`app/services/mail_sender.py`.**

- `MailSender` (abstract): `send(message: EmailMessage) -> str`. Sync.
- `SesMailSender`: a `boto3` `sesv2` client in `settings.s3_region` (the app's only general AWS
  region setting; staging sets it from `var.aws_region`), `Config(connect_timeout=5,
  read_timeout=30, retries={"total_max_attempts": 1})`. Calls `send_email(FromEmailAddress=<From
  address>, Content={"Raw": {"Data": message.as_bytes()}}, ConfigurationSetName=…)` with no
  `Destination`, so SES takes the recipients from the To and Cc headers. Returns `MessageId`.
  Refuses (before any call) when `SES_CONFIGURATION_SET` is unset.
- `SmtpMailSender`: `smtplib.SMTP(smtp_host, smtp_port, timeout=10)`, `send_message`, returns the
  email's own `Message-ID`. Dev only; no login or TLS.
- `get_mail_sender()`: `"ses"` → SES, `"smtp"` → SMTP, unset → None.
- Failures raise `SendError`, a subclass of the existing `TransportError` (`services/mail_transport.py`,
  otherwise unchanged), carrying `code` (the AWS error code, e.g. `MessageRejected`,
  `AccountSendingPausedException`, `MailFromDomainNotVerifiedException`, or the exception name for a
  network failure) and `outcome_unknown` (see below). Only the code is logged: never a recipient,
  subject or body.

**Settings** (`core/config.py`): `mail_transport: Literal["ses", "smtp"] | None` and
`ses_configuration_set: str | None`, both blank-is-None like the other optional strings. Staging
already sets `MAIL_TRANSPORT=ses` and `SES_CONFIGURATION_SET=mbai-staging-outbound` (LP-988).
`.env.example`: `MAIL_TRANSPORT=smtp`, `SES_CONFIGURATION_SET=`, each with a comment.

**Compose.** `backend/.env` sets `SMTP_HOST=localhost`, which inside a container is the container
itself. `docker-compose.yml`'s worker and `docker-compose.images.yml`'s api and worker now set
`SMTP_HOST: mailhog`. The API in normal dev runs on the host, where `localhost:1025` is MailHog's
published port, so it needs nothing.

**Script** `app/scripts/send_test_email.py --to <address> [--html] [--from-address …]`: builds a
sample email (From "Test Processor, MortgageBoss Test" `<lf-test@mb-mail.localhost>` by default, CC
the same test address, Reply-To the From address) and sends it through `get_mail_sender()`; prints
the provider message id. Refuses when no sender is configured, and **with SES refuses any recipient
outside `@simulator.amazonses.com`**, so the script cannot email a person.

## Why there are no retries in the SES call

botocore retries timeouts and 5xx answers by default. If SES accepted the email and only its answer
was lost, a retry sends the borrower the same email twice, and nothing can take it back. So the
client makes one attempt.

**`total_max_attempts`, not `max_attempts`.** The brief asked for `retries={"max_attempts": 1}`.
botocore's `max_attempts` counts *retries*, so that setting means one retry and two sends; measured,
the client's config became `total_max_attempts: 2`. `test_ses_makes_exactly_one_attempt` makes SES
answer 500 and counts the HTTP requests: 1 with `total_max_attempts: 1`, 2 with the brief's setting
(mutation checked).

A lost answer is not a clean failure. A read timeout or a dropped connection after the request went
out raises `SendError(outcome_unknown=True)`: the email may have gone. A connect failure or an SES
refusal is `outcome_unknown=False`: it did not.

## For LP-994

```python
from app.services.mail_sender import SendError, get_mail_sender
from app.services.outbound_mime import build_mime

message = build_mime(
    from_name=f"{approver_name}, {company_name}",
    from_address=file_address,           # lf-…@<company domain>
    to=recipient,
    cc=approver_email,
    reply_to=file_address,
    subject=draft.subject,
    body=draft.body,                     # footer tag already in it
    html=draft.body_format is BodyFormat.HTML,
    in_reply_to=…, references=…,         # when replying in a thread
)
raw = message.as_bytes()                 # save to outbound/<id>.eml (get_mail_storage) before sending
sender = get_mail_sender()               # None → stay on copy-and-send
provider_id = sender.send(message)       # → external_message_id
```

- The SES call is **sync** and can take up to 30 seconds. The worker is sync, so call it directly;
  from async code use `asyncio.to_thread`.
- `SendError.outcome_unknown` is the "sending not confirmed" case: leave the row for a person, do not
  mark it failed and unwind (the email may have gone). `outcome_unknown=False` is a clean failure.
- A `ValueError` from `build_mime` is our bug or bad data (a newline in a subject), not a provider
  failure: nothing was sent.
- `loan-email.md` §15a sketched the transport as `send_raw(mime_bytes, sender, recipients) ->
  SentResult`. The brief's `send(message) -> str` was built instead; the recipients come from the
  headers.
- `boto3` is not a direct dependency in `pyproject.toml`; it comes with `anthropic[bedrock]` and
  `aioboto3`, as `botocore` already does for `storage/s3.py`.
