# LP-611 — Four defects from the bank-statement run

## 1. A raw borrower UUID in front of a processor

> "borrower **7558383f-dfbb-47c3-8b3f-aa1ca5494987**: documented monthly income is absent…"

`derived.py` embedded `subject_id` into 28 tag reasonings. Those reasonings are engineer-facing
provenance **and** the text a `couldnt_check` finding shows, so the id reached the screen. The finding
already carries the subject, which resolves to the borrower's name — so it was redundant as well as
leaked. All 28 now read "this borrower".

Third identifier shape to get out: a dotted tag id, then a content id (`doc<hex>`), now a dashed UUID
that neither pattern matched. `leaked_identifiers` covers the family now rather than the instance.

## 2. A name check contradicting ID-1 — the same bug as LP-606, one rule over

| | verdict |
|---|---|
| **ID-1** | satisfied — "The borrower's name is consistent across all income and identity documents." |
| **`xsrc.identity.name_consistency`** | yellow — "Borrower name differs across sources: ADITYA TALLURI (pay_stub); **TALLURI ADITYA** (drivers_license); aditya talluri…" |

Surname-first is how a driver's licence prints a name, and case is not a fact about a person. Its
`_norm` folds case and whitespace and nothing else, so it cannot tell a name *order* from a different
human being; ID-1's tolerant comparison can.

**Retired**, exactly as LP-606 retired its employer sibling. I fixed one and left the other, which is
the argument for auditing a family rather than patching an instance.

## 3. Converting correctly and still calling it a conflict

LP-607 fixed the arithmetic. The next run produced:

> "Stated monthly income of $13,166.67 conflicts with documented biweekly gross pay which **converts
> to approximately $13,136 per month**"

Two tenths of one percent, described as a conflict. Income documents never match a stated figure to
the dollar — a stub covers a different period, a bonus lands in one month — so a small difference is
the normal state of a correct file.

The prompt now names a threshold, and it is **not invented for the prompt**: ten percent is the bar
`_check_income_variance` already uses, so the AI filling that rule's gap applies the same standard
rather than a stricter one. A test pins the two together.

## 4. A discrepancy between two different accounts

> "Stated Bank of America checking account with $10,000, but documented **Wells Fargo** account shows
> only $6,526.74"

Two accounts at two banks. That their balances differ is not a finding; the honest observation is that
the stated account has no statement. The prompt now requires checking that both sides are the same
object before calling their difference a discrepancy.
