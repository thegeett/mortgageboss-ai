# LP-393-1 — Standalone income-scenario snapshot builder for thin-n calibration

## What this ticket is

Six rules (IN-7, IN-10, IN-11, IN-12, IN-13, AS-11) are blocked purely on SAMPLE SIZE: their tags are
per-borrower and LF-6T3N has only **2 borrowers**, so each caps at **n=2** (AS-11 at n=3) — a smoke test, not a
measurement (LP-390-5/6; LP-392 confirmed the ceiling on real data). The wiring is fixed (LP-385/390-1) and the
tags produce; **the ceiling is the FILE, not the code — a DATA problem.** This builds a STANDALONE synthetic
snapshot with ~11 scenario borrowers (+ asset accounts) so those tags reach n>=6 and can be calibrated. It is
**Level 1** (a synthetic snapshot of parsed data structures, NOT generated PDFs): it measures the AI's
REASONING about income scenarios, which is what is blocked; extraction is separately calibrated.

## Acceptance criteria (met)

- A standalone `build_income_calibration_snapshot()` with own loan/borrower/content ids — **no LF-6T3N
  collision**, never merged, LF-6T3N byte-unchanged (asserted both ways).
- Each scenario borrower carries only its scenario's minimum documents.
- The income tags + `asset.liquidation_terms` reach n>=6 (reported).
- The ambiguous scenarios carry NO encoded answer; the clear-cut expectations live in code/tests, never a
  worksheet.
- No tag/rule/producer/prompt change; `ACTIVE_RULE_IDS` unchanged (20); full suite green.

## Phase 0 — the argument (D1-D4)

- **D1 — the minimum borrower.** The per-borrower enumerator reads `borrower.{n}.borrower_id` from MISMO; the
  context (`subjects._borrower_context`) = that borrower's MISMO facts + the documents `belongs_to`-attributed
  to it, filtered to the income types. So the minimum viable borrower = **one `borrower.N.borrower_id` MISMO
  fact + N income documents with `belongs_to`** — no bank statement, no DL, no MISMO beyond the id.
- **D2 — the fields that drive each tag** (verified against the prompt, not assumed): `has_2yr_history` /
  `is_declining` read `tax_year` + `wages_tips_other_comp` across the docs; `same_line_of_work` reads
  `employer_name` + the role (an `occupation` field — the context sends ALL document fields); `continuance_3yr`
  reads a STATED income end (`end_date` on a VOE). The scenarios vary exactly those.
- **D3 — separation.** Own id namespace (the `93…` prefix for loan/borrower ids; `inc-*` content-ids),
  disjoint from LF-6T3N's `11111111…/22222222…` + doc ids. The module imports neither LF-6T3N builder and they
  do not import it (asserted by source inspection); LF-6T3N still has exactly 2 borrowers after building this
  (asserted).
- **D4 — can `continuance_3yr` be exercised?** Only partly, honestly. It reads a STATED income end; standard
  W-2 employment yields `unknown` (LP-385). A fixed-term VOE with an end date (B14) produces `no` — so the tag
  gets a real but NARROW n. `continuance_3yr` cannot easily reach `yes` (documents rarely evidence a 3+ year
  horizon), so **IN-13 stays thin even with the probe** — it needs fixed-term/other-income variety AND
  `income.type` (a different producer), not just more borrowers. **IN-12 cannot be exercised at all here:** it
  needs `has_2yr_history` for a SELF-EMPLOYMENT (tax_return) borrower, but income_stability reads only
  w2/pay_stub/voe/1003 — a tax-return-only borrower yields `unknown`. IN-12 stays blocked on the producer gap
  (LP-390-2a), not on n.

**Ambiguous outputs (reported, NOT judged — Priya's blind labels decide in LP-393-3):** B9 (2% drop) → the AI

the tag works when a stated end exists, but standard employment abstains — n stays at 1.

**Per-borrower isolation:** every borrower produced its tags from only its own documents (the context count
equals the borrower's own attributed docs — asserted keyless).
