# LP-117.5 — Commit reference docs + reserve `playbook_id` + Phase 3.5 architecture ADR (foundation)

**Type:** Chore / Foundation · **Epic:** Phase 3.5 / Epic A · **Blocks:** LP-118
**Status:** complete · **Date:** 2026-07-07

## What this ticket is

Phase 3.5's engine plan references playbook IDs (`AS-1`, `CR-4`, …) throughout, but the LP-116
audit found (a) the reference documents existed only as external artifacts, not committed repo
files, (b) no rule carried a `playbook_id`, and (c) the cross-cutting architecture decisions made
after the audits were recorded only in the external plan, not in the repo. This ticket fixes all
three — it **commits the reference docs under `docs/rules/`**, **reserves `playbook_id` as a
first-class, additive, nullable field** on the current live-rule layer, and **records the Phase 3.5
engine architecture as ADR-239** — so downstream tickets rely on committed, version-controlled
sources + a stable `playbook_id`, and the "why" of the architecture lives in the codebase. It does
**not** build the runtime table (that is LP-118, now done) and changes **no rule behavior**.

> **Note:** this is the expanded re-run of LP-117.5. The docs + `playbook_id` + seed work landed
> earlier; this pass adds the **Phase 3.5 architecture ADR** (ADR-239, step 5.5) grounded in the
> [fact-namespace-foundation](../audits/fact-namespace-foundation.md) audit.

## Assumptions and decisions

- **Docs location = `docs/rules/`.** Matches the existing `docs/<area>/` convention
  (`audits/`, `phases/`, `tickets/`) rather than inventing a new scheme.
- **`.docx` → markdown conversion (not committing the binaries).** The two files arrived as Word
  `.docx` with a doubled `.md.docx` extension. Committing binary Word docs would defeat "version
  controlled, not external artifacts," so they were converted to real markdown and the `.docx`
  removed. Conversion is a faithful format change, not content authoring — verified row/heading
  counts and spot-checked full cell text.
- **Seed generated, not deferred.** The xlsx was readable via `uv run --with openpyxl` (an
  ephemeral dependency — project deps untouched), so the seed was generated. The 133 rows were
  **not** hand-typed.
- **Seed preserves the playbook's real vocabularies verbatim.** The actual `Status`/`Scope`/`Layer`
  values are richer than the ticket's simplified examples (`Status` includes `EXTRACT`, `BLOCKED`,
  `NOW`, `EXISTS?`, `SCOPE?`, `IN PROGRESS`, …; `Scope ∈ {IN, ?, OUT}`). Rather than force them
  into `IN/PHASE 4.5/V2` + `NOW/EXTRACT/BLOCKED`, the seed carries them as-is; LP-118 treats them
  as data.
- **Conservative `playbook_id` mapping.** Populated only where the playbook rule name/semantics
  match a live rule unambiguously (mostly the identity + income + gift + large-deposit rules).
  The fraud/red-flag rules (`dl_equals_subject`, `employer_equals_subject`), the count check, the
  reverse-liability/asset-missing checks, and the generic subject-address/loan-amount checks were
  left null — a wrong mapping is worse than a null one (per the ticket).
- **`CR-1` for undisclosed debt.** The live rule compares credit-report liabilities to stated
  (application/MISMO) liabilities; mapped to `CR-1` (Undisclosed liability), the NOW/DET
  undisclosed-liability playbook rule. (`CR-4`, "Undisclosed tradeline (report vs app)", is a
  plausible alternative; `CR-1` chosen as the canonical undisclosed-liability rule.)
