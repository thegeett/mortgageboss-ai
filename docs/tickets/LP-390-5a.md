# LP-390-5a — Re-score `apparent_category` with Priya's free-text labels mapped to the enum

## What this ticket is

LP-390-5 scored `txn.apparent_category` at **24.5%** — but that was a **scoring artifact**, not the AI's
accuracy: Priya's goldens are free text (`"transfer to some one"`, `"Credit card payment"`, `"trasfer"`) and
the AI outputs the enum (`transfer_own`, `debt_payment`), so a byte-compare scored semantic MATCHES as wrong.
This applies **LP-379-F's already-built free-text→enum mapping** (`apparent_category_relabel.relabel`) to her
goldens **at scoring time** (never mutating her committed free text), then re-scores. `apparent_category` gates
AS-2, AS-12, AS-5 — the whole transaction-rule cluster was blocked on this measurement.

**The live model scores are a point-in-time run** (claude-sonnet-4-5, 2026-07-22); the mapping + split are
deterministic and pinned keyless (`test_apparent_category_rescore_lp390_5a`).

## Phase 0 — the mapping + the split (deterministic, no AI)

`apparent_category_relabel.relabel` (LP-379-F) is the mapping — **confirmed-only** (mapped only where the
transaction DESCRIPTION supports the category), **held-on-ambiguous** (the generic memo → held, never guessed),
**uncertainty-preserving** (`"not sure it's own transfer"` → `unknown`, held), and it **never emits an
off-enum value**. The AI's widened LP-379-E enum (12 values incl. `transfer_third_party_in/out`,
`debt_payment`) matches the mapping's `_ENUM` exactly, so a correct widened prediction scores correct.

**Split of the 50 goldens** (`map_apparent_category_goldens`, pure):

| | count | breakdown |
|---|-------|-----------|
| **CONFIRMED (scored)** | **17** | payroll 8, interest 4, transfer_own 4, transfer_third_party_in 1 |
| **HELD (not scored)** | **33** | generic memo (`CARD PURCHASE / PAYMENT`, no payee) 30, uncertain-note→`unknown` 2, typo 1 |

The 30 held rows sit on the identical payee-less memo Priya categorized eight ways from the AMOUNTS + the
un-redacted file — a judgment the prompt forbids the AI from making (categorize from the payee, not the
amount). Held, never scored wrong (LP-379-F's gate-of-record finding).

## Phase 1 — the re-score (same AI run, scored two ways)

| Scoring | n | accuracy-when-concrete | |
|---------|---|------------------------|---|
| **(A) raw byte-compare** | 50 | **24.5%** | reproduces the LP-390-5 artifact exactly |
| **(B) mapped, confirmed subset** | 17 | **100% (16/16)** | the REAL accuracy |

Per value on the confirmed subset: **payroll 8/8, interest 4/4, transfer_own 4/4** — every concrete prediction
correct. The single non-match:

> `transfer_third_party_in` → AI predicted `unknown` (conf 0.6) on `INBOUND PAYMENT RECEIVED`: *"generic and
> provides no information about the source… could be payroll, transfer, refund… cannot determine."*

That is an **abstention on a payee-less memo** (the same memo-richness case as `has_identified_source`'s one
miss), not a mis-category. So **accuracy-when-concrete = 100%**, unknown-rate = 5.9% (1/17). **No prompt bug**
— the AI never mis-categorized any value, widened or otherwise.

## Phase 2 — the verdict

**`apparent_category`'s real accuracy is 100% concrete (n=17), not 24.5%.** The 24.5% was purely the
free-text-vs-enum artifact, now fixed. This unblocks the transaction-rule cluster — with one honest caveat the
gate of record forces:

- **AS-12 → calibratable-now (ratify).** It reasons over `apparent_category` BROADLY (no single trigger value),
  so the 100%-concrete measurement + `has_identified_source` 93.8% support it directly; it ships ratify (a
  human ratifies every verdict, LP-376-B), so the tags need only surface a pattern. Flipped to
  `calibratable-now`, `validated:false` (Priya pending).
- **AS-2 → calibratable-now (auto), with a caveat.** Both its load-bearing tags now measure
  (`apparent_category` + `has_identified_source`). BUT AS-2 FIRES on `apparent_category == loan_proceeds`, and
  **LF-6T3N has zero loan_proceeds transactions** — the tag is measured broadly, but its `loan_proceeds` value
  is n=0 (untested). So `measured_accuracy` is recorded as `0.938` (the weaker MEASURED gate,
  `has_identified_source`), NOT `apparent_category`'s 1.0 — the number does not over-read the untested trigger.
  Flipped to `calibratable-now`, `validated:false`; Priya weighs the loan_proceeds gap before sign-off (a file
  with a loan-proceeds deposit would strengthen it).
- **AS-5 → stays not-calibratable-yet.** `apparent_category` is measured, but AS-5 gates on
  `apparent_category == gift` (n=0 on LF-6T3N) AND the LP-335 / ADR-302 D2 question stands: `gift` is arguably
  a rule CONCLUSION, not a tag value. AS-5's blocker is now a **design** question, not a calibration gap — held
  until that call is made.

**No real prompt bug** to fork into its own ticket — the model's only "miss" was an honest abstention on a
payee-less memo. **The 30 held generic-memo rows are the data gap** (LP-379-F): they need payee-naming memos to
be scorable, not a model fix.

## Phase 3 — what changed + equivalence

- **`apparent_category_relabel.map_apparent_category_goldens`** (new, pure): applies `relabel` to the
  worksheet's apparent_category rows and returns `(confirmed golden dict, held list)` — the confirmed dict
  feeds LP-390-5's `score_snapshot_against_golden`. Reused, not a second mapping.
- **`test_apparent_category_rescore_lp390_5a`** (new, keyless): the 17/33 split on the committed golden; held
  rows excluded from the confirmed set; **Priya's committed free text UNCHANGED** (asserted); a widened enum
  value (`transfer_third_party_in` / `debt_payment`) scores correct, not wrong.
- **`activation_bars.yaml`:** AS-2 + AS-12 → `calibratable-now` (`validated:false`, proposed 0.90 bar,
  `measured_accuracy 0.938`, caveats); AS-5 rationale updated (design-blocked). The count test
  (`calibratable-now == 3 → 5`) and the LP-389 gate test (AS-2 held on `validated:false`, not
  `not-calibratable-yet`) updated.
- **EQUIVALENCE:** no tag/rule/producer change; **her committed golden is byte-unchanged** (the mapping is a
  scoring-time layer); `eligible_rule_ids()` unchanged (`AS-9, AS-10, ID-5, IN-1, IN-4, IN-5`);
  `ACTIVE_RULE_IDS` unchanged (**17** — AS-2/AS-12 are `validated:false`, so nothing activates); full suite
  green.

## Assumptions, decisions & gaps

- **No new ADR.** The per-rule bar principle (all load-bearing tags measured → calibratable) is the existing
  LP-380 mechanism; this applies it after clearing the apparent_category blocker. The one judgment — flipping
  AS-2/AS-12 to `calibratable-now` while their trigger value (`loan_proceeds`) is n=0 — is recorded as a
  caveat on the bar (Priya's to weigh), consistent with LP-380's "proposed default, validated:false".
- **Reused LP-379-F's mapping verbatim** — no second mapping invented; her committed free-text golden is
  untouched (a test pins it).
- **Confirmed-only; the ambiguous held** — 33 rows reported as un-scorable-on-this-file (the redacted-memo /
  memo-richness limit), never scored wrong.
- **Reported gaps (not this ticket):** AS-2's `loan_proceeds` and AS-5's `gift` are n=0 on LF-6T3N — a file
  needing those transactions would validate the specific triggers; the 30 payee-less memos need descriptive
  memos; AS-5's gift-as-conclusion design question (LP-335 / ADR-302) needs a call.
