# LP-206 — Documents section assembler (option-2 belongsTo)

## Summary

The second Stage-1 assembler: reads each ACTIVE document's already-extracted facts
(LP-201 confidence) and its already-stored borrower links (LP-202) and produces the
snapshot's `documents` section. It does **not** extract and does **not** run
matching — it READS the stored links. Amends LP-204 to widen `belongsTo` to the
option-2 shape (a list of resolved `{borrower_id, name}` refs).

Architectural decisions recorded in **ADR-243** (`decisions.md`).

## Phase 0 findings (incl. contradictions flagged)

- **LP-201 storage:** `extracted_data` = `{field: {value, source, confidence}}` +
  `additional_sections`; `Document.current_extraction`.
- **LP-202:** `get_document_borrower_links(db, document_id)` returns links
  **already filtered for soft-deleted document/borrower**; `Borrower.full_name`
  resolves the name.
- **Document:** `SoftDeleteMixin` (`deleted_at`), `document_type` slug, `is_current`.
- **belongsTo was NOT `str|None`** (ticket premise) — LP-204 already typed it
  `list[BorrowerLink]|None`; I reshaped to `BorrowerRef` id+name.
- **Extraction PII is pre-masked** — `account_number_masked` / `taxpayer_ssn_masked`
  (never raw); `social_security_wages`/`_tax_withheld` are amounts, not SSNs. So no
  `from_raw`; pre-masked fields → `PiiField` with a canonical last-4 display +
  `match_hash=None`.
- **camelCase vs snake_case** — the snapshot is snake_case (LP-203/204/205); kept
  snake_case for consistency (full camelCase pass deferred).
- **Real-file limitation** — LF-6T3N has 0 stored links (matcher never run) and the
  dev DB lacks LP-201's `extractions.confidence` columns, so the smoke can't run
  there; DB-backed pytest (correct schema) is the coverage.

## Assumptions & decisions

- **Option-2 belongsTo (ADR-243):** resolved `{borrower_id, name}` refs (tuple,
  immutable); `None` = no borrower resolved; confidence/method dropped from the
  snapshot (kept in the DB link). Raw asserted name → `fields.asserted_name`.
- **Soft-delete honesty:** active/current docs only; refs only for still-active
  borrowers.
- **Confidence faithful, never fabricated;** PII pre-masked → `PiiField` +
  `match_hash=None`; absent≠empty via omission.
- **Document ordering:** `(document_type, created_at, id)` — deterministic.

## Post-review hardening (code review, 2026-07-10)

The review caught a **raw-PII leak** — the PII allowlist was `{account_number_masked,
taxpayer_ssn_masked}`, but W-2 stores `employee_ssn` and 1099 stores `recipient_tin`
**RAW** ("as written"), so those flowed into a plaintext `Field.value` in the snapshot.
See the [ADR-243](../../decisions.md) amendment.

- **[security] Complete PII routing.** `_PII_FIELDS` maps each sensitive field to
  `(PiiKind, pre_masked)`: raw fields → `PiiField.from_raw` (masked + per-file hash,
  raw discarded); pre-masked fields (incl. the previously-mistyped `id_number_masked`)
  → the new `PiiField.pre_masked` primitive. A drift-guard test asserts every
  `# SENSITIVE` extractor field is routed (so a new one can't leak silently); the PII
  test now seeds a raw SSN/TIN and asserts no raw value appears.
- **[correctness] `_confidence` → `coerce_optional_confidence`** (LP-201), restoring
  the `[0,1]` guard the hand-rolled copy dropped.
- **[efficiency] N+1 fixed** — borrower links loaded in one `document_id IN (…)` query
  and grouped; the eager extraction load filtered to the current version.
- **[correctness] `asserted_name`** now aliases the same already-built name Field (was
  a second copy normalized with `.strip()` — the two could disagree), and no longer
  clobbers a real extracted field.
- **[test] Tripwire** now catches an SSN-shaped `\d{3}-\d{2}-\d{4}`, not just `\d{9,}`.

Deferred: `belongs_to=None` still conflates "matched borrowers later removed" with
"never resolved" (a marker is an LP-208 concern); schema-declared PII (annotate
`PiiKind` on the extraction `TypedField`) — the drift-guard test is the interim; and
the `_scalar` naming/dedup across the two assemblers.
