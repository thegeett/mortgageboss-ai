# LP-204 — Snapshot model (frozen, three sections)

## Summary

The frozen, per-run **Stage-1 snapshot model** the assemblers (LP-205/206/207)
will fill and the AI evaluator will later read. One immutable object with three
**raw, un-correlated** sections — `mismo`, `documents`, `calculations` — built on
LP-203's `Field`/`PiiField` primitives. This ticket defines the *shape only*:
nothing populates or persists it. Lives in
`app/verification/snapshot/model.py`; exported from the package `__init__`.

Architectural decisions recorded in **ADR-241** (`decisions.md`).

## Acceptance criteria

- [x] Frozen Pydantic v2 models (`frozen=True`, `extra="forbid"`) for the snapshot.
- [x] Three sections: `mismo` (`dict[str, Field | PiiField]`), `documents`
      (`tuple[DocumentSnapshot, …]`, each `{document_type, belongs_to (nullable),
      fields}`), `calculations` (`{dti, ltv, mi, reserves}`, each
      `Calculation{value, breakdown}` or `None`).
- [x] Top-level `loan_file_id`, `run_id`, `created_at`, `snapshot_version`.
- [x] **absent ≠ empty** preserved (via the LP-203 primitives) and distinguishable
      after a JSON round-trip.
- [x] **No linking/reconciliation field** anywhere — the model structurally cannot
      correlate a document to a MISMO key or a borrower id (`belongs_to` is a raw
      `str | None`, never a foreign key).
- [x] Tests: immutability (top-level + nested; mutation raises), JSON round-trip of
      a full three-section snapshot, the `Field | PiiField` union round-tripping all
      four variants, absent-vs-empty distinguishable, snake_case JSON keys,
      `extra="forbid"`.
- [x] ADR added (ADR-241) and referenced here.
- [~] CI green: **ruff clean (check + format)**; mypy/pytest not executed in this
      sandbox — see *Verification* below.

## What was built

- **`model.py`** — `Snapshot` (top-level) with `mismo`, `documents` (a `tuple`),
  and `calculations`; `DocumentSnapshot` (`document_type`, nullable `belongs_to`,
  `fields`); `Calculations` (four optional `Calculation`s); `Calculation`
  (`value` + `tuple[CalculationLine, …]`); `CalculationLine`
  (`label`, `value`, `source`); `CalcSource` StrEnum
  (`stated|extracted|computed|manual`); `SnapshotField = Field | PiiField`;
  `SNAPSHOT_SCHEMA_VERSION = 1`. Every model `frozen=True` + `extra="forbid"`.
- **`__init__.py`** — re-exports the new model symbols alongside the LP-203
  primitives.
- **`tests/verification/snapshot/test_model.py`** — the suite above.

## Assumptions & decisions

- **snake_case, not camelCase (corrects the phase plan).** The plan wrote
  `documentType` / `belongsTo`, but **no camelCase aliasing exists anywhere in the
  codebase** (the only `alias_generator` hit was stale `.pyc` from a deleted file).
  Inventing a camelCase alias layer would be a fabricated convention, so the model
  uses snake_case attributes *and* snake_case JSON keys, consistent with the whole
  backend. (ADR-241.)
- **`Field | PiiField` round-trips via smart union + `extra="forbid"`, no
  discriminator.** The two shapes have disjoint key sets (`value` vs
  `display`/`match_hash`); with `extra="forbid"` the wrong variant fails validation,
  so Pydantic's smart union parses each back as its original type — including the
  tricky *absent Field* vs *absent PiiField* case. Verified empirically with an
  equivalent Pydantic v2 repro (all four variants type-preserved + equal). The
  LP-203 primitives were **not** modified.
- **Real immutability = frozen + tuples.** `frozen=True` blocks attribute
  reassignment but not mutation of a nested `dict`/`list`, so every sequence
  (`documents`, `breakdown`) is a `tuple`. The section `dict`s (`mismo`, `fields`)
  are shallow-frozen — documented as an accepted limitation; the immutability tests
  assert attribute reassignment raises and that `documents` is a non-appendable
  tuple.
- **Calculations kept deliberately light.** `Calculation`/`CalculationLine` do not
  reimplement the calculator line schemas (`services/dti.py`, `ltv.py`, `mi.py`,
  `calculators.py`); LP-207 maps those in, preserving each line's `source` tag. A
  not-computed calculation is `None` (absent), not an empty `Calculation`.
- **absent representation is the assembler's choice.** A field no source supplied
  may be omitted from its dict *or* stored as `Field.missing()` / `PiiField.missing()`;
  the model permits both.

## Deferred / follow-up

- Populating the model (assemblers LP-205/206/207) and persistence (LP-209).
- Deep-freezing the section dicts (e.g. an immutable mapping) was considered and
  rejected for now — it complicates JSON round-trip for no current benefit; the
  frozen-attribute guarantee + tuple sequences are sufficient for a build-time
  artifact.
