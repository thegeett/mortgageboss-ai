# LP-204 — Snapshot model (frozen, three sections)

## Summary

The container for the Stage-1 snapshot: a frozen, three-section Pydantic model
(`mismo`, `documents`, `calculations`) built on LP-203's `Field`/`PiiField`
primitives, referencing LP-202's resolved document→borrower links. It is the
schema every assembler codes against and the shape persisted as JSON (LP-209).
Nothing populates it yet.

Architectural decisions recorded in **ADR-241** (`decisions.md`).

## Acceptance criteria

- [x] `MismoSection`: flat `key → Field | PiiField` map.
- [x] `DocumentEntry`: `{ document_type, belongs_to, fields }`; `belongs_to`
      references the resolved LP-202 link, nullable + list-capable (joint docs);
      raw asserted name stays in `fields`.
- [x] `DocumentsSection`: ordered list; empty list is present ("no docs") and
      distinct from an absent section.
- [x] `CalculationsSection`: `{ dti, ltv, mi, reserves }`, each `{ value, breakdown }`
      preserving per-line source tags; cash-to-close excluded.
- [x] `Snapshot`: `{ loan_file_id, run_id, created_at, snapshot_version, mismo,
      documents, calculations }`; all models frozen (mutation raises).
- [x] No cross-section linking is expressible (structural).
- [x] Absent ≠ empty preserved at field and section level, through construction
      and JSON round-trip.
- [x] Lossless JSON round-trip: PII as display + `match_hash (str|None)` with no
      raw value; nullable confidence + source; source tags; absent≠empty.
- [x] Extensible: `snapshot_version` + open field maps; no breaking change for
      additions.
- [x] Tests: immutability, round-trip, PII-safe, absent≠empty (field + section),
      belongsTo null/single/joint, calc source tags.
- [x] ADR added (ADR-241) and referenced here.
- [x] CI green: ruff, mypy, pytest.

## Phase 0 findings

- **LP-203 primitives (hardened versions) are the base:** `Field`
  `{value, confidence, source, absent}` and `PiiField`
  `{display, match_hash(str|None), confidence, source, absent}` — both frozen,
  `extra="forbid"`, with `present()`/`missing()` and derived `confidence_source`.
  Their `extra="forbid"` + mutually-exclusive keys make a `Field | PiiField` union
  round-trip unambiguously (verified) — no discriminator needed.
- **LP-202 link:** `document_borrower_links` is many-capable; `MatchMethod`
  (`exact|normalized|fuzzy`) reused for `belongs_to`.
- **Calculator line items** (`DtiLineItem`/`LtvLineItem`/`CalcLine`) carry
  `{key, label, amount, source, overridden}` with `source` a free calculator-vocab
  string — the container's `CalcBreakdownLine` mirrors that.
- **Pydantic v2**, frozen via `model_config`.

## What was built

`app/verification/snapshot/model.py`:
- `SNAPSHOT_VERSION = 1`; `SnapshotField = Field | PiiField`.
- `BorrowerLink` `{borrower_id, confidence, method}` — the resolved LP-202 link.
- `MismoSection` (`facts` map + `absent`), `DocumentEntry`
  (`document_type`, `belongs_to`, `fields`), `DocumentsSection`
  (`entries` + `absent`), `CalcBreakdownLine`, `CalculationEntry`
  (`value` + `breakdown`), `CalculationsSection` (dti/ltv/mi/reserves + `absent`).
- `Snapshot` — the frozen top-level with metadata + the three sections
  (default present-empty).
- Section `present()`/`missing()` factories + `absent`/`is_present`, mirroring
  LP-203's `Field`.

Exports updated in `__init__.py`; tests in
`tests/verification/snapshot/test_model.py` (17 cases).

## Assumptions & decisions

- **`belongsTo` split (ADR-241):** `belongs_to` is the *resolved* reference
  (`list[BorrowerLink] | None`) — `None` = unresolved, a non-empty list = one/many
  (joint). A validator rejects `[]` (use `None`). The **raw asserted name stays an
  ordinary `Field` in `fields`** — the resolved link and the raw claim are separate
  (mirrors ADR-239). `belongs_to` references a borrower *entity*, not a section, so
  it is not a cross-section link.
- **No cross-section linking — structural.** No field references another section's
  keys/entries, so a MISMO↔document correlation cannot be expressed in the type.
  The MISMO map's keys are plain strings, not anchors.
- **Absent ≠ empty at the section level:** each section has an `absent` marker +
  `present()`/`missing()`, so an empty `entries` list (present) ≠ an absent
  section. Preserved through JSON round-trip.
- **Union without a discriminator:** relies on LP-203's `extra="forbid"` (Field has
  `value`, PiiField has `display`/`match_hash` — mutually exclusive), so the blob
  round-trips to the right type without adding a `kind` tag to the primitives.
- **Extensibility/versioning:** `snapshot_version` stored for readers; field maps
  are open `dict[str, …]`; container models keep Pydantic's default `extra` (not
  `forbid`) for forward-compatible additions — only the primitives forbid extras.
- **Calculations fit, not called:** `CalcBreakdownLine.source` is a free string to
  hold any calculator tag losslessly; money stringified for exact JSON;
  cash-to-close is not a field.

## Post-review hardening (code review, 2026-07-09)

A review found the model let the blob express facts the DB/contract forbids, and
made immutability/round-trip claims the code didn't fully back. Applied:

- **[correctness] `CalculationEntry.value` silently coerced `int`→`bool`** (`1` →
  `True`). A `mode="before"` validator now rejects a raw `int`/`float`/`Decimal`
  (the calculator must stringify; `bool` flags stay allowed) — mirroring LP-203's
  `Field.value` guard.
- **[correctness] `belongs_to` accepted duplicate `borrower_id`s** — the DB has
  `UNIQUE(document_id, borrower_id)`. The validator now rejects a repeated borrower.
- **[correctness] `BorrowerLink.confidence` had no bound** — now `PydField(ge=0, le=1)`,
  matching the `DocumentBorrowerLink` DB CHECK, so the snapshot can't hold a
  confidence the source row couldn't.
- **[correctness] `created_at` accepted a naive datetime** — a validator now requires
  tz-awareness so per-run timestamps order unambiguously.
- **[correctness] `snapshot_version` was never checked on read** — a `model_validator`
  now rejects an unrecognized version (loud failure, not a silent mis-read of a
  future shape).
- **[honesty] Immutability docstrings downgraded** to state the real guarantee:
  `frozen` blocks attribute reassignment; the contained collections are immutable
  **by convention**, not deep-frozen (see the deferred item below).
- **[consistency] `MatchResult.method` aligned to the `MatchMethod` enum** (was a
  `Literal`), so the matcher, the DB row, and the snapshot `BorrowerLink` share one
  vocabulary; `document_borrower_links` no longer re-wraps it.

Tests added for each guard (int→bool, duplicate borrower, out-of-range confidence,
naive datetime, unknown version).

## Deferred / follow-up

- **Union round-trip depends on a full dump.** `SnapshotField = Field | PiiField`
  disambiguates by key-presence (`extra="forbid"`); an absent `PiiField` and absent
  `Field` both collapse to `{"absent": true}` under `model_dump_json(exclude_none=True)`
  and reload as `Field`. **LP-209 must persist with a full dump (no `exclude_none` /
  `exclude_defaults`)**; a discriminated union is the robust fix but re-touches
  LP-203's frozen primitives — deferred.
- **`belongs_to=None` conflates "unresolved" with "resolved to nobody."** A `resolved`
  marker distinguishing them is an LP-206 decision (LP-206 does the resolution and
  knows whether "not attempted" is reachable).
- **Shared bases (cleanup).** The `absent`/`is_present`/`missing()`/`_absent_is_empty`
  pattern is hand-rolled per section (5× with `Field`/`PiiField`), and
  `model_config = {"frozen": True}` is repeated on 8 classes — extract a `_FrozenModel`
  + `_AbsentableSection` base (relates to the deferred `ConfidenceCarrier` from
  ADR-238). `absent` itself is NOT derivable here (present-empty is a distinct valid
  state) — keep the flag, share the machinery.
- **Deep immutability caveat:** `frozen=True` blocks attribute reassignment at
  every level (tested) but does not deep-freeze a contained `dict`/`list` — Pydantic
  can't, and a `frozendict` would fight JSON round-trip. The maps/lists are
  immutable by construction (built once by the builder, never mutated); callers must
  not mutate them. A deep-freeze wrapper is a possible future hardening.
- **Out of scope (later tickets):** populating any section, the assemblers
  (LP-205/206/207), the builder (LP-208), DB persistence (LP-209), calling
  calculators, and any real loan-file data.
