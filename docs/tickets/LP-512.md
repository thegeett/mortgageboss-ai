# LP-512 — A rule that changes its subject enumeration orphans its old findings

**Status:** open (not started) · **Severity:** medium — silent, and misleading in the UI
**Found by:** LP-509-A3 / LP-511

## The defect

When a rule's `subject_enumeration` changes, its existing findings keep the OLD subject key. The next run
produces findings under NEW keys, so the old rows match nothing in reconciliation:

- they are not superseded (different subject key),
- they are not marked `no_longer_applies`,
- they persist indefinitely, displaying values computed by code that no longer runs.

## Evidence

LP-509-A3 moved IN-3 from `loan` to `per_borrower`. After the deploy, IN-3's finding on LF-WCHG still
read `updated_at 2026-08-14`, two days before the run, with pre-fix reasoning and `source_facts:
["loan"]`. It sat in the Needs-attention tab as a live `open` finding. A processor reading it would be
looking at a number the system no longer computes.

Note the contrast, which is what localises the bug: **AS-2, AS-12, PC-2, PC-3 and PC-7 reconciled
correctly** to `no_longer_applies` in the same run — 97 of them. Those rules kept their subject and only
changed VERDICT. Reconciliation handles a verdict change; it does not handle a subject-key change.

## Why it matters beyond this instance

Nothing warns. The rule looks live, the finding looks current, and the only way to notice is to compare
`updated_at` against the run. Any future enumeration change — and they happen; LP-332 did exactly this
to IN-1 — silently leaves ghosts.

## Suggested approach

Reconcile per RULE, not only per (rule, subject): when a rule runs, any prior non-terminal finding for
that rule whose subject key is absent from the current result set becomes `no_longer_applies`. That is
already the meaning of the verdict ("the subject left the file since a prior run") — an enumeration
change is exactly that, from the finding's point of view.

Care needed: a rule that produces ZERO evaluations in a run (LP-513's case) must be distinguished from a
rule that did not run at all, or a transient failure would mass-retire live findings.

## Acceptance criteria

- [ ] A rule whose enumeration changes retires its old-subject findings to `no_longer_applies`
- [ ] A rule that produced no evaluations because it did not run does NOT retire anything
- [ ] A test that changes a fixture rule's enumeration and asserts no orphan survives
- [ ] Backfill: the existing orphaned IN-3 row on LF-WCHG is retired
