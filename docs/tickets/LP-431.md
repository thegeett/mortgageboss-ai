# LP-431 — IH-1 (insurance coverage adequacy) — STOP: blocked on an extractor extension

## What this ticket is

IH-1 was planned as a CALCULATIVE rule (coverage vs loan amount / 80% of replacement cost). **Priya's answer
REPLACED that rule** with a loss-settlement-BASIS check: `replacement_cost_basis = true → adequate; false →
inadequate; missing → manual review`. This ticket set out to write it. **Outcome: STOP** — the loss-settlement
basis field is not extracted (not typed-core, not even solicited by the prompt), so per LP-405 IH-1 cannot be
built on the current extractor. This is an **extractor-extension** ticket, not a rule ticket — the outcome the
ticket flagged as likely. **No spec, producer, fixture, or activation was written.** A guard test pins the STOP.

## D0 — the regulatory premise (recorded; UNVERIFIED here)

Priya's ruling rests on a specific agency change: **Fannie Mae / Freddie Mac retired the coverage-vs-loan-balance
and 80%-of-replacement-cost comparison, effective 2026-03-18.** So IH-1 is a loss-settlement-basis check, not
arithmetic. **This cannot be verified from the codebase, and the entire rule shape depends on it** — recorded in
ADR-340 with its stated effective date so a future reader can re-check the basis. Not independently researched
(out of scope); the rule is not hedged against the old calculation.

## D1 — the field's existence + typing → THE STOP

The `homeowners_insurance` extractor's **typed core** is: `named_insured, carrier_name, policy_number,
property_address, coverage_amount, annual_premium, effective_date, expiration_date`. **There is no
loss-settlement-basis field.** The extraction prompt does not solicit it (zero mention of
replacement/settlement/ACV), so it will not reliably appear in the grouped `additional_sections` catch-all
either. Per **LP-405** (no rule may depend on the free-form, per-document, uncoerced catch-all), **IH-1 cannot be
built.** There is also **no per-item settlement granularity** — so the ACV-roof nuance (below) has no home
either.

## D2 — scope: only IH-1's own condition

IH-1's catalog description is *"Insurance adequacy … dwelling coverage vs loan amount/replacement"* (calculative)
— the retired arithmetic. Priya named three adequacy conditions; **only the loss-settlement basis is IH-1's**:

- **Required hazards covered** → siblings: **IH-6** (flood insurance), **IH-8** (wind/hail), **IH-2** (mortgagee
  clause) — not IH-1.
- **Deductible within agency limits** → an **unwritten candidate**; it needs Priya's agency limits (a
  threshold), another reason it is not IH-1 (whose ruling has no percentage).

Bundling three checks into one rule would be processor noise (the AS-8/AS-10 two-rules-one-inadequacy lesson).

## D3 — the condo/PUD exception is a different rule

Priya's *"a condo/co-op/PUD master policy must cover ≥ 100% of the project improvements' replacement cost"* is an
ARITHMETIC test on a DIFFERENT document (a master policy). The catalog already reserves it as **IH-7** ("Condo
master policy") — a separate candidate, not IH-1. To be correct, IH-1 would also need to **exclude condos** (so
it does not apply the dwelling-basis test to a master policy) — but **no confirmed `property.type` / condo
indicator tag exists** (the `loan.purpose` situation, LP-424 item 4). That scoping gap is part of what the
extractor-extension ticket must resolve.

## D4 — the value shape

Her rule is `true / false / missing` → a three-outcome rule: replacement cost → **satisfied**, ACV → **fired**,
missing → **couldnt_check** (her "manual review" — never a fabricated pass; a policy whose basis can't be read is
not adequate by default). It would read the binder (a document→loan promotion may be needed, the
`ins.loan_effective_date` shape, or a per-document read). **Moot until the field exists.**

## D5 — subject match + the IH-3 boundary

IH-1 (adequacy) and IH-3 (effective date) both read the homeowners binder; their reasons would be distinct
(settlement basis vs the effective-date-vs-closing compare). **Moot until the field exists.**

## D6 — no Priya threshold

Her rule as stated has **no percentage** — that is the point. So IH-1 would be `no-ai-dependency` and activate
without a sign-off (the IH-3 shape) — **once the field exists.** (The deductible sub-check WOULD need her limits,
another reason to scope it out.)

## D7 — provability

LP-417's binder scenarios (`build_insurance_in_force_snapshot`, etc.) carry `coverage_amount` + `effective_date`
only — **no settlement-basis field** (they cannot, since it is not extracted). So even a fixture cannot exercise
IH-1 today. The extractor extension must add the field before a scenario can prove the rule.

## The proof

**None** — no rule was written, so there is nothing to run. On LF-6T3N the question is moot regardless (it has no
binder, LP-414 A3). The guard test asserts the extractor gap (the STOP's cause) and that IH-1 is not
written/active.

## Activation

**Unchanged — ACTIVE stays 35.** No rule was added. The 35 previously-live rules are identical.

## Assumptions / decisions

- The STOP is the honest outcome (LP-405): a rule may not depend on the free-form catch-all, and the field is
  not typed-core.
- IH-1 is a loss-settlement-basis **structural** check (three outcomes, no threshold), not the catalog's
  calculative arithmetic — recorded in ADR-340; the catalog is updated when the rule is actually built.
- The guard test is the tripwire: when a typed-core `loss_settlement_basis` field is added, it turns red,
  signalling that IH-1 can now be written.

## New gaps / candidate rules spun off

- **The extractor extension (the blocker):** add a typed-core `loss_settlement_basis` field (enum
  `replacement_cost / actual_cash_value / unknown`) to `HomeownersInsuranceExtraction`, teach the prompt to read
  the loss-settlement/valuation clause, add a **per-item (roof) override** for the ACV-roof exception, and
  provide golden files. Then IH-1 is a trivial `no-ai-dependency` structural rule (the IH-3 shape). **Its own
  ticket.**
- **The ACV-roof nuance:** *"roof coverage may be settled on an actual-cash-value basis"* — an ACV roof must NOT
  fail a replacement-cost dwelling. Needs per-item granularity the extractor lacks (part of the extension).
- **IH-7 (condo/PUD master policy):** the ≥100%-of-project-replacement-cost arithmetic on a master policy — a
  separate candidate (likely similarly extractor-gated; LP-415 found the condo questionnaire has no extractor).
- **A condo indicator tag** (`property.type`): needed so IH-1 excludes condos — none confirmed (LP-424 item 4).
- **The deductible check:** a candidate needing Priya's agency limits (a threshold).
- **The legacy investor overlay:** some investors still apply `min(100% RC, max(100% loan, 80% RC))` (UWM /
  Sun-West may differ) — recorded, NOT built; a question for Priya on overlays.

## ADR

**ADR-340** — IH-1 is a loss-settlement-basis check, not the retired coverage-vs-loan arithmetic (Priya's ruling,
effective 2026-03-18, on record for re-check); its field is not extracted, so LP-431 STOPs at an
extractor-extension boundary; the legacy overlay is recorded but not built; the condo/PUD exception is IH-7 (a
separate candidate); and the ACV-roof nuance needs per-item granularity the extractor lacks.
