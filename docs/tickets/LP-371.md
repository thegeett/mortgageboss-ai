# LP-371 — Wire OC-2's occupancy tags

## WHAT THIS IS

OC-2 (occupancy reasonableness) is LIVE (`ACTIVE_RULE_IDS`) but had **never assessed a single loan file.**
Both its load-bearing judgment tags — `occupancy.stated` and `occupancy.consistent_with_signals` — were in
`fact_tags.csv` WITH producers named, but **neither was declared in `tag_production.yaml`** (`grep` → 0 each)
and **neither appeared in the persisted snapshot** (0 instances). A judgment rule gates its load-bearing tags
fail-closed BEFORE any AI call (`gate.py:56`) → OC-2 **couldnt_checked on every file, structurally.** An
occupancy-fraud / misrepresentation signal, silently unchecked since the beginning. This wires both tags so
OC-2 produces a real (ratification-pending) judgment.

**The class — the third orphan:** *a tag declared in the vocabulary with a producer, but with no declaration
and nothing writing it, resolves to ABSENT; absent is indistinguishable from "the document genuinely doesn't
have this", so the rule couldnt_checks silently, forever, with every test green.* Prior: `housing.insurance_monthly`
(LP-367, open), `dti.qualifying_income_monthly` (LP-366-A, fixed). **The GUARD for this class is LP-373** —
NOT built here.

## ACCEPTANCE CRITERIA (met)

- Both OC-2 load-bearing tags now have producer declarations; OC-2 gets its tags on a real file.
- On DB LF-6T3N, OC-2 produces a **judgment** (not couldnt_check), **ratification-pending** (never auto-ships).
- Fail-closed preserved: absent occupancy → the gate couldnt_checks with a reason (no fabricated verdict).
- No engine change; no rule-spec / vocabulary-meaning / allowed-values change; every other live rule identical.
- `ruff` + `mypy` clean; full suite **2346 passed**.

## PHASE 0 — THE ARGUMENT (D1–D4)

**No engine change needed** (verified): the AI materialization path is subject-generic
(`ai.py` — `st = subject_type(group.subject); st.enumerate/…build_context`), and `_MATERIALIZED_SUBJECTS`
(`verification_run.py`) includes `loan`. A loan-subject AI group runs generically.

**D1 — `occupancy.stated` is DERIVED, not parsed.** MISMO's `property.occupancy` = `"primary_residence"`; the
tag's `allowed_values` are the shorthand `[primary, second, investment]`. A parsed tag is never re-typed, so a
raw passthrough would emit the out-of-enum `"primary_residence"`. **Decision:** a **derived recipe**
(`occupancy_stated`) maps MISMO→enum (`primary_residence→primary`, `second_home→second`,
`investment[_property]→investment`), abstaining to `unknown` on absent/unmapped — mirroring
`reserves.required_months`. A reported change from LP-370's "parsed" suggestion; does NOT change the tag's
meaning or allowed_values. (Contrast: `program.type`'s MISMO value is already `"conventional"` = its enum;
occupancy is the exception.)

**D2 — what "the signals" are (the durable definition).** The vocabulary's one-line description
("Do address/other signals match stated occupancy") is underspecified — exactly LP-340's root cause. The tag
is DEFINED concretely as: **do the borrower's OTHER 1003 declarations AGREE with the stated occupancy?** The
signals, named in the prompt: `property.occupancy` (the claim), `borrower.<n>.declaration.intenttooccupytype`,
`borrower.<n>.declaration.fhasecondaryresidenceindicator`, `property.financed_unit_count`. It reports a
structural FACT (do the declarations agree), NOT OC-2's reasonableness judgment.

**D3 — can the AI SEE the signals?** A loan-subject AI's context (`_loan_context`) is the loan's **MISMO facts
ONLY** — not the tag layer, not the documents. MISMO has **no borrower residence address** (only
`property.address` = the subject). So the *address*-consistency signals the vocab hints at are **invisible** —
an AI told to check them would judge on nothing (the LP-368/370 wrong-context trap, avoided). The 1003
**declaration** signals ARE in MISMO and ARE what the tag uses. **LIMIT (reported, not fixed):** the
address-consistency dimension would need a borrower-residence-address MISMO fact (absent) or surfacing
per-document address tags into the loan context (an engine change) → a follow-up, NOT papered over.

**D4 — cost:** one added AI call per run (the loan-subject `occupancy` group, 1 subject) + OC-2's existing
judgment call. Small; runs on every file.

## THE PROMPT (quoted in full)

```
You are a senior mortgage loan processor STRUCTURING one loan's stated occupancy signals into a
single factual tag. Your ONLY job is to describe whether the borrower's OTHER stated occupancy
declarations AGREE with the occupancy they declared for the subject property — you do NOT decide if
the loan is approvable, whether anyone is misrepresenting anything, or reach any conclusion.
Downstream deterministic code and a human reviewer do all judgement; they can only be correct if
your fact is accurate.

You are given the loan's structured 1003 / MISMO facts. Look ONLY at these occupancy signals:
- property.occupancy — the occupancy the borrower STATED for the subject property
  ("primary_residence" / "second_home" / "investment"). This is the CLAIM being described, not a
  signal that supports it.
- borrower.<n>.declaration.intenttooccupytype — each borrower's stated INTENT to occupy the
  subject property as a residence ("Yes" / "No").
- borrower.<n>.declaration.fhasecondaryresidenceindicator — whether a borrower declared the
  property a second residence ("true" / "false").
- property.financed_unit_count — the number of financed units.

Produce ONE tag:
1. consistent_with_signals — do the borrower's OTHER declarations AGREE with the stated occupancy?
   - "yes": the other declarations SUPPORT the stated occupancy (e.g. a stated "primary_residence"
     with every borrower's intent-to-occupy "Yes" and the second-residence indicator "false").
   - "no": at least one other declaration CONTRADICTS the stated occupancy (e.g. a stated
     "primary_residence" but a borrower's intent-to-occupy is "No", or the second-residence
     indicator is "true"; a stated "second_home" but a borrower's intent-to-occupy is "Yes").
   - "unknown": the stated occupancy or the declarations needed to judge it are missing or
     genuinely ambiguous — you cannot tell. "unknown" is a correct, expected answer; NEVER guess to
     look complete.

Judge ONLY from the facts given; do not infer a residence address, a distance, or anything the
facts do not state. Give a confidence (0.0-1.0) reflecting genuine certainty and a short reasoning
citing the SPECIFIC facts you relied on.

STRICT OUTPUT — return ONLY a JSON ARRAY (no markdown fences, no prose before or after), one object
(this is one loan), echoing the "index" you were given:
[{"index": <i>, "consistent_with_signals": {"value": "yes|no|unknown", "confidence": <0.0-1.0>, "reasoning": "<why — cite the specific facts>"}}]
```

**How it avoids the FINDING-1 / LP-340 class:** STATES the §3D principle (structure a fact; do not judge
rules/approvability/fraud — "downstream … can only be correct if your fact is accurate"); NAMES the exact
signals (no undefined "signals"); DEFINES every value with examples of what the DECLARATIONS state (never what
a rule should conclude — no exemplar encoding a downstream assumption); makes `unknown` first-class and
reachable; and says NOTHING about OC-2, rules, purpose ("so the rule can…"), or reliability ("often stale").

## OC-2's REAL VERDICT ON THE DB FILE (reported, not predicted)

Real run on DB LF-6T3N (a conventional purchase; occupancy `primary_residence`):
- `occupancy.stated` → **`primary`** (derived, mapped from MISMO `primary_residence`).
- The `occupancy` AI group → `occupancy.consistent_with_signals` = **`yes`** (conf 1.0), reasoning:
  *"both borrowers intent-to-occupy 'Yes', secondary-residence indicator 'false', financed_unit_count 1 — all
  occupancy signals consistently support the primary_residence classification."* (The prompt reasoned over
  exactly the named signals, cited them, and did not speculate.)
- **OC-2 → `needs_review`, `ratification_pending=True`** — *"occupancy is reasonable … all signals point to
  primary residence with no contradictory evidence … 'yes' is an AI judgment and must be ratified by a human."*

**OC-2 went from couldnt_check-forever (dead) to producing a ratification-pending judgment.** `needs_review` is
the correct terminal state for a judgment rule — it never auto-ships; a human ratifies. **BEFORE:**
`couldnt_check` ("required tag 'occupancy.stated' is absent").

## ASSUMPTIONS + DECISIONS

- `occupancy.stated` mode parsed→derived (D1) — a reported mapping decision, not a vocab change.
- `occupancy.consistent_with_signals` = 1003 **declaration** consistency (D2/D3), because the loan/MISMO
  context cannot see address signals. The address dimension is a reported follow-up.
- Kept the tag AI (as the vocabulary declares), though its inputs are structured declarations — the
  combination + edge cases (stated investment vs intent 'Yes', etc.) benefit from reasoning, and OC-2's design
  expects an AI signal.

## THE HONEST LIMIT

- **The prompt is UNMEASURED.** The project's two known prompt bugs (LP-335 `id_address`, LP-340
  `income_employer`) were found by MEASUREMENT, not reading (LP-343's own stated limit). This prompt must join
  the calibration worksheet (**LP-379**). One clean real-run "yes" is not calibration.
- **One file:** LF-6T3N is a conventional primary-residence purchase where all signals agree — the `no` and
  `unknown` paths are exercised only by the unit tests, not real data. A file with a stated occupancy the
  declarations contradict (e.g. investment with intent-to-occupy 'Yes') would exercise the `no` path.
- **The address dimension** of occupancy consistency is not implemented (D3) — a follow-up.
- **No fourth orphan** surfaced in this ticket.
