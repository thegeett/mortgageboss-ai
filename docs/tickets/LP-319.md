# LP-319 — AI-at-rule-time judgment rules (OC-2)

**Status:** Complete. **Branch:** `phase3_new_AI_arch_finding_stage2`.
**ADR:** [ADR-259](../../decisions.md). **Depends on:** LP-313/314 (the AI-call clone),
LP-315 (the gate + result), LP-316 (needs_review), §3D.

## What it is

Builds the path for the ~36 rules whose judgment CANNOT reduce to a deterministic tag query — the
**AI IS the evaluator**. Because these are the highest-stakes, least-structurally-armored rules,
they get **procedural armor**: reason over TAGS (not raw docs), **mandatory human ratification**,
confidence-gated, fail-closed. Proven end-to-end with **OC-2** (occupancy reasonableness). This is
the PATTERN; OC-2 is the reference implementation.

- **Tests** — `tests/verification/rule_engine/test_oc2.py` (14, keyless).

## Assumptions & decisions

- **Armor in the evaluator, not the prompt.** The prompt asks for an honest judgment; the *evaluator*
  enforces mandatory ratification, the fail-closed gate, and the honest fallbacks — so a prompt
  regression can't let a judgment auto-ship.
- **Mandatory ratification = terminal verdicts `{needs_review, couldnt_check}` only.** A judgment
  rule never reaches `satisfied`/`fired`. The AI's actual yes/no/unknown lives in the
  `rule_judgment` tag + the reasoning; the verdict is `needs_review` (LP-316's ratification-pending
  outcome) with `ratification_pending=True`. Confidence never lets it escape ratification — that's
  the point for the least-checkable rules.
- **Reason over tags, not raw docs** — the discipline that keeps a judgment rule reviewable and
  grounded in the same clean facts as everything else, rather than an opaque "ask the LLM about the
  PDF" call. The context is built purely from `snapshot.tags.by_subject["loan"]`.
- **Loan-level subject convention.** OC-2's structural inputs (`occupancy.stated`,
  `occupancy.consistent_with_signals`, `id.current_address_type`, `property.address_normalized_match`)
  are loan-level and are NOT produced by the current pipeline (Stage A/B produce only `txn.*`) — they
  come from OC-1/ID-4, out of scope. They land under a loan-level subject `by_subject["loan"]` (a
  documented convention this ticket introduces); keyless tests inject them. Absent → gate →
  couldnt_check.
- **rule_judgment tag stage = B.** A judgment correlates cross-entity structural facts (the Stage-B
  role); `tag_role=RULE_JUDGMENT` is the real distinguisher from a shared `structural_fact`.
- **Load-bearing gated set = `{occupancy.stated, occupancy.consistent_with_signals}`** — without a
  stated occupancy and a consistency signal there is nothing to judge; the address tags refine the
  judgment but do not gate.

## How this generalizes to the ~36 judgment rules

Every judgment rule follows the OC-2 shape: **assemble tag context → LP-315 gate → AI judge (the
reused clone) → ratification-pending verdict + a `rule_judgment` tag**. Only the prompt and the
structural-tag set change per rule. `ratification_pending` + `rule_judgment` + reason-over-tags are
the reusable armor; a new judgment rule is a prompt + a tag list + a load-bearing subset.
