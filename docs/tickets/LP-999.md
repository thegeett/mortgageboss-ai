# LP-999 — Keep the processor's name in From

## The problem

LP-998's real send to Gmail arrived from a bare `lf-afcw@mail.staging.mortgageboss.ai`. The borrower
saw a file code, not who wrote to them. The email the app built was right: the stored `.eml` said
`From: "Geet Thaker, MortgageBoss" <lf-afcw@…>`. The name was lost at SES.

`SesMailSender.send` passed SES a separate `FromEmailAddress`, set to the bare address
(`parseaddr(...)[1]`). SES writes that value over the email's From header, so the name was gone by
the time the email left.

## The fix

`SesMailSender.send` now passes the full From, name included, as `FromEmailAddress`: the same name
and address as the email's own From header. It is built with `email.utils.formataddr`, which quotes a
name containing a comma (`"Geet Thaker, MortgageBoss" <…>`) and encodes a non-English one
(`=?utf-8?b?…?= <…>`), as SES requires. One comment in `app/services/mail_sender.py` says why.

## Which option, and why

The brief offered two options: leave `FromEmailAddress` out so SES reads the From header itself, or
pass the full From. Both were tried against SES with the mailbox simulator, and SES accepted both.
The second is the one kept.

- **Left out:** documented to work, but we had never seen SES do it.
- **Passed in full:** relies on the behaviour LP-998 actually showed, that SES writes
  `FromEmailAddress` over the header. Now that value carries the name. Being explicit takes the
  guesswork out.

- `tests/services/test_mail_sender_lp993.py`:
  - The `Stubber` test now expects `FromEmailAddress` to be `"Priya Thaker, ABC Mortgage" <lf-y36e@…>`.
  - New: `test_the_sent_from_header_keeps_the_processors_name`, run for an English and a non-English

  - with the field left out, 3 tests fail.

  two names). ruff, ruff format and mypy are clean.

## Proved in staging

| Check | Result |
|---|---|
| SES with the field left out (simulator, from my machine) | Accepted, `010001a193e727ce-…`. Delivery event at 21:39:47 UTC (`unmatched`, as expected for a test send with no row) |
| SES with the full From (simulator, from my machine) | Accepted, `010001a193f7319e-…`. Delivery event at 21:57:47 UTC (`unmatched`) |
| Deploy | Staging runs `staging-ffab93a0` (api and worker task definitions :110) |
| Send from a MortgageBoss file to the user's Gmail | **Gmail shows the sender as "Geet Thaker, MortgageBoss"** (checked by the user) |

## Doc changes (for `docs/email-communication/loan-email.md`, not edited here)

- The From-name issue that LP-998 recorded is fixed (LP-999). The borrower sees "<processor>,
  <company>" with the file address.
- Under the SES send: `FromEmailAddress` is the email's full From (name and address); SES writes it
  over the From header, so it must never be the bare address.
