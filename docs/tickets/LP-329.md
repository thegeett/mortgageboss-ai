# LP-329 — Document-type applicability (GAP-C)

## What it is

A per-document rule had to enumerate EVERY document, flooding `couldnt_check` across every non-matching
one (ID-7's title rule on a paystub; ID-9's POA rule on a W-2 — a non-title/non-POA doc has no title/POA
tag, so the gate `couldnt_check`ed it). This let a spec DECLARE which document types it applies to, with
out-of-scope subjects resolving to **`not_applicable`** (§8 Tab 4), NEVER `couldnt_check`.

## Acceptance criteria

- [x] A spec declares an `applicability: TagCondition` (document-type / subject predicate); resolved by
  shared machinery across the deterministic + judgment evaluators. No document types in any evaluator.
- [x] **THE §8 HONESTY CONTRACT:** out-of-scope → `not_applicable` (Tab 4, no finding); in-scope-but-
  degraded → `couldnt_check` (Tab 1, persists). They never collapse.
- [x] Filter BEFORE the gate — an out-of-scope subject is not gated, makes no AI call, emits no tag.
- [x] NO FLOOD: ID-9 over 30 docs with 1 POA → 1 evaluation + 29 `not_applicable`, ZERO `couldnt_check`.
- [x] ABSENT-DOCUMENT decided: non-matching → `not_applicable` (visible, no vanish); required-doc-missing
  is a declared-per-rule future flag (recommended, deferred).
- [x] ID-7 + ID-9 authored as data + activated; ID-9's output tag via the LP-328 overlay.
- [x] EQUIVALENCE: every existing rule unchanged (specs without applicability behave as today). No
  rule-id/family branch. ruff + mypy + full suite green.

## Assumptions & decisions

- **A declared predicate, resolved by shared machinery** — the sixth application of the
  declared-key-resolved-generically pattern. The value (`title_commitment`/`power_of_attorney`) lives
  ONLY in the spec YAML; a test asserts the evaluators contain no document-type literal.
- **The document type is a structural subject fact.** `DocumentEntry.document_type` (the classifier's
  known vocabulary) is injected by the `per_document` enumerator as `document.document_type` — like the
  content_id, always present (an unclassified doc → `"unknown"` → the applicability `couldnt_check`s,
  honest). This makes the predicate a plain `TagCondition` — no entry-passing, no parallel mechanism.
- **THE §8 HONESTY CONTRACT (the heart), enforced by filter-before-gate + the existing verdict mapping.**
  out-of-scope → `not_applicable` (dropped from findings — Tab 4); in-scope-but-degraded → the gate →
  `couldnt_check` (persists yellow — Tab 1); the predicate tag itself absent/`"unknown"` → `couldnt_check`
  (can't tell if it applies). The flood is gone because `not_applicable` creates no finding while
  `couldnt_check` would create a yellow.
- **Out-of-scope costs nothing** — the applicability runs before the gate, so an out-of-scope subject is
  never gated, makes no AI call, emits no tag.
- **ABSENT-DOCUMENT decision.** Non-matching subjects each emit a visible `not_applicable` (never a
  silent vanish). A file with zero documents of the type → all not_applicable (the rule genuinely
  doesn't apply). The distinct "a REQUIRED document is missing → `couldnt_check`" case is declared-per-
  rule (whether title is required is a Priya question) — RECOMMENDED as a future `expected: true` flag,
  DEFERRED here (ID-7/ID-9 are not always-required).
- **ID-7 shape (D2).** Uses the existing `id.title_vesting_consistent` verdict tag via a deterministic
  structural rule (fired when `== "no"`) — the verdict already exists; a consistency gather would
  duplicate it. Scoped to `title_commitment`.
- **not_applicable visibility.** It is a visible RuleEvaluation but is dropped at persistence (the
  existing not_applicable semantics, like ID-10). Persisting it as a Tab-4 finding is a separate
  findings/UI concern (noted, not this ticket).

## Which rules activated vs waiting

- **Activated:** ID-7 (deterministic per_document, `title_commitment`) + ID-9 (judgment per_document,
  `power_of_attorney`) — their tags materialize (`id.title_vesting_consistent` via `id_title`;
  `id.poa_present_and_acceptable` via `id_poa`; `document.document_type` injected), and non-matching
  docs resolve to not_applicable (no flood). The materialization stage auto-runs `id_title`/`id_poa`
  (derived from the active rules' load-bearing tags).

## New generalization gap surfaced (reported, NOT patched)

- **Required-document → couldnt_check.** A missing REQUIRED document (e.g. a title commitment expected on
  a purchase) should be `couldnt_check` (Tab 1), not silently `not_applicable`. This is declared-per-rule
  (a future `expected: true` flag) — recommended, deferred (it needs the per-rule "is this document
  required?" Priya input). No rule silently vanishes today (per-subject not_applicable is visible).
