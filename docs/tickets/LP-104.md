# LP-104 — Wrap long needs-list titles instead of clipping to one line

- **Ticket:** LP-104
- **Status:** Completed
- **Date:** 2026-07-03
- **Scope:** Frontend-only

## The bug

On the Needs list, AI-generated need **titles** are long descriptive sentences, but they were clamped
to a single line and truncated with an ellipsis — cutting off information the processor needs to read
(e.g. "Two years of personal tax returns (1040s with all schedules) for both borrowers to verify
reported income and reconcile W-…"). The full text existed (the reasoning below rendered fully); only
the title was clipped.

## The mechanism (confirmed, not assumed)

A **one-line CSS clamp** — Mechanism #1, not a flex width-competition. In
`components/file/needs/need-card.tsx` the title was:

```tsx
<p className="truncate text-sm font-semibold text-gray-900">{need.title}</p>
```

Tailwind `truncate` = `overflow-hidden text-ellipsis whitespace-nowrap` → one line + ellipsis.

The button/menu side was already sound: `NeedActions` is `shrink-0` and the outer row is
`items-start`, so the **Confirm** button + "…" overflow menu already top-align and don't get squashed
when the title grows. The only knock-on was the status **dot**, whose inner row used `items-center`
(fine on one line, but it would float to the vertical middle once the title wrapped).

## The fix

`components/file/needs/need-card.tsx` — the title row only:

- Removed `truncate` so the title **wraps in full** (these titles are long by design → show the whole
  thing; no ellipsis, no shortening). Added `min-w-0` so it wraps cleanly inside the flex row.
- Switched the inner dot+title row from `items-center` to `items-start` and nudged the dot down
  (`mt-1.5`) so it sits on the **first line** of the title as it wraps.

The Confirm button + "…" menu stay top-aligned (outer `items-start`, `NeedActions` `shrink-0`) as the
title grows to 2–3 lines. Short titles still render on one line, dot aligned. The description, status
pills, "Proposed — review" pill, priority pill, source/"AI" marker, reasoning note, and satisfied-by
line are untouched (their `pl-4`/`ml-4` indentation still aligns under the title text).

## Out of scope (unchanged)

Needs data, need-generation, the Confirm/Adjust/Waive/Dismiss actions, the reasoning text, the pills,
and the satisfied-by line. The satisfied-by **filename** keeps its own `truncate` (a filename, one
line is correct) — that's not the need title.

## Verification

- `pnpm biome check`, `pnpm tsc --noEmit`, `pnpm build` — all pass.
- `needs-dashboard.test.tsx` → 12 passed (no regression to the needs list).
- No ADR — a contained CSS clamp→wrap fix.
