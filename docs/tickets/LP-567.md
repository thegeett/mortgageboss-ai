# LP-567 — wire document→borrower linking into the extraction pipeline

**Status:** done · **Found:** 2026-08-19, from the first snapshot staging ever persisted

## The defect

A staging snapshot held **16 documents and 0 borrower links**.

`assign_document_borrower_links` has existed since LP-202 and is well tested. The snapshot's
`belongs_to` has read `document_borrower_links` since LP-206. The producer simply had no caller
in the running system — its only reference outside tests was `app/scripts/stage1_artifact.py`, a
developer script:

```
backend/app/scripts/stage1_artifact.py:37: from app.services.document_borrower_links import assign_...
backend/app/scripts/stage1_artifact.py:69:     rows = await assign_document_borrower_links(db, document)
```

So on every real run the table stayed empty and `belongs_to` resolved to `None` for every
document. The service's own docstring still said "Nothing consumes the links yet (LP-206 will)" —
LP-206 built the *reader* and the producer was never connected to it.

**Consequence.** On a two-borrower file nothing in the snapshot says whose pay stub, whose W-2 or
whose bank statement any document is. That is the input `per_borrower` rules need (LP-513), and
it is why per-borrower attribution has been weak.

## The fix

One call in `_extract_branch`, immediately after `create_extraction_version` — the moment the
extraction asserting the name becomes current (that function flushes, so the new row is visible
to the linker's `is_current` query inside the same transaction).

Placed **before** the status branches, so it covers the completed, low-confidence and failed
paths alike, and so a type override re-linking through `reprocess_document_extraction` — the
flow where re-attribution matters most — gets it for free.

It runs inside a **SAVEPOINT** (`db.begin_nested()`, as `snapshot/builder.py` does). Linking is
additive metadata; the extraction is the expensive, already-paid-for result of an AI call, and a
DB error while attributing must not take it down. The rollback also undoes the linker's opening
`DELETE`, so a failure leaves the previous version's links standing rather than wiping them —
stale beats absent.

Zero links stays a legitimate outcome, not an error: the type asserts no name
(`closing_disclosure`, `form_1098`), or the asserted name matches nobody above threshold. The
success log carries `link_count` so the two are distinguishable in CloudWatch.

## Verified by removing the fix

Both halves were checked by deletion rather than assumed:

| removed | result |
|---|---|
| the whole call | `test_the_pipeline_links_the_document_to_its_borrower` and `test_a_re_extraction_replaces_the_links...` fail |
| only `begin_nested()` | `test_a_linker_failure_never_costs_the_document_its_extraction` fails — the document ends `FAILED` with `DBAPIError` |

The savepoint test was **vacuous when first written** (it raised a Python exception after a
harmless `SELECT`, and passed with or without the savepoint). It now issues `select 1 / 0`, a real
Postgres error that aborts the transaction — the failure mode the savepoint exists to contain.

## Scope

The matcher is unchanged — this is wiring, and matching keeps its own suite in
`tests/services/test_document_borrower_links.py`.

Documents that never produce a typed extraction (Tier 3 free extraction, which stores
`generic_analysis` on the document rather than an `Extraction`) still get no links. That is
correct for now: `asserted_names_for` keys on `document_type`, and an untyped document asserts no
name field to match on.

**Existing files are not backfilled.** Links are computed at extraction time, so a document
already extracted stays unattributed until it is re-extracted. LF-WCHG's 16 documents need a
reprocess before their snapshot shows `belongs_to`.
