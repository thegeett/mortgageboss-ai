# LP-337 — LF-6T3N labeling worksheet + a deep single-file calibration (a BIAS HUNT)

## WHAT THIS IS — AND IS NOT (read this first)

- **IS:** a **BIAS HUNT** on one real, de-identified file (LF-6T3N), scored through the **Anthropic
  production model** — the path actually shipped (ADR-279, Geet's decision). LP-334 found a live systematic
  bias at n=2 (`id.current_address_type` presumed a driver's-licence address `prior` because *our own prompt
  exemplar taught it*; LP-335 fixed it). That single find justified its whole cost. Keyless calibration
  **structurally cannot** catch that class — replayed labels agree with the prompt that produced them.
- **IS NOT:** validation. **n=2-5 finds BIASES, not RATES** (LP-334's own conclusion). LF-6T3N is ONE
  conventional purchase → most tags get n≤6.
- **THE CONSEQUENCE:** **a clean result here does NOT unblock the ~15 inert rules.** Activation needs RATES;
  rates need **n≥20 across VARIED files** (FHA / refi / condo / self-employed) + Priya's D2 bars. This
  ticket finds bugs; it does **not** open the activation gate. **Anyone reading "all tags passed" as
  validation would be wrong.**
- **THE ONE EXCEPTION — `txn.*` genuinely reaches n≥20** (see the coverage table): the highest-value
  scorable family, because it feeds **LIVE AS-1** (never accuracy-checked) and gates AS-2/AS-5/AS-12.

under a minute** at the harness's bounded concurrency (4). Negligible — the constraint is the human labels,
not the compute.

## THE WORKSHEET (Phase 1 — the instrument; this ticket's first deliverable)

LF-6T3N has **NO ground-truth labels**. Without them, a live run reports what the AI *said*, not whether it
was *right*. So the first deliverable is the instrument; the **human** produces the truth.

- **Where:** `docs/calibration/lf6t3n-labels-mechanical.csv` (50 rows) + `docs/calibration/lf6t3n-labels-judgment.csv`
  (98 rows). Generated by `app/verification/eval/worksheet.py::write_worksheets` — **deterministic + keyless**
  (from the snapshot, no API key, no AI).
- **Each row carries:** the tag id + its allowed values (incl. `unknown`), the transaction's
  **date / amount / direction / description** and its statement id (enough to label WITHOUT opening the
  file), the consuming rules + whether they're LIVE, and empty `golden_label` + `labeler_note` columns.
  **The AI's prediction is NOT in the artifact** — a labeler who sees the model's answer anchors to it.
- **THE SPLIT — who labels what (the point of the ticket: a small, specific ask):**
  - **MECHANICAL (Geet — a factual read from the line):** `txn.is_money_in` (50 rows). Read the direction;
    credit = in, debit = out. Fill `golden_label` with `in` / `out` / `unknown`.
  - **JUDGMENT (Priya — Geet's label would be another guess):** `txn.apparent_category` on ambiguous wires
    (50), `txn.has_identified_source` / sourcing (16), and the free-text tags (32). Fill `golden_label` from
    the allowed values; for the free-text tags, write the counterparty/source you'd expect (human review —
    NOT %-scored).
- **How to fill:** open the CSV, put the correct value in `golden_label` for each row you can judge; leave a
  row blank to skip it. `load_golden()` reads only the filled rows.
- **PII-safe:** the worksheet contains only the already-de-identified snapshot's transaction date / amount /
  direction / description + opaque content-ids. No names, no account numbers (the statements' `fields` are
  empty). It widens no exposure.

## THE NUMBERS (Phase 3) — AWAIT THE HUMAN LABELS

**No accuracy numbers are reported yet — the worksheet is not filled, and fabricating them would defeat the
measurement.** This is the correct outcome, not a failure. The scoring machine is BUILT and PROVEN to run:

- `calibrate_lf6t3n(snapshot, golden, reasoner=…)` runs the real `txn_stage_a` reasoner and scores
  predicted-vs-golden (reusing LP-334's `ScoredTag`/`summarize`/`failing_cases`). It records per instance:
  **predicted / golden / confidence / reasoning / the transaction context** — so a wrong tag is inspectable
  (LP-334's value was the per-case reasoning, not the %).
- **Proven keyless:** a stub-reasoner test builds an honest mechanical golden for `is_money_in` (from the
  `direction` field) and shows the scorer catches both correct (16 credits) and wrong (32 debits) — the
  measurement machine works before a key is spent.
- **Unfilled → no numbers:** `calibrate_lf6t3n` with no Stage-A golden returns `[]` (not a crash, not a
  fabricated score).
- **Live is opt-in** (`LP334_LIVE=1`), never gated on a key's mere presence. Once the worksheet is filled,
  the full run over LF-6T3N's `is_money_in`/`apparent_category` (n=50) is **the system's first real rate
  measurement** — scoped precisely: *on one conventional purchase file.*

**When the run happens, report `txn.*` FIRST and most fully, with its n; free-text tags get per-case detail,
no string-equality %.**

## THE FAILING CASES + THE PROMPT-EXEMPLAR HUNT (Phase 3)

The actionable output is the per-case failures (predicted / golden / the AI's reasoning) — populated once the
labels land. **The specific hunt is for FINDING-1's class:** does any failing case's *reasoning* reveal that
a **prompt exemplar** taught the error? The `id_address` prompt literally defined `prior` as *"e.g. an old
driver's-licence address"* — that one phrase was the bug. **The `txn_stage_a` prompt is the audit target
here** (read `tag_production.yaml`'s `txn_stage_a.system_prompt` against the `is_money_in`/`apparent_category`
failures); the Stage-B sourcing, income, and asset prompts remain unaudited (their tags don't reach n on this
file). **EVALUATE, DON'T FIX:** any bias found becomes its own fix ticket — no prompt is tuned in this pass
(LP-335: one principled change, measure once, never iterate against the numbers).

## WHAT AN n≥20 RATE MEASUREMENT WOULD STILL NEED

- **VARIED real files** that don't exist in the repo yet: a real FHA, a refi, a condo, a self-employed
  borrower (2-yr returns), a multi-borrower file — each de-identified. `txn.*` reaches n≥20 on a SINGLE file;
  every other family needs the variety to accumulate n and to exercise the un-encoded matrix cells (ADR-278).
- **Priya's D2 activation bars** (still pending) — the risk-weighted unknown-rate / accuracy thresholds a tag
  must clear to ship into a trusted verdict.
- **FINDING-2's fuzzy-scoring method** (separate ticket) — to score the free-text `counterparty` /
  `source_reference` tags at all.
