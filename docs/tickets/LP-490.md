## ⚠️ Two things I did not deliver as asked

### 1. The pre-filter was not built

Phase C asked for a deterministic pre-filter before every model call — same type + payment within $1 +
balance within $1 → match with no call; type mismatch → no-match with no call — and for the **fraction
resolved deterministically** to be reported.

**It is not built, and no fraction is reported**, because inventing a number here would be worse than
admitting the gap. The reason is structural: the pre-filter has to live in the **shared AI producer**
(`tag_materialization/ai.py`), which today builds a context for **every** enumerated subject and calls
once per group. There is no per-subject skip mechanism — `applies_to` filters *documents*, not subjects,
and nothing lets a group say "this subject is already decided, do not ask". Adding one changes machinery
every AI group rides, which is a change I was not willing to make incidentally inside a six-rule ticket.

**Consequence, stated plainly:** CR-1/CR-4's matcher asks the model about every liability subject,
including pairs a one-line comparison would settle. That is a cost and latency issue, not a correctness
one — but it is exactly the kind of "we'll do it later" that never gets done, so it is recorded here as
the first follow-up, not buried.

### 2. Vocabulary drift tests are partial

CR-6's and CR-10's numeric matrices are declared in `reference_values` and pinned by test. But CR-8's and
CR-10's **prompt-side** vocabularies (the value domains) live in the spec's `judgment.value_domain`,
which is already the single source — there is no second copy to drift from. The CR-12-style
spec↔producer drift test applies where a producer *mirrors* a spec list; only `credit_derogatory`'s type
list has that shape, and its values come from the generated `fact_tags.csv` enum rather than a hand
copy. So there is less drift surface than the ticket assumed, and I did not manufacture tests for copies
that do not exist.

## ⚠️ Cost — an unintended spend, reported

**Total model spend this ticket: roughly $0.30–$0.60, none of it intended.**

The first version of CR-1's test passed `ai_reasoners={"credit_profile": _ScriptedMatcher(...)}`. That
overrides **one** group; `materialize_tags` runs **every** declared group, and the rest fell through to
the **real model**. The run made roughly 40–60 live Sonnet calls (~1k input / ~150 output each).

**Fixed:** the seam is now `{**stub_materialization_reasoners(), "credit_profile": ...}`. A full suite
run makes **zero** network calls (`grep api.anthropic.com` → 0), and that test file went **133s → 0.16s**
— the runtime collapse is the proof. The bench corpus was never re-run.

**The lesson worth keeping:** a partial reasoner seam is not a seam. Overriding the group under test
leaves every other group live.

## The rules

**CR-1 — one matcher, two views.** LP-483 built the comparison once (`credit_profile` on the liability
subject, ADR-375). CR-1 reads the per-liability judgment directly so the finding names **which debt**;
CR-4 reads the derived borrower rollup. A parametrized test evaluates **both** rules against one
materialised snapshot and proves they cannot disagree. Scoped to `credit_report_reported`, so a stated
liability with no tradeline yields no finding rather than a permanent couldnt_check (CR-12's lesson).
**⚠️ Two-sided failure, recorded for whoever sets the bar:** a false match hides the undisclosed debt this
rule exists to catch; a false non-match fabricates a condition on a clean file.

**CR-6 — never fires.** An unseasoned event is `needs_review` ("an exception needs underwriting review"),
because extenuating circumstances can shorten every period. Seasoning runs from the **event's own date**;
the recipe abstains when it is absent rather than substituting the report date, which would let a
four-year period complete the moment someone re-pulled credit. **⚠️ The Chapter 13 split is not
expressible** — one `bankruptcy` value — so **48 months is applied to every bankruptcy** (the
conservative side; applying 24 would clear a Chapter 7 two years early). **⚠️ Foreclosure, short sale and
deed-in-lieu have no completion date** anywhere, so those rows will abstain often. Consumer lates are a
separate track and were deliberately left out — folding them in would apply a four-year bar to one
30-day late.

**CR-8 — Priya's gate, implemented as given.** `structured_history_confident=false` → `needs_review`,
"Mortgage payment history could not be reliably interpreted." It is the **first** prompt instruction,
before any interpretation, with the measurement in the prompt itself. A judgment rule ratifies every
verdict, which is the right shape: even a confident 60+ late is an underwriting decision.

**CR-10 — the matrix, and the axis that does not exist.** Every cell declared as data. **⚠️ The
DU-vs-manual axis is not a fact on any file** (LP-501), so no `loan.agency` or
`loan.underwriting_method` was invented — the value domain carries an honest
`manual_underwriting_not_supported`, and a test asserts neither tag was declared. **⚠️ The prompt is told
never to fall back to the one-unit-primary cell** (no payoff at any amount, the most permissive), because
an absent occupancy would otherwise clear every collection. Mortgage charge-offs stay in CR-6.

## What calibration would require

| rule | labels on | how many / what |
|---|---|---|
| CR-1 / CR-4 | each **tradeline** | "is this debt on the application?" — needs files with **both** a report and stated liabilities. **One** exists today |
| CR-5 | each **borrower** | needs files with **real inquiry activity** — the corpus has one row |
| CR-6 | each **event** | type + date. Needs files with **real bankruptcies and foreclosures** — the corpus has none |
| CR-8 | each **tradeline** | `is_mortgage` and `structured_history_confident`, plus a ground truth for the history — **which means reading the source PDFs**, not the extracted fields |
| CR-10 | each **collection** | medical status + balance. Needs files with **real collections** — the corpus has none |

⚠️ **Every one needs real files, not fixtures** (ADR-332, and the LP-487 amendment): a self-authored
derogatory event or collection leaks its own answer, and the naming/format variance that makes these
judgments hard is exactly what invented data does not reproduce.

## Assumptions and decisions

1. **`input_resolves` is the LP-485 development-mode meaning** — inputs declared and resolvable, not
   verified end-to-end on a live file.
2. **The conservative side of every unexpressible distinction**: 48 months for all bankruptcies; an
   unknown-medical collection **contributes** to the aggregate; an approval without readable eligibility
   abstains.
3. **The aggregate abstains if any balance is unreadable** — a partial sum could clear a $1,000 or
   $2,000 threshold the file does not clear.
4. **No test was skipped, xfailed, deleted or weakened.** Census updates carry their cause.

## No ADR

**ADR-375 already records the matcher architecture** — the per-liability judgment as the calibration
unit, with the borrower rollup derived from it — and this ticket *reused* it rather than changing it.
The decision that would have been architectural is the **pre-filter boundary**, and that was not built
(above), so there is nothing settled to record. When it is built it should carry the ADR, because CR-4,
TI-1, TI-2, PC-1 and RE-1 will all follow it.
