# LP-601 — A guard that only runs on a cache miss never sees stored prose

## What shipped, after the fix for it shipped

LP-599 banned "correctly" from composed finding text, because DT-8's spec had been rewritten to stop
claiming a lien is *correctly* excluded — a claim requiring knowledge that the lien sits on the subject
property, which nothing established. Guard added, tested, deployed. The next staging run still read:

> "The existing mortgage with UNITED WHSLE MORT is **correctly excluded** from the debt-to-income
> ratio."

`compose_findings` calls `compose` only for cache MISSES:

```python
misses = [fid for fid, key in keys.items() if key not in cache]
```

That sentence was already in `finding_prose` from the previous run. **Every guard added after a
composition is stored is invisible to it.** The fix was correct and unreachable — the third time in
this sequence of tickets that a change was right and inert (the cross-source parser, DT-8's producer
reading the wrong field name, and now this).

## The fix

One `rejection_reason(summary, composition)` used in **two** places: inside `compose`, and as a filter
on the way out of the cache. A cached composition that fails the current rules is dropped, becoming a
miss, so it is recomposed under the rules as they are now.

That makes every *future* guard self-healing rather than applying only to findings nobody had composed
yet. Routing `compose`'s own checks through the same function means the two paths cannot drift — a
guard added to one and forgotten in the other is the failure this ticket is about.

The line it must not cross: the cache exists so identical facts do not pay for a second model call.
Re-checking must not turn every hit into a miss, and a test pins that an acceptable cached composition
is still reused with no model call.

## Tests

4 new. Two drive the whole pass against a database — **no test drove `compose_findings` before, which
is why this shipped.** Mutation-checked in both directions: removing the re-check fails the healing
test, and dropping every cache hit fails the reuse test.

Full suite green: **5450 passed**.

## Still true after this

The composer is a model rewriting engine text, so a guard is a filter, not a guarantee of good prose.
What this ticket buys is that the filter now applies to everything on screen, not only to what was
composed after the filter was written.
