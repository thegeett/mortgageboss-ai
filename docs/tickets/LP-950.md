## Design

**The placeholders are named.** `condition_reading.GENERIC_NAME` ("What the lender asks for") and
`GENERIC_ACCEPTABLE` ("What the lender's words describe") replace the two literals (`_generic_item`, and
`condition_plan`'s copy of the name). They are internal words and may never reach an email.

**Masking** (`condition_drafts.mask_accounts`, code only). A run of digits (hyphen-joined groups count as
one run) that is not part of a word, a dollar figure or a decimal, and has five or more digits, becomes
`****` plus its last four. The lender's loan number is kept whole (the emails already print it). Five is
the line the existing privacy test draws ("no long digit run" outside the loan number). Known cost: a
five-digit ZIP or PO box inside the lender's words is masked too; that is the safe direction.

**The lender's words** (`lender_words`): the condition's verbatim text, "TC:" marker and closing full stop
dropped, masked. Used by:
- `_plain_line(condition, item, letter)`: a line with no library `email`. The item's own acceptable form
  when it has a real one; otherwise "**Name** — as the lender wrote it: “…”", or the bolded words alone when
  the item has only the generic name. Never a placeholder.
- `_values`' `{instruction}` (TI-04's line), which copied the verbatim text unmasked before.
- `render_question`'s summary line, now masked.
The mortgagee clause on an insurance line is NOT masked: the insurer must print it exactly, and it is
the letter's, not a borrower's.

**One line per wording** (`_one_line_per_wording`), found by running the LF-DH8V case: a condition read
without a type can split into several generic items, each quoting the whole condition, so 7086's paragraph
printed twice in one borrower email. Identical lines become one, carrying both codes. Applied in
`borrower_lines`, `party_lines` and `lender_lines`.

**The lender email** (`lender_lines` + `render_lender`, dispatched in `render` for
`DraftRecipient.LENDER`):
- each line is a request: "**Please order the** <item>" for an appraiser's item (routed to the lender,
  LP-942), "**Please provide the** <item>" otherwise; the detail is the library's acceptable form, else the
  lender's words in quotes;
- the opening is "For **SURNAME · loan**(property). Could you help with this?" and never "the lender
  needs";
- the subject names the request: "SURNAME LOAN — final inspection request" when there is one named
  request, else "— N request(s)".

**Reuses.** `_library_item`, `fill`, `_file_name`, `_signature`, `_ol`, `Line`.

## Tests

`backend/tests/conditions/test_lp950_outbound_wording.py`, 16 tests:
- masking: an account number, a `#` account, an SSN shape → last four; the loan number, dollar figures,
  dates, a guideline id and a last four already short → unchanged;
- a generic line is the lender's words masked and carries no placeholder; a named generic item keeps its
  name and quotes the lender; the positive control, an item with a real acceptable form, keeps it;
- the lender email: PA-03's appraiser item reads "Please order the final inspection — completion report
  (1004D) …", subject "RIVERA 1226474352 — final inspection request", no "lender needs"; two requests
  count as "2 requests";
- **the guard**: `test_the_guard_knows_every_template` lists every `render_*` function in
  `condition_drafts` and must equal the four the guard renders, so a fifth template fails until it is
  covered; `test_no_template_carries_a_placeholder_or_a_long_digit_run` renders all four with generic
  inputs; and a positive control shows the build's old line would have been caught;
- **LF-DH8V end to end**: the UWM sheet on a file with no lender, read, planned and confirmed. Exactly five
  drafts (lender, borrower, title/attorney, LO, the underwriter question); no placeholder and no long digit
  run in any; the title email carries "loan number on all checks"; the lender subject ends "— 1 request"
  and its body says "Please order"; 7086's paragraph appears once.

Mutations, each restored from a copy:
- `lender_words` without masking: 2 fail;
- the placeholder accepted as an acceptable form again: 1 fails;
- `borrower_lines` without the one-line-per-wording step: the LF-DH8V test fails. (A first mutation,
  forcing `same = None`, passed and was the wrong mutation: the dict still collapsed the keys.)
