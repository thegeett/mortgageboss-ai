# LP-303 — AS-1 rule spec + load_rule_spec interface

## Summary

The **first Stage-2 rule artifact**. AS-1 (large-deposit sourcing sweep) is written as
a version-controlled **spec** — the DATA the evaluator prompt injects into the shared
spine's slots (`criteria` / `applicability` / `required_inputs` / `reference_values` /
`evidence_required` / `guideline_reference`) — and `load_rule_spec(rule_id)` is the
interface that reads + validates it. Nothing consumes the spec yet (the evaluator is
LP-304); this is the **spec + loader only**.

The spec format was **discovered from this one real rule** and is **provisional** — it
is generalized across all rules in **LP-308**. Architectural decisions in **ADR-249**.

## Acceptance criteria

- [x] `load_rule_spec("AS-1")` returns a frozen `RuleSpec` with **every prompt-spine
      slot populated** (+ the calculative-body / finding-identity extras).
- [x] The spec's `kind` (+ `numeric_check`) **agree with `rule_kinds.csv`** (LP-301);
      a deliberately mismatched spec raises `RuleSpecInconsistent`.
- [x] `reference_values` carry the **50%-of-income threshold as DATA** and the **honest**
      validation status (`priya_validated: false`, `threshold_needs_signoff: true`) —
      mirrored from the CSV and cross-checked. The threshold is not hardcoded in code
      (a test greps `app/verification` to prove it).
- [x] `required_inputs` reference **REAL post-LP-302a snapshot paths** (transactions +
      income + parent-entry account), never raw extraction (LP-302 Option A).
- [x] A malformed / incomplete / unknown-key / filename-mismatched / not-in-CSV /
      unparseable spec **fails loudly at LOAD** (`RuleSpecInvalid` / `RuleSpecNotFound`).
- [x] Interface is swappable (file today, DB later) — callers only ever call
      `load_rule_spec(rule_id)`.
- [x] Tests + ADR; CI green (ruff, mypy, verification suite: 327 passed).
- [x] **No** AI call / evaluation / prompt assembly (that is LP-304+).

## Phase 0 findings (incl. two contradictions flagged)

- **Spine injection slots** (`docs/stage2-evaluator-prompts.md:55-62`): `rule.id/name/
  category`, `rule.criteria`, `rule.applicability`, `rule.required_inputs`,
  `rule.reference_values`, `rule.evidence_required`, `rule.guideline_reference`. The
  **calculative body** (VARIANT 2) surfaces operands `compared_value (X)` /
  `threshold_value (Y)` + injects `{{ precomputed_values }}` — so the spec must carry
  the threshold and name the operand sources.
- **`rule_kinds.csv` AS-1 row:** `kind=calculative`, `evaluation_path=deterministic_
  bookend+ai`, `numeric_check=true`, `exact_match=∅`, **`priya_validated=false`**,
  **`threshold_needs_signoff=true`**.
- **LP-301 loader pattern:** `kinds.py` — frozen dataclass, `@lru_cache`
  `load_rule_kinds()`, `kind_for(rule_id)`, fail-loud `_validate`. `load_rule_spec`
  sits alongside in `specs.py` and composes with `kind_for`. **YAML** available
  (pyyaml 6.0.3).
- **Snapshot input paths (post-LP-302a / post-`70fac7c`):** deposits at
  `documents.entries[document_type=="bank_statement"].transactions[i]` (`.amount`,
  `.date`, `.direction` credit/debit `source=derived`, `.description` redacted);
  statement account at `documents.entries[].fields["account_number_masked"]`
  (pre-masked, non-matchable); qualifying income at
  `mismo.facts["borrower.<n>.income.<m>.monthly_amount"]` (aggregate at
  `calculations.dti.value["gross_monthly_income"]`).

- **⚠️ Contradiction 1 — `account` is not on `TransactionRecord`.** Commit `70fac7c`
  ("LP-302a review: remove per-row account") reverted the account-on-record change; the
  ticket sketch assumed transactions carry account (`subject_key_fields: [account, date,
  amount]`). **Resolution:** `required_inputs` references the account at its actual path
  (parent `DocumentEntry.fields["account_number_masked"]`); `subject_key_fields`'s
  `account` resolves from the parent entry, not the transaction. No blocker.
- **⚠️ Contradiction 2 — `priya_validated` true-vs-false.** The ticket sketch shows
  `priya_validated: true` ("CONFIRMED"); the CSV says `false` (+ `threshold_needs_
  signoff=true`). **Resolution:** the ticket's own instruction wins — *"do not mark
  validated if it isn't."* The spec records `false`; the 50% threshold is honest
  **proposed data pending Priya sign-off**. The loader cross-checks spec↔CSV and would
  reject `true` anyway.

## What was built

- `app/verification/rules/specs/AS-1.yaml` — the AS-1 spec (provisional-format caveat in
  the header). Input paths point at the snapshot (Option A); threshold recorded as data;
  gate status honest.
- `app/verification/rules/specs.py` — `RuleSpec` (frozen, `extra="forbid"`) + sub-models
  `Applicability` / `RequiredInput` / `ReferenceValues`; the `RuleSpecError` hierarchy
  (`NotFound` / `Invalid` / `Inconsistent`); `load_rule_spec(rule_id)` (cached, the sole
  entry point) + `_load_spec_from(dir, rule_id)` (uncached, dir-parameterized for tests)
  + `_check_consistency(spec, rule_kind)`.
- `tests/verification/rules/test_specs.py` — 17 tests (happy-path slots; kind/gate/
  numeric consistency + three mismatch raises; real snapshot paths + not-raw-extraction;
  threshold-as-data-not-code; malformed/empty/unknown-key/filename-mismatch/no-CSV-row/
  unparseable/missing-file; frozen).

## Assumptions & decisions (ADR-249)

- **Spec = version-controlled YAML**, one per `rule_id`, co-located with the kinds table.
- **Shape discovered from AS-1 → PROVISIONAL** (generalized in LP-308); caveat stated in
  the file, module, and model docstrings.
- **Input source RESOLVED = the frozen snapshot (Option A)**, never raw extraction.
- **`load_rule_spec` is the swappable, sole entry point**; frozen `extra="forbid"` model
  → malformed specs fail loud at load; four-exception hierarchy.
- **Kind/gate consistency with `rule_kinds.csv`** enforced (CSV = single gate of record).
- **Threshold recorded as honest DATA** — `priya_validated: false` (not confirmed).

## Deferred / follow-up
