# LP-209 — Snapshot persistence (immutable, per run)

## Summary

The final core Stage-1 ticket: persists a built LP-204 `Snapshot` (LP-208) as one
**immutable** JSONB record per run and reads it back losslessly. Insert-only,
write-once, append-only history, with a PII-clean-at-rest write guard. No viewer.

Architectural decisions recorded in **ADR-246** (`decisions.md`).

## Acceptance criteria

- [x] New `snapshot_records` table + Alembic migration:
      `{ run_id UNIQUE, loan_file_id (FK, indexed), created_at, snapshot_version,
      snapshot_json JSONB }`; full blob, not shredded.
- [x] Immutable: no `updated_at`, no soft-delete, no update path (append-only).

- [x] Append-only history: two runs → two rows, both loadable.
- [x] Tests (round-trip, immutability, history, PII-at-rest) + build→persist→load
      end-to-end + real-file smoke script.
- [x] Migration applies cleanly (offline DDL verified; single head).
- [x] ADR added (ADR-246) and referenced here.
- [x] CI green: ruff, mypy, snapshot suite.

## Phase 0 findings (incl. contradictions flagged)

- **Round-trip verified:** `model_dump(mode="json")`→`model_validate` and the
  string variant are both lossless (PII masked, absent≠empty preserved). Store the
  dict in JSONB; run the guard on the JSON string.
- **Version constant is `SNAPSHOT_VERSION`** (ticket's `SNAPSHOT_SCHEMA_VERSION`
  doesn't exist).
- **`build_snapshot` now takes `company_id`** (LP-208 review) — persistence is
  decoupled (receives a built Snapshot), so unaffected; the smoke/e2e test supply it.
- **No JSONB precedent** (app uses `JSON`) → used JSONB per the ticket (validates +
  queryable), documented divergence.
- **No DB-level immutability precedent** → enforced in code (insert-only, no
  `updated_at`/soft-delete/update method).
- **`run_id` not FK'd to `verifications`** — it's received by the builder, no
  guaranteed row (mirrors `findings.verification_id`'s origin). Bare UNIQUE UUID;
  `loan_file_id` → FK CASCADE.

## Assumptions & decisions

- **Full JSONB blob per run** (not shredded/dedup/diff) — simple, lossless; dedup is
  future-if-storage-hurts.
- **Immutable in code** (no update path; no `updated_at`/soft-delete); append-only
  history enables jump-back-to-previous-run.
- **Dup `run_id` raises** (write-once); the DB UNIQUE is the real guard.
- **PII-at-rest guard** (dashed SSN + 9+-digit bare run) fails the write loudly;
  word-boundary anchoring avoids false positives on hashes/money (verified).
- **JSONB** deliberately over the app's `JSON`; **`run_id` bare UUID** not FK'd.

## Deferred / follow-up

- **Dedup / diffing / delta-encoding** across a file's runs — future only if a full
  blob per run becomes a storage problem.
- **DB-level append-only guard** (trigger/REVOKE) — only if code-level enforcement
  proves insufficient.
- **Real-file smoke** needs this branch's migrations on the target DB (dev DB is
  stamped at `phase3_5_1`); DB-backed tests are the schema-correct coverage.
- **Out of scope:** the viewer/UI, history-browsing UI, cross-snapshot querying,
  triggering builds.
