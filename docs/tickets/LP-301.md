# LP-301 — Rule-kind classification: formalize + Priya-validate

## Summary

The Stage-2 foundation: turns the human-facing rule classification
(`docs/stage2-rule-classification.xlsx`) into the **canonical, machine-readable
routing table** the engine reads — a plain-text CSV + a thin loader — and stands up
the **Priya-validation gate** (tracking only). Data + validation-tracking; no engine
code.

Architectural decisions recorded in **ADR-247** (`decisions.md`).

## What was built

- `app/verification/rules/rule_kinds.csv` — the canonical routing table (133 rows).
  Columns: `rule_id, name, category, kind, evaluation_path, numeric_check,
  exact_match, priya_validated, threshold_needs_signoff, rationale`.
- `app/verification/rules/kinds.py` — the loader: `RuleKind` (frozen), `RuleKindName`
  / `EvaluationPath` enums, `load_rule_kinds` (cached), `kind_for`, `rules_by_kind`,
  `numeric_check_rules`, and gate helpers `unvalidated_rules` /
  `rules_needing_threshold_signoff` / `pending_threshold_signoff`.
- `app/scripts/generate_rule_kinds_md.py` — regenerates the `.md` from the CSV.
- `docs/stage2-rule-classification.md` — the companion table (generated).
- `tests/verification/rules/test_rule_kinds.py` — 10 tests.

## Assumptions & decisions (ADR-247)

- **CSV over YAML:** flat 10-column table → stdlib `csv`, no dependency (PyYAML is
  only transitive), maximally diffable. CSV is source of truth; the `.md` is
  generated from it (can't drift).
- **Structural exact-vs-fuzzy split made explicit:** "AI" in the eval path → fuzzy
  (`ai_fuzzy_match`); else exact (`deterministic_only`, no AI). 60 structural = 32
  exact + 28 fuzzy.
- **`calculative` ⟺ `numeric_check`** (29 each); six evaluation paths.
- **Validation gate is tracking only** — nothing is validated (all
  `priya_validated=false`); 22 calculative rules need a threshold sign-off before
  ship.

### Re-tags / flags for Priya (not silently chosen)

- **7 self-consistency calculative rules defaulted `threshold_needs_signoff=false`**

## How the gate works

Every rule starts `priya_validated=false`. `rules_needing_threshold_signoff()`
lists the 22 calculative rules whose regulatory threshold Priya must confirm;
`pending_threshold_signoff()` = those not yet validated (all of them today) — a
later ticket blocks shipping any rule in that list. LP-301 invents no sign-offs.
