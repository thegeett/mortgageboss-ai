# LP-111 — Needs consolidation (deterministic collapse + AI flags duplicates for confirmation)

- **Ticket:** LP-111
- **Status:** Completed
- **Date:** 2026-07-04
- **Scope:** Backend (needs consolidation) + minimal UI (possible-duplicate flag + merge/keep-both)

## The problem — one situation, 3-4 needs

A single $20,000 "due diligence fee" wire transfer spawned 3-4 overlapping needs (two+ near-identical
LOE requests + a sales-contract request). The duplication is a **multiplication of three
non-merging paths**:
1. **One fact → multiple findings.** The generic analyzer recorded the wire as BOTH an `OBLIGATION`
   and a `DISCREPANCY_CANDIDATE` finding.
2. **Each finding → a suggestion (LP-67).** `obligation_documentation` + `discrepancy_review`.
3. **The AI reasoner (LP-69) free-forms more** (LOE + sales-contract), `needs_type=null`, reworded
   every run.

Nothing merged by shared source, and the only dedup keyed on **exact** `needs_type` / `.lower()`
title — so reworded free-form needs slipped through and **accumulated** across the
per-document-arrival re-runs.

## The discipline — never silently delete a need

A duplicate is a minor annoyance; a **wrongly-dropped need is a major failure** (a required document
never gets collected → the file goes to the lender incomplete). Asymmetric → **UNDER-merge**: when
unsure, keep both. Deterministic layers merge only the CERTAIN cases; the AI only FLAGS the rest.

## The fix — deterministic floor + AI-flagged residue (`app/services/needs_dedup.py`)

1. **Collapse-by-source (certain).** Two PROPOSED needs of the SAME `needs_type` sharing a source
   finding (`source_finding_id` or the `source_facts` finding ref, LP-110) → merged (union-find).
   Mirrors `ingest_suggested_need`'s per-finding idempotency.
2. **Substance-identity (certain).** REUSE LP-93's `normalize_text` (NFKC + case-fold + dash/quote +
   whitespace) for a `(intent, title)` identity — **replacing** the exact `.lower()` match that let
   cosmetic variants through. Textual only, conservative.
3. **AI flag (never deletes).** The genuinely-reworded residue (different words, `needs_type=null`)
   is only FLAGGED (`duplicate_of_id`) for the processor to **confirm (merge)** or **dismiss (keep
   both)**. Conservative, high-confidence only, cheap classification model, gated by
   `needs_duplicate_flagging_enabled`.
4. **Generation-time reconciliation.** Existing needs (title + type) are fed into the reasoner's
   context (`FileContext.existing_needs` + prompt) so it stops REWORDING them into new duplicates —
   attacking the accumulation at the source.

**Safety boundary:** only a `PROPOSED` + `PENDING` need may be merged AWAY; a confirmed / waived /
adjusted / received need is a fixed point (a proposed duplicate merges INTO it). Merges preserve
provenance — the survivor keeps the UNION of both `source_facts` (composes with LP-108/109/110).

Runs in the needs task (`app/tasks/needs.py`) after `apply_ai_needs`, under the per-file lock:
deterministic `consolidate_needs` → then `flag_possible_duplicates`.

## What collapses (and what doesn't)

- **Deterministically merged:** an LP-67 suggestion + an LP-69 proposal for the same finding + same
  type; cosmetically-identical titles.
- **Left for the AI flag (then processor):** the reworded free-form LOEs (`type=null`, different
  words) — the deterministic layers can't be SURE, so they under-merge and the AI flags them.
- **Never merged (under-merge):** the LOE and the sales-contract both cite the wire but request
  DIFFERENT documents — different intent → both survive.

Net: the wire cluster collapses toward **~1 LOE + the distinct sales-contract need** — not
over-merged into one, not left at 3-4.

## Upstream one-fact→two-findings — investigated, not collapsed

`implications.py` maps `OBLIGATION → obligation_documentation` (recurring debt → DTI, "request
payment history") and `DISCREPANCY_CANDIDATE → discrepancy_review` ("reconcile this mismatch", Phase
3) — **genuinely distinct downstream purposes**. Collapsing the findings upstream would lose that
signal, so we **consolidate at the needs layer** (default) and preserve the findings. Noted as a
separate follow-up: typing a **one-time wire as `OBLIGATION`** (a recurring type) is an extraction
misclassification, not fixed here.

## Not in scope — source relevance (→ LP-112)

The separate NOISY-SOURCE problem (the AI attaching a tangential fact as a source — e.g. the
homeowner's-insurance need citing the wire when its real trigger is "Loan purpose = Purchase") is
source RELEVANCE, a prompt-quality fix with a different mechanism. Deferred to **LP-112**. Need
generation (what's proposed) is unchanged.
