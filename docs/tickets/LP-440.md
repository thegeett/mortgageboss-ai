## D1–D4

- **D1 — the split.** 108 = **18 diff-mode** (an `existing_extractor` — a DIFF REPORT, never a module) +
  **90 new-type**. The 18: pay_stub, w2, bank_statement, form_1099, voe, profit_and_loss,
  letter_of_explanation, investment_account, retirement_account, gift_letter, purchase_agreement,
  homeowners_insurance, mortgage_statement, property_tax_bill, hoa_statement, drivers_license, divorce_decree,
  tax_return.
- **D2 — name collisions.** No duplicate slugs. **4 specs cannot produce a valid Python identifier** (a leading
  digit) → `GenerationError`, hand-write later: `040 1040_personal_tax_transcripts`, `041 1065_…`,
  `042 1120_…`, `043 4506_t_…`. So **86 of 90 new-type generate**; the 4 are recorded in **ADR-345** (rename to
  a `form_` slug, per the `form_1099` precedent, or hand-write).
- **D3 — `_MAX_TOKENS`.** LP-434 emitted a flat 4096 because nested specs refused; they no longer do, and a
  list-bearing spec's model output is large. **Derived from the nested-list count** (guide §7): 0 → 4096, 1 →
  8192, ≥2 → 16384 — matching the shipping values (bank_statement/investment = 8192, credit-report/tax = 16384).
  Verified: business_license 4096, statement_of_account/appraisal/custom 8192, credit_report 16384. The generator
  can derive the rule → **no ADR for D3.** (The `test_extraction_budget_sizing` guard checks the 18 shipping
  modules by name; the new modules are correctly sized but not yet in that guard — step 7 extends it.)
- **D4 — what lands where.** New-type → `app/ai/extraction/<type>.py` + `app/ai/prompts/extraction/<type>.txt`
  + `tests/ai/test_<type>_extraction.py`. **No existing file is modified** — the 18 shipping `.py` are
  byte-unchanged (diff mode is a report), and no catalog/classifier/`__init__`/`_LIST_SPECS` is touched.
  (13 of the 86 modules overwrite LP-435's unwired starters with their current spec state — none is a shipping
  extractor.)

## The complete registration snippet report

`docs/schema-specs/_REGISTRATION_SNIPPETS.md` — one block per spec: the `EXTRACTORS` import + entry, the
`_PII_FIELDS` entries, the `_LIST_SPECS` `ListSpec` + registration, and the count cross-check(s). Every one a
snippet, never a patch. The 18 diff-mode specs carry a diff report (typed-core additions + their `ListSpec`s)
for hand-application.

## Assumptions / decisions

- **Nothing wired.** Every registration is a snippet in the report — that is what keeps the 36 live rules and
  the catalog `== 18` Tier-1 invariant untouched.
- **The module stays flat; lists live in the prompt block + the `ListSpec`/`_LIST_SPECS` snippets** (guide §4).
  The extractor's list-field *capture* (a model field + a wrapping parse) is step-7 wiring — see the new gap.
- **Every generated extractor is a STARTER, accuracy unvalidated** — stated in each module docstring; not tuned.
- **4 leading-digit specs left ungenerated** (ADR-345) — a rename/hand-write for step 1.

## NEW gap

- **The extractor does not yet CAPTURE its list.** The generated module is flat (typed_core only); the prompt
  asks for the list and the `ListSpec` is emitted, but the extractor has no model field to store the rows, and
  LP-437's `build_list_rows` expects `{value}`-wrapped rows while the flat-row prompt yields bare rows. Bridging
  the extractor↔snapshot list shape (a `list[dict]` capture field + a wrapping parse, or reading bare in the
  reader) is **step-7 wiring**, per list. Flagged, not silently shipped.
- **4 leading-digit specs** (ADR-345).

## What steps 1 and 7 must now do

- **Step 1 (tier merge):** promote the generated types to Tier-1 in `catalog.py` (bumping the `== 18` invariant),
  and rename the 4 leading-digit `document_type`s to `form_*` slugs (ADR-345).
- **Step 7 (wiring):** apply the `_REGISTRATION_SNIPPETS.md` blocks — `EXTRACTORS` entries, `_PII_FIELDS`
  entries, `_LIST_SPECS` registrations, classifier indicators — plus the per-list extractor capture + the
  per-rule consumers, and extend `test_extraction_budget_sizing` for the new modules.
