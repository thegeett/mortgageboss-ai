# LP-544 — AS-12 flags the borrower moving money between their own accounts

Found 2026-08-18 while measuring the money-out signal for [LP-543](LP-543.md). Not started.

## The defect

AS-12 produced five needs-review findings on LF-WCHG. The transaction descriptions behind them:

```
DIGITAL FEDERAL A2A XFERS SD# ADITYA        x3   $1,666.67 avg
ONLINE TRANSFER FROM DIGITAL FEDERAL …           $2,500.00
"Talluri A Way2Save Savings account ending in 3627"
```

`ADITYA` and `TALLURI` are the borrower's own first and last name — they appear together in the same
statement's other rows (`DISCOVER E-PAYMENT … TALLURI ADITY`). "Way2Save Savings" is a Wells Fargo
savings product, and the finding names the account holder outright.

So AS-12 is asking a processor to document the source of the borrower moving their own money between
their own accounts, as possible **borrowed funds**. Under B3-4.2 a transfer between a borrower's own
verified accounts is not a large-deposit concern at all; it is the same money, already sourced.

The payroll case is handled correctly, which shows the mechanism works when the perception exists:

```
SUNOVION PHARM DIRECT DEP … TAL    x4   $3,319.76   -> exempted by AS-12's payroll exemption
```

## Why it happens

`txn.has_identified_source` answers "is the source visible in the description?", not "is the source
the borrower themselves?". Nothing compares the counterparty to the borrower, so a self-transfer and
a transfer from an unknown third party are indistinguishable to the rule.

`txn.counterparty` is declared in `fact_tags.csv` (`"The other party if visible (employer, person,
institution)"`, consumers `AS-2, AS-5, AS-12, FR-5`) and **produced by nothing** — the same missing
Phase 2 perception FR-5 was blocked on.

## Why this is the better place to spend Phase 2

LP-543 measured FR-5's payoff on the current corpus at zero. This has four visible wrong findings on
the one file we have, and its fix is the same tag.

## Scope

1. Produce `txn.counterparty` (LP-519 Phase 2 — its own AI group scoped to depository statements,
   following the `txn_nsf` pattern rather than widening the required `txn_stage_a` group).
2. An own-account comparison. `stmt.owner_matches_borrower` (AS-6) is the precedent for matching an
   account holder against the borrower — reuse its matching rather than authoring a second one.
3. Extend AS-12's `exempt_when` with the own-account case, alongside `payroll` and `interest`. This
   keeps the clearing DETERMINISTIC — the model can only ever add a review, never remove one
   (ADR-336) — which is the property that makes the existing exemptions safe.

## Constraints

- A new perception tag is **held on calibration** until a labelling round scores it
  (`txn.is_nsf_or_overdraft`'s precedent). Producing it is not shipping it.
- The comparison must be conservative. Clearing a deposit on a *guessed* name match is the failure
  this rule exists to prevent, so an uncertain match must leave the finding standing, not clear it.
- Two accounts at the same institution are not the same account, and a joint account with a
  non-borrower co-holder is not the borrower's own money. AS-6's `stmt.non_borrower_co_holder`
  already models that distinction and should gate the exemption.
