## Phase 0 — the argument

### D1 — the `has_identified_source` reframing (why she read it redundant; how it's now distinct)
On a transaction, `apparent_category` (WHAT the deposit is) and `has_identified_source` (is its ORIGIN
verifiable) shared a **byte-identical `context`** column — the transaction's facts. Two rows, same facts,
different tag → she reasonably read the second as a repeat ("already evaluated in previous transaction") and
skipped all 16. The fix (finalized in LP-390-3a): the transaction IDENTITY leads the context (date; amount;
direction; description — exactly like `apparent_category`), THEN a short, plain-ASCII SOURCE-TRACE question
(LP-314a): *is this money-in's ORIGIN traceable to a verifiable source (a named payer/employer, the borrower's
own verified account, an itemized proceeds line) vs an unexplained deposit? yes/no/unknown (distinct from the
category = what the deposit is).* The tag and rule are unchanged; only the worksheet's prompt.

**Is it a framing fix or a deeper entanglement?** Both, partly. On a clear memo (`PAYROLL DIRECT DEPOSIT`, a
named transfer) the question is now cleanly answerable and distinct. On a **generic / redacted memo** (the
LP-379-F class) the honest answer is `unknown` — which is a valid label, not a skip; the reframing turns "I'll
skip this repeat" into "I can answer this (even if the answer is unknown)". So the reframing resolves the
redundancy PERCEPTION; the residual limit is memo richness, not the worksheet.

### D2 — the address fix (a data-entry correction, not a re-judgment)
Both `id.address_normalized` goldens held a borrower NAME (`Jordan A Rivera`, `Taylor M Nguyen`) — the same
values as the `id.name_normalized` goldens on the same documents. The **correct address is stated in each row's
own context** (`address=123 Maple Ave, Springfield IL 62704` / `456 Oak Street, Springfield IL 62704`), so the
correction is unambiguous and recoverable — not a guess, not a re-judgment. Fixed to the address (not blanked).
