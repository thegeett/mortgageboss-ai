# LP-327 — Multi-subject judgment evaluator (GAP-B)

## What it is

LP-323-ID-B's **GAP-B**: `judgment.py` was STRICTLY single-subject (it failed loud on ≠1 subject — the
OC-2 loan shape), so most of the ~36 judgment rules — per-borrower (citizenship eligibility) and
per-document (POA acceptability, altered-document detection, appraisal condition) — were blocked. This
ticket generalizes `judgment.py` to **declared subject enumeration** (the mechanism its siblings
`deterministic.py` / `consistency.py` already use), with **OC-2 unchanged as the equivalence proof**.

## Acceptance criteria

- [x] `evaluate_judgment_rule` enumerates subjects from the spec's `subject_enumeration` and returns one
  evaluation PER subject; the ≠1 fail-loud is removed.
- [x] Per subject: gate-before-AI → reason over that subject's TAGS → tag keyed to that subject →
  ratification-pending → one RuleEvaluation.
- [x] **Per-subject fail-closed:** one subject's gate/AI failure degrades ONLY that subject; the others
  evaluate. No wholesale rule failure.
- [x] **OC-2 EQUIVALENCE:** the OC-2 suite passes UNCHANGED (same verdict/confidence/gate/provenance/
  ratification-pending/tag keying). `evaluate_oc2`'s signature is unchanged.
- [x] `per_document` enumerator added; a NEW per-document judgment runs from a SPEC alone.
- [x] No `if rule_id ==` / family branch; ruff + mypy + full suite green (**2046 passed, 1 xfailed**).

## Assumptions & decisions

- **The per-subject loop** is the former single-subject body extracted to `_evaluate_one_subject`, run
  once per enumerated subject. Nothing about the armor changed — only that it now runs N times.
- **BATCHING / COST (honest):** **one bounded AI call per subject.** A judgment is a reasoned verdict
  per subject; batching N subjects into one call risks the position-degradation LP-313 guards against,
  and per-subject fail-closed is cleaner. So a per-document rule over N documents makes **N AI calls**.
  The orchestrator's `_required_ai_groups` gating already prevents running families no active rule reads.
- **Per-subject fail-closed** mirrors LP-321's partial-snapshot discipline at the rule level: each
  subject is self-contained, so one subject's AI failure/truncation/malformed → that subject
  couldnt_check/unknown-with-reason; the others are untouched.
- **Per-subject tag keying:** the registry returns `{subject_id: {tag_id: Tag}}`; the orchestrator merges
  each verdict tag under ITS subject. **OC-2 equivalence:** its `loan` subject → the tag lands under
  `LOAN_SUBJECT` exactly as before; an empty tags dict stays `{}`.
- **OC-2 equivalence is the proof** — `subject_enumeration: loan` yields exactly one subject → identical
  results; the OC-2 suite is unchanged.

## Which rules activated vs waiting + why

- **Activated:** none new — OC-2 remains the only active judgment rule (now via the multi-subject
  evaluator, identically).
- **ID-8 (citizenship, per-borrower) — BLOCKED, not authored.** A NEW gap surfaced: the `per_borrower`
  enumerator returns EMPTY tag maps (LP-325 consistency gathers across documents; borrower facts key
  under document content_ids, not under `borrower_id`). A per-borrower *judgment* reads the subject's tag
  map → empty → always couldnt_check. ID-8 needs a **borrower-tag-keyed enumerator + a producer that
  materializes borrower facts under `borrower_id`** — a separate ticket.
- **ID-9 (POA, per-document) — shape proven, UNACTIVATED.** The per-document judgment shape works (proven
  by the synthetic test). But activating real ID-9 needs (a) **GAP-C** (document-type applicability, or it
  floods couldnt_check on every non-POA document — `id.poa_present_and_acceptable` materializes there),
  and (b) a **NEW vocabulary output tag** for the verdict (a judgment `output_tag` is a vocabulary member —
  OC-2's `occupancy.reasonable` is in `fact_tags.csv` — and that CSV is generated from the xlsx, which
  cannot be hand-edited). Both are out of scope here.

## PRIYA / HUMAN-VERIFY additions (deferred with their rules)

- **ID-8** citizenship/residency eligibility criteria per program + investor overlays (DACA / non-permanent
  resident) — unencoded; needed when the per-borrower-judgment gap is closed.
- **ID-9** POA acceptability rules (occupancy limits, interested-party prohibition, durable vs specific,
  dating) — unencoded; needed when GAP-C + the output tag land.

## Other generalization gaps surfaced (reported, not patched)

1. **Per-borrower judgment** needs a borrower-tag-keyed enumerator + producer (blocks ID-8).
2. **ID-9 output tag** — the vocabulary is generated from the xlsx; a new judgment verdict tag can't be
   added without a vocabulary-pipeline change.
   (GAP-C — document-type applicability — was already recorded by LP-323-ID-B; ID-9 also depends on it.)

## What -C must cover

The full 13-point golden matrix for OC-2 (unchanged) and, once their gaps close, ID-8/ID-9 — including
ID-8's DACA/EAD/visa-expiry edges and ID-9's investment-property / interested-party / dated-after-note
POA edges (LP-323-A §4).
