# LP-315 — Thin deterministic rule engine + fail-closed gate (AS-1)

**Status:** Complete. **Branch:** `phase3_new_AI_arch_finding_stage2`.
**ADR:** [ADR-254](../../decisions.md). **Depends on:** LP-311 (spec + rule_tags),
LP-312/313/314 (the tags the rule reads), `rules/schema.py` (`satisfies`).

## What it is

**The payoff.** A rule finally READS the fact-tags and produces a verdict — with **no AI**
and **no `direction==` filter** in the rule. AS-1 becomes a thin query over `is_money_in` +
`amount` + `has_identified_source` + the spec threshold. Plus the **fail-closed gate**: a
low-confidence / unknown / absent / contradictory load-bearing tag can never yield a confident
`satisfied`. Engine + gate + AS-1 only; produces an in-memory evaluation **result**, not yet a
persisted finding (LP-316).

## Acceptance criteria

- [x] A generic fail-closed gate, run before every rule, with the fixed decision order:
  absent → `couldnt_check`, unknown → `couldnt_check` (distinct reason), contradiction →
  `needs_review`, below conf-floor → `needs_review`, else PASS. `verdict_confidence = min`
  of load-bearing confidences (parsed passthroughs' `None` ignored).
- [x] AS-1 as a thin rule: subject universe `is_money_in == "in"` (a **tag query**, not a
  label); fire iff `amount > threshold AND has_identified_source != "yes"` via `satisfies()`
  (no re-implemented `>`); no AI.
- [x] `has_identified_source == "no"` → **fired** (fraud case); `== "unknown"` → caught by the
  gate (`couldnt_check`), never reaches fire.
- [x] Threshold from the spec (`50%` → 0.5) applied to DTI-calc qualifying income; missing
  income → `couldnt_check`.
- [x] The result carries its load-bearing tags **inline** (provenance) + `verdict_confidence` +
  `threshold_used` + `priya_validated`; `priya_validated == false` → `gated_pending_signoff`.
- [x] No direction filter: a `"transfer"`/unlabelled deposit with `is_money_in == "in"` is
  evaluated, not dropped.
- [x] Deterministic; no persistence; no AI. ruff + mypy(`app/`) + full suite green (1891 passed).

## What was built (`app/verification/rule_engine/`)

- **`gate.py`** — `evaluate_gate(load_bearing, *, confidence_floor, contradiction)` →
  `GateResult`. The reusable safety core.
- **`as1.py`** — `evaluate_as1(subject_id, subject_tags, *, threshold_multiplier,
  qualifying_income, priya_validated, confidence_floor, contradiction)` → `RuleEvaluation`.
  Applicability → gate → fire arithmetic (reusing `satisfies`).
- **`engine.py`** — `evaluate_as1_rule(snapshot, *, confidence_floor=0.5)`: loads AS-1's spec,
  extracts the `50%` multiplier + `priya_validated`, reads income from the DTI calc, enumerates
  per-deposit subjects, runs gate+rule, returns `list[RuleEvaluation]`.
- **`result.py`** — `Verdict` (fired/satisfied/couldnt_check/needs_review/not_applicable),
  `LoadBearingTag`, `RuleEvaluation`.
- **Tests** — `test_gate.py` (8), `test_as1.py` (14), `test_engine.py` (7) — all deterministic,
  tag/calc fixtures, no AI, no DB.

## Assumptions & decisions

- **Gate decision order + absent ≠ unknown.** Absent (tag never produced) and `"unknown"` both
  block with `couldnt_check` but carry **distinct reasons**; contradiction and low-confidence →
  `needs_review`. A degraded input never reaches a confident verdict.
- **`verdict_confidence = min` of non-None confidences.** Parsed passthroughs (`txn.amount`,
  `confidence=None`) are effectively certain (§3D) and are ignored; only AI-judged confidences
  (`is_money_in`, `has_identified_source`) gate. Stated choice.
- **Applicability is a tag query, not a label** — `is_money_in` decides in/out/unknown; the
  `direction==` bug cannot recur at the rule layer.
- **Threshold from the spec (prose-parsed).** `reference_values.large_deposit_threshold` is
  prose (`"50% of …"`); the engine extracts the leading percentage → 0.5. Flagged: a structured
  threshold field would be cleaner (spec-shape gap for a future ticket).
- **Income from the DTI calculator** (`calculations.dti.value["gross_monthly_income"]`) — no
  loan-level income tag exists yet; the calc is the available source (matches the spec's
  `required_inputs` note). Missing → `couldnt_check`.
- **`satisfies()` reused** for the one comparison — the calculators' re-implement-the-`>` drift
  is deliberately not repeated.
- **Priya-pending:** AS-1's threshold is unvalidated, so every result is `gated_pending_signoff`
  — a later orchestrator withholds it from "shipped". Never silently shipped.
- **Confidence floor default 0.5** (spec has no floor field) — Priya-confirmable.
- **New package** `rule_engine/` (distinct from the old `verification/engine.py`).
  `load_rule_spec` is file-backed → the engine + tests need no DB.

## Deferred / out of scope (→ LP-316 and beyond)

- Any AI or tag production (LP-313/314); other rules; the orchestrator (LP-321); the discovery
