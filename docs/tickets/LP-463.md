# LP-463 — Classification Phase 2: let the classifier decline, stop overriding it, Tier 3 → scoped free extraction

54 of 268 (20%) were misclassified — mostly not judgment errors but the classifier **forced to pick when
nothing fit**, or its correct reading **overridden by the label**. Three changes: (1) make `unknown` a
first-class choice, (2) a reasoning-vs-label guard, (3) Tier 3 becomes free extraction scoped to
mortgage-relevant data. **No confidence threshold** — wrong calls ran 0.75–0.99, so a threshold would
suppress correct high-confidence calls and still miss the wrong ones.

Phase A is design + one real measurement (A5). No model calls.

---
## A1 — the prompt: does it offer `unknown`? how hard does it push to pick?

**Quoted** (`app/ai/prompts/classification/document_classifier.txt`): it **does** offer `unknown` — line 22
(`"one of the known type slugs above, or 'unknown'"`) and lines 38–42 ("If you are CONFIDENT the document is
NONE of the known types … return 'unknown' with a HIGH confidence. Do NOT force it into a known type"). But
two things push toward a pick: line 5 ("**Choose the SINGLE best-matching type**") frames the task as
picking, and — the real pressure — **declining costs everything downstream**: Tier 3 was a thin generic
analysis, so the model has little reason to decline. The reasoning field already NAMES the document ("one or
two short sentences DESCRIBING the document") — on 158 it wrote *"wiring instructions from a law firm"* — but
`document_type` comes **first** in the output and nothing uses the name.

**Proposed wording (Phase B):**
- **Name first.** Reorder the output so the model emits **`document_name`** — free text, "what this document
  actually is, in your own words" — BEFORE choosing `document_type`. Naming first improves the pick and gives
  the guard (A2) its input. (158's free name was more reliable than its constrained pick.)
- **Decline is legitimate.** Add: *"If no known type is a good fit, choosing `unknown` is the CORRECT answer,
  not a failure — the document will still be read and its mortgage-relevant facts captured. Do NOT stretch a
  poor-fitting type to avoid `unknown`."* This removes the "must pick" pressure now that Tier 3 reads the
  document properly (change 3).

## A2 — the reasoning-vs-label guard + false-positive risk

**The cases** (bench, confirmed): 158 — name "wiring instructions from a law firm" → `general_correspondence`
**@ 0.85** (⚠️ high confidence — the confidence gate would NEVER catch this; that is the guard's whole
point); 246 — "year-end performance and compensation summary … While it documents compensation …" →
`commission_income_statement` @ 0.45; 248 — same shape @ 0.40. The harm the guard prevents is the **T4 case**:
a Canadian T4 labelled `w2` with the **US W-2 schema applied** — plausible American tax numbers from a
Canadian form, and nothing downstream notices (these three were harmless only because their mislabelled types
have no extractor).

**Proposed guard: a model-emitted self-consistency signal, not a lexical diff.** In the SAME call, after
naming the document and choosing a type, the model emits **`type_matches_document`** (boolean): *"does the
`document_type` you chose faithfully describe the document you named? If NOT, set it false — we will flag for
review instead of applying a wrong label."* The pipeline flags `NEEDS_REVIEW` (reason `type_mismatch`) when
it is false, and routes the document to Tier 3 free extraction (a flagged document still gets read).

**Why this design, and the false-positive risk:**
- A **deterministic lexical comparison** (does `document_name` mention a catalog type ≠ the label?) was
  rejected: document names are free text ("wiring instructions", "Performance and Rewards statement") that
  rarely equal a catalog slug, so it would both **miss** real mismatches and **fire** on paraphrase — high
  FP *and* FN. The model is far better at "does my label fit what I just described."
- **FP risk of the model signal: LOW.** It fires only on the model's **own admitted contradiction** — the
  exact thing 158/246/248 show it already writes in prose. ⚠️ Ordinary hedging is NOT a contradiction:
  *"resembles a Loan Estimate but is more likely a Closing Disclosure"* → the model still commits to CD and
  sets `type_matches_document = true`. The guard fires on *"this is a T4, but the closest listed type is
  w2"* → false. The prompt states this distinction explicitly (hedge-and-commit vs name-A-label-B) to hold
  the FP rate down. The residual FP mode — a cautious model setting false on a genuine good fit — costs only
  a NEEDS_REVIEW + a free-extraction read, never a wrong label; it fails safe.

## A3 — the untyped snapshot section: location, marking, rule-inaccessibility

**Today** the Tier 3 output (`document.generic_analysis` + `document.full_text` + `DocumentFinding`s) is
stored on the `Document` but is **not in the snapshot at all**, and **no deterministic rule reads it**
(grep-confirmed: `app/verification/` references neither `GenericAnalysis` nor `DocumentFinding`). So the
baseline already honours "no rule depends on it" — the task is to surface it to **AI reasoning** without
breaking that.

**Proposed (Phase B), the LP-444 precedent exactly:**
- **Location + marking.** Add an ADDITIVE `untyped_extraction` attribute to `DocumentEntry` (snapshot),
  default empty — the same shape as LP-437 `lists` / LP-421 schedules, so **`SNAPSHOT_VERSION` stays 4** and
  the golden fixture still validates (the default fills it). It is self-marking: a field named
  `untyped_extraction`, carrying model-labelled/uncoerced values, distinct from typed `fields`.
- **Available to reasoning, opt-in.** AI contexts are built in `tag_materialization/subjects.py::_doc_context`
  which "reads only `fields`" by default; LP-444 added `ContextOptions.include_lists` as an **opt-in** to also
  serialise `entry.lists`. Add a parallel **`include_untyped`** opt-in (capped, PII-scrubbed, truncation-
  marked, exactly like `include_lists`) so a cross-source group that wants it gets it and every existing
  group is byte-identical.
- **No deterministic rule may read it — enforced.** Deterministic rules/recipes read `entry.fields`,
  `entry.transactions`, `entry.schedule_c/e` via the typed `read_field` paths; none reach
  `untyped_extraction`. Structural enforcement: it is not a `Field`/`PiiField` (the type the rule readers
  accept) and is not registered in any `read_field`/enumerator. **Plus a test** asserting no rule module and
  no recipe references `untyped_extraction`, and that it reaches AI context only under `include_untyped`.

## A4 — the free-extraction prompt: scope without listing fields

Listing fields would recreate a schema — the point is that none fits. **Scope by RELEVANCE + EXCLUSION,** not
a field list. The prompt asks for mortgage-relevant CATEGORIES — parties + roles, dollar amounts + what each
is for, dates + what each marks, account / property / loan identifiers, obligations & terms — and
**explicitly excludes** boilerplate: legal disclaimers, IRS/agency "notice to …" instructions, marketing
blocks, cheque-stub voucher furniture, headers/footers/page numbers. The rule the model is given: *"capture a
value only if a mortgage loan file would care about it; if it is a disclosure, an instruction, marketing, or
page furniture, SKIP it."* The existing Tier-3 slots (parties/dates/amounts/findings/summary) are close and
kept; the change is (a) the mortgage-relevance scoping + boilerplate exclusion, and (b) **dropping the
`full_text` dump** (the "extract everything" noise: a W-2's ~35 Notice-to-Employee lines, a pay stub's
voucher block).

**Cost verdict:** the 744 Tier-1 docs (79%) are untouched. The 100 existing Tier-3 docs swap one analysis-tier
call for another (≈ neutral). The measurable NEW cost is **~15 calls per 943-doc run (< 2%)** — the
`NEEDS_REVIEW` documents that now get read — plus a bounded, unpredictable increase from legitimate declines
(≤ the ~54 misclassifications; each replaces a *wrong* Tier-1 extraction or a Tier-2 summary with a free
extraction, so cost-neutral-to-cheaper). **Net: roughly +2–6 % of AI calls, each comparable to today's Tier-3
call — not a cost blow-up.** Decision input, reported not buried. (Free extraction stays on the analysis tier
— `anthropic_model_analysis`, Sonnet — so per-call cost is unchanged from today's generic analyzer; dropping
to Haiku is a future cost lever, noted not taken.)

## A6 — already-classified documents

**Nothing reclassifies automatically.** Classification runs once, in `_process_document`, on upload; there is
no reclassification job or trigger. The 943 documents already classified and stored under their (sometimes
forced) labels are **unaffected** — this change alters only how NEWLY-processed documents are classified and
routed. Re-running the corpus would apply the new behaviour, but that is a manual bench action, out of scope.

## Proposed Phase B (pending sign-off)
1. **Prompt + result:** `document_name` (named first) + `type_matches_document`; strengthen the decline
   wording. `ClassificationResult` gains `document_name` + `type_matches_document`; parse both.
2. **Guard:** pipeline flags `NEEDS_REVIEW` (reason `type_mismatch`) when `type_matches_document` is false,
   and routes flagged/`unknown`/low-confidence docs to Tier 3.
3. **Tier 3 → scoped free extraction:** rework the Tier-3 prompt (mortgage-relevance scope + boilerplate
   exclusion; drop `full_text`); surface the output into a new additive `DocumentEntry.untyped_extraction`;
   add `ContextOptions.include_untyped` (opt-in) so AI cross-source can read it; a test proves no

4. **Routing:** catalog types tried first; free extraction is the fallback; `needs_review` documents also
   route to Tier 3.
5. **NOT:** a confidence threshold; touching catalog-typed extraction; making the untyped section
   rule-readable; the splitter; confusable-pair cues (Phase 3).

## PHASE B — build

1. **Decline + name-first** (`document_classifier.txt`, `classification.py`): the prompt names the document
   FIRST (`document_name`), then picks a type OR declines; declining to `unknown` is stated to be correct
   (the document is still read). `ClassificationResult` gains `document_name` + `type_matches_document`
   (default True — a missing self-check never spuriously flags). `document_name` is NOT logged (PII-adjacent
   like `reasoning`); the boolean self-check is.
2. **The guard + routing** (`document_processing.py`): when `type_matches_document` is False the wrong label
   is **not applied** — the type is stored `unknown`, the model's rejected pick + name go to the activity
   detail, and the document is routed to Tier 3 (READ) with review reason `type_mismatch`. Low-confidence
   docs likewise route to Tier 3 (READ) with reason `low_confidence`, then `NEEDS_REVIEW` — no longer left
   unread. Catalog types are tried first; a confident, self-consistent classification takes its normal path
   unchanged.
3. **Tier 3 → scoped free extraction** (`generic_analyzer.py` + its prompt): the prompt now scopes to
   mortgage-relevant categories + an explicit boilerplate-exclusion list, and the `full_text` transcription
   (the "extract everything" noise) is dropped. Free extraction reads natively, so it gets a **page cap**
   (`tier3_max_pages = 50`) to avoid the same 100-page limit LP-462 fixed for classification — Tier-3-only,
   the typed extractors are untouched. Stays on the analysis tier (Sonnet).
4. **The untyped snapshot section** (`snapshot/model.py`, `documents_section.py`, `subjects.py`): an additive
   `DocumentEntry.untyped_extraction` (`SNAPSHOT_VERSION` stays 4; the golden fixture validates), populated
   from `document.generic_analysis`, identifier-scrubbed (`_scrub_untyped`, the `_DESC_REDACT` backstop) so
   no raw account/SSN reaches the snapshot at rest. Surfaced to AI reasoning ONLY via the opt-in
   `ContextOptions.include_untyped` (the LP-444 `include_lists` mirror). **No deterministic rule reads it** —
   `_doc_read_field` reaches `fields` only; enforced by a source-scan + read-path test.
5. **No confidence threshold** added; catalog-typed extraction untouched; the untyped section is not
   rule-readable; no splitter; no confusable-pair cues (Phase 3).

## ADR
- **Why declining is now legitimate.** With free extraction behind it, `unknown` is cheap — honest
  uncertainty no longer costs the document its data (Tier 3 reads it either way). And **every decline is
  evidence for a missing catalog type**: the `document_name` on an `unknown` names what the taxonomy lacks
  (wire instructions, compensation letters, HOA budgets, lease amendments, e-sign certificates).
- **The reasoning-vs-label guard.** A model-emitted `type_matches_document` flags the model's own admitted
  contradiction (low FP: hedging commits, contradiction declines). It prevents the T4→`w2` harm — a wrong
  schema applied to a confidently-mislabelled document, invisible downstream — which the confidence gate,
  by construction, cannot (0.85 on 158).
- **The untyped-section constraint.** `untyped_extraction` is available to AI reasoning via an opt-in
  (`include_untyped`), never to a deterministic rule — model-chosen labels and uncoerced values must never
  drive a deterministic decision; a test enforces it.

## NEW gaps found (reported)
- **075's assessment dollar terms weren't captured** by free extraction — the `tier3_max_pages = 50` cap (or
  the terms living in the bylaws section) left the per-unit dues out, though the units / structure / deed
  restrictions came through. A deeper cap or the splitter would close it; a bigger cap trades token cost.
- **Tier-3 full-text search dropped.** Dropping the `full_text` transcription (the boilerplate noise) also
  removed full-text indexing for unrecognized documents — a low-value feature that carried the boilerplate,
  but a behaviour change worth noting.
- **075 is a multi-document package** (its free extraction surfaced embedded deed-restriction + lead-paint
  documents) — a concrete splitter case, reinforcing LP-462's flag.
