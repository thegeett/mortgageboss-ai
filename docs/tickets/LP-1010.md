# LP-1010 — Copy to the processor

Step 4 (Receive), third ticket. Code, tests and a dev check. Nothing deployed, nothing committed.

## What and why

**When a borrower's email reaches a file, the processor gets a copy in her own inbox.** She works from her
mailbox; without a copy, a reply sits on the file until someone opens it.

**Who gets it:** the last person who sent an email from the app on that file with **Send** (decision 11-04).
She was CC'd on that email, so she is the one in the conversation. Loan files have no assigned processor. "I've
sent it" (sent from her own mail app) doesn't count, because the app never sent anything. If nobody has sent
from the app on that file, no copy goes out; the email is on the file as unread.

**Why no attachments** (decision 11-04): outbound mail never carries documents (LP-815; customer data stays off
plain email). The copy says how many attachments are on the file and links to it; she previews and accepts
them in the app.

**How it is sent:** by the worker, straight after the ingest commit (the message is saved first). No outbound
`Communication` row and no `send_draft`; one activity entry on the file records it. No retry: if it fails, the
file says so, and the email is on the file either way.

## The skip rules

A copy goes out only for a message **routed to a file when it arrived**, and only on its first insert. Each skip
logs `processor_copy_skipped` with a reason code and the message id, nothing else.

| Code | When |
|---|---|
| `not_routed` | Not on a file at ingest (unmatched, or still pending). Move to file never sends a copy |
| `rejected` | Its disposition was reject (virus, failed DMARC policy) |
| `auto_reply` | An out-of-office or other automatic reply (`is_auto_reply`) |
| `delivery_notice` | A bounce or delivery notice (`is_dsn`) |
| `bulk` | Bulk or list mail (`is_bulk`) |
| `our_copy` | It carries `X-MortgageBoss-Copy`, so a copy that comes back to a file address is never copied again |
| `no_recipient` | Nobody has sent with Send on this file |
| `she_sent_it` | Her address is the sender |
| `already_has_it` | Her address is in To or Cc, read from the stored message's headers (reply-all already reached her) |
| `suppressed` | Her address is on the company's suppression list |
| `no_address` | The company has no file address (no active domain, or `FILE_ADDRESSES_ENABLED` off) |
| `domain_problem` | The company's domain is in `problem` |
| `sending_off` | The company isn't switched on for sending |
| `no_sender` | No mail sender on this server (`MAIL_TRANSPORT` unset) |

The last four are the same rules as the Send button: they come from one function, `company_send_blocker`, which
`transmit_blocker` now also uses (see "What changed").

Addresses are compared lower-cased and trimmed. A redelivery of a message already stored (`created=False`)
never reaches any of this.

Four more codes cover cases the brief did not name (see Open 2): `no_message`, `no_sender_address`,
`raw_unreadable`, `no_link_origin`.

## The email

Sample, from the dev check (MailHog):

```
From: Jordan Rivera via Summit Mortgage Processing <lf-hwkm@mb-mail.localhost>
To: priya@summit-demo.com
Reply-To: jordan.rivera@example.com, lf-hwkm@mb-mail.localhost
Subject: Re: LP-1010 check
X-MortgageBoss-Copy: 1
Auto-Submitted: auto-generated
X-Auto-Response-Suppress: All
Precedence: bulk
Content-Type: text/plain; charset="utf-8"

Reply from Jordan Rivera on LF-HWKM. Reply normally, or open the file: http://localhost:3000/loan-files/LF-HWKM/communication

Here are the two statements.

2 attachments are on the file: http://localhost:3000/loan-files/LF-HWKM/communication
```

- **From** name: the sender's display name, or their address when there is none, then "via" and the company
  name. The address is the file address, so it is signed by our domain.
- **Reply-To**: the sender and the file address. A plain Reply from her mail app reaches the borrower and puts a
  copy on the file.
- **Subject**: the original, or "(no subject)".
- **Body**: plain text. The email's own text comes from `inbound_mime.body_text` (LP-1009); with none, "(This
  email has no text.)". The last line reads "1 attachment is" for one, and is left out with none.
- **Headers**: the marker, and `AUTO_REPLY_SUPPRESSION_HEADERS` so her out-of-office doesn't answer it. Its
  Reply-To would reach the borrower.

**Recorded on the file:** "A copy was emailed to <full name>" (`communication_sent`), or "Could not email a copy
to <full name>" (`communication_failed`). Both have `kind: processor_copy`, the inbound message id and her user
id in the detail, plus the provider's message id or the error code.

## What changed

| File | Change |
|---|---|
| `services/processor_copy.py` (new) | `copy_recipient`, `send_processor_copy`, the body text, the marker |
| `tasks/inbound.py` | `_ingest_message` calls the copy after its commit when `created` is true. `_copy_to_processor` runs it in its own session and never fails the ingest. New task `inbound.copy_to_processor` for the dev injector |
| `api/dev.py` | The injector queues `inbound.copy_to_processor` after its commit, for a new message only: the API must not send (rule 8) |
| `services/email_send.py` | `company_send_blocker`: the company rules out of `transmit_blocker` (file address, domain `problem`, sending switched on, mail sender), as codes. `transmit_blocker` uses it and shows the same sentences as before |
| `services/outbound_mime.py` | `build_mime(reply_to=…)` takes one address or a list. Each item is checked as one bare address, like To |
| `tests/conftest.py` | Records `copy_to_processor.delay` instead of pushing it to Redis, like the other two queued tasks |

**Who:** `copy_recipient` reads the approver from the evidence record (`communication_evidence.approver_user_id`,
event `sent`), as the worker does (`tasks/outbound.py`). It takes the latest outbound row with
`send_requested_at` on the file, and skips a user who is inactive, deleted, or in another company.

**The activity entry** uses the existing `communication_sent` and `communication_failed` types. A new type would
need a constraint-swap migration (ADR-037), and this ticket adds none. The detail has no `communication_id`, so
nothing that reads those types for an outbound email (`delivery_events`, `condition_drafts`) picks it up.

**The link** is `UPLOAD_LINK_BASE_URL` (`settings.upload_link_base_url`), read through
`upload_links.usable_link_origin()`, the same check the upload links use. No new setting. In staging it is set
for the worker too: the API and worker share one environment block (`infra/envs/staging/main.tf`, module
`compute`). It points to `/loan-files/<LF-XXXX>/communication`.

**Time limit:** `_copy_to_processor` catches every error except Celery's soft time limit. That one goes on to
`poll_queue`, which stops the batch, as it does for a slow save. The message is already saved, so a redelivery
deletes it without a second copy. Found while writing this ticket, not in the brief; tested.

No migration, no new table, no new setting.

## Open

1. **A lost answer from SES is recorded as "Could not email a copy".** `SendError(outcome_unknown=True)` means
   it may have gone. No retry, so she gets at most one copy either way, but the file can say "could not" for a
   copy she received.
2. **Codes the brief did not list:** `no_message` (the row is gone), `no_sender_address` (no From; there is
   nobody to reply to), `raw_unreadable` (the stored original can't be read, so To/Cc can't be checked) and
   `no_link_origin` (`UPLOAD_LINK_BASE_URL` fails its check outside development). Each skips rather than send
   something wrong.
3. **The copy carries `Precedence: bulk`** (part of `AUTO_REPLY_SUPPRESSION_HEADERS`). It stops auto-responders,
   but some mail filters treat bulk mail as low priority. Watch for it landing in a Promotions or junk folder in
   LP-1012.
4. **Any Send counts, even one that later bounced or failed**, as long as a person pressed Send.
5. **The copy is not on the Communication timeline**, only in the file's activity, as briefed (no outbound row).
6. **Sending runs inside the poll batch.** A slow provider (SES read timeout is 30 s) takes time from the 180 s
   batch limit. At pilot volume it is fine; if not, move the copy to its own queued task.
7. **The copy is not threaded** (no `In-Reply-To`): it starts its own thread in her mailbox, under the
   original subject.

### From the review (2026-11-05), not fixed

One review round ran on the working tree. All findings below are recorded, not fixed: there are few users
for now, and they are deferred until volume or a pilot report makes them matter. Numbers 9 and 10 were
checked by running them; the rest come from reading the code.

8. **No limit on copies.** Anyone who has seen the file address (it is in every email's Reply-To) can send
   many different emails to it, and each one sends her a copy from our signed domain. That floods her inbox
   and hurts the domain's reputation with SES. `send_draft` has a per-address limit (`_refuse_if_rate_limited`);
   the copy has none. *Fix later:* a per-file cap (e.g. 1 per 5 minutes, 20 a day), skipped as `rate_limited`.
9. **A stranger's display name appears on an email from our domain.** The From name is the sender's own
   display name plus "via <company>". A sender can call themselves "Summit IT Support – Password Reset", and
   she receives that name on a DKIM-signed email from the file address, which makes the copy useful for
   phishing. *Fix later:* use the sender's address in the From name, not their display name; the body's first
   line can keep the name as plain text.
10. **A line break in the subject or sender name breaks the copy** (checked by running it). A subject that
   decodes to text with a line break makes `build_mime` refuse, so the file wrongly says "Could not email a
   copy". A sender name with a line break raises while the headers are read, before anything is recorded;
   `_copy_to_processor` logs `processor_copy_task_failed`, and the file says nothing. *Fix later:* replace line
   breaks with spaces in both, and read the name inside the error handling.
11. **A bounce or complaint about a copy is never recorded.** Delivery events are matched to a
   `Communication` row, and the copy has none (as briefed). Her address is never suppressed, so later copies
   keep going to a dead or complaining mailbox and count against SES. *Fix later:* record the copy's provider
   message id where `delivery_events` can find it, and suppress on a hard bounce or complaint. Needs a decision,
   because the brief said no outbound row.
12. **A Bcc'd processor gets a second copy.** The "already has it" check reads only To and Cc. If the borrower
   Bcc'd her, she is not in either header, though SES did deliver to her. *Fix later:* also check
   `envelope_recipients`.
13. **A copy can go out for a deleted file.** `send_processor_copy` doesn't check `loan_file.deleted_at`. If the
   file was deleted between routing and the copy, it is still emailed, with a link to a deleted file. *Fix
   later:* skip as `file_deleted`.
14. **The attachment count includes unsafe or still-scanning files.** "2 attachments are on the file" can be
   wrong when one was flagged as malware or rejected. *Fix later:* count only safe or pending ones, or say "2
   attachments arrived".
15. **A hard kill between the send and the commit loses the record.** She has the copy, but the file shows no
   entry, and a redelivery doesn't send or record it again. Rare, and nothing is sent twice. Goes with Open 6:
   moving the copy to its own task fixes both.
16. **The send rules still exist in a third place.** `company_send_blocker` holds the company rules for the Send
   button and the copy, but the outbound worker (`tasks/outbound.py` `_build`) still checks them by hand, so a
   rule added later could be missed there. In `send_processor_copy`, the `file_address is None or sender is
   None` checks repeat what the blocker already answered. *Fix later:* use the blocker in `_build` and drop the
   repeats.
17. **Small tidy-ups.** `company_send_blocker` returns a plain `str`, so adding a code without its sentence in
   `_COMPANY_BLOCKER_SENTENCE` crashes the Send button at runtime and mypy can't catch it (use a `Literal` or
   StrEnum). The email is parsed twice (once for headers, again in `body_text`).
