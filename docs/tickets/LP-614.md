# LP-614 — Switch off the legacy cross-source pass; the Old findings tab goes AI-typed and frozen

## Ask

> "ok now also remove Old findingd, also do not make any AI call for Old Finding."
> "keep the tab but simple no AI call for it."
> "for Old Finding tabs not for cross check."
> "in Old FIndings tab there must be no deteminstic rules."

So: keep the tab, stop the AI call behind it, and keep deterministic rules out of it. The snapshot
cross-check (LP-586 onward) is a different feature and is **not** touched.

## What the legacy pass was

`verification.run_cross_source` — enqueued per run, alongside the governed rule pass, on the same
run row. Two halves:

- **an AI half** — one model call per run, writing `cross_source.*` findings (origin
  `ai_cross_source`);
- **a deterministic half** — ~16 hand-written `xsrc.*` rules (origin `deterministic_rule`, no
  `evaluation_outcome`).

Both populate the Old findings tab, because that tab is "everything with no `evaluation_outcome`".

## Why both halves are off

**The AI half** spent this month being confidently wrong in ways its own text disproved: a $6,028
biweekly gross "conflicting" with $13,166.67 a month (the same money); a stated Bank of America
balance "conflicting" with a documented **Wells Fargo** one (two different accounts); an employer
mismatch over one trailing letter. Each was patched in turn — LP-607 taught it to annualise, LP-611
gave it a threshold and a same-object rule — and the next run found a new way.

**The deterministic half** is off on evidence, not by association. Sixteen rules; across the two
real files on staging exactly **two** ever fired:

```
deterministic_rule | xsrc.income.employer_name_consistency | 4
deterministic_rule | xsrc.identity.name_consistency        | 3
```

and both were already retired from `CROSS_SOURCE_RULES` (LP-606, LP-611) for contradicting IN-5 and
ID-1 — their `_norm` folds case and whitespace and nothing else, so it cannot tell "AMERICAS" from
"America", or a licence's surname-first printing from a different human being. The other fourteen
have produced nothing on real data, and eleven map to an **active** governed rule (ID-2, ID-3, ID-4,
IN-1, CR-1, RE-1, AS-1, OC-1, PC-2, PC-3).

## The change

**1. Stop enqueueing it** — `app/api/verification.py` no longer calls `_enqueue_cross_source`, and
the helper is gone.

**2. The task body is a no-op guard** — `app/tasks/cross_source.py::_run` logs
`cross_source_pass_skipped` and returns, for any task already queued at deploy time.

It **touches nothing**, deliberately. The obvious "disabled" body marks the run COMPLETED and
returns — and that is a false-green: this task and the governed rule pass share one run, and the
rule pass is the completion authority (LP-377-C). Completing the run here would report a finished
verification while the rules were still running, which is the exact failure `_enqueue_rule_engine`
warns about in its own docstring. The first draft of this ticket did that; the test that caught it
is `test_cross_source_task_makes_no_ai_call_and_leaves_the_run_alone`.

`run_cross_source` in `app/services/cross_source.py` is left intact rather than gutted — an early
return buried in it would have left ~120 lines unreachable and broken sixteen tests that still
correctly describe what that pass did.

**3. The Old findings tab is AI-typed only** — the legacy query in `app/api/verification.py` now
filters `origin == AI_CROSS_SOURCE` instead of both shown origins. This is what satisfies "no
deterministic rules in Old Findings": the six live `xsrc.*` rows on staging were rendering there,
and switching the pass off does not remove rows already written. They are **not deleted** — they
stop being displayed.

**4. The LP-523 CLI script was repointed** — `app/scripts/run_verification.py` enqueued *only* the
cross-source pass and never the rule engine, so a script-triggered run ran the legacy sweep and no
governed rules at all. With the sweep off it would have created a run and enqueued nothing. It now
enqueues `_enqueue_rule_engine`, which is what "run verification" means. Found by a collection
error, not by the grep that preceded the change — the grep looked for `run_cross_source_pass` and
this site imports the helper by name.

## Nothing is deleted

Reconcile never runs, so the 181 stored `ai_cross_source` findings stay exactly as they are. The
tab keeps its history instead of emptying itself on the next run; it simply stops growing.

## Note for whoever reads this next

Staging is currently running a build that predates the LP-606/LP-611 retirements — there are
`xsrc.identity.name_consistency` rows created 2026-08-21. Change 3 hides them regardless of which
build is deployed.

## Tests

- `test_cross_source_task_makes_no_ai_call_and_leaves_the_run_alone` — the reasoner raises if
  called; no findings written; run stays RUNNING with `completed_at` null.
- `test_creating_a_run_does_not_enqueue_the_legacy_cross_source_pass`
- `test_retired_xsrc_findings_do_not_render_in_the_legacy_tab` — an `xsrc.*` row is in neither list.
- `test_governed_pass_enqueued_on_a_miss_and_the_legacy_sweep_is_not` plus the cache/force/failure
  tests, re-pointed from the sweep's enqueue to the rule engine's (the LP-606 precedent: what they
  protect is cache and failure-surfacing behaviour, which is pass-agnostic).
