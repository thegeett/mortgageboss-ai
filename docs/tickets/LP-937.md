# LP-937 — Superseded failures

- **Ticket:** LP-937 · Phase 4.5 Stage 3 follow-up
- **Source:** the product owner, 2026-09-29: "When a passing document has done an item, earlier failed
  checks for that item stop counting in 'Failed a check' and stop showing in the Next step token. They
  stay in the history and on the detail sheet as 'replaced by <document>'."
- **Closes:** the open item and decision row "A failed upload keeps saying so after a better document has
  done its item" (Stage 3B acceptance).

## Design

**Superseded, defined once.** A failed evidence row (checked, a check failed, not accepted) is superseded
when:
- its item is **done**; and
- another evidence row for the **same item**, which arrived no earlier, **passes**: accepted, or failing
  no check.

The passing row is "the document that replaced it". A failure on an item that is not done yet still
counts. So does a failure whose item another route closed (her "I'll do it" tick has no document to name).

**Two statements of the rule, pinned to agree:**
- `condition_evidence.superseded_by(row, item, rows)` in Python, used by the sheet;
- `conditions.has_failed_check()` in SQL, used by "Failed a check" and its filter. It gains a `NOT
  EXISTS` for the same condition.

A test builds the S3-12-then-S3-08 sequence and asserts both statements.

**What changes on screen:**
- **"Failed a check"** (the summary count and its filter) stops counting the condition. Nothing else in
  the bar moves.
- **Next step:** `ConditionEvidencePublic.failed` is false for a superseded row, so the list's first
  token ("Evidence failed a check — page 6") no longer fires. The client needs no rule of its own.
- **Detail sheet:** the card stays, dimmed, with its checks as they were, and a line in place of the
  re-ask / accept-anyway callout (`ConditionEvidencePublic.superseded`):
  - a rejected upload reads **"Replaced by Capital One statements ··9912 · July and August 2026 · 12
    pages"**;
  - a statement that failed only "Enough for closing" on its own is still evidence (it is in the
    package), so "replaced" would be false. It reads **"Enough for closing together with <document>"**.

  Its findings' buttons are not offered: the answer belongs on the document that is evidence.
- **History:** unchanged. The `condition_evidence_checked` event keeps its failed count, as the record
  of what happened when the document arrived.

**No migration.** Superseded is derived from rows that already exist, so it can never go stale.

## Done, and the test for each

`backend/tests/conditions/test_superseded_failures.py` (5 tests). Each asserts the SQL half (the
count and the filter) and the Python half (the sheet's `failed`) together.

| Asked | Test |
|---|---|
| once a passing document has done an item, earlier failures stop counting in "Failed a check" | `test_a_failure_stops_counting_once_a_passing_document_does_its_item`: 3 → 1 (7086 waits on its deposit) → 0 once the deposit is explained; the filter and the sheet agree at each step |
| … and stop showing in the Next step token | the same test: `failed` is false on the superseded rows, which is the field the list's token reads |
| they stay in the history | the same test: the `condition_evidence_checked` event of the 5-page statement keeps `failed: 1` |
| … and on the detail sheet as "replaced by <document>" | the same test ("Replaced by Capital One statements ··9912 · July and August 2026 · 12 pages", its checks unchanged); `test_the_sheet_names_the_document_that_passed_not_a_later_failure` |
| a failure still counts while its item is not done | `test_a_failure_still_counts_while_its_item_is_not_done` (the positive control) |
| a statement short on its own is completed, not replaced | `test_a_statement_short_on_its_own_is_completed_not_replaced` ("Enough for closing together with …") |

**Frontend:** `evidence-section.test.tsx` — a superseded card shows its line and its checks as they
were, and offers no re-ask, no accept anyway and no finding answers.

**Mutations**, each restored from a copy:
- **Killed:** the SQL clause off; its "item done" clause; its order (`>=` made `<=`); the Python rule
  off; its "item done" clause; its order; its "passes" clause (it named a later upload that also failed;
  killed by the label test); the "together with" wording; `failed` ignoring superseded; and the card's
  two guards (callout and findings).
- **Equivalent, and pinned instead:** the SQL half's "the later row passes" and "for the same item".
  A done item takes no new evidence (`_takes` requires an awaiting item). So every failed row on a done
  item came before the document that did it, and those two clauses cannot change the answer.
  `test_a_done_item_takes_no_new_evidence` pins that invariant; removing it from `_takes` fails the
  test.

**Records:** the open item and the decision row are marked decided and built; the deferred line struck;
ADR-414 amended.
