# LP-458 — Schema-gap remediation, Phase 1: fields that exist and return null

The 268-doc bench-vs-free comparison flagged declared fields returning null on documents that (per the
free reader) carry the value. Phase 1 was to fix the ones that are prompt/extractor problems, not schema
gaps. **The headline result: most of the flagged nulls were the free reader OVER-recalling, not bugs —
the bench extractor was more correct.** Three fields were genuinely fixable and are fixed; the live-rule
item (IH-1) was found to be *unsafe to change* and was left as-is.

## Item 1 (IH-1) — reverted; the ADR lesson

IH-1 reads `replacement_cost_or_coinsurance_basis`. The recall fix (accept a dwelling endorsement whose
name literally says "replacement cost", exclude personal-property and mere "additional amount") **failed
in both directions** on re-extraction: **117 stayed null** (no recall gained) **and 114 wrongly populated
`"replacement cost"`** — a control that must stay null (the guard broke; the model conflated the
personal-property / master-policy language). So the change was **reverted**.

**ADR — why a correctly-designed anti-conflation field under-recalls (and must keep under-recalling).**
The field has a known confusable neighbour (Coverage C "Personal Property Replacement Cost"). Its
precision guard is *working*; the "misses" are the free reader over-recalling. The one genuine dwelling
signal (117's endorsement) sits one word away from a rider that must NOT populate (104's HQ-220), and a
prompt can't reliably hold that line — pushing recall re-opened the exact conflation the field exists to
prevent. **On a field with a confusable neighbour, a wrong value is worse than the null; precision wins,
and IH-1 stays as-is.** `couldnt_check` on 104/114/116 is the honest, correct verdict (the doc does not
state the dwelling basis).

## ⚠️ Mechanism finding — shipping prompts are hand-maintained (affects Phases 2 & 3)

The generator runs in **diff-mode for every shipping extractor** — it emits only a *"STARTER PROMPT —
REPLACE WITH…"* placeholder and a `.diff.md` report; it **never overwrites** a shipped prompt. All 109
shipped prompts carry that STARTER header. So a **spec `prompt_hint` edit does NOT reach any shipped
prompt** — the fix must edit the prompt `.txt` directly (and the spec is updated only for documentation).
`homeowners_insurance.txt` in particular is hand-edited well beyond the starter (the LP-446/447
anti-conflation block is not in any spec field).

**Guard added** (`test_homeowners_prompt_is_hand_maintained_not_the_bare_starter`): fails LOUD if the
hand-maintained homeowners prompt is ever replaced by the plain starter — a silently-overwritten prompt
would break IH-1's precision without any test noticing.

**For Phases 2 & 3:** a spec edit won't reach these prompts. Prompt/list changes must be applied to the
`.txt` directly. A full "which shipped prompts diverge from their spec-generated output" survey
(regenerate-and-diff across all 109) is a worthwhile follow-up.
