# LP-419 — Write IN-12 (a self-employed borrower needs 2 years of income history)

## What this ticket is

IN-12 has been **structurally dead / blocked since LP-390-2a**. It read `income.has_2yr_history` `per_document`
at the `tax_return` subject, but the tag is produced `per_borrower` (LP-385) — so on a real file it always
`couldnt_check`. The naive fix (re-scope to read `has_2yr_history` per-borrower) is **FORBIDDEN**: that tag is
income-type-agnostic, so a bare re-scope fires **identically to IN-11**, destroying IN-12's self-employment
specificity (ADR-310). A `strict` xfail encoded the debt.

**LP-418 built the missing piece:** `income.is_self_employed` (derived, borrower-subject, a deterministic
promotion of the already-measured `income.type`). LP-419 uses it: IN-12 is re-scoped to `per_borrower` and
**gated on `income.is_self_employed == yes`**, then checks the history. **The applicability gate IS the rule** —
it is the only thing that distinguishes IN-12 from IN-11.

## The rule (as written)

| condition | outcome |
|---|---|
| `income.is_self_employed == no` (W-2 borrower) | **`not_applicable`** — out of scope, not a gap |
| self-employed AND `has_2yr_history == no` | **`fired`** |
| self-employed AND `has_2yr_history == yes` | **`satisfied`** |
| `is_self_employed == unknown`, or absent | **`couldnt_check`** |

Deterministic block: `applicability: {tag: income.is_self_employed, op: eq, value: "yes"}` (the AS-8 tag-predicate
pattern — NOT a document-type predicate, so no `applicability_expected`); `load_bearing_tags`/`gated_tags` =
`[income.has_2yr_history]`; outcomes fired (`has_2yr_history == no`) / satisfied (default). Reuses the generic
deterministic evaluator — no per-rule Python.

## D1 — the applicability gate + the xfail's resolution

The gate is what makes IN-12 ≠ IN-11. From `resolve_applicability`: `is_self_employed == no` → `not_applicable`
(scope-false, Tab 4); `is_self_employed` absent / `"unknown"` → `couldnt_check` (Tab 1, cannot tell if it
applies); `is_self_employed == yes` → the rule applies → the history branch.

**The xfail (`test_in12_..._structurally_dead_pending_a_producer`), resolved — and the result is subtle and
important.** The old body set only `has_2yr_history=no` (no `is_self_employed` — the tag didn't exist when it was
written). Against the correctly-gated IN-12 that yields **`couldnt_check`, so the strict xfail did NOT xpass on
its unchanged body.** That is the *correct* signal, not a failure: **had it xpassed on `has_2yr_history` alone,
IN-12 would be firing without the self-employment gate — the ADR-310 forbidden fix.** The deferred debt is paid
by *adding the producer input* (now possible via LP-418), so the test is deliberately rewritten to
`test_in12_self_employment_history_fires_the_debt_is_paid_lp419`: with `is_self_employed=yes` + `has_2yr_history=no`
it **FIRES**, and a companion assertion pins that *without* the gate it stays `couldnt_check` (the forbidden fix
can never silently return).

## D2 — the IN-11 boundary (observed, both verdicts)

On the **same** self-employed borrower with `has_2yr_history=no`, **both fire** (verified directly and end-to-end
on the materialized scenario):

| rule | verdict | reason |
|---|---|---|
| IN-11 | fired | "this income lacks a 2-year history — variable income needs an adequate history to be used" |
| IN-12 | fired | "self-employment income lacks a 2-year return history — a Form-1084 cash-flow analysis needs two years of returns and cannot be supported" |

**Resolution (argued, not assumed):** the double-fire is the accepted precedent (AS-8/AS-10, IN-5/IN-6, AS-2/PC-5)
— two rules surfacing related-but-distinct concerns. The standards genuinely differ (Fannie B3-3.1-01 variable-
income averaging vs B3-3.2 self-employment / Form 1084); IN-11's generic over-fire is a **pre-existing documented
limitation** (its own ticket). **IN-12's reason is provably distinct** (asserted). **IN-11 was NOT changed** (an
equivalence proof would be required to touch a live rule; not in scope).

## D3 — the honest activation ending: HELD (ACTIVE unchanged, no 30 → 31)

The ticket's premise ("income.type already measured, LP-379-D") is **overridden by the code of record**: IN-13's
bar reads `income.type UNSCORED`; LP-395 calls it "thinly measured **n=2**"; LP-380/LP-394 say unscored. IN-12's
self-employment **scope gate** rests on `income.type` (via the derived `is_self_employed`). By the exact IN-13
precedent (a live-rule bar that reads `income.type` → `not-calibratable-yet`), IN-12 cannot claim a validated
calibratable bar.

- The **verdict** tag `has_2yr_history` is measured 100% (LP-393-6) and Priya-validated at 0.9 via IN-11 — that
  half is fine.
- The **scope** gate rests on the unscored `income.type` — the remaining blocker.

So the bar moves **`needs-producer` → `not-calibratable-yet`**: the LP-390-2a producer / structural-death blocker
is **resolved**, but a calibration blocker on `income.type` remains (the same wave LP-394 says "clears IN-8, IN-9,
IN-13 in one pass" — IN-12 joins it). `is_eligible` returns False (fail-closed, "when in doubt, hold"), so
**`ACTIVE_RULE_IDS` stays 30**. IN-12 activates when `income.type` is scored and the bar is signed off — a
one-line flip (the IN-6 / LP-412 pattern).

## D4 — the subject match

From `load_declarations()`: `income.is_self_employed` = **borrower**, `income.has_2yr_history` = **borrower**;
IN-12 `subject_enumeration` = **per_borrower**. Producer key == consumer key — no structural death.

## D5 — provability

The income-scenario fixture is all-employment (`income_stability` does not read tax returns; IN-12's case is
un-exercisable there). Added a standalone scenario `build_self_employed_no_history_snapshot()` in
`fire_path_scenarios.py` (`95…` namespace): one self-employed borrower (a tax return + a 1003). The test
materializes `income.type == self_employment` (income AI group) → the LP-418 promotion → `is_self_employed == yes`
→ IN-12 **fires** (and IN-11 fires too — D2 observed end-to-end).

## D6 — threshold

"2 years" is a **fixed Fannie B3-3.2 agency rule**, not a Priya window; Priya already settled `has_2yr_history`'s
meaning (LP-393-6). The `threshold_needs_signoff: true` the CSV carries refers to the 1084 add-back METHOD (the
follow-on calculator), not this history check. No new validated threshold. The hold is `income.type` scoring, not
a window.

| `is_self_employed=yes`, `has_2yr_history=no` | **fired** |

- **IN-11 on the same self-employed no-history borrower:** fired (the double-fire, distinct reason).
- **LF-6T3N:** its borrowers are W-2 — with `income.type` perceived as W-2 income the promotion reads

  keyless stub `income.type` is honest-unknown → IN-12 `couldnt_check` (the correct fail-closed state) — both are
  recorded in the test.
- **The xfail:** did **not** xpass on its old body (couldnt_check — the gate was absent); resolved deliberately to
  a passing FIRE assertion + a forbidden-fix guard.
- **Activation:** IN-12 **held** (not-calibratable-yet, not eligible); `ACTIVE_RULE_IDS` = 30 (unchanged); the 30
  live rules identical (IN-11 especially, asserted).
