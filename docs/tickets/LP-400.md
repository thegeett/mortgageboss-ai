# LP-400 — Add stmt.holder_name_variance + stmt.non_borrower_co_holder

## What this ticket is

Priya's ruling (post-LP-399): a name difference should FLAG for attention but the document still COUNTS; a joint
account should flag a non-borrower co-holder. The current `stmt.owner_matches_borrower` enum (`yes/no/unknown`)
can't express *"matches, but with a discrepancy worth a look."* This adds two SEPARATE fact-tags alongside it so
the discrepancies can be SURFACED instead of swallowed. **The tags DESCRIBE; a rule (later, Priya's) JUDGES.**
This ticket only makes them produce — AS-6 is untouched.

## Acceptance criteria (met)

- `stmt.holder_name_variance` + `stmt.non_borrower_co_holder` declared + produced by `stmt_facts` on the
  document subject (same one call — no cost increase).
- `stmt.owner_matches_borrower` + `stmt.is_reserve_eligible` semantically UNCHANGED (enums intact; the 5
  LF-6T3N goldens still `yes`).
- The variance values are descriptive observables, not verdicts; `unknown` reachable; a reason always present.
- AS-6 untouched; `ACTIVE_RULE_IDS` unchanged (24); LF-6T3N + the fixtures untouched; full suite green.

## Phase 0 — the argument

- **D1 — tag definitions + value sets.**
  - `stmt.holder_name_variance`: `none | middle_absent | middle_differs | nickname | surname_differs | other |
    unknown` — HOW the stated holder name differs from the borrower it matched. *Which* kinds warrant attention
    is **Priya's (a RULE decision), flagged, not settled here.**
  - `stmt.non_borrower_co_holder`: `yes | no | unknown` — is there an additional, non-borrower holder (joint
    account)? Reasoning names them.
- **D2 — describe vs judge.** The values are descriptive KINDS (`middle_differs`, `nickname`), not verdicts
  (`acceptable`/`flag`). **The key design call: SPLIT `middle_differs` (a DIFFERENT middle — N1, the risky
  case) from `middle_absent` (a DROPPED middle — P1, benign).** The ticket's initial `middle_name` value would
  collapse them and re-create the exact problem at a finer grain — the rule could not tell N1 from P1. The
  differs-vs-absent distinction is a FACT, so it belongs in the tag.
- **D3 — does `owner_matches_borrower` change? NO.** Its clause is verbatim unchanged; the variance moves to the
  new tag. Its 5 LF-6T3N goldens stay `yes` (verified below). It keeps answering only the match question.
- **D4 — fixture coverage** (LP-398's 8): N1 → a `middle_differs`; P1 → `middle_absent`; P2 → `nickname`;
  N3/N4/N6 (non-borrowers) → `none`; N5 → co_holder `yes`. **Achievable n per new tag** below. `surname_differs`
  has **no scenario (n=0)** — a fixture gap (its own ticket).
- **D5 — cost.** `stmt_facts` makes ONE call producing its tags; 2 → 4 tags is the same call. No per-document
  cost increase.

## The prompt extension (quoted — tags 1/2 verbatim unchanged, 3/4 added)

> 3. holder_name_variance — WHEN owner_matches_borrower is "yes", DESCRIBE how the stated holder name DIFFERS
>    from the borrower it matched … "none" … "middle_absent" — a middle … present on ONE side and absent on the
>    other ("Jordan Rivera" vs "Jordan A Rivera") — a DROPPED middle, not a different one; "middle_differs" — a
>    DIFFERENT middle name/initial ("Jordan M Rivera" vs "Jordan A Rivera") … "nickname" … "surname_differs" …
>    "other" … "unknown". Report the OBSERVED difference only; NEVER guess an identity not in "loan_borrowers".
> 4. non_borrower_co_holder — is there an ADDITIONAL account holder … who is NOT one of the loan_borrowers?
>    "yes" (name the non-borrower holder) | "no" | "unknown". … ORTHOGONAL to owner_matches_borrower.
