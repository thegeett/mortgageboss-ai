# LP-377-D — Gate per-document AI groups to relevant doc-types (fail-open)

## WHAT THIS TICKET IS

A per-document AI structuring group runs on EVERY document and abstains where it doesn't apply (LP-368: 95
abstention instances, each a paid call returning "no"). **LP-378 upgraded this from cost to CORRECTNESS:**
`income_amounts` over-produced a confident `documented_monthly` on mortgage statements, property-tax bills, and
bank statements — documents with no income emitting income figures. This declares each group's `applies_to`
doc-types and gates the dispatcher on them — **failing OPEN wherever the classifier is unsure.** It removes
redundant CALLS and the over-produced GARBAGE — **never a legitimate tag, verdict, or confidence.**

## ACCEPTANCE CRITERIA

- Each per-document group declares `applies_to` (or `all`), verified against its prompt + LP-378's map.
- The gate is generic (no group-id / doc-type branch), fails open (unknown / no-match / gate-off → run all),
  and keeps the prompt's abstention backstop.
- Equivalence-except-garbage on LF-6T3N: every legitimate tag identical; income_amounts' non-income
  `documented_monthly` gone. `GATE_AI_GROUPS=0` restores brute-force. Full suite green.

## PHASE 0 — THE ARGUMENT

**Dispatch site & the confidence gap.** Per-document groups dispatch in `produce_ai_group_tags`, where
`st.enumerate(snapshot)` yields `(content_id, DocumentEntry)` and `DocumentEntry.document_type` is in hand.
But `DocumentEntry` carries **no `classification_confidence`** (it lives on the DB `Document`, not the
snapshot — plumbing it is a v5 snapshot bump that breaks persisted v4, out of scope). **So the low-confidence
fail-open is unavailable at the gate — reported, and the gate fails open on doc-type only, naming the
confident-mistype residual.**

**D1 — declared applicability (the 13th declared-key-resolved-by-registry).** `applies_to: [doc_types]` or
`all` per group (below). **D2 — the gate:** keep a document iff `GATE_AI_GROUPS=0` OR non-document group OR
`applies_to=all` OR `document_type ∈ {None, "unknown"}` (fail-open) OR `document_type ∈ applies_to`. No
group-id branch. **D3 — equivalence** proven deterministically (the gate is a pure filter — for the docs a
group processes, the call is identical to brute-force; a real two-run byte-diff would only add model noise)
plus one real gated run showing income_amounts' garbage gone. **D4 — the saving** below.

## THE EQUIVALENCE-EXCEPT-GARBAGE PROOF (gated real run on LF-6T3N — reported, not predicted)

Re-ran the dormant probe with the gate ON (170.3s, real sonnet-4-5, persisted nothing). **`income_amounts`
produced real income values on ONLY `{w2: 11, pay_stub: 12}`** — vs LP-378's brute-force
`{w2: 12, pay_stub: 12, bank_statement: 6, investment_account: 4, mortgage_statement: 8, property_tax_bill: 2}`.

| group | brute-force (LP-378) doc-types with a real value | **gated** | verdict |
|---|---|---|---|
| `income_amounts` | w2, pay_stub, **bank, investment, mortgage, tax** | **w2, pay_stub only** | ✅ **garbage gone** (~20 fabricated income values on non-income docs removed) |
| `income_employer` | w2, pay_stub | w2, pay_stub | ✅ identical |
| `stmt_facts` | bank_statement | bank_statement | ✅ identical |
| `asset_facts` | investment_account | investment_account | ✅ identical |
| `income_docs` (all) | every doc-type | every doc-type | ✅ identical (un-gated) |

**The correctness fix is confirmed on real data:** the ~20 confident `documented_monthly` values on mortgage
statements, property-tax bills, bank statements, and investment accounts — the values that would fabricate an
IN-1 income discrepancy — are gone, because `income_amounts` never processed those documents. The legitimate
w2/pay_stub values remain (w2 shows 11 vs 12 — one W-2's `documented_monthly` abstained this run: model
non-determinism, not the gate; the gate processed all 8 income docs both times).

**Two honest notes on model non-determinism** (why a real two-run byte-diff is not the equivalence method —
the deterministic filter is): (1) `income_stability` (un-gated, `all`) returned 6 stray non-unknown values
this run vs 0 in LP-378 — model variance on an un-gated group; LP-378's finding that per-document stability is
unreliable stands. (2) the one-W-2 abstention above. Neither is a gate effect — the gate is a deterministic
filter, proven in the CI tests; the real run confirms the intended garbage removal on income_amounts.

## FAIL-OPEN & THE RESIDUAL

- **Layered fail-open** (all → run the group): `GATE_AI_GROUPS=0`, non-document group, `applies_to=all`, a
  document typed `unknown`/`None` (LP-377-A's untyped docs), or a matching type.
- **The backstop survives:** a fail-open document a group shouldn't read still gets the prompt's abstention
  (an "unknown" tag), never a wrong value — the gate never removes that safety (tested).
- **The confident-mistype residual (reported):** no per-document classification confidence in the snapshot, so
  a document confidently mis-typed (a title doc typed `w2`) is gated by its wrong type and its group is
  skipped. Mitigated by the unknown fail-open + wide lists; named in a test, not hidden. Closing it = plumb
  `classification_confidence` into the snapshot (a v5 bump — its own ticket).
- **Reversibility:** `GATE_AI_GROUPS=0` → brute-force, no redeploy (tested).
- **Single-file caveat:** LF-6T3N is the only seeded real file → the equivalence guarantee is single-file. An
  FHA, a refi, a condo, and a self-employed file would strengthen it; the reversibility flag is the net.

## TESTS

- The gate skips KNOWN-inapplicable docs, keeps matching + unknown (fail-open); income_amounts produces on the
  w2, NOT on a mortgage statement (the correctness fix); `GATE_AI_GROUPS=0` runs every group on every doc;
  the abstention backstop survives a fail-open doc; the confident-mistype residual is named; the gate source
  has no group-id / doc-type branch. Existing materialization/rule suites unchanged (893 passed) — no
  legitimate tag lost; the frozen fixture trace (produce_tags=False) is untouched.
