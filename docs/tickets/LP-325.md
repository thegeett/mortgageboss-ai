# LP-325 — The cross-source consistency primitive (the third rule shape)

## What it is

LP-324 gave the engine two rule shapes: **AS-1** (per-transaction, deterministic) and **OC-2**
(loan-level, judgment). LP-323-ID-A found a THIRD shape neither models: *"gather fact T for subject S
across ALL sources, compare them, judge agreement."* This ticket builds that primitive as a **declared
spec shape** (data, per LP-324) run by ONE generic evaluator — NOT a third hardcoded evaluator, and
with **zero per-rule Python**.

The design is the **exact bookend → AI-fuzzy residue** (mirrors LP-314 candidate-then-judge): the
deterministic path does the mechanical compare; the AI judges only the small ambiguous residue; exact
matches never call the AI.

## Acceptance criteria

- [x] A declared `consistency` evaluation block on `RuleSpec` (mutually exclusive with
  `deterministic`/`judgment`; kind↔CSV consistency preserved).
- [x] A generic `evaluate_consistency_rule(spec, snapshot, *, reasoner=None, confidence_floor=None)`
  running ANY consistency rule from its spec.
- [x] The `per_borrower` enumerator (distinct borrowers from `belongs_to`, first-seen order).
- [x] **ABSENT ≠ EMPTY / ABSENT ≠ DISAGREEING:** a source lacking the fact is excluded (not a
  mismatch); `<2` instances after filtering → `couldnt_check` (a single source is not agreement); an
  `"unknown"` gathered value → `couldnt_check` (distinct reason).
- [x] Reuse `evaluate_gate` (unknown / below-floor over the gathered instances), `reason_rule_judgment`
  + the injected reasoner seam (LP-313/314 AI machinery), and the LP-319 ratification armor. No new AI layer.
- [x] **EXACT COMPARE bookend** (after declared normalization): all equal → agree → NO AI. `exact` mode:
  differ → discrepancy → NO AI. `fuzzy` mode: differ → the AI judges the SMALL differing set only.
- [x] The fuzzy leg carries confidence + reasoning + `source_facts`; malformed/truncated/transport
  failure → `couldnt_check`/cannot-tell, NEVER a defaulted agree; a fuzzy verdict is ratification-pending.
- [x] Registry dispatch **by evaluation block** (a structural rule may be deterministic OR consistency).
- [x] **ID-2** (SSN, exact) and **ID-4** (address, fuzzy) re-expressed AS DATA — no per-rule Python.
- [x] Tests (keyless via the reasoner stub); ruff + mypy + full suite green (AS-1/OC-2 unchanged:
  **2001 passed, 1 xfailed**).

## Assumptions & decisions

- **The gather model (a note for the -B materialization ticket).** Cross-source facts are keyed by
  **document** `content_id` in `tags.by_subject`; documents link to borrowers via `belongs_to`. So
  "gather T for borrower B across sources" = scan the documents whose `belongs_to` includes B and read
  T from each document's tag map. The `gather_tag` AND its `gather_filter` tag are read from the **same
  source subject** (each document that states an address carries both `id.address_normalized` and that
  address's `id.current_address_type`). This is the coherent shape the `id.*` producers must target.
- **Exact bookend → AI-fuzzy residue (the cost + certainty property).** Most files match exactly — the
  deterministic bookend decides those with NO AI call. The AI is invoked ONLY on the differing residue
  of a `fuzzy` rule, and its context is ONLY the differing values + their sources — never the file.
- **The declared filter + the mailing-vs-residence trap.** ID-4 gathers only sources where
  `id.current_address_type == "residence"`, so a prior/mailing driver's-licence address is not a false
  discrepancy. An absent filter tag → the source is excluded (not of the required type), never counted
  as disagreeing.
- **ABSENT ≠ DISAGREEING and `<2` → couldnt_check.** A source lacking the fact is excluded; a single
  remaining source is not "agreement" (→ couldnt_check). This is the ID-4 mailing-only edge and the
  ID-2 null-hash edge — both couldnt_check, never a false match/discrepancy.
- **Normalization is DATA.** A declared chain of normalizer keys (`strip`/`casefold`/`drop_punct`/
  `collapse_ws`) — resolved by a registry, extensible (e.g. a date normalizer) with one entry, no
  code-per-rule.
- **The ratification invariant is per-path (LP-325 refinement of LP-319).** A fuzzy AI verdict may land
  `satisfied` (benign variance) OR `fired` (real discrepancy) while ratification-pending; the exact
  bookend's `satisfied` and exact-mode's `fired` are NOT pending. `result.py:58`'s docstring described
  OC-2's always-needs_review *policy*, not a universal law (nothing reads the flag) — updated, no
  behavior changed.
- **ID-2/ID-4 stay out of `ACTIVE_RULE_IDS`.** They are proven as data (specs + 18 tests + the
  registry-dispatch test passing an explicit `rule_ids`), but the live orchestrator does not run them
  until the `id.*` producers materialize — else every run would couldnt_check them.
- **Schema gap found?** None. The filter, normalization, exact/fuzzy split, judge value mapping, and
  outcomes are all declared as data; no `if rule_id == ...` anywhere.

## Which families this unblocks

Every **cross-source** rule shape: the ID family (ID-1 name, ID-2 SSN, ID-3 DOB, ID-4 address, ID-7
marital/title), income **stated-vs-documented** (IN-1/IN-3), credit **app-vs-report** liabilities
(CR-1), and the **property address** across sources (PC-3/PR-7). A new one is a spec + its tags.
