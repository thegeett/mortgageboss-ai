# LP-313 — Tag production: Stage A (per-entity atomic tags) for transactions

**Status:** Complete. **Branch:** `phase3_new_AI_arch_finding_stage2`.
**ADR:** [ADR-252](../../decisions.md). **Depends on:** LP-312 (the Tag model + tags
layer + content_ids), LP-310 (the cross-source clone target).

## What it is

The **first ticket where the AI produces fact-tags**. It reads the raw transactions from a
snapshot, produces the atomic **per-transaction** Stage-A tags, and writes them into the
tags layer (LP-312) — each tag citing its transaction's stable `content_id`. This
establishes the tag-production **pattern** every later pass follows: honest structuring
prompt → bounded batches → fail-closed parse → cache-by-content → write keyed by content_id.
**Stage A only, transactions only.**

## Acceptance criteria

- [x] A shared "structure, don't conclude" system prompt (facts, not conclusions;
  `"unknown"` always available; never guess).
- [x] Produces `txn.is_money_in` + `txn.apparent_category` (AI-judged) and `txn.amount` +
  `txn.date` (passthrough), each with `source_facts=(content_id,)`.
- [x] **Passthroughs are not re-typed by the AI** — `amount`/`date` carry the raw value
  (`produced_by="parsed"`, `confidence=None`).
- [x] **The direction bug is gone:** every transaction is tagged; a `transfer`/`ACH`/null
  label still gets an `is_money_in` — there is no `direction=="credit"` filter anywhere.
- [x] **Fail-closed honesty:** an omitted tag / truncated response / AI error / off-vocabulary
  value → `value="unknown"` **with a reason**, never a default; a genuine AI `"unknown"` is
  preserved as-is.
- [x] **Bounded batching** (15/call); a >20-transaction input splits into multiple calls.
- [x] **Cache-by-content-fingerprint:** an unchanged transaction reuses its tag; a changed one
  re-produces; identical transactions share one call.
- [x] `complete()` reused; a **timeout added** (`asyncio.wait_for`); `AIClientError` handled
  gracefully. Stale `verification/evaluators/` not imported; numbers not re-typed by AI.
- [x] All tests **keyless** (injected stub reasoner). ruff + mypy(`app/`) + full suite green
  (1838 passed).

## Assumptions & decisions

- **Which tags are Stage-A transaction tags.** Passthrough: `txn.amount`, `txn.date`
  (already-parsed). AI-judged: `txn.is_money_in` (`in|out|unknown`), `txn.apparent_category`
  (the vocabulary's 8 categories + `unknown`). All `tag_role=structural_fact`, `stage=A`,
  `tag_version=1`. Confirmed against `fact_tags.csv` / the vocabulary.
- **content_ids never reach the AI.** The batch numbers transactions 1..N; the model echoes the
  index; the orchestrator maps index→transaction and attaches `content_id` itself — robust to
  the model mangling opaque ids, and no id-shaped string in the prompt.
- **Cache keyed on the raw content fingerprint** (date+amount+direction+description), not the
  content_id — so identical-content transactions share one AI judgment and an unchanged
  transaction is a hit across runs. Only complete successes are cached (failures retry).
- **`produced_by="parsed"` for passthroughs** per the vocabulary/ticket, even though the raw
  amount originated from extraction — the tag is a deterministic passthrough (not AI-judged);
  the raw provenance/confidence still lives in the raw layer the tag cites via `source_facts`.
- **Batch = 15** (within the ticket's 15–20). **Model:** `anthropic_model_extraction` (Opus),
  temperature 0 for reproducibility (mirrors cross-source).
- **How the direction bug is now structurally impossible:** the pass iterates and tags **all**
  transactions; direction is an AI judgment (`is_money_in`) over meaning, not a filter — there
  is no code path that drops a transaction for its label.

## Deferred / out of scope (→ LP-314 and beyond)

- **Stage B / correlation tags** (`txn.has_identified_source`, `source_reference`,
  `is_recurring` — need cross-transaction/account matching).
- **Other atomic transaction tags** (`counterparty`, `is_nsf_or_overdraft`,
  `implies_obligation`) — easy follow-ons on this same pattern.
- Other entities (liabilities/income/…), rules, findings, `from_tag` population, the discovery
  lane. The stale `evaluators/` is not imported; numbers are never re-typed by the AI.
