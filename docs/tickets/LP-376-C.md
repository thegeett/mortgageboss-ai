# LP-376-C — Findings speak processor language

## WHAT THIS TICKET IS

The tabs render, the outcomes are right (LP-376/376-B), and a loan processor still cannot read them. Every
`couldnt_check` reason was an engine-internal sentence naming a tag or an operand — never the document that
is missing, never what to do. **The engine's honesty was never the bug — its vocabulary was.** This ticket
changes WORDS, not VERDICTS.

## ACCEPTANCE CRITERIA

- No user-facing reason contains engine vocabulary (a tag id, `operand`, `load-bearing tag`, `subject`, a
  content-id hash).
- Every `couldnt_check` names WHAT is missing in mortgage terms + a shape-appropriate next step.
- The 8 identical untyped-document rows collapse to a readable summary, WHICH ones still recoverable.
- No outcome/verdict/tab/count change; `ACTIVE_RULE_IDS` unchanged; the legacy list identical; suites green.

## PHASE 0 — THE ARGUMENT

**The root (confirmed).** The reasons are hardcoded in the evaluators, interpolating an engine id —
`consistency.py:447` (`'{gather_tag}'`), `gate.py:68` (`'{tag_id}'`), `applicability.py:43`
(`'{applic.tag}'`), `deterministic.py:278` (`'{operand}'`). The spec supplies only outcome templates
(`on_agree`/`on_disagree`) + `how_to_fix`; couldnt_check was never routed through a human string.

**D1 — where human text lives.** The evaluator knows the SHAPE of a failure (missing document / <2 sources /
low confidence); it does NOT know the DOMAIN (that the fix is "get the 1003"). Decision: **a declared
`tag_id → mortgage-noun-phrase` registry** (`rule_engine/reasons.py`, keyed by tag — the sanctioned
declared-registry pattern, NOT a per-rule-id branch) lets the evaluator name WHAT is missing generically; the
ACTION stays SHAPE-derived (honest: "classify it", "a consistency check needs two", "review it" — never an
invented domain action). Per-rule domain actions belong in a spec's `how_to_fix` (precedent exists); **that
authoring for ~130 rules is a scoped follow-up, not this ticket.** No per-rule-id branch anywhere.

**D2 — naming the document.** At the reason site, `applic.value` = the expected doc-TYPE (`title_commitment`)
— reachable, humanizes to "title commitment." The FILENAME is not reachable (subject_key is a content-id; no
doc index at the reason site) — I did NOT plumb it (that is an engine change / LP-375's subject-label finding
at the reason level). The doc-type is enough and always reachable.

**D3 — the untyped-document collapse: UI, not engine.** Each untyped doc is a distinct `(rule_id,
subject_key)` couldnt_check, and **LP-322's reconciler keys on exactly that** — an engine collapse would
change subject keys and break carry-forward/retire. **UI grouping keeps the model intact** and preserves
which N. Decision: collapse in the UI (group by `(rule_id, message)`, one summary row, expandable). Cost: a
frontend grouping; zero engine/model change.

**D4 — the action.** Shape-derived and honest, folded into the reason (not a new field). Where no action is
honestly knowable it is not invented — e.g. "only 1 document states the date of birth — a consistency check
needs at least two" (it does NOT guess "get the 1003", which document to add is domain knowledge).

**The first case is not wording** (confirmed): `absent_document_couldnt_check` already composes the right
sentence and is CORRECTLY suppressed by the 4 untyped docs (LP-330 — an untyped doc might BE the title
commitment). One root — 4 unclassified documents — three symptoms (ID-7/ID-9's noise, the suppressed good
sentence, ID-4's poisoned filter). **The classifier gap is its own ticket** (out of scope; reported below).

## WHAT WAS BUILT

- `rule_engine/reasons.py`: the declared `fact_label` registry (tag id → mortgage noun phrase, with a
  humanized-stem fallback so no dotted id or hash ever reaches a processor) + `document_label` / `enum_label`.
- The four reason sites + the LP-372 excluded-note + the ID-4 filter-gate reason, rewritten to use it.
- Frontend `groupBySameReason` + `CollapsedFindings`: within a Tab-1/2/3 outcome group, findings sharing a
  rule + reason render as ONE summary row (with a count, expandable to the members). Collapses the 8
  untyped-document rows to 2 (ID-7, ID-9), and AS-1's 15 identical satisfied rows to 1. Model untouched.

## THE UNTYPED-DOCUMENT DECISION + ITS COST

UI grouping (D3): the 8 rows become 2 readable summaries ("a document could not be classified — it may be the
title commitment/power of attorney …"), each expandable to its 4 members. The engine, LP-322's reconciler,
and the `(rule_id, subject_key)` keys are untouched — the collapse is display-only. Cost: a reader who wants
to know WHICH four expands the summary; the individual subject rows still carry only a content-id (the
subject-label gap, LP-375 — reported, not solved here, and out of this ticket's scope).

## TESTS

- `test_human_reasons.py`: **the ticket in a test** — scans each site's reason for a dotted id, a content-id
  hash, or the engine words, and asserts it is clean AND names the missing fact/document.
- The many gate/consistency/applicability/eval tests that asserted the OLD strings updated to the new human
  ones (both directions: absent vs present-but-unclear stay distinct; the genuinely-absent-document good
  sentence is unchanged in meaning).
- Frontend: N identical-reason findings render as one summary + a count, expandable to the members.
- **Equivalence asserted**: every verdict/outcome identical (this ticket changes words); full backend suite
  **2382 passed**; frontend **297 passed**; ruff + mypy + biome + tsc green.

## ASSUMPTIONS / DECISIONS + WHAT'S STILL OPEN

- **No verdict changed** — grep-audited; the failing tests were all string assertions, never verdicts.
- **Rules whose action is not knowable get no invented action** (D4) — the <2-sources reason names the shape,
  not a specific document to fetch.
- **Per-rule human action text (`how_to_fix` for couldnt_check) is NOT authored here** — the evaluator's
  shape-derived step suffices for the live set; authoring domain actions for ~130 rules is a scoped
  follow-up if a processor needs rule-specific guidance.
- **The classifier gap is its own ticket** — 4 documents on LF-6T3N could not be typed; this is the single
  root behind ID-7/ID-9's noise, the suppressed good sentence, AND ID-4's filter (LP-372). Fixing the
  classification collapses all three at the source.
- **The legible SUBJECT label** (LP-375) is still unreached — a content-id is not a document a processor
  recognises; the collapse mitigates the noise but not the identity. Reported.
