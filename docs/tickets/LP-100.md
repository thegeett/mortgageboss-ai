# LP-100 — Purpose-gating in the rules framework (gate purchase-specific rules off refinances)

- **Ticket:** LP-100 (second ticket of the refinance epic, LP-99/100/101)
- **Epic:** Phase 3 — Refinance support
- **Status:** Completed
- **Date:** 2026-07-01

## Summary

The rules applicability framework had **no PURPOSE dimension** — `ApplicabilityScope` is
`ALL_LOANS | PROGRAM | LENDER` only, and `RuleGate` keys on typed numeric facts, not `loan_purpose`.
So a rule couldn't be declaratively scoped purchase-only / refi-only. The visible bug: the
purchase-agreement doc rule (`conv.docs.purchase_agreement_present`) **fired on refinances**,
flagging a missing purchase agreement a refi legitimately doesn't have → a spurious YELLOW finding.

LP-100 adds a PURPOSE dimension to the framework (composing with the existing scopes + `RuleGate`,
reading `loan_purpose` + `refinance_type` from LP-99), gates the clearly-purchase-specific rules to
purchase-only, and adds the refi-specific need-set. **Under-gated, not over-gated.** See **ADR-225**.

## The gap (confirmed by the audit)

- No PURPOSE gate: `ApplicabilityScope` = `ALL_LOANS | PROGRAM | LENDER`; `RuleGate` reads numeric
  facts (is_manual, property type) via a `Condition`, not `loan_purpose`.
- `conv.docs.purchase_agreement_present` (`credit_property_docs.py`) — description says "(purchase
  transactions)" but nothing ENFORCED it → fired on refis (the spurious finding).
- `xsrc.terms.price_vs_contract` (cross-source) — purchase-specific, but only "safe by absence" on a
  refi (fires only when the contract fact is present, which a refi lacks). Worth gating by intent.
- `fha.doc.pre_appraisal_sales_contract` — reads `documents.sales_contract_present` "(purchase)"; a
  refi has no sales contract. Purchase-specific.
- DTI rules are program-based (Conventional vs FHA) — refinance doesn't change DTI limits. NOT gated.
- `loan_purpose` / `refinance_type` were used **nowhere** in verification before this ticket.

## The fix — a PURPOSE dimension (don't special-case one rule)

- **`PurposeScope`** (`purchase` / `refinance` / `cash_out` / `rate_term`) — a new field on
  `Applicability`, ORTHOGONAL to `scope`. It COMPOSES with the program/lender scope and `RuleGate`
  (a rule can be "Conventional AND purchase-only"). `None` = every purpose (default; the ~110
  existing rules are unchanged).
- **Enforced per-rule in the engine**, parallel to `RuleGate` — NOT at `registry.resolve`, so the
  LTV/DTI calculators that resolve through the registry are untouched. `engine.evaluate` and
  `cross_source.engine.evaluate_cross_source` take `loan_purpose` + `refinance_type` (from the
  `LoanFile`) and SKIP a purpose-mismatched rule (`evaluated=False`, never a finding) via the pure
  `purpose_applies`.
- **`purpose_applies` — the under-gated truth table:** skip a rule ONLY on a *known* mismatch. An
  unknown `loan_purpose` (or unknown `refinance_type` on a cash-out/rate-term gate) errs toward
  APPLYING the rule. Wrongly gating a rule OFF could HIDE a real finding (dangerous); an extra
  over-flag is safe.

  | scope | applies when | skipped when |
  | --- | --- | --- |
  | `PURCHASE` | purchase, or unknown | known refinance |
  | `REFINANCE` | refinance, or unknown | known purchase |
  | `CASH_OUT` | cash-out refi, or refi w/ unknown type | known purchase / known rate-term |
  | `RATE_TERM` | rate-term refi, or refi w/ unknown type | known purchase / known cash-out |

## Rules gated (clearly purchase-specific → PURCHASE)

- `conv.docs.purchase_agreement_present` (the visible bug — no longer fires on refis)
- `fha.doc.pre_appraisal_sales_contract` (a refi has no sales contract)
- `xsrc.terms.price_vs_contract` (safe by intent, not just by the absent contract fact)

## Deliberately NOT gated (under-gate caution — flagged for Priya)

- **`conv.ltv.purchase_max` / `fha.ltv.purchase_max`** — the "purchase **/ rate-term**" maximum a
  rate-term refi SHARES (LP-99). Gating them purchase-only would wrongly drop the LTV limit for
  rate/term refis. Left ALL/PROGRAM.
- **`fha.doc.case_number_and_amendatory_clause`** — keys on `documents.fha_case_number_present`,
  which ALL FHA loans (incl. refis) require; only its amendatory-clause sub-part is purchase-specific.
  Left ungated; note flags splitting the amendatory clause into its own purchase-only rule (Priya).
- **DTI** — program-based; never purpose-gated.

## The refi need-set

The needs floor (`needs_engine.py`) had `PURCHASE → purchase agreement`. LP-100 adds the refi analog:
a **REFINANCE** seeds the **existing mortgage statement** + **payoff statement** (the current lien
being refinanced). Grounded starter — validate-with-Priya; subordination for a 2nd lien is flagged,
not built. An unknown purpose seeds neither doc need-set.

## Grounded-starter / validate-with-Priya

The gating decisions (which rules are purpose-scoped) and the refi need-set are domain judgments —
each gated rule's `notes` and the need-set carry a grounded-starter / validate-with-Priya flag.

## Files

- `app/verification/rules/schema.py` — `PurposeScope`; `Applicability.purpose`; pure `purpose_applies`.
- `app/verification/engine.py` — `evaluate(...)` takes `loan_purpose` + `refinance_type`, skips a
  purpose-mismatched rule (parallel to the fact gate).
- `app/verification/cross_source/rules.py` — `CrossSourceRule.purpose`; gate `xsrc.terms.price_vs_contract`.
- `app/verification/cross_source/engine.py` — `_applies_to` + `evaluate_cross_source` check purpose.
- `app/verification/rules/conventional/_base.py`, `fha/_base.py` — `conv_rule`/`fha_rule` accept `purpose`.
- `app/verification/rules/conventional/credit_property_docs.py` — gate the purchase-agreement rule.
- `app/verification/rules/fha/property_docs.py` — gate the sales-contract rule; flag the case-number rule.
- `app/services/verification_engine.py`, `app/services/cross_source_deterministic.py` — pass the file's
  `loan_purpose` + `refinance_type` into the engines.
- `app/services/needs_engine.py` — the refi need-set (existing mortgage statement + payoff).
- `tests/verification/test_purpose_gating.py` (new) — the truth table + engine + cross-source gating.
- `tests/services/test_needs_engine.py` — the refi need-set; the "thin floor" test now uses unknown purpose.

- Does NOT purpose-gate DTI; does NOT over-gate (ambiguous rules stay ALL-purpose + flagged); does not
  change LP-99's `refinance_type` parse (consumes it).
- Tests use a **constructed** refi loan (`loan_purpose=REFINANCE`) — there is no refi MISMO fixture yet.
- **LP-101** adds the refi MISMO fixture + the end-to-end flow test (import → LTV → rules → findings),
  asserting the LP-99 fix (cash-out → stricter limit) and this LP-100 fix (no purchase-agreement finding
  on a refi) over a real import path.
