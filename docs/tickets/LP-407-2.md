## D1 — DT-5's redundancy: STOP (vacuous), do NOT wire

DT-5 = *"Insurance premium in DTI — premium used vs binder — numeric compare"* (`rule_kinds.csv`). Both operands
trace to **one extracted field**:

- **"premium used in the DTI"** → the DTI's insurance line reads `homeowners_insurance.annual_premium ÷ 12`
  (`services/dti.py` `_extracted_monthly(..., "annual_premium", annual=True)`).
- **"the binder"** → `housing.insurance_monthly` (the only insurance figure in the snapshot) reads the **same**
  `annual_premium ÷ 12` (LP-374).

There is **no independent stated insurance figure** in the snapshot: MISMO carries no insurance line, and the
`DtiOverride` (a processor-entered figure that *could* diverge from the binder) is **not exposed as a snapshot
tag**. So DT-5 would compare the binder **to itself** → always trivially equal (or `couldnt_check` on a
multi-binder ambiguity) → **it can never fire.**

- This is **not the ticket's hard-stop** (a duplicate of a *live* rule): `rule_kinds.csv` marks **IH-4 "Premium
  matches DTI" as "(dup DT-5)"**, but *neither IH-4 nor DT-5 is live*. It is worse than benign — the check is
  **vacuous**, so wiring `ins.premium_annual` would be dead wiring for a rule that cannot fire.
- **Scope boundary LP-407-3 must respect:** DT-5 (and its twin IH-4) is not writable as "premium-used-vs-binder"
  until an **independent** premium source exists — a stated loan-terms/1003 insurance figure, or the DTI's
  **override-applied** insurance line surfaced as a fact. Until then, DT-5 comes **off** the wire-and-write list.
  Do not write it against `housing.insurance_monthly` on the assumption the compare is real.

## D3 — the conversion producer's shape (the periodicity hazard)

- **Taxes** (`annual_tax_amount`) and **insurance** (`annual_premium`) are unambiguously **annual → ÷12**; no
  periodicity field. `housing.taxes_monthly` mirrors `housing.insurance_monthly` exactly.
- **HOA** carries a `dues_frequency`. **The DTI's `_extracted_hoa_monthly` DEFAULTS an unstated/unrecognized
  frequency to monthly** (`divisor.get(frequency, 1)`). That is a silent 12× miscalculation risk. **My
  `housing.hoa_monthly` has NO default — an unmapped/unstated frequency FAILS CLOSED to `unknown`** (a tag must
  not assume a periodicity). Stricter-than-or-equal-to the DTI (abstains where the DTI assumes) — the
  `housing.insurance_monthly` "agree-or-abstain, never looser" discipline. **Recorded as an ADR** (below).

## D4 — the subject-per-tag / rule-subject match (verified, anti-structural-death)

PC-2 / DT-2 / DT-4 all enumerate the **loan** subject (like OC-1 / AS-8 / PC-7), so every tag they read must key
under `loan`. Verified with the deterministic operand resolver (`_resolve_operand`): a loan-enumerated rule's
`tag`/`loan_tag` operands read the loan-subject map; a per-**document** tag is unreachable.

| tag | mode / subject | read by | reachable at loan? |
|-----|----------------|---------|--------------------|
| `property.purchase_price` | parsed / **loan** (MISMO) | PC-2 | ✅ |
| `contract.sales_price` | parsed / **document** (the PA) | (the promotion) | — document fact |
| `contract.loan_sales_price` | derived / **loan** (promotes contract.sales_price) | PC-2 | ✅ |

## D5 — the `not_applicable`-enablers (argued per tag)

- **`housing.taxes_monthly`** (taxes are *required* on owned real estate): `unknown → couldnt_check` is correct
  — a missing tax figure genuinely can't be checked. No `not_applicable` state.
- **`housing.hoa_monthly`** (HOA is *optional*): a no-HOA property *should* reach `not_applicable`. But this is a
  **number** tag — a number has no `not_applicable` enum, so it collapses "no HOA" and "unreadable HOA" into
  `unknown`. **The number tag alone cannot enable DT-2's not_applicable.** **Gap reported for LP-407-3:** DT-2's
  applicability must gate on HOA-statement **presence** (a presence signal, not this amount tag) to reach
  `not_applicable` on a no-HOA property; otherwise a no-HOA file `couldnt_checks`. I did **not** invent a presence
  tag (out of this ticket's "conversion producer" scope, and NO-new-mechanism).
- **`contract.loan_sales_price` / `property.purchase_price`**: a purchase without a contract/price is a real
  couldnt_check (there is no "not applicable" purchase); `unknown` is right. (A refinance has no purchase
  agreement — PC-2's not_applicable there would need a `loan.purpose` gate, the same open item PC-7 has.)

## Every assumption / decision

- **DT-5 stopped, not wired** — a vacuous self-compare today; the boundary is recorded for LP-407-3.
- **`contract.loan_sales_price` promotion** — the `contract.loan_closing_date` pattern; the idiomatic way to make

- **HOA fails closed on unstated/unrecognized frequency** — diverges from the DTI's assume-monthly default (ADR).
- **Multi-bill taxes abstain** — no `created_at` in the snapshot + no subject-property match (a later refinement)
  → any two tax bills → unknown, mirroring `housing.insurance_monthly`'s multi-binder abstain.
- **Fixture not modified** — the field-name/HOA gap is reported for a fixture ticket, not fixed here.

## DT-5's scope boundary for LP-407-3 (restated)

**Do not write DT-5 (or IH-4) as "premium used vs binder" against `housing.insurance_monthly`.** Both sides are
the binder's `annual_premium` today. DT-5 needs an independent premium source first (a stated loan-terms/1003
insurance figure, or the override-applied DTI insurance line as a fact) — a producer/extractor question, not a
tag-wiring one.

## ADR

- **ADR-328 (new)** — a monthly-conversion tag fails closed to `unknown` on an unstated/unrecognized periodicity,
  diverging from the DTI's assume-monthly default: a tag must not silently assume a periodicity (a 12× error);
  it abstains, stricter-or-equal to the DTI (the `housing.insurance_monthly` "agree-or-abstain, never looser").
