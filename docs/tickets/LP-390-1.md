# LP-390-1 — Fix IN-10/IN-11 per-borrower consumption

## What this ticket is

LP-385 moved the income_stability producer to the per-BORROWER subject (income trend is a cross-document
question). But **IN-10** (`is_declining`) and **IN-11** (`has_2yr_history`) still read those tags at the
per-DOCUMENT subject — so they read a subject where the tag no longer lives → **couldnt_check on every file,
silently**, every test green (the AS-1/ID-2/OC-2/ID-5 structural-dead class — a **sixth instance**). LP-385
flagged it as its own ticket; this is it. The fix is a pure spec re-scope.

## Acceptance criteria

- IN-10/IN-11 enumerate `per_borrower` and read the borrower-subject tag through the real path.
- Fail-closed (no evidenced trend → couldnt_check with a reason); per-borrower isolation (no cross-borrower
  feed).
- The fiction-asserting tests are rewritten to the true path.
- IN-10/IN-11 stay INERT (`ACTIVE_RULE_IDS` unchanged) — but now reach the rule (calibratable).
- The tags' subject is unchanged (LP-385 owns it); the 17 live rules identical; full suite green.

## Phase 0 — the argument

**D1 — the tags ARE at `borrower` (confirmed).** `tag_production.yaml`: `income.is_declining` and
`income.has_2yr_history` are both `{mode: ai, subject: borrower, data: income_stability}` (LP-385). The premise
holds.

**D2 — re-scope, don't re-produce. SIMPLER than ID-5.** ID-5 (LP-389-A) needed a promotion recipe because its
source was `subject: document`. Here the tag is ALREADY at the borrower subject — so IN-10/IN-11 read it
DIRECTLY through the per_borrower enumerator's merged map (exactly how IN-1 reads its borrower-subject
shortfall). The fix is a pure SPEC change: `subject_enumeration: per_borrower`, drop the
`document.document_type == w2` applicability, point the operands at the borrower subject. No recipe, no
producer change, no per-rule branch.

**D3 — no new threshold.** IN-10 ("any decline flags") and IN-11 ("2-year history") read enum tags
(yes/no/unknown); both already carry `priya_validated: false`, `threshold_needs_signoff: true`. No numeric
value to add or flag.

**D4 — the fiction tests.** `test_in10_declining_...`, `test_pin2_in11_...` (test_income_family_eval.py) and
`test_in10_declining_scoped_to_w2` (test_income_family.py) hand-placed the tag at the W-2 DOCUMENT subject and
asserted FIRED — green only because they wired the tag where the rule wrongly read it. Rewritten to the true
per-borrower path.

**A NEW gap found (reported, deferred by scope): IN-12 is the same class.** IN-12 reads the SAME
`income.has_2yr_history` (borrower subject) `per_document` at the tax-return subject — the identical latent
mismatch. Out of this ticket's scope (LP-390-2 audits the other income rules); left as-is with its fiction test
in place. **IN-13 already reads its borrower-subject tag per_borrower (correct).**

## Phase 1 — the re-scope

For IN-10 and IN-11: `subject_enumeration: per_document → per_borrower`; `subject_key_fields:
[content_id] → [borrower]`; removed the `deterministic.applicability` (`document.document_type == w2`); the
`required_inputs` snapshot_path now names the borrower subject; the criteria/scope prose is per-borrower. The
operands / outcomes are unchanged (they now read the borrower-subject tag). No code, no recipe.

## Phase 2 — IN-10/IN-11's real per-borrower evaluation (reported, not predicted)

On the wired LF-6T3N fixture with income_stability materialized (a borrower with `is_declining=yes` /
`has_2yr_history=no`, another with `no` / `yes`):

| Rule | Borrower A (declining / no history) | Borrower B (stable / has history) |
|------|-------------------------------------|-----------------------------------|
| IN-10 | **FIRED** ("income is declining year-over-year") | **SATISFIED** |
| IN-11 | **FIRED** ("lacks a 2-year history") | **SATISFIED** |

**The distinction that matters:** BEFORE = couldnt_check because the tag isn't at the subject (the bug); AFTER
= a real per-borrower read (satisfied / fired), or couldnt_check WITH A REASON when the trend genuinely can't
be established (unknown / low-confidence AI). The rule can now DISTINGUISH. Per-borrower isolation holds
(borrower A's trend never feeds borrower B's).

**Still INERT, now calibratable.** IN-10/IN-11 are NOT in `ACTIVE_RULE_IDS` and stay held — their tags are AI
and UNSCORED, so their bars are `not-calibratable-yet` (the income wave scores them, then may activate). The
input now REACHES the rule (the subject mismatch is gone), so they are no longer structurally dead — the hold
is on calibration, not the mismatch. (`input_resolves` is a no-AI concept; it does not apply to these AI
rules — the gate for them is the calibration half.)
