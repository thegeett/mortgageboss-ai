# LP-518 — AS-12 materiality floor, widened exemption, and per-rule finding grouping

## The problem

LP-516 stopped AS-12 sending payroll deposits to a human, but left the rule asking its borrowed-funds
question of **every remaining money-in transaction at any amount**. There was no notion of size in the
rule at all, so a $0.03 savings-interest posting produced the same review item as a $20,000 wire.

On LF-WCHG this was masked: all ten money-in deposits happened to fall between $1,000 and $3,356, so the
absence of a threshold never showed. It would show on the first file carrying ordinary small credits.

A second, quieter problem: AS-12's ten findings rendered as ten separate rows. The existing collapse
(LP-376-C) keys on `rule_id + message`, and a judgment rule's message is written by the **model**, so it
differs per subject — ten groups of one, nothing collapsed.

## What the guideline actually says

Researched this ticket, with the distinction between the two numbers as the main finding.

**Purchase.** Fannie B3-4.2-02 (page dated 12/14/2022):

> A large deposit is defined as a single deposit that exceeds 50% of the total monthly qualifying income
> for the loan.

**Refinance.** The same page, transaction-type table:

> Refinance transactions: Documentation or explanation for large deposits is not required; however, the
> lender remains responsible for ensuring that any borrowed funds, including any related liability, are
> considered.

So on a refinance the 50% test is *precisely the part that is waived*, and what survives is a
borrowed-funds duty carrying **no threshold of its own**. Inheriting 50% there would import a test the
guide withdrew. Any floor on a refinance is therefore a triage choice, and a lower one is the point —
it is the only test still running on that loan purpose.

Two further findings recorded here so they are not re-derived:

- **Aggregation across deposits has no guideline basis.** Every agency text found is framed per-deposit;
  summing is an overlay implementing the general borrowed-funds duty, not the large-deposit definition.
  Not built here — see "Deliberately not in scope".
- **Agencies size this on different denominators, not different numbers.** Fannie on monthly qualifying
  income, Freddie on eligible assets, FHA on Adjusted Value. Only Fannie's form is implementable,
  because no fact on any file records the destination investor. Recorded in the spec so nobody later
  assumes 50% is universal.

## What changed

### 1. A `materiality` block on judgment specs (`rules/specs.py`)

New `Materiality` model: `observed` and `basis` operands plus `fraction_by_loan_purpose`, a map from
`loan.purpose` value to a `reference_values.values` key. Reuses the existing `Operand` DSL rather than
inventing grammar — AS-1 already computes `0.5 x dti.qualifying_income_monthly` the same way.

Validated at load: fraction keys must name declared reference values (a typo would degrade every
subject silently); operands must be decimal `tag`/`loan_tag` (the judgment evaluator resolves them
without a snapshot, so a `calc` operand would read None on every subject).

### 2. The gate (`rule_engine/judgment.py`)

Runs after `applicability` and **before** the fail-closed gate and the AI call — an out-of-scope deposit
costs no model call, which is the whole saving.

**It has two outcomes, and `couldnt_check` is deliberately not one of them:**

| condition | outcome |
|---|---|
| every input resolved, `observed <= floor` (strict — the guide says "exceeds") | `not_applicable` |
| every input resolved, `observed > floor` | in scope, finding carries the derivation |
| any input unresolved | **in scope**, finding says the floor could not be sized |

The last row is the load-bearing decision and it was a mid-implementation correction. The first draft
returned `couldnt_check` for a missing purpose or income. That is wrong here:
`dti.qualifying_income_monthly` derives from **MISMO stated income** and abstains to `unknown` whenever
no import states an income line — a large share of real files. Failing those to `couldnt_check` would
have stopped asking the model altogether and handed the processor *less* than they had before the gate
existed. A floor is a triage filter this rule added, not an input its question depends on.

### 3. The derivation is in the finding text

A bare threshold is unauditable. Findings now read:

> the AI judged 'no' — an AI verdict a human must ratify (it never auto-ships); **$8,000 is above the
> $5,000 (50% of $10,000 qualifying income) materiality floor**

and when it could not be sized:

> ...; **no materiality floor could be sized for this loan, so it was reviewed at any amount (qualifying
> income is not established)**

### 4. `exempt_when` accepts a list of alternatives

`interest` joins `payroll`. A list is **any-holds**, deliberately the opposite of `applicability` (where
a list is a conjunction) — scope narrows with each predicate, an exemption list widens, and the guide
itself reads as alternatives ("payroll, the Social Security Administration, or IRS or state income tax
refund, or a transfer of funds between verified accounts").

The floor already removes the $0.03 interest case, so this earns its keep in the one place the floor
does not reach: a low-income refinance, where 10% of a small income can sit below a month's interest on
a large balance. Clearing that by citation beats clearing it by size.

**Not** extended to SSA or tax refund: `txn.apparent_category` has no value for either, so declaring
them would be a predicate that never matches — the LP-516 failure mode.

`_guideline_exempts` now returns the *matching* condition rather than a bool, so the message names the
exemption that actually cleared the deposit rather than the rule's first one.

### 5. Findings group per rule (`frontend/`)

`groupBySameReason` → `groupByRule`, keyed on `rule_id` alone. Callers already group within one outcome
bucket, so a group never mixes `open` with `satisfied`.

The collapsed header could no longer show `first.message` — with differing messages that attributes one
deposit's finding to all of them. `collapsedSummary` shows the shared message when members agree
(LP-376-C's behaviour, preserved) and names the subjects when they differ:
`3 findings — $3,300 on 3/2, $1,000 on 3/14, $2,400 on 3/28`.

## Decisions

**50% purchase / 10% refinance, both decided.** The 50% is quotable from B3-4.2-02. The 10% is an
overlay chosen by the product owner, not derived from data — recorded as such in the spec, with the
arithmetic shown in the finding so a processor can judge the number themselves. Per the standing
direction, the decision *is* the sign-off: `threshold_needs_signoff: false`.

An earlier draft set `threshold_needs_signoff: true` and widened `kinds.py`'s calculative-only invariant
to allow it on judgmental rules. Both reverted once the direction was given. `priya_validated` stays
`false` to match every other rule in the repo — flipping it is a repo-wide policy change (a test asserts
0/136), out of scope here.

**Below the floor is invisible, not "satisfied".** `not_applicable` is never persisted. The alternative
— filing screened-and-cleared small deposits under Satisfied — puts the processor back in front of the
noise the floor exists to remove.

**Strict `>`.** Matches the guide's "exceeds" and AS-1's own hard-fire branch on the same guideline, so
the two rules cannot disagree at the boundary.

## What this does to the numbers

Not predicted. LP-516 shipped on a prediction that turned out to be wrong (it did nothing at all on a
real run), so this ticket states the mechanism and measures the effect after deploy.

Mechanically, on LF-WCHG (a refinance): its non-payroll transfers run $1,000–$3,356. Whether they clear
a 10%-of-income floor depends on the file's qualifying income, which derives from MISMO stated income
and may be `unknown` — in which case the rule behaves exactly as it does today and says so. Measure,
don't assume.

## Deliberately not in scope

- **The loan-level aggregate** (multiple sub-threshold deposits from one counterparty summing above the
  floor). A per-deposit rule structurally cannot see this: AS-12 enumerates `per_deposit` and the
  judgment context carries one transaction, the same wall LP-498 hit on FR-5. Closing it needs a
  loan-subject derived tag doing the grouping deterministically plus a rule reading it — and it should
  cite the general borrowed-funds duty, not the large-deposit definition, since aggregation has no
  guideline basis. Worth doing; a floor without it trades visible noise for an invisible gap.
  Note for whoever builds it: avoid the word "structuring" in finding text — it is a BSA/AML term
  (31 U.S.C. 5324) with criminal connotation and no mortgage-side definition.
- **SSA / tax-refund exemptions** — need vocabulary values and tagger-prompt changes first.
- **An `op: in` on `TagCondition`** — four evaluators spell the comparison `x if op == "eq" else <ne>`,
  so a third operator added without giving them a shared comparator would be silently evaluated as `ne`.
  A comment now says so at the field. The list form of `exempt_when` avoided needing it.

## Verification

- `tests/verification/rule_engine/test_as12_materiality_floor_lp518.py` — 12 tests. The decisive one is
  `test_the_same_deposit_is_out_on_a_purchase_and_in_on_a_refinance`: $2,000 sits between the two
  floors, so an identical deposit with identical income resolves opposite ways.
  `test_an_unknown_income_reviews_at_any_amount_rather_than_reporting_a_gap` guards the design decision
  above. `test_the_purpose_map_covers_every_loan_purpose_the_vocabulary_allows` fails if the vocabulary
  gains a third purpose, forcing a decision about its fraction rather than silently disabling the floor.
- `test_as12_guideline_exemption_lp516.py` — updated for the list form; all 9 still pass.
- `rule-findings-tabs.test.tsx` — 3 new cases covering differing messages, subject summarisation, and
  the preserved identical-message behaviour.
