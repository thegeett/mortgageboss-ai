# LP-344 — Converge the two txn Stage-A prompts (one shipped, one measured)

## WHAT THIS IS

A measurement-validity bug, not a prompt bug. LP-343's audit found TWO prompts producing the same `txn.*`
tags — and **your only real measurement scored the wrong one.** LIVE AS-1 runs the standalone
`STAGE_A_TRANSACTION_SYSTEM_PROMPT` (`app/ai/tag_production.py`); LP-337's calibration (98%, n=50 on
`txn.is_money_in`) measured the generic `txn_stage_a` group's YAML text. They had already DRIFTED. The
audited prompt, the measured prompt, and the SHIPPED prompt were not guaranteed to be the same text — and
were not. This ticket makes them one, and makes drift impossible to merge.

## ACCEPTANCE CRITERIA (met)

- One prompt TEXT for `txn.*` Stage-A; the measured prompt and the shipped prompt **cannot** differ (a guard
  fails if they do).
- LIVE AS-1 identical — the frozen LF-6T3N trace unchanged, AS-1's suite unchanged, `ACTIVE_RULE_IDS`
  unchanged, batching preserved.
- The drift CLASS closed (a guard against a second `txn.*` producer diverging), not just the instance.
- Honest verdict on the 98%. Fix nothing else; re-measure nothing here.

## THE TWO PATHS, TRACED (call sites — the code, not the audit summary)

| path | producer | prompt text |
|---|---|---|
| **LIVE run** (`verification_run.py:406`) | a dedicated `stage_a` step → `produce_stage_a_transaction_tags` (standalone) | `STAGE_A_TRANSACTION_SYSTEM_PROMPT` |
| **LP-337 calibration** (`worksheet.calibrate_lf6t3n`) | `produce_ai_group_tags(txn_stage_a)` (generic) | the YAML group's `system_prompt` |
| **frozen eval trace** (`harness.py:170`) | `produce_stage_a_transaction_tags` (standalone) | `STAGE_A_TRANSACTION_SYSTEM_PROMPT` |

**Confirmed:** `materialize_tags` (the generic path) is called with `only_subjects={document, loan,
borrower}` — deliberately EXCLUDING `transaction`, so the generic path **never produces txn tags live**.
The drift claim is CORRECT: calibration used the generic YAML text; AS-1 ships the standalone text.

## THE TEXT DIFF

The standalone (shipped) is the richer text; the YAML (measured) was thin:
- **`is_money_in`:** standalone — *"the DIRECTION of funds, resolved from MEANING, tolerating ANY label the
  bank used (credit / debit / … / a raw sign / or nothing). … Do NOT assume a positive amount means 'in'."*
  YAML — *"direction of funds: 'in' | 'out' | 'unknown'."*
- **`apparent_category`:** standalone DEFINES each value (*"transfer_own (a transfer between the borrower's
  own accounts)"*, *"vendor (an ordinary purchase / merchant)"*); YAML listed them UNDEFINED (LP-343 F5).
- The standalone also states the §3D principle and a NORTH STAR on honesty/`unknown`; the YAML did not.

## D1 — THE DIRECTION (why (c), with the code as evidence)

- **(a) migrate the live path onto the generic group** (LP-326's original intent) — **REJECTED by the
  code.** The live txn flow is two-stage (Stage-A → Stage-B sourcing); Stage-B is not a generic group (it is
  the separate `tag_correlation` producer), which is exactly WHY LP-326 deferred the migration.
  `materialize_tags` excludes `transaction` on purpose. Migrating would re-architect the live AS-1 path for
  no measurement benefit — against the equivalence mandate.
- **(b) delete the YAML group** — REJECTED: `txn.is_money_in` / `apparent_category` are DECLARED `mode: ai,
  data: txn_stage_a`; the group must exist for the declaration to validate.
- **(c) one text, single-sourced by a guard; live untouched — CHOSEN.** The standalone constant is the
  canonical text (it lives in `app/ai`, the clean lower layer — `app/ai` does not import `app/verification`,
  and must not). The YAML group's `system_prompt` is set byte-identical to it, and a guard fails if they
  diverge.

**Rewiring `calibrate_lf6t3n` to literally call the standalone producer was considered and REJECTED:** it
would break the keyless stub harness and cross the `app/ai ⊥ app/verification` layering, for a guarantee the
two standing guards already give (see below). **Batching:** the live standalone path is untouched (its
15-per-call batching intact) — no call-count regression; the generic producer also batches at 15.

## HOW THE DRIFT CLASS IS CLOSED — two standing guards

1. **TEXT guard (new, `test_txn_stage_a_prompt_convergence`):** `STAGE_A_TRANSACTION_SYSTEM_PROMPT` ==
   the `txn_stage_a` group's `system_prompt` (byte-identical, stripped only for the YAML block scalar's
   trailing newline). Edit one without the other → red.
2. **PRODUCER guard (pre-existing, `test_txn_roundtrip_through_the_generic_producer_is_equivalent`):** given
   identical judgments, the generic and standalone producers assemble IDENTICAL tags.

Text-identical **+** producer-equivalent ⇒ the calibration (generic path) measures **exactly** what LIVE
AS-1 (standalone path) ships. Neither can drift without a failing test. That is the acceptance criterion —
achieved by guards, which is a stronger CONTINUOUS guarantee than a one-time rewiring.

## D2 — THE 98% IS VOID AND MUST BE RE-EARNED (the honesty point)

LP-337's 98% measured the **thin YAML `is_money_in` instruction** via the generic producer. AS-1 ships the
**richer standalone text** (label-tolerant, anti-bias on sign). A different prompt → the number does not
transfer. **The project currently has NO valid accuracy measurement of the shipped `txn.*` prompt.** It is
NOT quietly inherited. It gets re-earned in **LP-345** (re-run against the converged prompt, with Priya's
judgment rows, so the whole picture — incl. the unmeasured `apparent_category` — is measured once).

## THE DUPLICATE-PRODUCER SURVEY (reported, not fixed)

Does any OTHER tag have two producers (a hardcoded path + a declared group)? **No — txn Stage-A is the only
one**, and this ticket converges it. The Stage-B sourcing tags (`txn.has_identified_source`,
`source_reference`, `counterparty`) are produced by `tag_correlation` ONLY and are **not declared as a
generic group** — so there is no second text to drift against (a single producer; a different gap, LP-343
F1 — its own ticket). All `id.*` / `income.*` / `stmt.*` / `asset.*` groups have no hardcoded twin. Asserted
in `test_txn_stage_a_is_the_only_dual_producer_and_stage_b_is_single`.

## WHAT WAS BUILT

- `tag_production.yaml`: `txn_stage_a.system_prompt` converged to the standalone text (byte-identical), with
  a comment pointing at the guard.
- `tests/…/test_stage_a_convergence.py`: the TEXT drift guard; the calibration-measures-shipped-text
  assertion; the converged-text-keeps-the-exemplary-properties check; the dual-producer survey assertion;
  the `ACTIVE_RULE_IDS` equivalence.
- ADR-283.
- **No `app/` engine/rule/spec logic changed. No prompt text improved.** The live path, the standalone
  producer, and `calibrate_lf6t3n` are untouched.

## NO RE-MEASURE HERE

Per LP-335's discipline (one change, measure once), the live calibration was NOT re-run. The re-run is
LP-345. **State plainly:** a `txn.*` number produced before LP-345 is about the wrong prompt; the first
valid one comes from LP-345 against this converged text.

## NEW GAP (reported)

The single-source is enforced by a GUARD (two physical copies kept identical), not a single physical string,
because `app/ai` must not import `app/verification` (layering) and the YAML declaration requires a
`system_prompt`. If a future refactor gives `app/ai` a layering-clean way to own the one string the YAML
references, the guard becomes redundant — until then it is the mechanism. Reported, not patched.
