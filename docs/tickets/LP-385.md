# LP-385 — The per-borrower income context (fix income_stability's producer)

## Problem

LP-378's dormant-tag-layer probe measured `income_stability` producing **0 / 120** — it
materialised **nothing**. The other five dormant income/asset groups produced usable tags;
`income_stability` alone was structurally silent.

The root cause is not a bug in the producer — it is a **subject mismatch**. `income_stability`'s
four tags each ask a question **about a borrower's income across time**:

- `has_2yr_history` — is this income evidenced across ≥2 consecutive years?
- `is_declining` — is there a year-over-year decrease?
- `same_line_of_work` — after a job change, is the new role the same line of work?
- `continuance_3yr` — is the income likely to continue 3+ years?

Every one of these is a **cross-document** question. But the group was declared
`subject: document` — so the AI producer was called **once per document, seeing one document at a
time**. A single W-2 cannot evidence a *two-year trend*; a single pay stub cannot show a *decline*.
The per-document framing made the questions **structurally unanswerable**, and the honest producer
returned nothing. 0/120 was the producer being correct about an impossible question.

## Phase 0 — the design argument (reported before changing anything)

The gate of record is the tag layer, not the ticket text. Four things were confirmed against the
code before the change:

- **D1 — the subject is the fix, not the prompt.** The `borrower` subject (LP-332) already exists,
  already enumerates one subject per MISMO borrower keyed by the LP-332 `borrower.{n}.borrower_id`
  link, and already carries the whole `Snapshot`. The primitive to gather a borrower's documents was
  one context-builder away — no new subject type, no new plumbing.

- **D2 — the terms are undefined.** The four tags had no written definitions anywhere. A producer
  cannot be honest about a term it cannot define. The definitions written into the new prompt (below)
  are **defensible defaults flagged for Priya (the domain expert) — they are NOT validated.** This
  ticket proves the producer *materialises*; LP-379 measures whether the judgments are *correct*.

- **D3 — attribution must be by evidence, never a guess.** A document is gathered for a borrower only
  via `belongs_to` — the LP-202 evidence-based document→borrower link (SSN/name resolved at upload).
  A document with **no** `belongs_to` is **not** gathered for anyone. The context is honestly
  incomplete rather than fabricated from a mis-attributed document (LP-332/LP-336: "never a guessed
  attribution").

- **D4 — who consumes these tags.** Five dormant rules read them:
  - **IN-7 / IN-13 / IN-14** read them **per_borrower** — this producer satisfies them directly.
  - **IN-10 / IN-11** read `is_declining` / `has_2yr_history` **per_document**. Moving the tags to the
    borrower subject means these two rules now read a subject that no longer carries the tag. This is
    a **reported gap**: IN-10/IN-11 need a per_borrower spec change to consume the borrower-keyed tag.
    Out of scope here (all five rules are dormant); tracked for the rule owner.

## The change

Three coordinated edits (the declarations validator requires a group's `subject` to match its tags'
`subject`, so they move together):

1. **`subjects.py` — `_borrower_context` extended.** It now returns
   `{"borrower_mismo": {...}, "documents": [...]}`: this borrower's MISMO facts **plus** every
   document attributed to them by `belongs_to`. This is the generic **per-borrower-over-documents**
   primitive — any future borrower group asking a cross-document question inherits it. Fields carry
   `PiiField` **masked displays only** (via `_field_value`) — no raw PII in the prompt. Unattributed
   documents are skipped (D3). The return **shape** changed from a flat MISMO dict to the
   `{borrower_mismo, documents}` pair; `income_stability` is the only group that uses
   `build_context` for the borrower subject, and the DERIVED borrower producers use `read_field`
   (unaffected), so nothing else had to change.

2. **`tag_production.yaml` — the four tags move to `subject: borrower`**, and the `income_stability`
   group becomes `subject: borrower`, `context_builder: borrower`. `applies_to` was **dropped** — it
   is a LP-377-D per-*document* gate concept and is moot (and rejected by the validator) on a borrower
   group. This reconciles cleanly with LP-377-D rather than contradicting it.

3. **The prompt was rewritten** with a §3D "structure the facts, don't decide qualification" framing,
   the four **defined** terms (each with an explicit `yes`/`no`/`unknown` rubric), and `unknown` made
   first-class ("If NO income document is attributed to this borrower, every tag is `unknown`"; "A
   single year of documents is `no`, not a guess"). The full prompt is in
   `tag_production.yaml` (the `income_stability` block).

## Phase 3 — the probe (reported, not predicted)

Re-ran the LP-378-style probe **off-path, persisting nothing**, on the real DB loan file **LF-6T3N**,
now materialising `income_stability` under the **borrower** subject
(`only_subjects={"borrower"}`, `only_groups={"income_stability"}`, real model
`claude-sonnet-4-5`). Result:

```
LF-6T3N: 2 enumerable borrowers
  borrower 59e173ce: 13 attributed docs, 4 income docs -> [pay_stub 2026-06-05, pay_stub 2026-05-22, w2 2025, w2 2024]
  borrower 16cf50cc: 13 attributed docs, 4 income docs -> [pay_stub 2026-05-22, pay_stub 2026-06-05, w2 2024, w2 2025]

  borrower 59e173ce:  has_2yr_history=yes  is_declining=no  same_line_of_work=yes  continuance_3yr=unknown
  borrower 16cf50cc:  has_2yr_history=yes  is_declining=no  same_line_of_work=yes  continuance_3yr=unknown

income_stability: 6 real / 8 observations   (LP-378 per-document was 0/120)
```

`income_stability` **now produces**. Each borrower's call carried **only that borrower's** four income
documents (59e173ce → Bank of America / an employer change; 16cf50cc → Novant Medical Group) — no
cross-feed. The two `unknown` values on `continuance_3yr` are **correct**: standard W-2 employment
states no continuation horizon, and the prompt is meant to abstain there.

**This is production, not correctness.** The probe proves the tags materialise with document-grounded
reasoning; whether `has_2yr_history=yes` etc. are the *right* calls against a human golden is LP-379's
job, unmeasured here.

## Tests

`tests/verification/tag_materialization/test_per_borrower_income_context.py` (4, all no-network):

- `test_context_gathers_the_borrowers_attributed_documents` — a borrower's context holds **both** of
  their W-2s (the cross-document view) and **none** of the other borrower's.
- `test_unattributed_document_is_not_gathered_for_any_borrower` — a `belongs_to = None` document is
  gathered for nobody (D3, fail-closed).
- `test_borrower_with_no_income_docs_has_empty_document_context` — no attributable docs → empty
  document context (honest incompleteness), MISMO facts retained.
- `test_income_stability_materializes_per_borrower_no_cross_feed` — the tag keys under the
  **borrower_id** (not a document content_id), and each borrower's AI call saw only its own
  employer — the LP-332 masking class, pinned.

Full backend suite green (`tests/verification/` + `tests/services/test_verification_run.py`). No rule
activation changed (all five consuming rules remain dormant).

## Assumptions & decisions

- **Term definitions are defensible defaults flagged for Priya, not validated** (D2). Written to make
  the producer honest and testable; LP-379 measures accuracy.
- **IN-10/IN-11 per-document consumption is a reported gap**, not fixed here (D4) — they need a
  per_borrower spec change to read the now-borrower-keyed tags. All five rules are dormant, so no live
  behaviour changed.
- The `_borrower_context` return-shape change is safe because `income_stability` is the sole
  `build_context` consumer on the borrower subject; DERIVED borrower producers use `read_field`.

See ADR-301.
