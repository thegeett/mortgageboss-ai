# LP-331 — Borrower-keyed facts for per-borrower judgment (GAP-D)

## What it is

LP-327's GAP-D: the `per_borrower` enumerator returned EMPTY tag maps (it exists for LP-325 consistency,
which uses it as a *grouping key* and gathers document-keyed facts itself). A per-borrower **judgment**
reads the subject's tag map → empty → always `couldnt_check`. This blocks ID-8 (citizenship eligibility)
and every per-borrower judgment. This was a **design ticket**: the choice propagates to ~a large slice of
the 36 judgment rules, so it was argued on code evidence before building.

## The design argument (both options, the evidence, the choice)

### Where ID-8's tags actually live (the deciding evidence)
- **`id.citizenship`** — `app/models/borrower.py::Borrower.citizenship` → materialized into MISMO as
  `borrower.{n}.citizenship` (`app/verification/snapshot/mismo_section.py`). A **borrower-level 1003/MISMO
  fact keyed by borrower INDEX**, NOT on any scanned document. LP-326's `{mode: parsed, subject: document,
  data: citizenship}` declaration is **aspirational and wrong** — no document has a `citizenship` field;
  it never materialized.
- **`program.type`** — entity=loan in `fact_tags.csv`, and **not declared in `tag_production.yaml`** → not
  materialized. A **loan-level** fact.
- **No consistency rule gathers `id.citizenship`** (grep of `specs/` → nothing) — ID-8 is its only consumer.
- **`consistency.py` discards the enumerated tag map** (`for subject_id, _subject_tags in
  enumerate_subjects(...)` — the `_subject_tags` is unused; it gathers via its own doc index).

### The two options, weighed on that evidence
- **Option 2 — the judgment declares a gather over the borrower's documents. REJECTED for ID-8.** Its
  facts are not on documents; gathering `belongs_to` documents finds neither citizenship (MISMO) nor
  program (loan). Exactly the "some borrower facts are genuinely borrower-level from the 1003/MISMO" case
  the gap-owner flagged.
- **Option 1 — borrower-keyed facts. ADOPTED, its AGAINST rebutted.** The divergence objection (a fact in
  two keyings that can disagree, resolving which is a hidden consistency mechanism in the producer) does
  NOT apply: `id.citizenship` has ONE source per borrower and NO document-keyed consumer, so there is no
  duplicate keying to diverge.
- **Third option — make ID-8 a loan-level judgment (like OC-2). Rejected:** collapses per-borrower
  eligibility into one loan verdict, wrong for multi-borrower files.

### The winning shape — a DECLARED-keying assembly (the eighth application)
The `per_borrower` enumerator now **assembles** each borrower's subject map: the borrower's OWN facts
(`by_subject[borrower_id]`) + the loan-level SHARED facts (`by_subject["loan"]`) merged in (borrower-own
overrides), each fact from its **one declared keying**. This reconciles `per_borrower`'s two meanings with
one enumerator — grouping key for consistency (which ignores the map), populated subject map for judgment.

## Acceptance criteria

- [x] A per-borrower judgment reasons over EACH borrower's own facts (not an empty map): 2 borrowers → 2
  RuleEvaluations, each with its own subject_key + rule_judgment tag, each ratification-pending.
- [x] Borrower isolation (A's facts never in B's prompt); loan-level facts shared into each context.
- [x] Per-subject fail-closed (A's citizenship missing → A couldnt_check naming what's missing; B still
  evaluates); gate-before-AI (a gated borrower makes no AI call, emits no tag); armor (every verdict
  ratification-pending).
- [x] **EQUIVALENCE:** OC-2, ID-1..ID-7, ID-9, AS-1 identical; suites + the LF-6T3N trace unchanged;
  **ID-4's residence filter still works** (consistency ignores the populated map — asserted).
- [x] No rule-id/family branch; a new per-borrower judgment runs from a spec alone. ruff + mypy + full
  suite green.

## Assumptions & decisions

- **One enumerator, two meanings.** Consistency uses `per_borrower` as a grouping key and discards the
  map (verified) → ID-1/2/3/4 and LP-326's document keying are untouched (equivalence free). Judgment
  reads the assembled map.
- **Declared keying, merged generically.** A fact lives in its ONE declared keying (LP-326 production
  subject): borrower-level under `by_subject[borrower_id]`, loan-level under `by_subject["loan"]`. The
  enumerator merges loan-shared + borrower-own (borrower-own overrides). No per-rule config, no rule-id
  branch — the eighth application of declared-key-resolved-generically.
- **Multiple values.** Not ID-8's case (one MISMO citizenship per borrower). A future per-borrower
  judgment over a document-sourced + multi-valued fact would add the LP-325 gather LEG reasoning over the
  SET (disagreement visible to the AI — resolving it is a consistency rule's job). NOT built (YAGNI, reported).
- **Absent-subject.** A file always has borrowers, so ID-8's absent-subject case is moot; a borrower whose
  facts are absent → couldnt_check for that borrower (fail-closed), not the LP-330 missing-document case.

## What this implies for FUTURE per-borrower judgments

- Employment reasonableness, income stability, etc. — same mechanism: their borrower-level facts key under
  `by_subject[borrower_id]`, loan-level facts shared, and if a fact is ALSO document-sourced and gathered
  by a consistency rule, the gather leg (deferred) reasons over the set. The keying is DECLARED per tag;
  the assembly is generic.

## Which rules activated vs waiting

- **ID-8 — authored, NOT activated.** Its inputs don't materialize: (1) `id.citizenship` must be
  materialized under `borrower_id` from MISMO `borrower.N.citizenship`, which needs a **`borrower_id ↔
  MISMO-index` resolution** (MISMO keys by index; `per_borrower` enumerates `belongs_to` UUIDs); (2)
  `program.type` is unmaterialized. Both are the new gap below. The MECHANISM is proven (synthetic +
  fixture tests); ID-8 stays out of `ACTIVE_RULE_IDS` until its tags materialize (LP-325/326/327 restraint).

| Item | Rule | Encoded default | Must confirm |

A wrong encoded eligibility rule is a serious, silent, permanent **fair-lending** error — hence the
default is deliberately conservative (answer "unknown" when the tags don't support a confident, program-
specific call) and every verdict is ratification-pending.

## New generalization gap surfaced (reported, NOT patched)

- **`borrower_id ↔ MISMO-index` resolution + borrower-fact materialization.** To materialize per-borrower
  1003/MISMO facts (`id.citizenship`, and future income/employment facts) under `by_subject[borrower_id]`,
  a producer needs to map MISMO `borrower.N` to the `belongs_to` `borrower_id`. Plus `program.type` needs
  a loan-level declaration. A small follow-on that activates ID-8 (and re-keys `id.citizenship` off its
  wrong `document` declaration).
