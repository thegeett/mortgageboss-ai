# LP-118.8 — Link documents to borrowers (the "whose document is this" matching)

**Type:** Story · **Epic:** Phase 3.5 / Epic B · **Depends:** LP-118.6, ADR-239
**Status:** complete · **Date:** 2026-07-07

## What this ticket is

Documents attach to the loan **file** with no borrower link. Correct identity checking (ID-1 name,
ID-2 SSN, ID-3 DOB, IN-5 employer) is **per-borrower** — "does *this* borrower's W-2 match *this*
borrower's stated identity" — so without knowing whose document is whose, a naive check false-flags
on every multi-borrower file (Bansari's stated name vs Akash's bank statement → false "name
inconsistent"). This ticket adds the borrower↔document **association** and the **matching logic**
that determines whose document each one is, and surfaces it in `borrowers[].documents[]` (the shape
LP-118.6 built).

**Scope held:** this PROVIDES the link the identity rules need; it does **not** build those rules
(ID-1/2/3, IN-5) and executes no verification rule. Model + matching-logic + namespace wiring only.

**THE SAFETY RULE (the heart of this ticket):** a **wrong** assignment is worse than **no**
assignment — a mis-filed document would make the identity rules produce **false** findings. So:
confident unambiguous match → assign; ambiguous / weak / no-name → leave **UNASSIGNED** with a
recorded reason, never a forced guess; a joint document → link to **multiple** borrowers.

## Acceptance criteria — and how each was met

- [x] **A borrower↔document association exists, reversible migration; null = unassigned.** →
  `document_borrower_links` table (a **link table**, so a joint doc links to multiple borrowers),
  with `confidence` + `method` provenance; migration `f3a9c2d5e8b1` (verified up/down on Postgres).
  A document with no link is unassigned/file-level.
- [x] **Assign ONLY on a confident match; ambiguous/low/no-match left UNASSIGNED with a recorded
  reason — never force-assigned.** → the matcher requires the best score `>= 0.7` **and** a clear
  margin `>= 0.2` over the runner-up; otherwise no link + a note (`no_name` / `no_match` /
  `ambiguous`) on `Document.borrower_match_note`. Tested (ambiguous "C. Patel" with two same-initial
  Patels → unassigned, not guessed).
- [x] **No-identity documents (contract, appraisal) stay file-level.** → owner-name keys exclude
  `buyer_name`/`seller_name`/`donor_name`; a contract with only a buyer name yields no candidate →
  `no_name`, unassigned. Tested.
- [x] **Joint documents link to multiple borrowers.** → `_extract_names` joint-splits a name field
  (`"Bansari Patel and Akash Patel"` → two candidates); the matcher links each. Tested → `joint`.
- [x] **Name variations (middle initial, suffix, abbreviation) match via fuzzy matching.** →
  suffix-stripping + token matching + first-initial matching (`Bansari K Patel`, `Bansari Patel Jr`,
  `B. Patel` → Bansari). Tested.
- [x] **`borrowers[].documents[]` populated for assigned docs; `documents[].borrower_id` set where
  assigned.** → the fact-builder reads the persisted links: each borrower's matched docs nest under
  it (a joint doc appears under each), and the file-level `documents[].borrower_id` is the single
  owner (None for joint/unassigned). Tested.
- [x] **LF-6T3N multi-borrower: each borrower's docs associate correctly — no cross-assignment.** →
  the multi-borrower (Bansari + Akash Patel) namespace test asserts each borrower has only their own
  doc (+ the joint), never the other's. This is the exact bug the ticket targets.
- [x] **Confidence/provenance recorded on associations.** → `confidence` + `method` on each link
  row; the unassigned reason on `Document.borrower_match_note`; the matcher returns the full
  structured outcome; the service logs counts (never names — PII).
- [x] **SCOPE: no identity rules built, no rule executed.** → only the link + matcher + namespace
  wiring; tests confirm linking/matching only.
- [x] **`docs/tickets/LP-118.8.md` written** (this file).

## What was built

- **`DocumentBorrowerLink`** (`app/models/document_borrower_link.py`) + migration `f3a9c2d5e8b1` —
  the link table (one row per (document, borrower), `confidence`, `method`) and a nullable
  `documents.borrower_match_note` for the unassigned reason.
- **The matcher** (`app/services/document_borrower_matching.py`) — a **pure** `match_documents`
  (name normalization/tokenization, suffix + initial handling, the assign/ambiguous/no-match policy)
  and `assign_documents_to_borrowers(db, loan_file)` which extracts owner names, runs the matcher,
  and **replaces** the file's links + notes.
- **Fact-builder wiring** (`app/verification/fact_namespace/builder.py`) — reads the persisted links
  to populate `borrowers[].documents[]` (per-borrower refs) and set file-level
  `documents[].borrower_id` (single owner only).
- **Tests** (`tests/services/test_document_borrower_matching.py`, 11) — the pure-matcher safety
  cases + the DB service + the multi-borrower namespace regression.
- **Reference update** — `docs/reference/fact-namespace-structure.md` reflects that
  `borrowers[].documents[]` / `documents[].borrower_id` are now populated.

## Assumptions and decisions

- **Link table, not a `Document.borrower_id` column.** A joint document legitimately belongs to
  multiple borrowers, which a single FK cannot express; a link table (one row per match) supports
  joint + carries per-link `confidence`/`method` provenance.
- **Assignment policy (the safety thresholds):** a borrower is a contender at score `>= 0.7`;
  assignment requires the best contender to beat the runner-up by `>= 0.2` (a *clear* winner). Two
  close contenders → `ambiguous` (unassigned). Scores: exact full-name-token `1.0`; first+last
  (middle ignored) `0.9`; first-initial + last `0.7`; same-surname-different-first `0.2`;
  surname-only `0.3` (below the bar). **Last name must match** to score at all — the anchor that
  prevents cross-assignment on a shared surname.
- **Owner-name keys are curated + conservative:** `full_name`, `employee_name`,
  `account_holder_name`, `borrower_name`, `recipient_name`, `name`. **Excluded:** `buyer_name`,
  `seller_name`, `donor_name` — ambiguous ownership (a gift donor / contract seller is not the
  borrower), so those documents stay unassigned rather than inventing a borrower.
- **Joint split** on ` and ` / `&` / `;` (not commas — a "Last, First" would be mis-split).
- **Unassigned reasons** (`no_name` / `no_match` / `ambiguous`) are persisted on
  `Document.borrower_match_note` and returned by the matcher — reviewable + eval-testable.
- **The namespace reads the PERSISTED links** (single source of truth): `assign_documents_to_borrowers`
  writes them; the builder reads them. So the runner (LP-121) must call assign before building the
  snapshot; the builder is robust to no-links (empty `documents[]`, as in LP-118.6). This keeps one
  source of truth and avoids the builder and the persisted table diverging.
- **File-level `borrower_id` is single-owner only** — a joint doc has `borrower_id=None` at the file
  level (the per-borrower nesting carries the joint linkage), matching the LP-118.6 `DocumentRef`
  shape (`borrower_id: str | None`) without changing it.
- **PII:** the service logs counts only, never names.

## Follow-ups

- **Unblocks ID-1 (name), ID-2 (SSN), ID-3 (DOB), IN-5 (employer)** — per-borrower identity
  consistency can now compare *this* borrower's documents to *this* borrower's stated identity.
- **LP-121 (runner):** call `assign_documents_to_borrowers` before assembling the fact snapshot so
  `borrowers[].documents[]` is populated on a live run.
- **Eval set (LP-143):** whose-document matching carries **silent mis-assignment risk** (a cousin of
  the extraction/canonicalization risk) — feed the confidence/method + the unassigned reasons into
  the eval set; a wrong high-confidence assignment is the failure mode to catch.
- **Extraction dependency:** matching only sees names the extractor produced; a document whose owner
  name isn't extracted stays unassigned (`no_name`) — improving those extractors improves coverage.
