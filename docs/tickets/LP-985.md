# LP-985 — VPC endpoints for SQS and the SES API; Route 53 reachability decided

- **Ticket:** LP-985, the fifth of the step-1 tickets in `loan-email.md` §15.
- **Status:** applied to staging (account `058190633983`, us-east-1) on 2026-10-20 (US Eastern).
  Route 53 deferred to step 3 (decided at the checkpoint).

## What and why

The app's tasks run in private subnets with no NAT gateway, so they have no route to the internet.
They reach AWS services only through interface VPC endpoints, one per service, listed in
`interface_endpoint_services`. A service missing from that list does not give an error: the call
simply hangs until it times out.

The email feature needs two more services:

- **SQS**: the worker reads the inbound mail queue and the delivery-events queue (LP-983).
- **The SES API**: the worker sends email, and the api creates tenant identities.

It deliberately does not need these:

- **SNS**: the worker never calls it. SNS delivering to SQS happens inside AWS.
- **KMS**: S3 and SQS call KMS on our behalf; the task never does.
- **STS**: tasks get their credentials from the ECS container metadata endpoint.

A third service, **the Route 53 API**, is needed in step 3, when the api creates tenant hosted zones.
See "Route 53" below.

## What changed

  with a comment on what each one is for and why SNS, KMS and STS are absent.

## Route 53 — decided: defer to step 3

**A private endpoint exists**, so step 3 needs no NAT gateway, Lambda or admin script:

- service name `com.amazonaws.route53`, private DNS name `route53.amazonaws.com`, offered in us-east-1a
  (from `describe-vpc-endpoint-services` above);
- AWS added PrivateLink for the Route 53 API in November 2025 ("Amazon Route 53 DNS service now
  supports AWS PrivateLink", AWS What's New).

**Why it was not added now.** Nothing calls Route 53 until step 3, and adding it today would cost
about $7.30 a month for nothing. It also cannot be added through tfvars alone: the network module
always builds `com.amazonaws.${var.aws_region}.${each.value}`, and the Route 53 name has no region in
it. A `"route53"` entry would ask for `com.amazonaws.us-east-1.route53`, which does not exist, so the
apply would fail.

**What step 3 needs to do:**

1. In `infra/modules/network/main.tf`, `aws_vpc_endpoint.interface`, pass through unchanged any list
   entry that already starts with `com.amazonaws.`:
   ```hcl
   service_name = startswith(each.value, "com.amazonaws.") ? each.value : "com.amazonaws.${var.aws_region}.${each.value}"
   ```
   The existing short names produce the same service names as before, so the plan should show no
   change to the seven existing endpoints.
2. Add this entry to `interface_endpoint_services` in `infra/envs/staging/terraform.tfvars`:
   ```hcl
   "com.amazonaws.route53",
   ```
   The endpoint's `Name` tag becomes `mbai-staging-com-amazonaws-route53` (from the existing
   `replace(each.value, ".", "-")`).
3. Expected plan: one create, `module.network.aws_vpc_endpoint.interface["com.amazonaws.route53"]`.
