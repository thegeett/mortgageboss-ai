# LP-597 — Four rules stopped overclaiming, and the composer stopped inventing

All five defects came off one verification run of LF-3CVT, a refinance with **zero documents
uploaded**. That state is the sharpest honesty test the engine gets, and it can only be run once per
file. Six of thirty findings came back `satisfied`; two of those were wrong and one was vacuous.

## AS-4 — reserves cleared on a five-property borrower

`satisfied`, reading *"Fannie Mae guidelines require no minimum reserves for a one-unit principal
residence."* True of the matrix cell, and wrong about the file: B3-4.1-01 also requires **2%** of
aggregate UPB at 1–4 financed properties, **4%** at 5–6, **6%** at 7–10. The real export carries five
retained first liens totalling $2,190,383.

AS-4's own docstring had said for two tickets that it does not model this, *"because neither the
financed-property count nor the aggregate UPB reaches the snapshot"*. LP-596 put the REO schedule
there, so it does now. New `needs_review` branch, **ordered after `fired`** so a genuine shortfall
against the occupancy matrix still wins.

Two things the arithmetic gets right and is easy to get wrong, both mutation-pinned:

- **The tier counts the subject; the balance excludes the principal residence.** Five other properties
  is *six* financed → the 4% tier. The guide separately excludes the borrower's own home from the
  aggregate. So one property counts for the tier and is excluded from the balance. On the real file:
  $1,879,121 × 4% = **$75,164.84**.
- **`needs_review`, not `fired`.** The overlay is a dollar requirement; the calculator reports months
  of PITIA. Converting needs the housing payment, gated on exactly the files where taxes and insurance
  have not arrived. The rule reports that the overlay applies and hands the comparison to a human.

## DT-8 — the wording, and the guard its own guideline demanded

The **verdict was not changed**, deliberately, and against my first recommendation. An application is
authoritative about the borrower's own intent; a refinance definitionally retires the subject lien
(B3-6-07 governs consumer debts paid off *to qualify*, not this); and downgrading would put a
permanent item on every refinance file where the form already answered.

What was wrong was the sentence: *"its payment is **correctly** excluded from the **back-end
debt-to-income ratio**"* claimed the lien sits on the subject property (nothing checked it) and
asserted a property of a ratio that is **gated** whenever taxes and insurance are missing.

And the guard: DT-8's guideline text says *"A mortgage secured by other property the borrower retains
remains an obligation and stays in the ratio"*, and nothing tested it. New `liab.payoff_contradicted`
compares the payoff marking against the REO schedule's disposition, **matched by balance** — the join
LP-596 proved exact. A lien marked paid off whose property is marked `Retain` is the form disagreeing
with itself. No threshold required.

The test caught a real inertness bug: the producer first read `unpaid_balance` (the MISMO spelling)
where the canonical name is `balance`, which would have returned `None` on every liability and shipped
a guard that never fired.

## MI-1 — MI cleared off the borrower's own estimate of value

`satisfied`: *"the loan-to-value is 79% ... so no mortgage insurance is required"*, with **no
appraisal on the file**. B2-1.2-01: *"For refinance transactions ... the property value is the current
appraised value."* `_conservative_appraised_value` deliberately falls back to the stated estimate so
the worksheet always has a denominator — correct for a display, wrong for a rule that *dismisses* a
requirement. If the appraisal lands lower the loan crosses 80% and MI is required after all.

New `loan.ltv_basis_is_appraised` gates **only the clearing direction** → `couldnt_check`. The
`needs_review` branch needs no guard: a stated value that already exceeds the threshold is if anything
optimistic.

`test_mi1_cannot_fire_from_any_outcome` asserted the exact outcome list; its real invariant is "MI-1
can never fire", which a `couldnt_check` cannot violate. Updated with that reasoning recorded.

## OC-1 and IN-2 — one bug, in the composer, not the specs

- IN-2: *"The file contains pay stubs, but none of them display a pay date."* There are none. IN-2's
  spec has no `couldnt_check` branch at all — the engine's generic text was what the model was handed.
- OC-1: its spec says *"agrees with the file's other occupancy **declarations**"* (the 1003's own
  fields). The composer wrote *"consistent across all loan **documents**"*.

Both invented a corpus to make an absence read concretely. The prompt already forbade it (*"Use ONLY
facts present in the summary"*) and **could not be obeyed**: nothing in the summary said what the file
contains. `FactSummary` now carries `documents_on_file`, with a prompt rule anchored to both real
sentences.

Two traps inside this fix, both now pinned:

1. `to_json` filters falsy values, so `documents_on_file: 0` — the single most load-bearing value it
   carries — **would have been dropped**, shipping the fix inert.
2. The count must NOT come from `document_filenames`: that map is loaded only when a document-*subject*
   finding exists, so its size reads zero on files with plenty of documents. A false zero would license
   exactly the invention it prevents. Counted independently.

## Composition coverage

Every persisted finding is already submitted to the composer, satisfied included. What varies is
**acceptance** — a composition is rejected when it invents a number, asks for an unrequested document,
talks about the software, leaks an identifier, or asks for work on a pass. Rejection is a real safety
mechanism, but the fallback is the raw template, and templates read as engine prose (lowercase,
mid-sentence) because they were written to be rewritten. On the real run that left DT-8 and MI-1
reading unlike every finding beside them.

`compose` now retries **once** on a recoverable rejection, with the specific reason appended — at
temperature 0 a bare retry mostly reproduces the same draw. Transport failures are not retried here;
the client already has its own policy.

**`not_applicable` cannot be composed, because it is never persisted** (`rule_findings.py:45`,
"NOT_APPLICABLE is absent → not persisted"). That tab is structurally empty on every file, so there is
nothing there to rewrite. Making it composable is a separate decision about persisting those verdicts.

## Tests

30 new across four files, every guard mutation-checked — dropping the subject from the tier count,
leaving the principal residence in the aggregate, reordering AS-4's branch ahead of `fired`, the DT-8
inertness bug, restoring DT-8's old wording, filtering the zero document count, and removing the
retry each fail the suite. Full backend suite green: **5417 passed**.

## Follow-ups

- AS-4's finding says "2% to 6% of the aggregate liens" rather than "$75,164.84". Templates
  interpolate operands only, and `deterministic.py` `couldnt_check`s on ANY unresolvable declared
  operand *whichever outcome would match* — so declaring the overlay figures would mean one REO
  property missing a lien balance takes out AS-4's occupancy check too. Containment was worth more
  than the number in the sentence; a rule that owns the overlay could legitimately gate on it.
- An absent REO schedule reads "no other financed properties", not "unknown". Abstaining on absence
  would turn AS-4 into a `couldnt_check` on nearly every file without that section. Written into the
  test rather than hidden.
