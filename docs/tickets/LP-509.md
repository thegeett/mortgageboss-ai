# LP-509 — the rule engine reports ~115 false findings on its first real file

**Branch:** `lp_509_false_findings_rule_engine`
**Found on:** staging, loan file **LF-WCHG** (run `dd4e6fca-7de3-4553-b173-cb412ed57b07`, 2026-08-14)
**Method:** the C7 query stage against staging + the borrower's real document set + the rule engine source

---

## What this ticket is

The governed rule engine reached staging for the first time on 2026-08-14 and produced **162 findings on one
loan file, 132 of them in "Needs attention"**. A processor reads that as 132 defects.

Investigation against the database, the borrower's actual documents and the source puts the real number at
**about 13**. Roughly **115 findings should never have been shown**, and separately **the one defect a
processor would most want is missing entirely** (§D1).

The findings are not random. They come from **four root causes amplified by per-subject fan-out**, and four
of the seven defects were *predicted in comments in this repository* before they happened (§E).

| Bucket | Count |
|---|---|
| Confidently wrong | ~111 |
| Wrong as shown, honest given its inputs | 4 |
| Defensible | 4 |
| **Genuine** | **~13** |
| Total "Needs attention" | 132 |

`open` 3 · `couldnt_check` 115 · `needs_review` 14 — verified by query, reconciles exactly to 132/162.

> **Scope note.** LF-WCHG is a **rate/term refinance** of a detached single-family home, with 14 of the
> borrower's ~30 documents uploaded. Both facts matter: several defects are purchase-only rules that have
> never been exercised against a file where they do not apply.

## A. Rule defects — the code is wrong

### A1 · AS-2 and AS-12 evaluate money going OUT → **104 findings**

`per_deposit` enumerates **one subject per bank-statement transaction** (57 here), not per deposit — the
docstring says so. AS-1 gates on `txn.is_money_in`, so its money-out subjects become `not_applicable` and are
never persisted. **AS-2 and AS-12 have no such gate.**

Proof by query:

```
as1_subjects | as2_subjects | as12_subjects | as1_inside_as12
     10      |      57      |      57       |       10
```

Same enumerator, same transactions; AS-1's 10 are a strict subset. The result is *"the deposit's source could
not be found in the file"* asked of an ATM transaction fee (`txn.apparent_category: "fee"`, confidence 1.0),
a Geico premium, a Dominion Energy bill, an AT&T bill and a Planet Fitness charge.

- `AS-2.yaml` — `gated_tags: [txn.has_identified_source]`
- `AS-12.yaml` — `load_bearing_tags: [txn.apparent_category, txn.has_identified_source]`
- `AS-1.yaml` — `gated_tags: [txn.is_money_in, txn.amount, txn.has_identified_source]` ← the difference

**Fix:** add `txn.is_money_in` to both. Two lines. Removes 104 of the 115.

### A2 · ID-6 can never pass, on any file → **1 RED**

`_APP_REQUIRED_FIELDS` (`derived.py:384`) requires the MISMO fact keys `borrower.1.name` and
`property.address`. `mismo_section.py` emits `borrower.{n}.first_name` / `.middle_name` / `.last_name` and
`property.address_line` / `.address_line_2`. **Neither required key is emitted by anything.**

Confirmed twice — by source, and by the finding itself, which reported `borrower.1.ssn` and `loan.amount`
present (those keys exist) while calling the other two missing.

This is not specific to LF-WCHG. **Every loan file in the system gets a RED "the application is incomplete".**

### A3 · IN-3 — three stacked arithmetic defects → **1 RED**

Message: `YTD gross 78781.26 over 4 month(s) = 19695.32/mo vs documented 52615.42/mo → shortfall 0.6257`

1. **YTD summed across pay stubs.** The two stubs carry `36,376.62` and `42,404.64`; their sum is *exactly*
   78,781.26. YTD is cumulative — April already contains March. The correct figure is the latest, 42,404.64.
2. **`documented_monthly` summed across documents.** `52,615.42 ≈ 4 × 13,154`, against a borrower earning
   ~$13,100/mo. Both tags are declared `subject: document`; `_income_numbers` sums across subjects.
   `income.documented_monthly` has `applies_to: [pay_stub, w2, uniform_residential_loan_application]`.
3. **`elapsed_months = max(pay_dates).month`** treats a pay date of 4 April as four full months elapsed
   (~3.1 have).

⚠️ **Fixing 1 and 2 alone leaves the finding firing**: 42,404.64 ÷ 4 = 10,601/mo against ~13,136 documented is
still a 19% shortfall, over the 0.1 tolerance. Against the true elapsed period it is 13,679/mo — no shortfall.
All three must be fixed together.

Also cosmetic, but processor-facing: the message prints a raw `Decimal` —
`0.6256740894589456855043635497` — where it should read `62.6%`.

### A4 · False undisclosed-mortgage alarm → **2 findings** (DT-6, RE-1)

Both state *"no mortgage liability stated on the application names a holder matching this statement's lender
('United Wholesale Mortgage, LLC')"*.

The stated liabilities contain exactly that:

```
Revolving / CITI / 49.00  ||  Revolving / DISCOVER BANK / 35.00
Revolving / APPLE CARD/GS BANK USA / 25.00  ||  MortgageLoan / UNITED WHSLE MORT / 3186.00
```

A name-normalisation failure between the credit-abbreviated form and the servicer's legal name. RE-1 tells a
processor a mortgage may be undisclosed when it is plainly disclosed — a serious false alarm.

### A5 · Purchase-only rules on a refinance → **3 findings** (PC-2, PC-3, PC-7)

`loan_purpose = refinance`, `refinance_type = rate_term`. A rate/term refi has no purchase contract. The specs
name the cause themselves:

> PC-7: *"⚠️ SCOPE (D4): PC-7 is LOAN-WIDE, not applicability-scoped. There is NO loan-purpose /
> transaction-type tag to scope it purchase-only, so a REFINANCE … → couldnt_check"*

**AS-2 shares this root cause** — earnest money is a purchase concept and it ran here too.

## B. Data-promotion gaps — the data exists, nothing carries it

### B1 · Property type is never derived → **4 findings** (CO-1, CO-3, CO-4, IH-7)

All four say *"the property type has not been determined"*. The database already holds:

```
property_type | attachment_type | construction_method | financed_unit_count | occupancy_type
   (empty)    |    Detached     |      SiteBuilt      |          1          | primary_residence
```

and the **imported** MISMO (status `completed`, no parse warnings) holds:

```xml
<AttachmentType>Detached</AttachmentType>
<PropertyInProjectIndicator>false</PropertyInProjectIndicator>   <!-- decisive -->
<PUDIndicator>false</PUDIndicator>
<PropertyEstateType>FeeSimple</PropertyEstateType>
<FinancedUnitCount>1</FinancedUnitCount>
```

`PropertyInProjectIndicator = false` is decisive: a condominium is by definition a property *in a project*.
(`AttachmentType = Detached` alone is **not** sufficient — Fannie recognises detached condominiums. This was
checked specifically.) **The parser does not capture `PropertyInProjectIndicator` at all.**

`_condo_scope` (`derived.py:1193`) reads only `property.type`; absent → abstain. Had it resolved, the branch
`if next(iter(property_types)) != "condo": return "n/a"` makes all four `not_applicable` — **never persisted**.

`tag_production.yaml` already records the gap: *"On the current fixtures MISMO property_type is null on all
three files… an honest source-data gap."*

### B2 · `loan.purpose` exists as a column, not as a tag

`loan_files.loan_purpose` is populated. No tag promotes it, so no rule can scope on it. Underlies A5 and AS-2.

## C. Blocking infrastructure

### C1 · No snapshot has ever persisted for this file

`select … from snapshot_records where display_id='LF-WCHG'` → **0 rows.** Every run is refused by
`verification_persist_snapshot_failed error=RawPiiAtRestError`; `observations` is empty too.

The per-document tag values the rules evaluated therefore exist **nowhere readable**. That is why A3's YTD
double-count could be proven by arithmetic but `documented_monthly` could only be inferred.

**This now blocks diagnosis, not just reproducibility** — verifying the A3 fix means reading those tags. Fix
before A3. Likely the known over-broad guard (a legitimate ≥9-digit identifier trips it), but that is
unconfirmed because the payload cannot be read.

## D. A real defect the engine missed

### D1 · The hazard insurance policy has expired

`Home Insurance (2).pdf` is an ACORD 27 with a term of **06/25/2024 – 06/25/2025**. It is now **13 months
lapsed**, on a refinance being processed in 2026.

Nothing flagged it: IH-3 (hazard insurance in effect at closing) abstained for want of a closing date, so the
expiry was never compared against anything. **This is the finding a processor would most want, and it is in
none of the 162.**

A `couldnt_check` on the closing date silently swallowed an unconditional fact — the policy is expired
regardless of when closing is.

## E. Root causes — why seven defects, not one

Measured: the **tag** namespace is clean — 94 tags consumed by rules, 190 produced, **0 real gaps**. The
failures are all at boundaries where a string is a contract and **no registry exists to validate it**.

| Boundary | Registry | Guard | Defects |
|---|---|---|---|
| Extractor field names | schema specs, `_PII_FIELDS` | ✅ `test_every_parsed_declaration_names_a_real_field` | — |
| Distrusted fields | `distrusted_fields.yaml` | ✅ `test_every_distrusted_field_reaches_a_rule` | — |
| Tag ids | `tag_production.yaml` | ✅ effectively | — |
| **MISMO fact keys** | ❌ none | ❌ none | **A2, B1** |
| **Tag subject granularity** | declared, unchecked | ❌ prose only | **A3** |
| **Applicability vs enumerator** | ❌ none | ❌ none | **A1, A5** |
| **Entity-name matching** | ❌ none | ❌ none | **A4** |

**E1 — no guard on MISMO fact keys.** `test_every_parsed_declaration_names_a_real_field` fails with
*"name a field that cannot exist → the tag is ABSENT and its rule…"* — a description of A2, built for
extractor fields and never generalised to the fact namespace.

**E2 — granularity documented in prose, not enforced.** `_income_numbers` states the hazard verbatim
(*"keying a monthly figure under each of a borrower's N paystubs would sum to Nx the income here"*) and A3
does exactly that. Worse, `_borrower_documented_monthly` already contains the correct distinct-and-abstain
fix, citing "the exact PIN #1 false-green" — and it never propagated to the loan-level sibling.

**E3 — applicability is per-rule discretion.** Three rules share an enumerator; one filters, two do not, and
nothing makes the divergence visible in review.

**E4 — known gaps live in comments, not failing tests.** Four of these were predicted in-repo before they
occurred (A3, A5, B1, and `_PII_FIELDS`' list-row note). A comment and an `xfail` cost the same to write.

**Amplification** is why four causes look like a catastrophe:

| Root cause | Fan-out | Findings |
|---|---|---|
| One missing `is_money_in` gate | × 2 rules × 47 money-out transactions | 104 |
| One underived `property_type` | × 4 condo-family rules | 4 |
| One absent `loan.purpose` tag | × 3 purchase rules | 3 |
| One wrong fact key | × 1 rule, **every file** | 1 |

`couldnt_check` is deliberately fail-loud — a missing input must never read as a pass — but nothing dampens a
*systemic* gap, so one structural error becomes a hundred rows in front of a processor.

## Acceptance criteria

1. AS-2 and AS-12 gate on `txn.is_money_in`; LF-WCHG's AS-2/AS-12 findings drop from 114 to ≤ 20, and none
   has a money-out `txn.apparent_category` (`fee`, `vendor`, `debt_payment`, `transfer_third_party_out`).
2. ID-6's required fact keys resolve against keys `mismo_section.py` actually emits; a complete 1003 reaches
   `satisfied`. A regression test pins that the required set is non-empty **and** every key is emitted.
3. A guard asserts **every MISMO fact key referenced by a recipe is emitted by `mismo_section.py`**, with an
   explicit `_KNOWN_UNPRODUCIBLE` escape hatch mirroring the parsed-declaration test.
4. `_income_numbers` refuses a tag declared `subject: document`, or IN-3 stops using it. IN-3 on LF-WCHG
   either abstains or reports no shortfall; the message renders a percentage.
5. Liability-holder matching normalises `UNITED WHSLE MORT` ↔ `United Wholesale Mortgage, LLC`; DT-6 and RE-1
   stop firing on LF-WCHG.
6. A `loan.purpose` tag exists; PC-2/PC-3/PC-7 and AS-2 are `not_applicable` on a refinance.
7. Property type is derived from `PropertyInProjectIndicator` + `AttachmentType` + `PUDIndicator`; CO-1, CO-3,
   CO-4 and IH-7 are `not_applicable` on LF-WCHG.
8. Snapshots persist for LF-WCHG (`snapshot_records` non-empty), or the refusal is understood and recorded.
9. LF-WCHG's "Needs attention" is **≤ 20**, with every remaining finding attributable to a real gap.
10. An expired hazard policy is detected independently of the closing date (§D1) — or, if deferred, a ticket
    exists saying so.

## Stop and report

- Any fix that requires relaxing `couldnt_check`'s blocking behaviour. The honesty contract is not the bug.
- Any rule whose correct applicability is a domain question (does AS-12 apply to a rate/term refi at all?).
- If the snapshot refusal (C1) turns out to be a genuine unmasked identifier rather than the known over-broad
  digit rule — that is a PII finding, not a query-path bug.
