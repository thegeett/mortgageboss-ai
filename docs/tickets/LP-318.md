# LP-318 — Calculators as structured tags (from_tag + fail-closed)

**Status:** Complete. **Branch:** `phase3_new_AI_arch_finding_stage2`.
**ADR:** [ADR-258](../../decisions.md). **Depends on:** LP-310 Area 3 (the calculator table),
LP-312 (the null `from_tag`), LP-315 (the gate + confidence convention), §3D.

## What it is

Wires each snapshot calculator's breakdown lines to the fact-tags that produced them (`from_tag`)
and makes the calculators **confidence-propagating** and **fail-closed** like every other tag
consumer (§3D): a rule reading a calc now sees HOW it was built, can trace each line to a tag, and a
calc built on an unknown/absent required input degrades to **couldnt_check** instead of emitting a
confident-but-wrong number. Wrap-layer only — the pure arithmetic calculators are untouched.

## Acceptance criteria

- [x] `from_tag` populated on every DTI / LTV / MI / reserves breakdown line (income →
  `income.qualifying_monthly`, PI → `housing.pi`, taxes → `housing.taxes_monthly`, insurance →
  `housing.insurance_monthly`, debt → `liab.dti_payment`, loan → `loan.amount`, appraised →
  `property.appraised_value`, MI rate → `mi.factor`, assets → `asset.usable_value`, …); a computed
  line with no fact-tag → `"derived"`, **never a fabricated id**.
- [x] Confidence propagation: `calc_confidence = min` of feeding-tag confidences, ignoring
  parsed/derived passthroughs (LP-315). Unit-tested via the helper; `None` in production today
  (all inputs are passthroughs) — the mechanism activates when AI-confidence tags are wired.
- [x] **Fail-closed** (the LF-6T3N case): `housing.insurance_monthly` unknown (no binder) → the DTI
  is **gated** → the ratios are nulled + `gate_reason` names the insurance tag; the DTI does NOT
  emit a confident number. The unknown line surfaces `amount=None` (not a fabricated 0).
- [x] Absent feeding tag → gated with a **distinct** reason ("absent" vs "unknown").
- [x] A rule reading a gated calc → couldnt_check (AS-1's income read returns None on a gated DTI).
- [x] Existing calc/snapshot tests still pass for a fully-tagged, high-confidence file (value +
  breakdown unchanged); round-trip lossless with `from_tag` populated. `SNAPSHOT_VERSION` 3→4.
- [x] max_loan / self_employed intentionally untagged (deferred — no snapshot consumer). ruff +
  mypy(`app/`) clean; full suite **1931 passed, 1 xfailed**.

## Assumptions & decisions

- **Wrap at the service/snapshot layer, never the pure arithmetic.** The calculators stay the single
  source of truth; `map_*` / `_line` add lineage + gating + confidence.
- **`from_tag` is a lineage LABEL, not a live tag pointer.** The referenced tags (`housing.*`,
  `dti.*`, `property.*`, …) are a defined `fact_tags.csv` vocabulary but are NOT materialized in the
  snapshot (only `txn.*` Stage-A/B tags are). `from_tag` names which tag produced a line; all mapped
  targets are real vocabulary entries — computed lines are honestly `"derived"`.
- **The "absent≠0" bug is the thing gated.** Every calculator collapses a non-derivable input to 0
  (`effective = override ?? auto ?? 0`). LP-318 detects `auto_amount is None and not overridden` =
  UNKNOWN, surfaces `amount=None`, and gates the calc when a REQUIRED input is unknown/absent —
  DTI required = `{housing.insurance_monthly, housing.taxes_monthly}` (a missing binder/tax
  understates the payment → the ratio would be confidently too-low). `hoa`/`mi` are legitimately 0 →
  not required. An **override** of a non-derivable input is NOT unknown (a human vouched for it).
- **Gating vs None.** A gated calc is PRESENT (carries the reason + breakdown), not None — so the
  consumer learns WHY (couldnt_check), where None would say nothing. LTV/MI/reserves already return
  None when their core input is missing, so they add no new required-gating set.
- **Confidence is a built-but-dormant mechanism.** `min` over feeding-tag confidences, ignoring
  passthroughs; `None` today because every calc input is parsed/extracted/computed/derived. It
  activates when Hybrid AI tags (`income.qualifying_monthly`, `liab.dti_payment`) are materialized
  and wired — stated as the explicit choice per the ticket.
- **4-vs-6.** Only DTI/LTV/MI/reserves feed the snapshot. `max_loan` / `self_employed` are API-only
  with no snapshot consumer → **deferred** (tagging them now would be dead lineage; a test asserts
  they stay out of the section).
- **Behavior change, deliberately.** A file missing a required housing input now yields a gated DTI
  (couldnt_check) instead of a confident too-low ratio. The DB-backed calculators test — whose seed
  has no binder/tax — now asserts that gated path (it previously asserted the confident wrong number).
  Fully-tagged files are unchanged.

## Deferred

- Tagging `max_loan` / `self_employed` (no snapshot consumer). Materializing the housing/income
  fact-tags so `calc_confidence` reads real AI confidences. Extending required-gating sets to
  LTV/MI/reserves beyond their existing None-when-not-computable. No new calculators (no
  cash-to-close). No rule logic beyond consuming a gated calc.
