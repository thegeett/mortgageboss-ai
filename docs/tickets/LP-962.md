# LP-962 — Would the AI type conditions as well as the hand-written lender code maps? (measurement)

- **Ticket:** LP-962 · Phase 4.5 Stage 3 follow-ups (the owner, 2026-10-04)
- **Source:** the owner: "whether do we need to look the condition-code from our code? What is the purpose
  of looking at persisted code instead fresh AI?" and "why we dont use AI only and no lender base yaml?"
- **Nothing in the app changed.** This ticket is the measurement the decision waits on.

## The question

Three things get called "the code map":
1. the sheet readers that split a PDF into conditions;
2. the condition library (`types.yaml`), meaning what satisfies each type;
3. the per-lender code lists (`lender_codes/uwm.yaml`, `champions.yaml`), meaning "UWM 0006 is IV-01".

Only the third is in question. Today it decides a known code's type, and the AI's `library_type`
proposal is used only for a code the list does not have.

## Method

`backend/scripts/condition-typing-comparison.py` takes every distinct (lender, code) on the committed
sample sheets, sends each condition's text to the reading's real prompt (`read_v3`, the configured model,
which answered as `claude-haiku-4-5` through Bedrock) with **no type**, the way an unmapped code is read,
and compares the AI's `library_type` with the code list's `canonical_type_id`. It prints codes and type
ids only. Total cost was about $0.12.

## Result

**UWM: 21 conditions. The sample text matches each code's label, so this half is valid.**

| Verdict | Count | Codes |
|---|---|---|
| AI agrees with the list | **16** | 0006 0007 0132 0471 0562 0571 1582 1594 1947 5868 6132 6140 6178 6378 6637 7086 |
| AI gave no type (null) | 4 | 1228 final inspection, 1760 desk review ordered, 4235 prior-employer W-2/WVOE, 5853 REO mortgage statement |
| AI disagrees | 1 | 7383 "explanation for a $1,240 **deduction**": the list says CR-02 (liability not on credit report), the AI says AS-05 (large **deposit** explanation). **The list is right.** |

**Champions: 28 conditions. INVALID as a test of the list.** The Champions sample sheet
(`tests/conditions/champions_fixture.py`) was written with code numbers that do not match `champions.yaml`.
For example, the fixture's 261 asks for a flood determination, while the list's 261 is "E-sign certificate
for purchase contract". Its 7 disagreements and 13 nulls therefore say nothing about the list. They show
the AI choosing sensibly between the list's wrong type and none, which is not the question.

**The UWM corpus is synthetic.** The four UWM sheets are fixtures cut from the build spec. They were written
in UWM's layout and wording but are not real lender sheets. Real sheets are the next measurement.

## What it means

- On UWM-style text the AI types about **3 conditions in 4** the way the list does (16 of 21). It leaves 4
  untyped, because the prompt tells it to name a type only when one "clearly" fits, and it gets 1 wrong in
  a way that matters (a deduction read as a deposit would ask for the wrong explanation).
- Dropping the UWM list today would cost a type on **5 of these 21** codes. A missing type is not a crash:
  the condition gets AI items and needs her confirmation. But the library's matching and checks would not
  run for those 5.
- The per-lender **confirmations** already exist (`lender_condition_codes.confirmed_reading`). Once she
  confirms a reading for a code, it is reused on every later file.

## A production risk this found

The first run sent all 21 UWM conditions in **one** call, as `read_round` does for a round. The answer hit
the reading's **8192-token output cap** (`_MAX_TOKENS`) and came back cut off ("unreadable_response"), so
every condition would have fallen back. Batches of 6 used 1.3k to 2.7k output tokens each, about 400 per
condition, which puts the limit near **20 conditions per round**. A sheet with more than that (a full UWM
master list) could lose its whole reading. That was measured in this script's no-type setting; with types
the output per condition is similar, but that was not measured. **A fix (batching the reading) is its own
ticket.**

## Recommendation (for the owner)

- **Keep** the sheet readers and the library (items 1 and 2).
- **Stop writing per-lender lists by hand for new lenders.** For any lender without a list, the AI's type
  plus her confirmation, saved per (lender, code), becomes the list. Keep `uwm.yaml` as a seed for now,
  because it beats the AI on 5 of 21.
- **Re-measure on real sheets** (a real UWM round and a real Champions certificate, run through this
  script) before deciding whether to retire `uwm.yaml`, and **fix `champions_fixture.py`** so its codes
  match the real list, or drop the Champions half.
- **Batch the reading** so a large sheet cannot lose its whole reading.
