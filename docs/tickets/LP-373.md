# LP-373 — The orphan guard: fail loud when the vocabulary promises a tag nobody produces

## WHAT THIS TICKET IS

**Three times** a tag was declared in `fact_tags.csv` with a producer named while **nothing produced it** —
and each was found by accident, after a LIVE rule was already dead, with every test green throughout:

| instance | found by | cost |
|---|---|---|
| `dti.qualifying_income_monthly` (LP-366-A, fixed) | tracing AS-1's bug | AS-1 had no loan-level income → read the DTI calc instead → **never evaluated a deposit** |
| `housing.insurance_monthly` (LP-367, **still open**) | LP-364 UI + LP-366-A | a required DTI-calc gating input has no producer → **the DTI can never compute on any file**; UI shows a fabricated **$0.00** |
| `occupancy.stated` + `occupancy.consistent_with_signals` (LP-371, fixed) | LP-370's audit | **OC-2 dead since the beginning** — occupancy fraud never assessed |

**THE ROOT:** the loader validates declarations that EXIST; it never checks that a vocabulary tag with a
producer HAS one. ABSENT is indistinguishable from "the document genuinely doesn't have this" — so it is
silent. This ticket closes the class with a guard. **It does not fix `housing.insurance_monthly` (LP-367)**
— it handles it honestly.

## ACCEPTANCE CRITERIA

- D1–D4 argued; the severity model justified by the real census, not framing.
- The full vocabulary census reported (first complete scan).
- A guard that FAILS on the pre-fix state (proven by construction) and PASSES on the fixed instances.
- Loud exemptions (each names a fix ticket + a "still-genuine-orphan" test); no silent allow-list.
- No false positives on legitimate authored-ahead tags; `txn.*` hardcoded producer not read as orphan.
- Equivalence (`ACTIVE_RULE_IDS` unchanged, every rule identical); ruff + mypy + full suite green.

## D1 — WHAT IS AN ORPHAN, PRECISELY? (three producer paths, not one)

A vocabulary tag (`fact_tags.csv` ∪ `vocabulary_extra.yaml`) that **nothing produces**. "Produced" has THREE
sources — a definition checking only `tag_production.yaml` is WRONG:

1. A declaration in **`tag_production.yaml`** (54 tags → `materialize_tags`).
2. The **hardcoded transaction path** — `services/tag_production.py` (Stage A: `txn.amount`, `txn.date`,
   `txn.is_money_in`, `txn.apparent_category`) + `services/tag_correlation.py` (Stage B:
   `txn.has_identified_source`). `producer.py`'s docstring: the live orchestrator "leaves the transaction
   Stage-A tags to their existing producer." **`txn.has_identified_source` is read by LIVE AS-1 and produced
   only here — a definition ignoring this path would false-positive on it (D1's trap).**
3. A live **judgment** rule's `output_tag` (produced by the judgment evaluator at rule time — e.g.
   `id.residency_eligible`, `id.poa_acceptable`, `occupancy.reasonable`).

## D2 — THE SEVERITY MODEL (the census decided it, not the framing)

An unproduced tag is a **build failure only when a LIVE consumer HARD-reads it**:
- a rule in `ACTIVE_RULE_IDS` reads it as a **gated** input (load-bearing / operand / gather / applicability
  / when-tag — the reads whose absence → couldnt_check), OR
- it is a **required input to the always-computed DTI calculator** (`_REQUIRED_DTI_TAGS` — the only
  tag-gated calc, built on every real run by `builder.py`, rendered in the UI; LP-367's shape).

Everything softer is **reported, not failed**: read only by INERT rules, by NO rule, or **softly** (a
judgment rule's `reasoned_over`, which is not gated — absence thins the AI's context but never
couldnt_checks). **Why:** a guard that fired on all 98 orphans would be muted within a week (LP-333's
uniform-couldnt_check dynamic); a guard that missed a live rule's orphan would be worthless. The three
instances were all HARD (two live-rule load-bearing/operand; one DTI-calc gate).

## D3 — WHERE IT LIVES: a TEST, not load-time

The guard needs `ACTIVE_RULE_IDS`, the rule specs, and the calc layer's `_REQUIRED_DTI_TAGS`. Making the
tag-vocabulary loader import the rule engine + specs + calculations to run this at load would **invert the
dependency** (the vocabulary is read BY the rule engine, not vice versa) — the exact reason LP-369 chose a
test. A CI test fails just as loudly without the coupling. (LP-369's parsed guard needs `app.ai.extraction.*`;
this one needs the rule engine — same inversion, same conclusion.)

## D4 — THE HONEST COVERAGE (the seam map — this is ONE seam of several)

This guard catches **vocabulary → producer** (a live-consumed tag nobody produces). It does **NOT** catch:
- a declared producer that EXISTS but never **runs** (the `_required_ai_groups` never-requested case,
  LP-333/368) — a different seam, **unguarded**.
- a declaration pointing at a nonexistent **field** — **LP-369's** parsed guard (document/transaction only;
  borrower/loan MISMO keys are data-dependent, skipped there).
- a tag that materializes but is **wrong** — calibration (**LP-379**).
- a **soft** `reasoned_over` orphan on a live rule — reported, not failed.
- a tag produced + consumed but **absent from the vocabulary** — this guard scans the vocabulary, so it
  cannot see `txn.source_strength` (read by live AS-1, produced by Stage B, not in `fact_tags.csv`).

## THE FULL VOCABULARY CENSUS (first complete scan — 156 tags)

| bucket | count | meaning |
|---|---|---|
| **fine** (produced) | 58 | declared / hardcoded-txn / live judgment output |
| **inert-orphan** | 73 | read only by inert rules — legitimate authored-ahead |
| **no-rule-orphan** | 22 | in the vocabulary, read by no rule — vocabulary drift |
| **LIVE-ORPHAN (dti-calc)** | **2** | `housing.insurance_monthly`, `housing.taxes_monthly` — **the guard FAILS here** |
| **live-soft-orphan** (reasoned_over) | 1 | `property.address_normalized_match` — reported, not failed |

**98 of 156 tags are unproduced** — overwhelmingly legitimate (the CR/PR/TI/MI/AS/IN/CO/etc. families are
authored ahead of their inert rules). Orphans by family: `liab` 14, `property` 13, `contract` 9, `calc` 7,
`ins` 6, `mi` 6, `title` 5, `txn` 5, `aus` 4, `flood` 3, `credit` 3, `program` 3, `income` 3, others ≤2.
**Every `id.*` tag (13/13) is produced** — the identity family (the live rules' home) is fully wired. The
machine census is reproducible from the guard's `_vocabulary()`/`_produced()`/`_live_hard_reads()` helpers.

**No FOURTH live-rule (hard) orphan exists** — after LP-366-A/369/371, zero live rules hard-read an
unproduced tag. But the complete scan surfaced three reportable items below.

## THE FOURTH ORPHANS FOUND (reported, NOT fixed — out of scope)

- **`housing.taxes_monthly`** — a *second* DTI-calc orphan alongside `housing.insurance_monthly`. The DTI
  calc requires BOTH; LP-367 named only insurance. **Same shape, same fix ticket (LP-367 must wire both).**
  Handled as a loud exemption here.
- **`property.address_normalized_match`** — a **live SOFT** orphan: OC-2 lists it in `reasoned_over`, nothing
  produces it, so OC-2's AI never sees that signal. It is **not** gated (no couldnt_check) — this is exactly
  the address-consistency dimension ADR-287 (LP-371) recorded as a **reported follow-up**. Not fatal.
- **`txn.source_strength`** — read by LIVE AS-1 and produced by Stage B, but **absent from the vocabulary**
  (opposite-direction drift). Invisible to this guard (it scans the vocabulary). Reported for a future
  vocabulary reconciliation.

## HOW `housing.insurance_monthly` IS HANDLED (LP-367 is still open)

The guard **WOULD fail the build on it today** — that is correct (it IS a genuine live orphan: the DTI calc
gates on it, on every file). It is handled by a **LOUD exemption** in `_KNOWN_LIVE_ORPHANS` naming LP-367 as
the fix ticket — NOT a silent allow-list — with `test_exemptions_are_still_genuine_live_orphans` asserting it
is STILL unproduced AND still live-consumed, so the exemption cannot rot into hiding a resolved tag.
`test_guard_catches_the_dti_calc_orphans_when_not_exempted` proves the guard fires on it (and taxes) without
the exemption.

## WHAT WAS BUILT

`backend/tests/verification/tag_materialization/test_vocabulary_orphans.py` — a test (D3), mirroring LP-369:
- `_produced()` = declarations ∪ the hardcoded transaction path (`_PRODUCED_OUTSIDE_DECLARATIONS`) ∪ live
  judgment `output_tag`s.
- `_hard_reads(spec)` = the gated reads (load-bearing / operand incl. `product` / gather / gather_filter /
  applicability / when-tag); **excludes `reasoned_over` (soft) and `output_tag` (produced)**.
- `_fatal_orphans(...)` — a pure function (real vocab OR a synthetic one) returning unproduced tags a live
  consumer hard-reads, minus exemptions.
- **THE GUARD** `test_no_live_consumer_reads_an_unproduced_vocabulary_tag` — asserts `_fatal_orphans` empty,
  with an actionable message naming the tag, its live consumers, and the fix.

**The guard's message** (quoted — it must tell a reader what to do):
> the vocabulary promises a tag nobody produces, and a LIVE consumer reads it (LP-373 bug class — the
> rule/calc couldnt_checks silently on every file):
>   `<tag>: <why>; live consumers=<rules or 'DTI calc'>` — declared in the vocabulary with a producer but NO
>   declaration in tag_production.yaml and nothing in app/ writes it. FIX: declare its producer
>   (tag_production.yaml) or wire it, OR — if intentional — add it to _KNOWN_LIVE_ORPHANS with a fix ticket.

**No app/ change** — the guard is pure test-layer introspection (no engine change; `ACTIVE_RULE_IDS`, specs,
and vocabulary all unchanged).

## TESTS

- `test_no_live_consumer_reads_an_unproduced_vocabulary_tag` — the guard (passes, with the two DTI orphans
  exempted).
- `test_guard_fires_on_a_synthetic_live_rule_orphan` / `…_dti_calc_orphan` — the guard CAN fail.
- `test_guard_catches_the_dti_calc_orphans_when_not_exempted` — it fires on the real open orphans
  (`housing.insurance_monthly`, `housing.taxes_monthly`) without the exemption.
- `test_three_known_instances_are_now_produced` — the fixed instances pass.
- `test_exemptions_are_still_genuine_live_orphans` — the allow-list cannot rot.
- `test_inert_and_no_rule_orphans_do_not_fail_the_build` — no false positives on legit authoring.
- `test_hardcoded_transaction_producer_tags_are_not_orphans` — `txn.has_identified_source` (Stage B) is
  recognised as produced (D1's trap avoided).

Full suite: **2357 passed, 5 skipped, 1 xfailed**; ruff + mypy green. `ACTIVE_RULE_IDS` unchanged.

## ASSUMPTIONS / DECISIONS

- **`reasoned_over` is SOFT, not fatal** — it is not gated; an absent `reasoned_over` tag degrades the AI's
  context but never couldnt_checks. So the guard fails only on HARD reads. `property.address_normalized_match`
  is reported, not failed.
- **`rule_tags.csv`'s consumer column is STALE** and NOT used for the live determination — the SPEC is
  authoritative (`rule_tags.csv` claims AS-1 reads `txn.source_reference`; AS-1's spec does not). It is used
  only for the informational family census.
- **The DTI calc is the only tag-gated always-computed calc** (`_REQUIRED_DTI_TAGS` is the sole `_REQUIRED_*`
  set in `calculations_section.py`); if a future calc gates on tags, its required set should join the guard.

## THE SEAM MAP

| seam | guard | coverage |
|---|---|---|
| vocabulary → producer (a live-consumed tag nobody produces) | **LP-373 (this)** | live-rule hard reads + DTI-calc required inputs |
| declaration → field (a declared key names a nonexistent field) | LP-369 | document / transaction subjects only |
| producer declared but never RUNS (`_required_ai_groups`) | — | **unguarded** (LP-333/368) |
| a materialized tag is WRONG | LP-379 (calibration) | value correctness |
| a produced+consumed tag not IN the vocabulary | — | **unguarded** (`txn.source_strength`) |
| a live-rule SOFT (`reasoned_over`) orphan | — | reported, not failed |
