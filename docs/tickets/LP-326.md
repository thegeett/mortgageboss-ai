# LP-326 — Generic vocabulary-driven tag materialization

## What it is

The fact-tag vocabulary defines ~140 tags; the pipeline materialized only the 4 `txn.*` Stage-A tags.
This vocabulary≠production gap blocked LP-318 (inert calculator `from_tag`), LP-319 (occupancy tags),
and LP-323-ID-A (`id.*`), and would block every wave. LP-326 makes production a **property of the TAG,
declared in the vocabulary and resolved by GENERIC producers** — adding a family's tags is declarations,
never new producer Python (mirroring LP-324's rules-as-data). Proven on `id.*`.

## Acceptance criteria

- [x] A production declaration per tag: MODE (`parsed`/`derived`/`ai`) + SUBJECT + mode data, in a
  version-controlled vocabulary companion (`tag_production.yaml`).
- [x] The projection loader **fails loud** on a declared tag whose mode data cannot resolve.
- [x] Three generic, registry-resolved producers with **no per-family branches** (asserted by a test).
- [x] `parsed`: maps the declared field; `produced_by="parsed"`, `confidence=None`; absent field → the
  tag is ABSENT; never AI-re-typed.
- [x] `ai`: reuses the LP-313 machinery (bounded batches, index-echo, honest parse, cache, stub seam);
  "unknown" preserved; off-vocab/malformed/truncation/failure → unknown-with-reason, never defaulted;
  confidence + reasoning + `source_facts` (stable content_ids); cache hit on unchanged input.
- [x] **LP-325 gather contract:** a document stating an address carries BOTH `id.address_normalized`
  AND `id.current_address_type` on the SAME subject → ID-4's residence filter works end to end (a
  mailing-only borrower → couldnt_check, not a discrepancy).
- [x] **ID-2 end to end** from parsed SSN hashes: matching → satisfied, differing → fired, a null-hash
  source excluded so <2 → couldnt_check.
- [x] **txn.\* round-trip EQUIVALENCE:** the generic AI producer reproduces the legacy Stage-A tags
  byte-for-byte; the LP-313/314 suites + the frozen LF-6T3N trace pass unchanged.
- [x] A NEW tag materializes from a declaration ONLY (proven in each mode).
- [x] Wired into the orchestrator; ID-2/ID-4 in `ACTIVE_RULE_IDS`. ruff + mypy + full suite green
  (**2022 passed, 1 xfailed**).

## Assumptions & decisions

- **The three modes, as a property of the tag.** `parsed` (map an extraction field — no AI, never
  re-typed), `derived` (a deterministic recipe), `ai` (reuse the LP-313 machinery). Declared per tag;
  the producer dispatches by mode.
- **SUBJECT ≠ entity — the LP-325 keying lever.** The declared subject is where the tag is KEYED in
  `tags.by_subject`, distinct from the logical `entity`. `id.*` cross-source facts are keyed under the
  DOCUMENT subject so a gather-tag and its filter-tag co-locate (the `id_address` group emits address +
  type together) — without this, ID-4's residence filter breaks.
- **Declaration-not-Python (the proof).** A brand-new tag materializes by adding a declaration only —
  shown for a synthetic tag in each mode. Adding the income/credit/property families later is
  declarations + (only if a new subject type) one context-builder entry; zero new producer Python.
- **parsed is NEVER AI-re-typed** (LP-313's discipline — re-typing invites hallucinated values), and
  **absent≠unknown**: a field no source supplied → the tag is ABSENT (not a fabricated "unknown"); a
  non-matchable hash (blank SSN) → absent, so a cross-source gather EXCLUDES it (never a null match).
- **Equivalence risk-control.** The live `txn.*` producers are untouched (frozen trace + LP-313/314
  suites pass unchanged); the generic producer's ability to reproduce `txn.*` is proven by a round-trip
  test. The declaration lives in `tag_production.yaml`, not `fact_tags.csv`, because that CSV is
  generated from the xlsx and a hand-edited column would be overwritten.
- **The 1003 required-field set is a STARTER** (LP-323-ID-A §5) — the authoritative set (incl.
  Declarations + co-borrower) is a Priya/guideline value.
- **Schema gaps found:** none.

## What this unblocks

Every wave's tags: the ID family (`id.*` now live for ID-2/ID-4), income stated-vs-documented, credit
app-vs-report, property address — each a declaration. **LP-318 Caveat A** (the inert calculator
`from_tag` / `calc_confidence`) is now newly WIREABLE — a calculator's input facts can be declared and
materialized as tags — but that wiring is **deferred** (not done here).

## Deferred

- The calculator `from_tag` wiring (LP-318 Caveat A — now possible).
- Migrating the live `txn.*` path onto the generic producer (equivalence already proven).
- The -B ID rules; other families' declarations (their waves).
