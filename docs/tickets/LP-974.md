# LP-974 — The plan screen, laid out as the agreed mockup

- **Ticket:** LP-974 (the owner, 2026-10-08).
- **Source:** the owner: "current design and mock design is different", then "go". The mockup is the
  "Plan screen explained" artifact, board "The plan as a path" (`Path.dc.html`).
- **Status:** built (frontend only).

## Why

LP-966 to LP-968 added the path, drafts and edits onto LP-966's layout, one card per task with its
select, ⓘ and meaning line. The owner had approved a different layout. The LP-967 ticket did say "each
task keeps its Next step select", but nobody told the owner that this meant the screen would not look
like the mockup. This ticket fixes every difference that is a layout choice. The differences that are
features still to come stay out of it.

## What changed

| Area | Before | Now (as the mockup) |
|---|---|---|
| Heading | "Check the plan, then confirm it" and three numbered how-to cards | "Here's how we'll get these N conditions cleared", plus one sentence; the cards are gone |
| Collapsed condition | One line per task, with an action chip, "Waits on…" and "Found:…" | **Route:** what the steps say. **Next:** the first step still ahead |
| Open button | "What you need to do" / "Hide details" | "See the plan" / "Hide the plan" |
| Opened, left | What the lender wants, when, why we suggest this, the lender's words, then Good to know on the right | What the lender wants, when, **How it gets done**, the lender's words, Good to know |
| Opened, right | A card per task (select, ⓘ, meaning, a small-dot path), then a dashed "Then" block | **One numbered timeline** for the condition: its own step, each task's steps, then the ending, with 26px numbered dots coloured by who acts |
| Edits | Under each task card | On each task's first step in the timeline. Each task's name is a badge there when the condition has more than one |
| Third box | "Already in the file" | "Already handled": it counts `willBeReady`, which includes tasks she marked done |
| "I'll do this myself" | as written | "I'll do this step myself" (the mockup's words) |

**"How it gets done"** holds each task's Next step select, its ⓘ and its meaning, plus the condition's
own step and "Why we suggest this". Until LP-970 brings routes, this is the only way to change how a
task gets done, and it is where the routes will go. **"Route:"** comes from the same `actionFor` phrase as
before, so it cannot disagree with the selects.

## Not the mockup yet, on purpose

- Route choices with Suggested and a reason: **LP-970**.
- "Add a step" and "I'll handle it my own way": **LP-969**.
- "Describe what you want to do": **LP-971**.
- **"Remove step"**: LP-968 chose not to build it. Delete is permanent, and Not needed covers the same need
  with a reason.
- **"Changed by you"** beside "Go back to the suggested plan": nothing on the condition says whether she
  changed it (that is only in the event history), so the link shows on its own, as before.
- **"Watch the file's inbox … and tell you when each condition is ready"** in the confirm list: left out.
  Accepting an attachment is hers (`accept_attachment` has one caller, the route), and no notification
  fires when a condition becomes ready. The sentence would not be true.

## Found on the way

**A condition whose only task she dropped was called unread.** `unworked` counted live tasks, so marking
the only task Not needed turned the row into "We couldn't work out what this one needs". The old card
layout showed that message alongside the crossed-out card; the new timeline would have hidden the card.

Fixes:
- `unworked` now counts every task.
- The timeline shows the crossed-out task with its reason and Undo.
- There is no ending: `ready_because` needs a live task.
- The collapsed row says "Nothing left: you marked every task not needed".

## Code

- **`lib/conditions/plan-path.ts`:**
  - `conditionPath(condition, context)` builds the one timeline as `PlanEntry` (step, item, leads). A
    dropped task keeps one entry. There is no ending when nothing is left.
  - `nextOf(entries)` returns the collapsed "Next:", skipping dropped and finished tasks.
- **`components/file/conditions/round-plan-panel.tsx`:**
  - new heading;
  - `routeOf`;
  - `PlanRow` with Route and Next;
  - `HowRow`, the select moved out of `StepCard`;
  - `Timeline`, which replaces `StepCard` and `PathList`;
  - `TaskEdits` gains an Undo for a dropped task;
  - removed: `HowStep`, `TaskLine`, `extraFor`.
