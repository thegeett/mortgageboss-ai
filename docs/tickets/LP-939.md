## Design

**The same reading as the app, without a database.**
- Each PDF sheet is read by `sheet_from_bytes`, the upload path's reader.
- Its rows become in-memory `Condition`s, typed as import types them: from the repo's lender code maps
  (`app/conditions/lender_codes/*.yaml`, chosen by the reader's name, `uwm` or `champions`).
- The script then makes the ONE model call `read_round` makes (`_ai_input` and `_ask_model`: the same
  prompt, model setting and token accounting) and composes every condition with `compose_reading`.
- Nothing is added to a session, and there is no database connection.

**The file summary sent to the model** is `_file_summary`'s shape without a file: no borrower names,
the lender as the reader names it, and the two letter facts the reading uses.

**The model** is the configured one: `ANTHROPIC_MODEL_EXTRACTION`, which the provider maps to
`BEDROCK_MODEL_EXTRACTION` under Bedrock (checked in `app/core/config.py`). The summary records the
setting, and each sheet records the id that answered.

**What the summary holds, and never holds.**
- Per sheet ("round"): the reader, the condition count, input and output tokens, the cost estimate,
  seconds (the model call's wall time), the model id, whether the whole call fell back, and an error's
  class name.
- Per condition: code, library type, item count, performers, confidence, a per-condition fallback flag
  (the model gave nothing for it), and the reading's source and status.
- Sheets are named "sheet 1", "sheet 2" in file-name order, because a file name can carry a borrower's
  name.
- No condition text, names, amounts, account digits or file names.

**Guards.**
- It refuses a sheets folder or an output path inside the repository.
- It asks before the model calls unless `--yes` is given.
- `--no-model` checks the pipeline for free.
- The summary is rewritten after each sheet, so a stop loses at most one.

## Checked (not run with the model; the owner runs it)

- **`--no-model` on a fictional sheet** (the UWM round 1 test fixture rendered to a PDF in the scratchpad,
  outside the repo, under a file name containing "Borrower"), plus one unreadable file:
  - 11 conditions were read and typed from the code map;
  - the unreadable sheet reported only `SheetUnreadable`.
  - Every string value in the summary was listed: lender codes, type ids, performer names, the reader
    name, sheet labels, source and status values, and the error class. "Borrower" appears nowhere.
- **An `--out` inside the repo** is refused, exit code 1.
- ruff, format and `mypy --strict` on the script are clean.

**Not verified here:** a real model call (the owner runs it), and the per-sheet `seconds` against a real
provider. The dry run's seconds are 0 because no call is made.
