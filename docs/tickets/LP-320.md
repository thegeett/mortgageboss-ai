# LP-320 — Observation channel + graduation

**Status:** Complete. **Branch:** `phase3_new_AI_arch_finding_stage2`.
**ADR:** [ADR-260](../../decisions.md). **Depends on:** LP-313/314 (tag production), LP-316
(findings), §3D + §7.

## What it is

Makes the system safe for the **unbounded real world**: when the AI meets a document/fact NOT in the
tag vocabulary (gift letter, divorce decree, trust agreement…), it records a **structured
observation** — never inventing a formal tag, never dropping the info — which **fails closed** to
human review if it relates to a finding, and feeds a **graduation log** that ranks recurring
unknowns for humans to formalize into tags+rules. The critical boundary: observations **INFORM**,
they never **RESOLVE** (only governed tags + rules resolve findings) — enforced structurally.

## Acceptance criteria

- [x] Unmapped document → a structured `Observation` (envelope + provenance) is recorded — NOT a
  fabricated formal tag, NOT dropped.
- [x] The INFORM-not-RESOLVE boundary: an observation relating to a finding does NOT change/resolve
  that finding's verdict (structural — the rule engine never reads observations).
- [x] Fail-closed: a `needs_tag` observation (or one attached to a finding) surfaces via
  `pending_review_observations` — the processor sees it even though no formal tag/rule handles it.
- [x] A novel/unclassified document ALWAYS yields ≥1 observation — even on AI failure (a fallback
  flagged `needs_tag`); never silently dropped.
- [x] Graduation log: the same observation type recurring across runs increments its tally (by a
  normalized signature); `top_graduation_candidates` ranks by frequency.
- [x] The gift-letter trace: a gift letter → an observation relating to the AS-1 finding that fails
  closed to human review and does NOT auto-resolve AS-1.
- [x] Migration up/down (verified on dev; converges with `create_all` — `alembic check` shows no
  drift on the new tables); new models registered in `models/__init__.py`. ruff + mypy(`app/`)
  clean; full suite **1953 passed, 1 xfailed**.

## Assumptions & decisions

- **INFORM, never RESOLVE — enforced structurally.** Observations live in their own table + service;
  the rule engine (AS-1/OC-2) reads the snapshot tags, never observations, so an observation
  physically cannot flip a verdict. This is the line that keeps extensibility from becoming a
  false-green vector: an ungoverned AI opinion can *attach* to a red flag but can never *clear* it.
- **Never invent a formal tag.** The AI records a free-labelled observation, not a governed
  vocabulary tag — formalization is a human/Priya decision (the graduation workflow), not an AI
  runtime action.
- **Never drop the info.** A novel document always yields an observation — including a `needs_tag`
  fallback when the AI call fails/truncates/malforms — so the file never looks clean merely because
  the system had no slot for what it saw.
- **Fail-closed to human review** = a query surface (`pending_review_observations`), and the finding
  is "marked" by *having* an attached needs_tag observation — no schema change to findings.
- **PII-safe, system-wide graduation.** The candidate row holds type + signature + count + timestamps
  ONLY (never raw values), so ranking recurring unknowns across all files/tenants leaks nothing;
  frequency = "what the vocabulary is missing most."
- **File-owned scoping** (like findings — `loan_file_id`, no `company_id`). `relates_to_finding_id`
  is SET NULL on finding delete: the observation is discovery data that outlives the finding.

## The gift-letter trace

A gift letter is not yet a formal tag. The AI records an observation
(`type=gift_letter_asserted`, value "document asserts a $20,000 gift related to deposit …",
`relates_to_finding_id`=the AS-1 finding, `needs_tag=true`). Result: AS-1 stays **open** (NOT
resolved — an observation can't clear it), the observation surfaces in `pending_review_observations`
(the processor sees the gift context), and the graduation tally for `gift_letter_asserted` climbs.
When a governed `gift.*` tag+rule is later formalized, THAT resolves it — never the observation.

## Deferred

- The human **formalization workflow** (graduation candidate → a committed tag+rule — a governed
  UI task). The concrete wiring of the channel into a **document classifier** (no producer of
  document-level tags exists yet; this ships the channel + AI step + `observe_unmapped` seam). No
  observation ever auto-resolves a finding; the AI never invents a governed tag.
