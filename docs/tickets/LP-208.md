# LP-208 — Snapshot builder / orchestrator

## Summary

Stitches the three Stage-1 assemblers (LP-205 MISMO, LP-206 documents, LP-207
calculations) into one frozen LP-204 `Snapshot`: calls them, wraps their outputs
into the three sections, stamps metadata (`loan_file_id`, received `run_id`,
tz-aware `created_at`, `snapshot_version`), and returns the frozen snapshot.
Stateless — no persistence (LP-209), no run-creation, no side effects.

Architectural decisions recorded in **ADR-245** (`decisions.md`).

## Phase 0 findings (incl. contradictions flagged)

- **Version constant is `SNAPSHOT_VERSION`** — the ticket's `SNAPSHOT_SCHEMA_VERSION`
  doesn't exist; used the real name.
- **Assemblers:** `load_mismo_section(db, loan_file) → dict`,
  `build_documents_section(db, loan_file) → list[DocumentEntry]`,
  `build_calculations_section(db, loan_file) → CalculationsSection`. So the builder
  wraps mismo (→`MismoSection.present`) and documents (→`DocumentsSection.present`);
  calculations is already a section.
- **Sections had `absent` + `present()`/`missing()` but no `reason`** → added
  `reason` + `failed(reason)` (the minimal amendment the ticket anticipated).
- **A `Verification` run model exists**, but `run_id` is received, not minted here.
- **Real-file smoke** needs this branch's schema (documents/calculations read
  extractions); the dev DB lacks LP-201's columns — but the builder is resilient, so
  it still produces a snapshot there (see below).

## What was built

- `app/verification/snapshot/model.py` — each section: `reason: str | None` +
  `failed(reason)` factory + validator (present ⇒ no reason).
- `app/verification/snapshot/builder.py` — `build_snapshot(db, *, loan_file_id,
  run_id)`; `_load_loan_file` (+ `LoanFileNotFound`); `_mismo` / `_documents` /
  `_calculations` (each `try/except` → present or `failed(reason)`); `_reason`
  (PII-safe, exception class only).
- Exports in `__init__.py`. Real-file smoke: `app/scripts/snapshot_smoke.py`.
- Tests: `tests/verification/snapshot/test_builder.py` (7 DB-backed) + a model test
  for the `failed`/`reason` invariant.

**Real-file result (LF-6T3N on the dev DB):** the resilient policy in action —
`MISMO present (122 facts)`, `documents absent (reason="documents assembler raised
ProgrammingError")`, `calculations absent (reason="calculations assembler raised
DBAPIError")` — an honest partial snapshot (the two failures are the dev DB's
missing LP-201 columns), not a crash. The complete all-three-present case is the
DB-backed happy-path test.

## Assumptions & decisions

- **Partial-failure policy (ADR-245):** present-populated / present-empty /
  absent-with-reason; never faked, never a lost snapshot.
- **PII-safe reason:** exception class name only, never `str(exc)`; logged as
  metadata.
- **run_id received, not minted;** `created_at` tz-aware; stateless, no side effects.
- **Broad-but-bounded resilience:** `except Exception` per section (Base exceptions
  propagate); a missing loan file is a hard `LoanFileNotFound` (nothing to snapshot).

## Deferred / follow-up

- **`belongs_to=None`** still conflates "matched then removed" vs "never resolved"
  (an open LP-206 note; the builder doesn't resolve it).
- **Real-file smoke complete run** needs this branch's migrations on the dev DB;
  DB-backed tests cover the all-present path.
- **Out of scope:** persistence (LP-209), triggering / run-creation, the viewer,
  assembler logic (called, not reimplemented), reconciliation, caching.
