# LP-123R — AS-8 bank-statement continuity (NEW rule, self-defined spec, provisional)

**Type:** Story · **Epic:** Phase 3.5 / Epic B · **Depends:** LP-122R (the per-rule pattern), the corrected
live-rule audit · **Status:** complete · **Date:** 2026-07-08

## What this ticket is

AS-8 checks **bank-statement continuity** — that a sequence of statements is unbroken (each statement's
ending balance carries into the next's beginning balance, no missing period). It is **rule #2** built
through the LP-122R per-rule pattern, and the **first genuinely new rule** (AS-5 established the pattern
as a live rule; AS-8 has no live counterpart).

**AS-8 is NOT a live rule** (confirmed by `docs/audits/live-rule-inventory-corrected.md` — the original
LP-123R premise that it was live was wrong). So there is **no live verdict to reproduce**: this implements
a spec **we define here**. Consequently it seeds **`validated=false` (provisional)** and its two domain
choices are flagged for Priya.

## The spec (as implemented)

**Group by ACCOUNT first — the core constraint.** Continuity is only meaningful *within* one account;
the evaluator NEVER compares one account's/borrower's statement against another's (that would be a false
finding). Grouping key priority:

1. `account_number_masked`, else
2. `account_holder_name` + `bank_name`, else
3. **ungroupable** → couldn't-check ("no account identifier — cannot group"). Never a blind comparison.

**Per account** (statements ordered by period):

- 2+ statements, every ending balance `==` next beginning balance (EXACT, no tolerance in v1) AND no
  missing-period gap → **SATISFIED**.
- a balance break OR a period gap (a statement appears missing) → **FINDING** (names the account, the two
  statements, the amounts/dates).
- exactly one statement → **COULDN'T-CHECK** ("need consecutive statements").
- 2+ statements but balances/periods not extracted for 2+ → **COULDN'T-CHECK**.

**Roll up honestly:** ANY account with a break/gap → overall **FINDING**; else ANY account couldn't-check
→ overall **COULDN'T-CHECK** (never report satisfied when something wasn't verified); ALL accounts
continuous → **SATISFIED**. Findings/couldn't-checks carry the other accounts' context too, so a partial
result (a verified account beside one that needs more) is never lost.

**Reasoning on every outcome:** doesn't-apply (no bank statements); couldn't-check (per-account: "one
statement" / "ungroupable" / "balances not extracted"); finding (the account + two statements + amounts);
satisfied (per account: the statements + that they chain) — all carried in the `RuleOutcome` provenance /
reasons, tagged `evaluator`-source (round-3 FIX 5).

### The Bank A / Bank B case (the one specifically raised)

- Two accounts, one statement each → **BOTH couldn't-check → overall couldn't-check**; A's ending is
  never compared to B's beginning. (`test_two_single_statement_accounts_is_couldnt_check_not_compared`.)
- Bank A continuous (Jan/Feb) + Bank B single → A satisfied, B couldn't-check → **overall couldn't-check,
  both surfaced** (A's verified chain is not lost).
  (`test_continuous_account_beside_single_statement_account_rolls_up_couldnt_check`.)

## The applicability (wire format — validates under `extra="forbid"`)

```json
{
  "scope": {},
  "triggers": { "all": [ { "kind": "entity_exists", "collection": "documents", "field": "document_type", "op": "eq", "value": "bank_statement" } ] },
  "required_inputs": [ { "kind": "document", "document_type": "bank_statement" } ]
}
```

- `"bank_statement"` is the exact classifier string (confirmed against `app/documents/catalog.py`).
- The schema can't express "2+ statements" or account grouping — **all** the count/grouping/continuity
  logic is evaluator-side. Applicability only gates "a bank statement exists".
- **Empty-documents tradeoff (accepted, LP-119 FIX 8):** a file with a non-bank document but no bank
  statement → **doesn't-apply**; a file with **no documents at all** → couldn't-check (the empty
  `documents` collection can't distinguish "reviewed, none" from "not loaded"). Same tradeoff as AS-5's
  no-asset case.

## Grouping key used (post-review — see Review fixes)

A COMPLETE, unique account key (review FIX 2+3): `(bank, account_type, masked#)` when the masked number
is present, else `(bank, account_type, holder)` — both REQUIRE `bank` + `account_type`, so a shared
last-4 across banks and checking-vs-savings never merge. Missing those disambiguators →
**ungroupable → couldn't-check** (never a blind comparison). The key is an OPAQUE hash token (ADR-149);
the outcome labels accounts ordinally ("account 1"). All the fields are materialized as TYPED facts in
`snapshot.bank_statements` (review FIX 8).

## Priya-flagged decisions (why `validated=false`)

1. **Balance tolerance** — v1 uses EXACT match (no tolerance). Real statements can have rounding/fee
   artifacts; Priya should confirm whether a small tolerance is warranted.
2. **One-statement-per-account → couldn't-check** (not satisfied) — the false-green guard says we can't
   claim "verified" from a single statement; confirm this is the desired behavior.
3. **Period-gap heuristic** — `_MAX_ADJACENCY_GAP_DAYS = 20` assumes a monthly cadence (a missing month
   shows a ~29-day gap; normal adjacency is a few days). A quarterly/irregular cadence would need a
   different value. The balance-break check is the primary signal; the gap check is secondary.

## Assumptions and decisions

- **Kept `rule_id = pb.as-8`** (not a new `xsrc.*` id): AS-8 has no `CROSS_SOURCE_RULES` entry, so the
  `pb.*` namespace is the honest id for a playbook-native rule — and it's exactly the "LP-120 fills the
  placeholder when built" path. Avoids a PK rename.
- **`evaluator` column left null** (as for AS-5) — dispatch is by `rule_id` via the code registry, not the
  DB column. (See pattern feedback.)
- **Balance-break is the deterministic core; period-gap is secondary** — a missing statement usually
  breaks the balance chain anyway; the gap check only adds value when balances coincidentally chain across
  a missing month.

## Pattern feedback (rule #2 — the first real test of the LP-122R pattern)

The pattern **held** for a substantially more complex rule (sequence + cross-element comparison +
grouping, vs AS-5's single boolean). What the build surfaced, for the pattern to absorb:

1. **"Built playbook rule" was a missing step.** AS-5 was a live `xsrc.*` rule already in the seed; a
   *playbook-only* rule being built for the first time had no seed mechanism. Added `_BUILT_PLAYBOOK` +
   a migration that flips the placeholder. Future playbook rules (most of the ~120) follow this, so it's
   now a first-class part of the pattern, not a one-off.
2. **The `evaluator` column is unused** (dispatch is registry-by-`rule_id`). Fine, but the pattern should
   say so explicitly so authors don't think they must populate it (or a later ticket should populate it
   for traceability).
3. **No-live-anchor certification works** — certifying against an explicit written spec (+ both-direction
   tests) substitutes cleanly for live parity, as long as `validated=false` and the domain choices are
   flagged. This is the template for every rule that isn't one of the 5 live-firing anchors.
4. **The couldn't-check escape hatch (round-3 FIX 8) was essential** — a continuity rule has many honest
   "can't tell" states (one statement, ungroupable, unextracted). Without it the rule would have had to
   lie (satisfied) or over-report (finding). Confirms that fix's value.

## Review fixes

A read-only review found the round-3 engine + migrations solid but the AS-8 evaluator flawed: four
false-verdict bugs on ROUTINE inputs (all in the grouping/continuity core, all untested), an engine issue
affecting every document-triggered rule, a latent required-input regression, and pattern-setting items
(AS-8 is the FIRST document-field evaluator — ~30 more inherit its patterns). Two anchors: **(A)** honor
never-compare-across-accounts with a COMPLETE grouping key; **(B)** set the document-field evaluator
pattern right, now.

**False-verdict fixes (routine inputs):**

- **FIX 1 — dedup by (account, period).** Statements were sorted + chained with no dedup, so a re-uploaded
  statement chained against itself → false "continuity broken". Now duplicates (same account+period+
  balances) collapse; same period + DIFFERENT balances → a conflict couldn't-check. (Tests:
  `test_fix1_duplicate_upload_is_not_a_false_finding`, `…_same_period_different_balances_is_conflict…`.)
- **FIX 2+3 — a COMPLETE, unique grouping key.** The old key was last-4-only (Chase ****6789 merged with
  Wells ****6789) and holder+bank (checking + savings at one bank merged). Now `bank` + `account_type`
  are always required; can't-disambiguate → couldn't-check, never a blind chain. (Tests:
  `test_fix2_same_last4_different_banks…`, `test_fix3_checking_and_savings_same_bank…`,
  `test_fix2_ungroupable_without_bank_or_type…`.)
- **FIX 4 — period_end required for the gap check.** A statement missing `period_end` used to join the
  balance chain but skip its gap check → a missing month could pass as SATISFIED. Now `period_end` is
  required to be usable → a hole surfaces as couldn't-check, never a false green.
  (`test_fix4_missing_period_end_not_silently_satisfied`.)

**Engine + pattern-setting (fleet-wide):**

- **FIX 5 — empty `documents` → DOESN'T-APPLY, not couldn't-check.** The FIX-8 "empty collection →
  UNKNOWN" rule was for plain-list facts that can't tell "zero rows" from "not loaded"; `documents` IS
  reliably loaded, so an empty one is a determinate "none". A `_RELIABLY_LOADED_COLLECTIONS` set now
  distinguishes them — every document-triggered rule on a zero-document file correctly doesn't-apply. The
  plain-list (asset/liability) couldn't-check behavior is unchanged. (`test_fix5_zero_documents_doesnt_apply`.)
- **FIX 8 — TYPED materialized statement facts (the document-field pattern).** `snapshot.bank_statements`
  now carries `BankStatementFacts` (period/balances/account fields), coerced ONCE in the builder via the
  SHARED `coerce_decimal`/`coerce_date` (mirroring `transactions[]`). The evaluator READS typed frozen
  values — no eval-time coercion, no 7th coercion copy. This is the standard the ~30 future document-field
  rules follow. (Snapshot schema bumped to v2.)
- **FIX 6 — single-level and nested required-inputs made consistent + finally tested.** Both use the same
  relevant-element rule (a scalar leaf makes every element relevant; an empty sub-collection is skipped).
  The comment now describes the behavior, and a multi-element test pins the line that had drifted four
  times. (`test_r3fix6_single_level_multi_element_relevant_semantics`.)
- **FIX 10 — ADR-149-safe grouping.** The grouping key is now an opaque hash token; the outcome labels
  accounts ordinally ("account 1"), so no real name / masked account rides into a loggable outcome (LP-162
  will log outcomes). Grouping stays correct. (`test_fix10_outcome_carries_no_pii`.)

**Cleanups:**

- **FIX 9 — Verdict-enum dispatch** in the evaluator (was stringly-typed `tuple[str, …]` + a dict literal),
  so mypy checks exhaustiveness.
- **FIX 7 — shared refi-scope invariant.** Extracted `enforce_refi_scope_invariant` /
  `finalize_applicability` into `app/verification/applicability/authoring.py`, imported by the seed
  generator (and available to any applicability-authoring migration) — the "a refi scope can't exist
  without loan_purpose" guarantee is now callable wherever applicability is authored, not seed-only.

AS-8 stays `validated=false` (provisional) — these fixes make its VERDICTS correct, not authoritative.

## Review fixes — round 2 (grouping/gap rewrite over-corrected)

The round-1 grouping/dedup/gap rewrite introduced four NEW correctness bugs in that same core (it
over-corrected — a COMPLETE key became a RIGID key — and re-implemented instead of reusing primitives).
Meta-lesson: **a complete key is not a rigid key; adding a disambiguator is not requiring it; reuse
existing primitives.**

- **FIX 1 — `account_type` is a FALLBACK disambiguator, not a hard requirement.** Round-1 returned
  ungroupable (→ couldn't-check) whenever `account_type` was blank, so normal chaining statements (blank
  best-effort AI type, but bank + masked# present) regressed to couldn't-check. Now `bank + masked#` is a
  sufficient identity; `account_type` only SPLITS when present and differing. (Tests:
  `test_r5fix1_blank_account_type_still_groups`, `…_differing_account_type_splits`.)
- **FIX 2 — overlapping/backwards periods are a PROBLEM, never silent SATISFIED.** Ordering by
  `period_start` only + a gap check that goes negative on overlap meant a nested quarterly+monthly pair
  read as "chains continuously" (false-green). Now `nxt.period_start < prev.period_end` → FINDING.
  (`test_r5fix2_overlapping_periods_not_satisfied`.)
- **FIX 3 — dedup keys on `(period_start, period_end)`, not `period_start` alone.** A distinct statement
  sharing a start (OCR slip) was silently collapsed, dropping its `period_end`. Now both are retained.
  (`test_r5fix3_*`.)
- **FIX 4 — reuse the shared whitespace-collapsing normalizer.** `_norm` did `strip().lower()` but not
  whitespace-collapse, so "Wells Fargo" vs "Wells  Fargo" split one account. Now imports the shared
  `normalize_text` (promoted from `canonicalize`), no third copy. (`test_r5fix4_*`.)

Cross-cutting closers landed with this round (shared with LP-124R): the snapshot schema bump is now
load-safe (`bank_statements` defaults to `[]` — a v1 snapshot upgrades gracefully, FIX 8); the evaluator
declares its `confidence_mode` as the seed's single source of truth (FIX 7); the ADR citation is
corrected to **ADR-150** (masking discipline), not ADR-149 (extractor dispatch) (FIX 10); and
`authoring.py`'s docstring is corrected to state the invariant's real enforcement scope (seed generator;
migrations must call the helper) (FIX 5).
