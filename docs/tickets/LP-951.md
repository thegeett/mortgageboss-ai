# LP-951 — Wrong-file warning

- **Ticket:** LP-951 · Phase 4.5 Stage 3 follow-ups, batch 4 (the staging trial)
- **Source:** [`phase4.5-staging-trial-2026-09-30.md`](../phases/phase4.5-staging-trial-2026-09-30.md)
  item 11, raised to High by the owner: "At import, if the sheet's borrower name or lender loan number
  differs from the file's, show a warning she can override. Record the override as an event."

## Design

**What is compared** (`app/services/condition_wrong_file.py`, code only). The sheet's surname and lender
loan number come from its title line (`condition_drafts.letter_title`: `LOAN APPROVAL CONDITIONS -
RIVERA - 1226500417`).
- **Borrower:** the surname against the file's active borrowers' last names. Any borrower matching is a
  match (a co-borrower counts); names are compared word by word, case-folded, so "Rivera-Lopez" matches
  RIVERA.
- **Loan number:** the file stores no lender loan number of its own. Measured: no column on `loan_files`,
  nothing from MISMO import, extraction or verification. So the number is compared against the numbers
  on the file's EARLIER imported sheets. *(Review: the measurement was too wide. There is no column, but
  the MISMO export's `LenderLoan` identifier lands in `mismo_imports.catch_all`, and extraction reads a
  `loan_number` from the closing disclosure and a lender-dashboard screenshot. None of them is a usable
  "file's number" today. See Review, finding 7.)* A file's first sheet has nothing to compare against; only the
  borrower is checked then.
- **A missing fact is never a mismatch.** No title line, no borrowers, no earlier sheet: nothing is flagged.

**Warn, then refuse until confirmed.**
- `GET /condition-rounds/{id}/wrong-file` → `WrongFilePublic | null`, for a DRAFT round only. It carries
  the names and numbers so she can judge (a company-scoped route, like the rest of the round).
- `POST /condition-rounds/{id}/import` takes an optional `ImportRequest {confirm_wrong_file}`. A mismatched
  draft without the confirmation is refused, 409 with `{message, code: "wrong_file"}` (the `_refused` shape,
  so a client can tell it from any other refusal). With it, the import runs and a round event
  `round_wrong_file_confirmed` is written, detail `{borrower_differs, loan_number_differs}`: which facts
  differed, never the names or numbers.
- A matching sheet imports exactly as before, with no event.

**Data.** Migration `2f6c8a1d9e47`: event kind `round_wrong_file_confirmed` (34 kinds). The downgrade
refuses while one exists.

**Frontend.** `RoundReview` reads `useWrongFile(round.id)`. When it is set, a warning above the rows says
what differs ("the sheet names GURUNG; this file's borrower is Patel"), and Import stays disabled until she
ticks "I checked: this sheet is this file's". `useImportRound` takes either the round id (as before) or
`{roundId, confirmWrongFile}`. History line: "Imported after a warning that the sheet may be another
file's".

**Reuses.** `letter_title`, the `_refused` 409 shape, the review screen's existing checkbox gate.

## Review

Reviewer: a fresh subagent, not the peer session. The peer session was not sanctioned by its user, so the
builder's reasoning was not inherited. I started from the diff, the trial item and the owner's sentence,
measured each claim, and mutated every guard on the path.

### Findings (8, all fixed but one, which is recorded)

1. **Two other doors turned a sheet into conditions without the check.** `enrich_round_with_pdf` serves
   the attach-PDF route and the inbound "merge into round" route. On an IMPORTED round it creates
   `Condition` rows directly (`_merge_conditions`). On a draft it adds rows, and the import check never
   sees that PDF's title, because the enrich deliberately does not store the PDF's text (`raw_text` stays
   the pasted page). So a GURUNG PDF attached to a pasted Patel round went straight onto the file with no
   warning, which is the staging trial's exact accident through a side door. **Fix:** the enrich runs the
   same comparison on the PDF's text. It counts the round's own pasted title as the file's number, and it
   runs before anything is stored. It raises `WrongFileRefused` unless `confirm_wrong_file`. Both routes
   answer 409 `{message, code: "wrong_file"}`. A confirmed override writes the same
   `round_wrong_file_confirmed` event. The attach route takes `confirm_wrong_file` as a form field, the
   inbound route takes it in `UseAsConditionSheetRequest`, and `merge_attachment_into_round` passes it
   through. Frontend: `lib/api/wrong-file.ts` holds `isWrongFileRefusal` and `withWrongFileConfirmation`.
   On that 409, `useAttachPdf` and `useForwardAttachmentAsSheet` (merge only) show the server's sentence
   in a confirm and resend only if she says yes. Cancelling rethrows, so the existing error toast says
   why. Tests: the attach door refused and then confirmed, for a draft round and an imported round. The
   sources and event are unchanged by the refusal. Positive control: this file's PDF attaches with no
   confirmation and no event. The forward door is refused and then confirmed. A pasted round's own title
   number is the file's number. On the frontend: the code is told apart from other 409s, yes resends with
   the flag, cancel sends nothing more, and both hooks put the flag where their route reads it.
   Other doors I checked: paste and upload both open a DRAFT, which goes through the import route.
   Reparse rewrites `raw_text` from the stored sheet before import. A manual round has no sheet text.
   No other code path sets `IMPORTED` (`condition_import.py:660` is the only writer).
2. **Accents and apostrophes gave false warnings.** Measured with the shipped `_words`: MUNOZ against
   Muñoz, OBRIEN against O'Brien and DELACRUZ against De La Cruz all came out "differs". Lenders print ASCII
   capitals. **Fix:** `_name_keys` strips accents (NFKD) and apostrophes (`'`, `’`, a backtick), then
   compares words plus the words joined. Tests are parametrized, including the compound cases
   (Muñoz-Garcia, O'Brien-Kelly), because the simple ones pass on the joined key alone. That is how
   mutations M1 and M2 first survived.
3. **A shared particle hid a real mismatch.** "DE LA CRUZ" against "De Leon" matched on "de". **Fix:**
   particles and suffixes (`de`, `la`, `van`, `jr`…) are not keys on their own. A name made only of one,
   such as Vietnamese "Le", still matches whole through the joined key. Tests: DE LA CRUZ/De Leon is
   flagged, LE/Le is not, SMITH JR/Smith is not, and ANN/Annabel is flagged (whole words only, never a
   substring).
4. **A hyphenated borrower switched the whole check off.** `letter_title`'s surname was `[^-\n]+?`, so
   `LOAN APPROVAL CONDITIONS - RIVERA-LOPEZ - 1226500417` did not match at all. Both facts came back
   None, and nothing was compared, the loan number included. **Fix:** the surname is `[^\n]+?`, ending at
   the last dash before the number, and the number ends at a word boundary. The drafts' subject lines
   gain the surname too. Test: the hyphenated title reads whole, and it is flagged on a Patel file and
   not on a Lopez file. The draft, reader and round-creation tests still pass (74).
5. **Champions sheets were never compared.** Champions prints `Date: … Loan #: 4400123456` on every page
   and has no UWM title line, so `letter_title` read nothing. **Fix:** `sheet_facts` falls back to
   Champions' `Loan #:`, with digits only, so dashes and spaces compare equal. The number is read the
   same way from the file's earlier sheets. Champions prints no borrower name, so only the number is
   compared for it. Test: a Champions number against an earlier UWM sheet is flagged, and the same
   number with dashes is not.
6. **The same surname twice was named twice.** The warning would have said "this file's borrowers are
   Patel, Patel". **Fix:** the file's surnames are deduplicated without regard to case, in order. Test
   added.
7. **The ticket's "measured: nothing from MISMO import, extraction" was wider than the evidence.**
   Re-measured: `MISMO16940192.xml` carries `<LoanIdentifier>16940192</LoanIdentifier>` with type
   `LenderLoan`, which falls to `catch_all`. The extraction prompts for `closing_disclosure` (`Loan ID #`)
   and `lender_dashboard_screenshot` read a `loan_number`. **Not wired, on purpose.** The one real MISMO
   number is 8 digits where the UWM sheets print 10, so comparing them would warn on every file. Whether
   a `LenderLoan` identifier is ever the wholesale lender's number is a question for the domain expert,
   so it is flagged rather than guessed. A CD normally arrives at closing, after the conditions. The
   claim is corrected in the Design section above and in the service docstring.
8. **The review screen could show a stale answer, and the 409 had no reader.** `useWrongFile` used the
   app's 60-second `staleTime` with `refetchOnWindowFocus: false`. Suppose she fixed a borrower's name
   on another tab, or a borrower was changed so the sheet no longer matched. The screen kept its cached
   answer for up to a minute. With a cached `null`, Import stayed enabled, and the server's 409 arrived
   as a toast with no checkbox to answer it. The builder's comment says the code lets "a client … offer
   the confirmation", but no client read the code. **Fix:** `staleTime: 0` on `useWrongFile`, and
   `useImportRound`'s `onError` refetches that round's wrong-file answer, so the warning appears.
   Tests: remounting refetches, and a failed import invalidates `wrongFileQueryKey(roundId)`.

Also changed: the history line was "Imported after a warning…". It is now "Kept as this file's sheet
after a warning that it may be another file's", because attaching or forwarding writes the same event.

### Checked and not findings

- **The confirmation can be replayed.** A client that always sends `confirm_wrong_file: true` skips the
  gate. The event is still written whenever a mismatch exists, so the override is never unrecorded. The
  gate's job is to make going ahead a recorded choice, and it does.
- **Event detail.** It holds two booleans and nothing else, and `ConditionEventPublic` projects nothing
  for the new kind. The event and CHECK parity tests pass (`test_activity_type_migrations.py` is in the
  targeted run).
- **Discarded rounds.** Only IMPORTED rounds count. Test added, and mutation M9 kills it.
- **Warning copy.** The "earlier sheets show" clause renders only when `loan_number_differs`, which
  requires an earlier number, so it never claims sheets that do not exist.
- **The check runs before the lock.** Another round imported in that gap could change the file's numbers.
  The gap is as narrow as the existing import lock's own note describes, and a stale answer warns at most
  once too often or too seldom. Not fixed.
- **Not read:** a generic sheet, or pasted text without UWM's title or Champions' `Loan #:`. Stated in the
  service docstring. The UI says nothing for those, which is true, because there is nothing to compare.
- **Out of blast radius, for the builder:** the attach success toast says "No new conditions, no second
  round" even when `added > 0`. That sentence predates LP-951.
