## What this ticket is

The companion to LP-115. LP-115 mapped the live **rule** inventory and found 13 fact-starved
cross-source rules. This audit maps the **extraction** side — what structured data the system
produces today — so we know which of those rules are blocked because a document has **no
extraction schema** vs. blocked because an extracted field simply isn't wired into the
fact-builder. It gates **Epic D** (blocker-schema build vs. extend) and **Epic C** (seed-rule
extractor-gap vs. fact-builder-gap). Read-only: read the registry, the per-type Pydantic
schemas, the extractor and pipeline code; gather evidence; write it down. No code changed.

## Assumptions and decisions

- **"Has a schema" = has a Mode-1 typed-core extractor** registered in `EXTRACTORS` that produces
  structured fields deterministic rules can read. A type that only classifies + summarizes
  (Tier 2) has **no schema** — this is the precise sense in which credit_report is "blocked."
- **Full vs. partial vs. none:** *none* = no extractor (Tier 2/3); *partial* = extractor exists
  but omits fields a live/planned rule needs (homeowners_insurance missing mortgagee/deductible);
  *full* = the target field-set is present. Because **no committed spec/playbook xlsx exists**
  (verified: `find -iname '*playbook*' -o -iname '*blocker*'` empty), "missing fields" for
  partials are judged against the standard mortgage-QC field-set for each document and flagged as
  such — a later ticket should tighten them against Priya's real target lists.
- **Extractor-gap vs. fact-builder-gap** decided by checking **both** sides: if the documented
  extractor produces the field **and** the stated (MISMO) side carries it, but
  `build_cross_source_facts` doesn't populate the `CrossSourceFacts` field, it is a **fact-builder
  gap**; if a document schema genuinely doesn't produce the field, it is an **extractor gap**.
- **AUS/DU classified as not-built AND not-cataloged** — it is the one blocker that isn't even a
  recognized type, so it needs a catalog entry before a schema.
- **Tax returns judged "present"** despite unproven accuracy — the schema and nesting exist; the
  audit records the accuracy caveat separately (§7) rather than downgrading the schema status.

## Follow-ups for later tickets

- **Epic D (blocker schemas) — build vs. extend is now decided per doc:** EXTEND
  `homeowners_insurance` (promote mortgagee-clause + deductible from catch-all); BUILD
  `credit_report`, `appraisal`, `flood_certification`, `title_commitment`, and `aus_du_findings`
  (+ add AUS/DU to the catalog). Credit report is the highest-leverage build — it unblocks the two
  `xsrc.liability.*` rules and the whole `CR-*` family.
- **Epic C (seed rules) — sequence the fast wins first:** the ~8 fact-builder-gap rules need only
  `build_cross_source_facts` wiring (+ small transforms), no new extraction —
  `price_vs_contract`, `ssn_consistency`, `dob_consistency`, `subject_address_consistency` are
  pure wiring; `income_variance`, `large_deposit_unsourced`, `stated_asset_missing_doc` add light
  logic. These should land before the extractor-gap rules that wait on Epic D.
- **Stated borrower-address persistence gap** (MISMO parses but doesn't persist it) must be closed
  for `current_address_consistency` to have both sides — a small model/migration change, noted for
  whichever ticket wires that rule.
- **Employer-address promotion:** `employer_equals_subject` needs the employer *address* promoted
  from catch-all into the pay_stub/w2/voe typed cores (a schema extend, not a new doc).
- **LP-117 (Priya session):** the format questions (credit report structured vs. PDF, DU
  structured vs. PDF, appraisal UAD XML vs. PDF) directly determine the build effort for the
  §4 BUILD blockers — a structured/XML source may allow a deterministic parser like MISMO rather
  than an AI extractor.
- **Future eval-set ticket:** the LP-102 truncation class (esp. `investment_account`,
  `bank_statement`, `tax_return`) and the absence of a plausibility check (§7) need a real
  labeled-document eval set; the LF-6T3N reserves-understatement incident is the reference case.
