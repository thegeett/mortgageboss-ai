## Design

**AS-04.** The receipt item listed `[earnest_money_receipt, cancelled_checks_evidencing_receipt_of_note_income]`.
The second type is canceled checks proving the borrower RECEIVED installment-note income, a different
document. The classifier already has one type for both forms B3-4.3-09 names: `earnest_money_receipt` is
"a receipt, an escrow/agent ACKNOWLEDGMENT OF RECEIPT OF MONIES, or a canceled check evidencing the
earnest-money deposit" (`ai/classification_prompt.py`). So the item takes `[earnest_money_receipt]` and
**no type is added**.

Not changed, and noted for the owner: `emd_withdrawal_proof` (the sourcing debit from the borrower's
account) exists and could also serve AS-04's source item. It was not asked for.

**The review table.** It said "generated from the library" and was not: LP-918 wrote it once, by hand. It
went stale when the Stage 3A acceptance gave DI-01's disclosure two performers (it still read "LO").
- New `app/conditions/library/review_table.py` renders the whole file from `load_library()` and the
  UWM and Champions code maps ("Seen as").
- The top 20 and their order are LP-918's choice. They stay as `TOP_20` in the module, since they are a
  selection, not something computed.
- `uv run python -m app.conditions.library.review_table` writes the file.
- The labels (Borrower, LO, "Title / escrow", "Ask a third party", …) are the ones the hand-written
  table used. The generator reproduced the old table exactly, except for the three intended changes:
  the header's note, AS-04's documents, and DI-01's "Borrower + LO".

**The test** (`tests/conditions/test_library_review_table.py`):
- the committed file equals `render()`;
- a positive control, where a one-word library change changes the output;
- the owner's two corrections, asserted by content;
- `TOP_20` is 20 distinct types that exist.
