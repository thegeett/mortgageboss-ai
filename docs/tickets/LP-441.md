# LP-441 — The tier merge; rename the four leading-digit types

## What this ticket is

Step 1 of the schemas-for-all-105 plan. LP-440 landed 86 generated modules that are **inert** — the pipeline
only runs extraction on Tier-1, and most schema'd types were Tier-2 (or, as this ticket discovered, not in the
catalog at all). This merges Tier-2 into Tier-1 for every type that has a schema spec (Geet's decision), fixes
the four leading-digit names, and — the extension Geet approved — reconciles the schema↔catalog vocabulary for
the unambiguous cases. **It wires nothing** (step 7): no `EXTRACTORS` / `_LIST_SPECS` / `_PII_FIELDS`.

## D1–D5

- **D1 — the rename blast radius.** The 4 leading-digit slugs appear in: the 4 JSON specs (`document_type`),
  and — after generation — the generated module/prompt/test names. They are **NOT in the catalog or the
  classifier** (they were never cataloged), so no catalog/classifier rename applied; only the specs + the
  generated files.
- **D2 — the replacement invariant.** `== 18` is replaced by **"a catalog type is Tier-1 IFF it has a schema
  spec"** (`test_tier_1_iff_the_type_has_a_schema_spec`) — it fails both ways (a Tier-1 with no spec, or a
  spec'd type left at Tier-2) and is pinned by a **drift-case test**. Plus **"every registered extractor's
  type is Tier-1"** (replacing "every Tier-1 has an extractor", which the merge deliberately breaks). Together
  they keep coverage deliberate without demanding it be complete — a raw count would pass no matter what
  drifted.
- **D3 — Tier-1 without an extractor (the safety gate).** `_route_by_tier` (`document_processing.py:196`):
  `if tier == TIER_1: extractor = EXTRACTORS.get(dt); if extractor: extract else: _complete_classified_only`.
  So a Tier-1 type with no registered extractor → **COMPLETED, classified-only** — never errors, never FAILED.
  Verified end-to-end on a real newly-promoted type (`credit_report`). The only change: a promoted type loses
  its interim Haiku summary and is classified-only until step 7 wires its extractor. **Clean — the merge is
  safe before step 7.**
- **D4 — which types move.** **18 promotions** (Tier-2 → Tier-1): appraisal, bankruptcy_discharge,
  birth_certificate, business_tax_return, condo_questionnaire, credit_report, earnest_money_receipt,
  employment_offer_letter, flood_certification, flood_insurance_policy, lease_agreement,
  permanent_resident_card, social_security_award_letter, social_security_card, survey, title_commitment,
  uniform_residential_loan_application, verification_of_deposit. Tier-1 18 → **36**; **52 catalog types
  without a spec stay Tier-2**; **72 spec types remain uncataloged** (Tier-3 fallback — the mapping report).
- **D5 — cost.** Tier-1 means a full extraction call per document instead of a cheap Haiku summary. With the
  merge, ~36 cataloged types (and, once step 7 + the vocabulary reconciliation land, up to ~108) route to
  extraction instead of summary — a larger, per-document Opus call in place of a 1–2 sentence Haiku gist. Geet
  has accepted this; stated here.

## ⚠️ THE VOCABULARY MISMATCH (what this ticket discovered, and Geet's extension)

The schema `document_type` vocabulary and the catalog/classifier vocabulary had **diverged** — only 26 of 108
spec types were in the catalog. The classifier emits **catalog** keys; the generated extractors are keyed by
**spec** type — so an unreconciled type is silently never reached. Per Geet: reconcile the **unambiguous** cases
now, **report the rest, guess nothing** (a wrong rename silently breaks routing).

- **10 UNAMBIGUOUS renames applied** (spec `document_type` → the exact catalog key): `application_1003` →
  `uniform_residential_loan_application` · `form_1099` → `1099` · `flood_insurance` → `flood_insurance_policy` ·
  `resident_alien_card` → `permanent_resident_card` · `social_security_card_copy` → `social_security_card` ·
  `bankruptcy_discharge_notice` → `bankruptcy_discharge` · `property_survey` → `survey` ·
  `rental_agreements_lease_agreements` → `lease_agreement` · `business_federal_tax_returns` →
  `business_tax_return` · `earnest_money_emd_receipt` → `earnest_money_receipt`. Those modules were regenerated
  under the catalog name (old-named files deleted), and those catalog types promoted to Tier-1.
- **21 UNSURE** (a plausible candidate, not applied) and **the rest NO MATCH** — the full 82-row table is in
  **`docs/schema-specs/_VOCABULARY_MAPPING.md`**. Reconciling them (add a catalog entry + a classifier
  indicator, or confirm the UNSURE candidate) is the follow-up that makes the remaining generated extractors
  reachable.

## Every test that changed and why

All are **legitimate consequences of the merge** (a promoted type moved tier), not masked regressions:
- `test_eighteen_tier_1_types` → **replaced** by `test_tier_1_iff_the_type_has_a_schema_spec` + the drift-case
  test (D2).
- `test_every_tier_1_catalog_type_has_an_extractor` → **replaced** by
  `test_every_registered_extractor_is_a_tier_1_type` (the merge deliberately makes Tier-1 types lack an
  extractor until step 7; the new test guards the reachable direction) + a real classified-only routing test.
- `test_tier_2_starter_types`, `test_spread_of_new_types` (catalog) and `test_tier2_*` (pipeline) → their
  Tier-2 EXAMPLE types (credit_report, flood_certification, verification_of_deposit, appraisal,
  bankruptcy_discharge, permanent_resident_card, URLA) were promoted; swapped for spec-less Tier-2 types.
No rule or extraction test changed. `ACTIVE_RULE_IDS` = 36; the 18 shipping extractors are byte-unchanged.

## Assumptions / decisions

- **Nothing wired** — tiers + names only; the registry (step 7) stays untouched, so the 36 live rules and the
  catalog↔classifier parity cannot move (tiers changed, not keys → the classifier indicator set is unchanged).
- **No mapping guessed** — only the 10 unambiguous renames applied; 72 reported.
- The replacement invariant is a real bijection guard, not a count.

## NEW gap

- **72 spec types remain uncataloged** (the vocabulary reconciliation) — their generated extractors are
  unreachable by the classifier until cataloged. `_VOCABULARY_MAPPING.md` is the backlog.
- The 4 form_* transcript types + `verification_of_mortgage`/`_of_rent`/`_of_assets` etc. are among the NO
  MATCH set — each needs a catalog entry + a classifier indicator (a taxonomy decision).

## What step 7 must now do

Apply `_REGISTRATION_SNIPPETS.md` — the `EXTRACTORS` entries, `_PII_FIELDS` entries, `_LIST_SPECS`
registrations — for the cataloged Tier-1 types (starting with the 18 already-promoted-and-generated), bridge
the extractor↔snapshot list capture (LP-440's gap), extend the budget guard for the new modules, and — the
prerequisite for the long tail — reconcile the 72 uncataloged types (`_VOCABULARY_MAPPING.md`) into the catalog
+ classifier.
