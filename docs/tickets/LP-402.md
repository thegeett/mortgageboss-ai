## Her rule, stated exactly

**`owner_matches_borrower`** (reports the CONFIDENCE of the identity match; the specific difference lives in
`holder_name_variance`):
- **`yes`** — essentially CERTAIN: exact name; a DROPPED middle ("Jordan Rivera" = "Jordan A Rivera"); a joint
  account listing a borrower.
- **`unknown`** — PLAUSIBLE but needs EVIDENCE: a nickname (Bob/Robert), a possible maiden/married surname, an
  uncertain given-name variant. "Flag for evidence" — the document still counts; don't force `yes`, don't
  reject `no`.
- **`no`** — a genuine NON-match: a non-person (trust/LLC/estate), an unrelated name, OR a CONFLICTING middle
  name ("Jordan M" vs "Jordan A" — a likely different person).

**`non_borrower_co_holder`** — the AI's reading was right: it asks *"is there a SECOND, extra holder who is NOT
a borrower?"* → a single-holder account is `no`.

**N1 (a different middle initial) → `no`** (answered in the worksheet; a conflicting middle = a likely different
person, distinct from the `unknown` soft cases).

### ⚠️ THE COUPLING FINDING — the conservative change broke the variance gate

`holder_name_variance`'s prompt gates on **`owner_matches == "yes"`** ("WHEN owner_matches is yes, describe how
the name differs"). Now that owner_matches returns `unknown`/`no` for the flag cases (N1/N2/N7/P2), the variance
tag answers **`none`** for them ("Since owner_matches_borrower is not 'yes', there is no variance"). So the
SPECIFIC difference — the whole reason "the document still counts via holder_name_variance" — is no longer
recorded for exactly the flag-for-evidence cases Priya's rule creates. Variance fell to 4/11. **This is a real
regression the conservative change surfaced.** **The fix — widen the variance gate from `yes` to `yes OR
unknown` — is its own ticket** (LP-402 scoped the variance prompt OUT). It is NOT dangerous today (no rule
consumes these tags — AS-6 deferred), but it must be fixed before AS-6 consumes them.
