# LP-620 — a couldnt_check that asks for a document must be requestable

## The report

On LF-ABRS the findings tab showed **"In the file — read or clarify these (8)"** with no request
button on any row, while six of those eight rows opened with "Upload the appraisal report",
"Obtain a Closing Disclosure…", "Obtain a second document stating the date of birth".

## Why it happened

The button and the message are produced by two unrelated mechanisms, and nothing reconciled them.

* **The message** is composed from the abstention reason plus the spec's `couldnt_check_fix`, and the
  composer is handed `document_kinds_on_file` with an explicit instruction not to ask for something
  already there (`app/ai/finding_prose.py:99`). Its requests were **correct** — LF-ABRS has no
  appraisal, no Closing Disclosure, one document stating the DOB.
* **The button** is gated on `missing_documents`, derived at read time from the spec's
  `requires_documents` (`app/schemas/verification.py:290`) — and used in exactly two places, which is
  why the section and the button always agree with each other and can disagree with the prose:

  ```
  splitByMissingDocument   → missing: f.missing_documents.length > 0     (rule-findings.ts:244)
  canRequest               → finding.missing_documents.length > 0        (rule-finding-actions.tsx:127)
  ```

`requires_documents` was wrong for these rules in two distinct ways.

**1. Under-declared.** The field held the documents a rule *reads*, not the one that closes its gap.
IH-2 declared only the insurance binder while asking for the disclosure that names the lender; IN-4
declared pay stubs and W-2s while asking for the VOE that carries employment dates; MI-1 declared
nothing at all though its own authored fix reads "Upload the appraisal report."

`finding_prose.py:205` had already recorded half of this — *"IN-4's fix offers a verification of
employment that IN-4 does not declare, and saying so is faithful"* — and worked around it on the
prose side. The button had no such workaround.

**2. Inexpressible.** `requires_documents` is a **presence** test: a group is satisfied the moment any
member is on the file. The consistency engine's single-source abstention needs one *more* source than
the file has, which no presence test can report. ID-2 and ID-3 computed "nothing missing" because a
driver's licence *is* on file — under a message asking for a second document.

## The fix

**Declarations corrected** (read-time classification only; no evaluation reads this field):

| Rule | Added | Why |
|---|---|---|
| MI-1 | `[appraisal]` | The LTV is computed from the value **stated on the application**; the MI threshold is against the **appraised** value. |
| IH-2 | `[closing_disclosure, loan_estimate]` | A mortgagee clause is checked against the document that names the lender. Alternatives — either disclosure names it. |
| IN-4 | `[voe]` | Pay stubs and W-2s being present is the case the rule is about; undated, they cannot establish start and end dates. |

IH-2 crossing to two groups tripped `test_no_active_multi_document_rule_is_left_silent` (LP-608),
correctly: it had no spec-level `couldnt_check_fix`, only one on the catch-all outcome, which the gate
never reaches (the DT-6 lesson). One was authored, naming both sides.

**A per-finding channel** for the case a declaration cannot express:

* `RuleEvaluation.requested_documents` — set only by an evaluator that knows the answer for *this*
  subject (`result.py`).
* Persisted into `details["requested_documents"]` (`services/rule_findings.py`).
* Preferred over the spec-derived list at read time, with a defensive parse — `details` is stored JSON
  that outlives the code that wrote it, and a blank label would render as "Request " and title a needs
  item after nothing (`schemas/verification.py`).
* Set by the consistency engine's `len(gathered) < 2` branch, worded by count: one source needs
  *another* document, none needs *a* document (`rule_engine/consistency.py`).

Everything else is untouched: an empty `requested_documents` falls back to today's behaviour, so every
rule already classified correctly stays as it was.

## Deliberately not changed

**IN-1** stays on the read side. Its message ("income documentation … either missing, incomplete, or
shows conflicting figures") names no specific document, and both pay stubs and W-2s are on file. Which
document would close it is genuinely unknown, and inventing one would send a processor after something
that may already be there. It needs a spec-level `couldnt_check_fix` first — tracked separately.

**The other 14 rules that can never be requestable** — AS-3, AS-5, AS-7, CO-5, CR-5, DT-8, ID-1, ID-4,
IN-5, OC-1, OC-2, PC-5, PE-1, PE-3 — declare `requires_documents: []` or omit it. Most are genuinely
application-data checks with nothing to request. They were not audited one by one here; only the rules
demonstrated on a real file were changed.

**Two needs items for one upload.** ID-2 and ID-3 produce different request labels, so a bulk request
creates two needs items where a single passport would satisfy both. The bulk path dedupes on a slug of
the label (`finding_resolution.py:508`) and cannot see that. Accepted for now: they are different
facts, and one upload closes both on the next run.
