# LP-847 — a message can be marked sent with no recipient

Status: spec. Second of four.

## The report

> "Bug: when I clicked Mark as sent in borrower tab, all tab's draft Mark as sent button became gray
> out."

Diagnosed differently from how it was reported, and the difference matters: nothing about clicking
in the borrower tab disables anything. `useSendDraft` holds no shared state between dialogs. Those
buttons were **always** grey, and opening the other tabs is when they were noticed.

## Two of my own decisions contradicting each other

LP-843 creates a non-borrower draft with **no recipient**, because that was the explicit ask: "if
any party's contact is not there then keep it empty in draft. processor mostly worry about a
message."

`canSend` requires `recipient.trim().length > 0`, and `SendDraftRequest.recipient` is
`Field(min_length=3)` on the server. So the ticket that made an empty To legitimate never looked at
the control that refuses one. A processor can compose the message and can never record that they
sent it.

This is the failure my own note names — check the reader, not just the writer — one ticket after
writing it down.

## Decided: allow it

The user's call, and it follows from how sending actually works: nothing in this product transmits.
A processor copies the body into their own mail client and sends it to an address they may know
perfectly well and have never typed into our system. "Mark as sent" records **that they did it**, so
refusing the record because our row has no address is us insisting on bookkeeping the processor does
not owe us.

## THE TRAP THIS WALKS INTO, found before building rather than after

`recipient` is not only stored. It keys two guards in `email_send`:

- `is_suppressed(address=recipient)` — harmless on empty, matches no bounce.
- **`_refuse_if_rate_limited(recipient=recipient)`** — `Communication.recipient == recipient`, one
  send per window and N per day. **Every empty-recipient send shares the key `""`**, so the second
  one — a title company after a lender, entirely unrelated — is refused with "was emailed less than
  N minutes ago" about a mailbox that does not exist.

Two blanks are not the same mailbox. Both guards are about A SPECIFIC ADDRESS and neither has
anything to say when there is none, so both are skipped rather than fed an empty string. That has to
be asserted: a rate limiter that silently groups unrelated parties is exactly the kind of
green-looking defect this run keeps turning up.

## The change

- `SendDraftRequest.recipient` accepts empty.
- `canSend` drops the recipient requirement.
- Suppression and rate limiting apply only when there is an address to apply them to.
- The record stores what it has, which may be nothing, and says so rather than implying a send to
  an unknown party.

**Not in scope, and recorded because it is real:** `min_length=3` accepted `"abc"` as an email, so
there has never been a format check here (found in the LP-841 review). Relaxing the bound does not
make that worse, and fixing it properly is its own decision about whether a processor may record a
send to something we cannot parse.
