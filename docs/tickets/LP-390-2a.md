# LP-390-2a — IN-12 + AS-5 subject-mismatch: both blocked on missing producers (report)

## What this ticket is

LP-390-2's audit flagged IN-12 and AS-5 as subject-mismatches (structurally dead — couldnt_check on every
file). LP-390-2a set out to fix them so the income wave's calibration set would go 12 → 14. **Phase 0 found
neither is a simple subject fix — both are blocked on a PRODUCER that does not exist.** Per the decision on this
ticket, **neither is fixed here**; both become producer subtasks under LP-390-8. This is a report + an honest
reclassification of the audit's "blocked" list.

## Acceptance criteria (as met)

- The true shape of each fix is argued from the code (D1–D4), correcting the ticket's premise where the gate of
  record disagrees.
- Neither rule is activated; `ACTIVE_RULE_IDS` unchanged (17); the 17 live rules identical; full suite green.
- The honest blocked state is recorded (the IN-12 structural-death xfail's reason updated to the real blocker).

## Phase 0 — the argument

### D1 — IN-12: NOT the IN-11 fix (gate-of-record correction)
IN-12 reads `income.has_2yr_history` at `<tax_return content_id>` (per_document, `document_type == tax_return`);
the producer places it at `subject: borrower` (`tag_production.yaml:81`, LP-385). So the tag never reaches it —
the same mismatch class as IN-10/IN-11. **But the IN-11 fix does NOT transfer.** The LP-390-1 reviewer already
pinned this (a `strict` xfail, `test_in12_..._structurally_dead_until_lp390_2`): a naive per_borrower re-scope
would make IN-12 fire **identically to IN-11** — both read the borrower's `has_2yr_history`, which is
**income-type-agnostic**. IN-12 (self-employment) and IN-11 (variable income) would become redundant.

**Keeping IN-12 self-employment-specific needs a borrower-level self-employment signal that does not exist.**
`income.type` HAS a `self_employment` value (`fact_tags.csv:21`) but is `subject: document`
(`tag_production.yaml:74`, produced by `income_amounts`) — not readable in the per_borrower map (which carries
only loan + borrower-own tags). The `income_stability` group (subject: borrower) produces
`has_2yr_history / is_declining / same_line_of_work / continuance_3yr` — **no income-type / self-employment
tag**. So there is no way, with existing tags, to scope IN-12 to self-employment borrowers.
→ **IN-12 is blocked on a producer** (a borrower-level self-employment signal — e.g. `income.type` promoted to
the borrower, or income-type-specific history tags), NOT a subject re-scope.

### D2 — AS-5: a subject redirection needs a linking tag that does not exist
AS-5 reads `txn.apparent_category` at `<gift_letter content_id>` (per_document, `document_type == gift_letter`);
the producer places it at `subject: transaction` (`tag_production.yaml:17`). A gift-*letter* document never
carries a *transaction* category. AS-5's two sides — the gift **letter** (a document) and the gift **deposit**
(a transaction with `apparent_category == gift`) — live on different subjects **with no linking tag**:
- There is **no gift-letter-presence tag** — only `income.voe_present` / `income.offer_letter_present` exist
  (for income docs, the `income_docs` group). No `gift.*` tag, no `gift_letter_present` in the generic tag
  layer (`grep` = 0). (`gift_letter_present` exists only as a *fact* in the legacy hardcoded rule engine —
  `CrossSourceFacts` — not the generic engine AS-5 runs in.)
- There is **no loan-level "a gift deposit is present" signal** aggregating transactions' `apparent_category`.

So redirecting AS-5's read alone cannot fix it: whichever subject it enumerates, one of the two sides has no
tag. → **AS-5 is blocked on a producer** (a gift-letter-presence tag, or a loan-level gift-deposit-present
derived tag), like IN-14 / AS-7.

### D3 — even after a fix, `gift` is data-blocked on LF-6T3N
`txn.apparent_category`'s `gift` value is UNMEASURED on LF-6T3N (LP-379-F: the file's redacted memos don't
support gift classification). So AS-5's tag would be calibratable-in-principle but blocked-on-data on LF-6T3N —
a distinct, further limitation beyond the producer gap.

### D4 — the fiction tests already exist and already record the honest state
- **IN-12**: `test_pin3_in12_minimal_check_only` exercises the evaluator by hand-placing `has_2yr_history` at
  the tax_return DOCUMENT subject (explicitly noted as NOT production behavior); the LP-390-1 review added
  `test_in12_..._structurally_dead_until_lp390_2` (strict xfail) pinning the production death. **This ticket
  updates that xfail's reason to the real blocker** (a borrower self-employment signal), since LP-390-2a does
  NOT fix it — leaving the name/reason as "until LP-390-2" would falsely imply a fix landed.
- **AS-5**: `test_as5_gift_chain_scope_and_fire` already documents the keying gap and asserts `couldnt_check`
  in production (hand-placing the tag only to exercise the logic). It already records the honest blocked state.

## The verdict — both blocked, neither fixed, neither blocks Priya

| Rule | Was (audit) | Is (this ticket) | The real blocker | Fix ticket |
|------|-------------|------------------|------------------|-----------|
| IN-12 | subject-mismatch | **blocked-on-producer** | no borrower-level self-employment signal (income.type is subject:document) | producer subtask (LP-390-8) |
| AS-5 | subject-mismatch | **blocked-on-producer** | no gift-letter-presence / gift-deposit-present tag | producer subtask (LP-390-8) |

**Neither death blocks Priya's session.** `income.has_2yr_history` already reaches IN-11 (calibration-ready) and
`txn.apparent_category` already reaches AS-2 (calibration-ready) — so fixing IN-12/AS-5 adds NO new calibration
target. Priya's tag list from LP-390-2 is unchanged.

**The income wave's calibratable count stays 12, not 14.** The ticket's premise (two simple subject fixes) was
wrong for both — both need producers first. This is the same shape as LP-390-2's IN-14 / AS-7 orphans, and it
moves IN-12 + AS-5 from "subject-mismatch (a spec fix)" to "blocked-on-producer" in the LP-390-8 fix list.

## What changed

**No production change** — no spec edit, no producer, no activation. One test update: the IN-12 structural-death
xfail's reason/name now names the real blocker (a borrower self-employment signal) instead of implying LP-390-2
fixes it. The AS-5 test already asserts the honest `couldnt_check`.

## Assumptions, decisions & gaps

- **Decision (this ticket): fix neither.** A naive IN-12 per_borrower re-scope is refused (it collapses IN-12
  into IN-11 — the reviewer's `strict` xfail encodes exactly this); the self-employment-specific version needs a
  producer that does not exist. AS-5 needs a producer that does not exist. Building those producers is
  explicitly out of this ticket's scope (report → LP-390-8 subtasks).
- **The eighth (AS-5) and confirmed-sixth (IN-12) structural-dead instances** — but reclassified: their fix is
  producer-first, not subject-first. See ADR-310.
- **NEW gaps reported (for LP-390-8):**
  1. A borrower-level self-employment signal (promote `income.type` to the borrower, or an `is_self_employed`
     flag / income-type-specific `has_2yr_history`) — unblocks IN-12 AND resolves IN-11's pinned over-fire
     (both need income-type scoping; a shared fix).
  2. A gift-documentation signal — a gift-letter-presence tag and/or a loan-level gift-deposit-present tag —
     unblocks AS-5.
- **The honest limit:** this is a static trace + a domain read; whether the proposed producers are the RIGHT
  modeling (e.g. income-type-specific history vs a set-membership operand on `income.type`) is a design call
  for the producer ticket, informed by Priya.

## ADR

ADR-310 — IN-12 and AS-5 are reclassified from subject-mismatch (a spec fix) to blocked-on-producer; the income
wave's calibratable count is 12, not 14; both are producer subtasks under LP-390-8. (A planning finding — it
reshapes the fix list, not the code.)
