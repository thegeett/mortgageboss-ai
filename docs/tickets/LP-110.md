# LP-110 — Every need shows its SOURCE (grounded to verifiable data, honestly attributed by origin)

- **Ticket:** LP-110
- **Status:** Completed
- **Date:** 2026-07-03
- **Scope:** Backend (needs model + generation + schema + migration) + frontend (need card)

## The gap — reasoning without a source

A need carried its REASONING (the AI's argument for why it's here, LP-67/69) but not its SOURCE —
the specific data that triggered it. So a processor could read the argument but couldn't VERIFY the
AI didn't hallucinate or MISREAD. This matters most for needs precisely because they are **the most
AI-driven, least-deterministic part of the system**: a need proposed on a misread carries a
plausible-but-wrong reasoning, and the source is what makes that reasoning FALSIFIABLE by the human
(click the source → "that's a rental, not self-employment income — the AI misread"). Extractions and
findings were already provenance-backed; needs weren't.

The one structured link that existed (`source_finding_id`, LP-67) was populated only for suggestion
needs AND was not exposed in `NeedsItemPublic` — captured but hidden, never reaching the UI.

## The principle

A need's source must ground out in something **deterministic and verifiable** (the imported field,
the document, the finding) wherever possible — never merely restate the AI's conclusion. A source
that is only more AI text gives the processor nothing to check against.

## The fix — per-origin source capture + unified honest display

| Origin | Mechanism | Attribution |
|---|---|---|
| `ai_reasoning` | **Capture at generation** — the AI CITES the FileContext fact(s) it reasoned over | **ai_identified** (verify) |
| `floor` | **Derive from the rule** — deterministic, at seed time | **deterministic** (certain) |
| `suggestion` | **Expose the existing chain** — `source_finding_id → finding → document` | **finding** (linked) |
| `manual` | none — the origin ("Added") is the source | `source` is null |

- **AI (capture).** `ProposedNeed.triggered_by` — a list of `{kind, label, ref?}` (kind ∈
  employer/income/asset/liability/finding/mismo_field). The prompt now asks the model to cite the
  specific record(s) it used, with `ref` = a finding's id where the JSON gives one (finding ids were
  added to `FileContext`). Parsed defensively (`_parse_triggered_by`: unknown-kind / empty-label
  facts dropped; a need is never dropped for lacking a source), persisted to the new
  `needs_items.source_facts` (JSON). Marked **AI-identified** — the AI's reading, worth a glance.
- **Floor (derive).** The rule already evaluates the data, so the source is derived deterministically
  at seed time and stored in `source_facts` (pay_stub/w2 ← "Employment income is stated";
  bank_statement ← "Assets are stated"; purchase_agreement ← "Loan purpose is Purchase"; refi
  statements ← "Loan purpose is Refinance"; drivers_license ← per borrower). Attributed
  **deterministic** (certain).
- **Suggestion (expose).** A `source_finding` relationship (eager-loaded with its document) surfaces
  the finding's description + its source document through the API. Attributed **finding**, carrying
  the finding id (`ref`) + the document filename — grounded and linkable.
- **Unified display.** `NeedsItemPublic.source` (`NeedSource` = `attribution` + `facts`) renders one
  "Source" affordance per need in `need-card.tsx`, mirroring the finding "Source" section + the
  extraction Quote provenance vocabulary so it looks native. **Honest attribution** is the key
  discipline: the deterministic pill (primary/certain) is visually distinct from the AI-identified
  pill (info + a "verify — the AI may have misread" note) — an AI reading is NEVER shown as fact.

## Scope boundaries

- **Additive only.** No change to need GENERATION logic (what needs are proposed) — only the source
  citation is added to the output. Composes with LP-108 (status) + LP-109 (matching documents); a
  test asserts all three coexist on one need with no regression.
- **Grounds to verifiable data, not AI prose.** AI sources carry a `ref` to the underlying record
  where one exists and are marked AI-identified; floor + finding sources are deterministic.
- **Grounded-starter (validate-with-Priya):** the AI-cited sources are AI-generated — the open
  quality question is "does the AI cite the RIGHT triggering fact?", flagged for Priya. Floor + finding
  sources are deterministic (reliable).
