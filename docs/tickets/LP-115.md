## What this ticket is

The Phase 3.5 gate. Before estimating or building the data-driven rule engine that scales
verification to the ~130-rule playbook, we needed the **truth** about which verification rules
actually fire today — because prior planning reconstructed the numbers from memory (the
"~30 exists" / 130-rule figures) and the pipeline map suspected they were wrong. This is a
**read-only audit**: read the code, trace the paths, gather evidence, classify every rule, and
write it down. No code was changed.

The key prior hypothesis to test: there are **two** deterministic engines but only **one** is
wired — the threshold engine (`services/verification_engine.py`, the LP-74 conv./fha. threshold
rules) is suspected dormant, with all live findings coming from the cross-source pass. This
audit confirms that hypothesis with evidence.

## What was actually done

1. **Mapped the entry point + orchestration.** Traced `POST …/verification/run` → fingerprint
   cache check → `create_verification_run` → enqueue `run_cross_source_pass` (Celery) →
   `run_cross_source` → deterministic rules + AI pass → persisted findings. Identified the two
   (and only two) finding generators. (Audit §2.)
2. **Inventoried the deterministic cross-source rules.** Read all 18 `CrossSourceRule`s and the
   fact-builder; cross-checked which `CrossSourceFacts` fields are populated vs. read-only
   defaults (grep confirmed the Tier-2 fields are assigned only in `facts.py`). Result: 5 can
   fire, 13 are fact-starved. (Audit §3a.)
3. **Inventoried the threshold engine + ran the caller search.** Enumerated the 107 registry
   rules (50 conv + 49 fha + 8 sample/regulatory) and proved no production caller of
   `run_verification`/`evaluate`. (Audit §3c, §6.)
4. **Inventoried the AI cross-source pass.** Documented the generator, the 10-type taxonomy,
   and the run-scoped graduation/dedup (defer on `fired_types`; `other` +
   `co_borrower_discrepancy` never suppressed). (Audit §3b, §4.)
5. **Inventoried the calculators.** Confirmed DTI/LTV/MI/reserves/max-loan/self-employed surface
   via calculator endpoints and write no `Finding` rows — a separate category — while reusing
   the dormant engine's threshold *data*. (Audit §7.)
6. **Deep-dived the employer rule** for LP-120. (Audit §5.)
7. **Cross-referenced the playbook.** Found no committed xlsx and no code mapping; extracted the
   AS-/IN-/CR- scheme from phase3_5_1.md and mapped where explicit. (Audit §3d.)
8. **Stated the dormant engine's fate options + recommendation.** (Audit §8.)

## Assumptions and decisions made during the audit

- **"fires-today" defined strictly** = wired into the run path **and** its input data is
  actually populated, so it can produce a finding on real data. A wired-but-fact-starved rule
  is **scaffolded-dormant**, not fires-today. This is the conservative classification the ticket
  asked for (prefer dormant unless firing can be shown), and it is what drops the deterministic
  count from 18 to 5.
- **The 13 fact-starved rules are classified `scaffolded-dormant`** even though they are a
  different *flavor* of dormant from the threshold engine (a fact-builder change away from
  firing, vs. needing a caller). The audit notes this nuance rather than inventing a fourth
  state, to stay within the ticket's three-state model.
- **The AI pass is counted as one generator, not N rules.** It is a single generative call, not
  enumerable rules; counting its 10 possible types as "10 rules" would repeat the kind of
  inflation this audit corrects.
- **Playbook IDs are mapped only where the plan doc is explicit** (IN-5, AS-1, CR-1, PR-2);
  everything else is marked "inferred". A sub-agent initially confabulated an AS-/IN-/CR-
  mapping with wrong line numbers; that was caught and discarded by re-verifying against the
  actual file (the whole point of the audit — don't trust reconstructions).
- **Calculators are a separate category**, not folded into either rule bucket, matching the
  ticket's step 5 and phase3_5_1.md:24.

  `run_verification` share a name; renaming one would prevent future mis-reconstruction.
