# LP-396 — Two isolated fixes: IN-12's wiring and AS-6's re-score (both still blocked, reasons established)

After LP-395 found the calibration wave doesn't exist, these were the next "the tag exists, the rule can't
consume it" candidates. Phase 0 (report before changing anything) found **both are still blocked** — but for
reasons the census/bar text did not yet state precisely. IN-12's stale bar is corrected; AS-6's re-score was
run and reproduced the old result, empirically confirming its producer fix never landed. Neither is activated.

## Phase 0 — the verdict per half

### A) IN-12 — WIRING, still blocked-on-producer (bar text was stale)

- has_2yr_history is **measured 100%** (LP-393-6) — so the bar's *"PRODUCED but UNSCORED — blocked on
  calibration"* was **stale** (the LP-394 finding). IN-12 is **not** calibration-blocked.
- Its real blocker is a **subject wiring mismatch**: IN-12 enumerates `per_document` (tax_return) while
  has_2yr_history is produced `per_borrower` — so on a real file it `couldnt_check`s (structurally dead, the
  IN-10/IN-11 class).
- **The naive fix is FORBIDDEN (LP-390-2a / ADR-310):** a plain `per_borrower` re-scope collapses IN-12 into
  IN-11 (both read the income-type-agnostic has_2yr_history), destroying IN-12's self-employment specificity.
  Keeping it specific needs a **borrower-level self-employment signal that does not exist** — verified: `income.type`
  is `subject: document`, and `income_stability` (the per_borrower group) produces no income-type tag. The
  strict xfail (`test_in12_self_employment_history_is_structurally_dead_pending_a_producer`) still encodes this.
- **Verdict: still blocked-on-a-producer** (a borrower-level self-employment tag — its own ticket). The disposition
  is unchanged from LP-390-2a. **Action taken: correct the bar** — `status: not-calibratable-yet → needs-producer`,
  and rewrite the rationale to name wiring + the forbidden re-scope + the missing producer, not calibration.

### B) AS-6 — re-scored; the producer fix never landed (still blocked-on-producer)

- **The ticket's premise is false per the code.** It assumed *"LP-390-8a fixed [the producer]… it should now
  produce real match/no-match verdicts."* **There is no LP-390-8a** — no ticket doc, no commit, and the
  `document` context builder (`_doc_context`) still sends only the statement's own fields, never the loan's
  borrower roster. So `stmt_facts` structurally still cannot compare a holder name to the borrowers.
- **Valid goldens DO exist** — contradicting the "blanked" worry, which was about the *DB* worksheet (LP-392).
  The committed **synthetic** worksheet `docs/calibration/lf6t3n-labels-judgment.csv` carries **8 filled
  `owner_matches_borrower` goldens, all `yes`** (5 bank statements + 3 investment accounts).
- **THE RE-SCORE (real reasoner, reported not predicted):** materialized `stmt_facts` on LF-6T3N and scored
  `stmt.owner_matches_borrower` against those goldens →

  | metric | value |
  |--------|-------|
  | scored | **5** (the bank statements) |
  | unmatched (no produced tag) | **3** (`inv1/inv2/inv3` — `stmt_facts` doesn't run on investment_account) |
  | AI prediction | **`unknown` on all 5** |
  | accuracy vs golden `yes` | **0/5** |

  The AI's own reasoning on every row: *"Account holder is 'Jordan A Rivera' but no borrower names were provided
  in the loan…"* — it correctly ABSTAINS (it can read the name on the statement but has nothing to compare it
  to). **This reproduces LP-390-5 exactly (100% abstain) — nothing changed, because the producer/context fix
  never landed.** The abstention is the fail-safe working, not an AI error.
- **Verdict: still blocked-on-producer** — the `stmt_facts` context fix (feed the borrower roster) is the real
  work, and it is not done. The AS-6 bar already states this correctly (*"Blocked on a PRODUCER/CONTEXT fix…
  not on scoring"*) — **no bar change needed.**

## Findings (correcting the plan)

1. **LP-390-8a never landed.** The AS-6 producer/context fix the plan assumed exists does not — `stmt_facts`
   still gets no borrower roster. AS-6 remains blocked-on-producer; the fix is to feed the group the loan's
   borrower names (its own ticket), after which the 8 existing goldens make it immediately scorable.
2. **A producer/worksheet scope mismatch on `owner_matches_borrower`.** The worksheet labels it on
   `investment_account` docs (inv1–3), but `stmt_facts` only runs on `bank_statement`/`money_market` — so those
   3 goldens can never be scored (they showed up as `unmatched`). The capacity model over-scopes the tag.
3. **IN-12 reclassified** `not-calibratable-yet → needs-producer` (the census/LP-394 called it `wiring`; the
   deeper resolution is a producer, matching IN-14's precedent and ADR-310).
