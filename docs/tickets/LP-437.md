# LP-437 — Generic nested lists: one mechanism for all 66

## What this ticket is

**The largest single unblock in the project: 61 of 108 specs refuse on the nested-list condition.** Each list
today costs ~5 hand-written files (a snapshot record class + a `DocumentEntry` attribute + a `build_*`
reshaper — the LP-421/ADR-061 pattern) → 66 × ~5 ≈ 330 edits. LP-436 established the collapse is real. This
ticket builds the generic mechanism: **one additive `lists` channel + a per-list declaration**, coexisting with
the three bespoke attributes (which feed live rules), no `SNAPSHOT_VERSION` bump, and a fail-closed `derived`
helper. The registry ships EMPTY — LP-438 emits the real declarations.

## D1–D5 (the argument)

- **D1 — the row shape.** `ListRow.fields: dict[str, Field]` mirrors `DocumentEntry.fields`. The snapshot
  `Field` (fields.py) carries value + confidence + `FieldSource` + `absent`, and works unchanged inside a row.
  **page/snippet are not carried into the snapshot `Field` for ANY field** (flat, transaction, or schedule),
  so "nothing lost" is accurate **relative to a bespoke list** — the fidelity is identical. `parse_typed_core`
  runs at EXTRACTION time (before storage); at snapshot time the shipped path uses `_typed_field` (reads the
  stored, already-coerced `{value, confidence}`) — reused here.
- **D2 — where field types come from.** The converter reads stored-coerced values via `_typed_field` — no
  runtime coercer needed. A per-doc-type `ListSpec` supplies the declared **field names** + the three helper
  declarations. Recommendation adopted: the emitted-spec/registry approach (`_LIST_SPECS`), mirroring
  `_SCHEDULE_DOC_TYPES`; LP-438 emits the real specs.
- **D3 — registration.** A declared `_LIST_SPECS: dict[document_type, tuple[ListSpec, ...]]` (LP-436's "a
  declaration is safer" over reading arbitrary payload keys). **Empty today** → every real document gets
  `lists={}`.
- **D4 — the additive proof (verified, not assumed).** No test byte-compares a snapshot to the committed
  fixture (`grep` for `model_dump_json() == fixture` returns nothing); the fixture loads via tolerant
  `Snapshot.model_validate` (harness.py:317), so a v4 fixture with no `lists` key fills the default and still
  loads. `test_specs.py:123` (`"transactions" in DocumentEntry.model_fields`) stays green. **No bump.**
- **D5 — the `derived` fail-closed contract.** A derived field maps a source value → a new field; an **unmapped
  value produces an ABSENT `Field`, never a fabricated value** — copying `_direction`'s absent-on-unknown
  discipline (the forged-deposit guard). Tested (`test_derived_is_fail_closed_absent_on_unknown`).

## What was built

- **`snapshot/model.py`** — `ListRow(fields, row_id)` + `DocumentEntry.lists: dict[str, tuple[ListRow,...]] = {}`
  (additive; version stays 4). The three legacy attributes untouched.
- **`snapshot/documents_section.py`** — `DerivedSpec` / `ListSpec` declarations, the empty `_LIST_SPECS`
  registry, the three helpers (`_derive_field` fail-closed, `_redact_field` reusing `_DESC_REDACT`,
  `stable_row_id` via `assign_content_ids`), `build_list_rows` (pass 1, no ids) + `finalize_lists` (pass 2,
  assigns `row_id`s), wired into `build_documents_section` **alongside** the three legacy builders.
- **`snapshot/content_id.py`** — `LIST_PREFIX = "lst"` (one guard-safe prefix; the list name is folded into the
  hashed content so rows across lists never collide).
- **`snapshot/traversal.py`** — `all_list_rows(snapshot, name)`, the `all_transactions` shape.

## THE PROOF (reported, not predicted)

A demo `ListSpec` (`activity`: fields date/amount/description, derived `direction` from `transaction_type`,
`redact` description, `stable_row_id`) run over a two-row extraction:

```
row 1  row_id=lst4a958efd5d4ede0b
    date         value='2026-05-01'                  conf=0.9  source=extracted absent=False
    amount       value='5000.00'                     conf=0.95 source=extracted absent=False
    description  value='PAYROLL ACCT [redacted] DEP'  conf=0.8  source=extracted absent=False
    direction    value='credit'                      conf=None source=derived   absent=False
row 2  row_id=lst4cde982a075532d3
    date         value='2026-05-03'                  conf=None source=extracted absent=False
    amount       value='200.00'                      conf=None source=extracted absent=False
    description  value='COFFEE SHOP'                 conf=None source=extracted absent=False
    direction    value=None                          conf=None source=None      absent=True   ← FAIL-CLOSED
```

- **Nothing lost:** value, confidence (0.95 preserved), and provenance `source` per field.
- **`redact`:** the 9+-digit run `123456789` → `[redacted]`; the sourcing signal (`PAYROLL`/`DEP`) kept.
- **`derived`:** `deposit → credit` (source=`derived`); **unmapped `mystery_type` → ABSENT** (never fabricated).
- **`stable_row_id`:** ids stable across two independent runs, distinct per row, guard-safe `lst` prefix.
- **Round-trip:** `model_dump_json → model_validate` preserves the list; `all_list_rows` reads it back.

## Assumptions / decisions

- **Coexist, never migrate** (AS-1/IN-12 are live) — the three legacy attributes are byte-unchanged.
- **No `SNAPSHOT_VERSION` bump** — additive default, the LP-421 precedent; a bump breaks the committed fixture.
- **`derived` fails closed** — absent on an unmapped value.
- **List data stays AI-invisible** — `_doc_context` reads only `fields`; this is the deliberate catch-all
  boundary that gated IH-1, recorded and left as a separate decision (LP-436 step 8 / ADR-343).
- The registry ships **empty**; the mechanism is proven via an in-test demo spec (no specific list is built —
  that is LP-438 + per-list consumers).

## New gap

- **AI reach for list data** remains closed by design. When a rule needs an AI reasoner to see list rows (e.g.
  credit-report tradelines), the context builders must be taught to emit rows — opt-in per group + a row cap
  (a 20+-row list is a real token cost). Not this ticket.

## What LP-438 must add

- **`_FORMAT.md`**: the per-list declaration (fields + `derived`/`redact`/`stable_row_id`), so a spec's
  `nested_lists` carry the mechanism's inputs.
- **The generator**: emit a `ListSpec` (and register it in `_LIST_SPECS`) for each spec `nested_lists` entry,
  turning the 61 nested-list refusals into declarations — plus, per list that feeds a rule, the consumer (a
  per-row enumerator or a derived recipe reading `entry.lists.get(name, ())`).
