# LP-602 / LP-603 — Three defects the first post-fix run exposed

## 1. A "mismatch" between two identical figures (LP-602)

Live on LF-3CVT after LP-598 deployed:

```
title:   "Existing mortgage balance differs between application and owned property schedule"
kind:    value_mismatch
sources: owned_property.1.lien_upb                      = "$451,829"
         liability.3.unpaid_balance (UNITED WHSLE MORT) = "$451,829"
detail:  "... both state $451,829, so they match. No mismatch exists here."
```

The title claims a difference, the kind claims a difference, and the body says there isn't one. A
processor scans titles, so this sends them after nothing.

**LP-598's guard was written for exactly this and missed it.** It looked for agreement PHRASES in the
detail — the list held `"these match"` and the model wrote `"they match"`. A wording check is a guess
about phrasing, and the figures were sitting in `sources` the whole time.

Now the check compares the cited VALUES: a finding claiming a difference whose sources all normalise
equal is dropped. Normalised through the same `_normalise` identity uses, so `"$451,829"` and
`"451829.00"` count as the same figure — without that, a model citing one source formatted and the
other raw would manufacture a discrepancy out of punctuation. The old phrase check stays as a second
line; it costs nothing and catches a different shape.

Two existing test fixtures failed when this landed, and they were **right to fail**: both claimed a
mismatch while carrying identical source values. Fixed to carry figures that match their own prose.

## 2. `calculation_blocked` used to route around a prohibition

Three of the four open cross-checks were missing-document findings wearing the wrong label:

- *"Income documentation absent — stated monthly income cannot be verified"*
- *"Credit report absent — tradeline verification..."*
- *"Appraisal document missing — stated valuation cannot be verified"*

The prompt says *"Do NOT report: a missing document on its own (the needs list tracks those)"*, and
the model complied with the letter by filing them under a kind that sounds like something else. The
prohibition now states that it holds **whatever kind is chosen**, names both evasions verbatim, and
says what `calculation_blocked` is actually for: a named computed figure that cannot be produced.

Only the DTI-gated finding qualifies, which is the one worth keeping.

## 3. A finding on the list that asks for nothing (LP-603)

OC-2 shipped this on a `needs_review`:

> "The stated primary residence occupancy is supported by the application."

A sentence that reads as a pass, sitting in Needs attention. OC-2 is a judgment rule and **ratifies
every verdict** (ADR-336), so even a confident "yes" reaches a human — and the text has to make that
ratification the ask rather than report that all is well.

The `settled` direction was already guarded ("do not write a pass as a task"). Its **inverse had no
check at all**: a finding that is not resolved must say what to do about it. A test pins the two
directions as exclusive, or every composition would be rejected whichever way it was written.

That guard also caught an incoherent test fixture of my own — a DT-8 *satisfied* case whose summary
was not marked settled, so a statement-style composition looked like a violation. Made coherent.

## And IH-3 asked for one side of a two-sided comparison

IH-3 compares an insurance effective date against a closing date. Its `couldnt_check_fix` presumed the
policy was already there — *"the policy's effective date"*, *"if more than one homeowners policy is in
the file"* — so on a file carrying **neither**, the ordinary state at intake, it asked only for the
Closing Disclosure. A processor who uploaded it would find the rule still unable to answer. It now
names both sides.

## Tests

11 new across two files, every guard mutation-checked: removing the value comparison, removing the
inverse guard, and reverting IH-3's fix each fail. Full suite green: **5457 passed**.

## Note on the cross-check transition

The re-keying migration reduced the churn but did not make it invisible, as LP-600 claimed it would.
Stored rows carried invented slugs, all of which map to `other`; the model — now given a vocabulary —
picked real categories. Different kind, different key, so eight resolved and five opened. There is no
honest mapping from `credit_report_absent` to one of six categories and guessing would have been
worse, so this was a one-time cost of introducing the vocabulary at all. Both sides now use it, so the
next run is the test of whether it is finally stable.
