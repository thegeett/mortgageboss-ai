# LP-610 — Nine fix texts that ask for both documents every time

## What the audit found

The question was whether IH-3 had really been fixed. It had not — it got a weaker treatment than IN-3,
and auditing for that shape turned up **nine** rules, not the five I guessed:

`AS-4`, `CL-1`, `CR-13`, `CR-6`, `ID-5`, `IH-3`, `PC-7`, `PR-2`, `PR-6`

Each needs two kinds of document. LP-603 and LP-608 made each one **name both sides**, which fixed the
original defect — a text that presumed which side was missing and asked only for the other. But naming
both means asking for both, every time. So a file carrying one of them is told to upload it again:
IN-3's symptom, one step milder.

IH-3 will hit this in phase 4 of the upload plan. The insurance arrives; no Closing Disclosure exists
yet; IH-3 asks for the insurance declarations page again.

## The fix, and why it belongs in the template

A composer may only choose among requests the template makes — its instruction is to make THE SAME
REQUEST as the fix text. So the alternative has to be written there, and `document_kinds_on_file`
(LP-609) is what lets it pick. Eight of the nine gained:

> "If one of the two is already in the file, upload only the other."

## PC-7 is not like the other eight

A uniform clause got it **wrong**, and reading the result back is what caught it. PC-7's two document
groups are **alternatives for one fact** — the closing date comes from the purchase agreement *or* the
Closing Disclosure — not two sides of a comparison. "Upload only the other" contradicted its own
preceding sentence and would have sent a processor after a document nothing needs. It reads:

> "Either document answers this, so if one of them is already in the file nothing further is needed
> for the date."

AS-4 needed hand-correcting too: the appended clause landed after a sentence about occupancy and unit
count, so "the two" read as referring to *those* rather than the documents. Moved next to the sentence
it belongs to.

Two of nine wrong from a mechanical edit is the argument for reading generated text back rather than
trusting the transformation — the same lesson this whole sequence keeps teaching about model output,
applied to my own.
