# LP-984 — SES account suppression list (bounces and complaints)

- **Ticket:** LP-984, the fourth of the step-1 tickets in `loan-email.md` §15.
- **Status:** applied to staging (account `058190633983`, us-east-1) on 2026-10-20 (US Eastern).

## What and why

SES can keep an account-wide "do not send" list. When an email hard-bounces, or the recipient marks
it as spam, SES puts that address on the list and refuses any later send to it. Sending again and
again to dead mailboxes, or to people who complained, is exactly what damages an SES account's
reputation, and a damaged reputation can get sending paused for the whole account.

This ticket turns the list on for `BOUNCE` and `COMPLAINT` in Terraform. Until our own suppression
code exists (step 2), it is the only thing stopping repeat sends to a bad address; after that it stays
as a backstop.

## What changed

- `infra/envs/staging/main.tf`: new `aws_sesv2_account_suppression_attributes.this`,
  `suppressed_reasons = ["BOUNCE", "COMPLAINT"]`, with `lifecycle { prevent_destroy = true }`. It is
  at env level, next to `module "outbound_mail"`, because it is one setting per account and region.

## Decisions

- **Always on, not gated on `outbound_mail_enabled`.** The first plan used
  `count = var.outbound_mail_enabled ? 1 : 0`. Review at the checkpoint removed it: suppression should
  be on in this account no matter what the outbound flag says.
- **`prevent_destroy`.** Deleting this resource could clear the account's suppression reasons, which
  would also remove the setting AWS had on by default. We never want that, so Terraform now refuses
  any plan that would destroy it. This was a concern raised at the first checkpoint; it is fixed here,
  not left as a follow-up. Removing the resource on purpose now takes two steps: delete the
  `lifecycle` block first, then the resource.
- The resource name and its one argument were checked against the pinned provider, aws 5.100.0
  (`terraform providers schema -json`): `suppressed_reasons` is a required set of strings.

## How to see or remove an address later

```bash
# Everything on the list, with the reason and when it was added
aws sesv2 list-suppressed-destinations --region us-east-1

# One address
aws sesv2 get-suppressed-destination --region us-east-1 --email-address someone@example.com

# Take an address off the list
aws sesv2 delete-suppressed-destination --region us-east-1 --email-address someone@example.com
```

Remove an address only when the reason is gone: for example, a borrower whose mailbox was full or
misconfigured has fixed it and asks to receive our emails again.

## What this does NOT do

- Our own suppression, and showing a bounce or complaint to the processor on the loan file, are step 2.
- No alarms on bounce or complaint rates (LP-987).
- No configuration-set-level suppression, and no custom suppression lists.
