# LP-613 — Order findings by rule id, numerically, in every section

## Ask

> "I want to order the findings by chronological order of rule id, per section wise, ordered in
> Must fix, ordered in couldn't check, ordered in in the file, ordered in Needs review, same
> thing in all findings tab."

Clarified in the thread: **numeric**, not lexicographic — `AS-10` sorts after `AS-4`, not between
`AS-1` and `AS-4`.

## What was there before

`groupByRule` built its group order from **first-seen order** — the order the API happened to
return findings in, which is `created_at` within a run. That is an artefact of the order the engine
evaluated subjects in, not information a processor can use. It also meant the same file could
render its sections in a different order run to run.

## The change

One function, `compareRuleIds`, in `frontend/lib/verification/rule-findings.ts`:

- Split a rule id into `family` + `number` (`AS-4` → `AS`, `4`).
- Same family → compare the **numbers** as integers (this is the numeric-sort requirement).
- Different family → compare the families alphabetically, so `AS-*` precedes `CR-*` precedes `DT-*`.
- A legacy id that does not parse (`cross_source.income_variance`, `xsrc.identity.name_consistency`)
  sorts **after** every governed id, and ties break lexicographically so the order is still total
  and stable.

`groupByRule` sorts its group order through it before mapping.

## Why one call site covers the whole ask

The ask named four sections plus "all findings tab". Every section on both tabs renders through
`groupByRule` — Must fix, Couldn't check, In the file, Needs review — so sorting the group order
inside it orders all of them, on both tabs, from one place. No per-section sorting exists to drift.

## Tests

`frontend/lib/verification/rule-findings-order.test.ts` — 7 tests, pinning:

- the numeric case that a lexicographic sort gets wrong (`AS-10, AS-4, AS-1, AS-8` →
  `AS-1, AS-4, AS-8, AS-10`);
- family-then-number ordering across families;
- legacy/unparseable ids sorted last, not interleaved;
- findings of one rule staying **grouped**, not scattered by the sort.
