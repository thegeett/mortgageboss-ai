# LP-517 — AS-2 is a purchase-only check, and applicability can now be a conjunction

**Status:** done · **Follows:** LP-509-A5 (which named this and did not do it)

## The problem

**Earnest money is a purchase concept. A refinance has none.** AS-2 checks earnest-money sourcing and
was not scoped by loan purpose, so on LF-WCHG — a refinance — it produced **10 `satisfied` findings for
a check that cannot apply**.

They were green, so they added no noise to Needs attention. That is what makes them worth fixing: they
are **false assurance**. 20 of the 34 rows in the Satisfied tab were AS-1 and AS-2 telling a processor
that large-deposit and earnest-money sourcing had been verified on a loan that has neither.

LP-509-A5 said so explicitly — *"**AS-2 shares this root cause** — earnest money is a purchase concept
and it ran here too"* — then scoped PC-2, PC-3 and PC-7 and left AS-2 with only the money-in gate.

## ⚠️ Refinance scoping is NOT symmetric across the assets family

This is the part that runs against intuition, and the guide is explicit. B3-4.2-02 waives large-deposit
**documentation** on a refinance but expressly **retains** the borrowed-funds duty:

> **Refinance transactions:** Documentation or explanation for large deposits is **not** required;
> however, the lender remains responsible for ensuring that **any borrowed funds, including any related
> liability, are considered.**

The logic: on a refinance the borrower brings no cash to closing, so *"prove this money is yours to
use"* is moot — but *"does the borrower have an undisclosed loan whose payment is missing from the
DTI"* is entirely live, because borrowed funds create a **liability**.

So **AS-12 must NOT be scoped out of refinances**; only the documentation-shaped checks are. Scoping
AS-2 out while leaving AS-12 in is the guideline, not an inconsistency.

## The mechanism: `applicability` accepts a conjunction

AS-2's scope is two facts — money-IN **and** purchase — and the DSL allowed one predicate. Both LP-509
and LP-516 bumped into this. Rather than a bespoke combined tag per rule (which merges two different
abstentions into one enum and loses the per-predicate reason), `applicability` now accepts a list.

```yaml
applicability:
  - {tag: txn.is_money_in, op: eq, value: in}
  - {loan_tag: loan.purpose, op: eq, value: purchase}
```

**Precedence, and it is not "first predicate wins":** every predicate is evaluated, then any
DEFINITELY-FALSE one gives `not_applicable` (scope-false beats data-missing — a money-out transaction is
out of scope whether or not the purpose is known), else any absent/unknown one gives `couldnt_check`
carrying **that** predicate's reason.

**`loan_tag` on a condition** mirrors the operand DSL's existing `loan_tag`. AS-2 is per-deposit while
`loan.purpose` is loan-level; without it the predicate is absent on every transaction and the rule
`couldnt_check`s all of them — measured, and **worse than leaving it unscoped**, since it moves 10 rows
from Satisfied into Needs attention.

Both are additive: a single condition is still valid and every pre-LP-517 spec is unchanged.

## Proof

| | verdict |
|---|---|
| purchase + money-in | the rule runs |
| **refinance** | `not_applicable` |
| purchase + money-**out** | `not_applicable` (LP-509-A1 preserved) |
| purpose **absent** | `couldnt_check` — never exempted |

## Expected effect

Satisfied **34 → 24**, with 10 moving to `not_applicable`. Needs attention unchanged. Fewer rows, none
of them lost — an honest tab.

## Not done: AS-1

AS-1 has the same gap (10 more `satisfied` on this refinance) but it is **not the same call**. The guide
says large-deposit documentation is *"not required"* on a refinance — not prohibited — so a lender may
still want them surfaced. That is a domain ruling, recorded in `priya-open-questions.md`.

⚠️ It also carries a live risk AS-2's did not: AS-1 returned `satisfied` only because every deposit fell
below its threshold. **Had one exceeded it, AS-1 would have FIRED on a refinance**, enforcing a
documentation duty the guide waives.
