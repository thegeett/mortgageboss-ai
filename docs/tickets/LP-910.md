## What was built

**Two shipped maps**, `uwm.yaml` and `champions.yaml`, **28 codes each**, each row carrying the
lender's own template id, a label, and optional defaults for bucket, owner hint and info-only.

**A loader** (`app/conditions/lender_codes/loader.py`) that validates on read and raises rather than
absorbs. **A seed step** (`uv run python -m app.scripts.seed_lender_codes`) that upserts them for
every lender claiming the matching `canonical_lender_key`.

## Decisions worth arguing with

**The seed matches on `canonical_lender_key` and never on the slug.** This is the STOP AND ASK the
survey raised (§15.1) and the product owner answered on 2026-09-23. `lenders` is company-scoped with
a slug unique only *per company* (ADR-045), chosen by each company — so a slug-keyed seed matches
nothing on some tenants and **the wrong row** on others, attaching UWM's code meanings to a different
lender's conditions with nothing downstream able to tell. A lender with the key unset is **skipped and
reported**, never guessed at; its codes arrive as `OBSERVED_UNMAPPED` on first import, which is the
path any unknown code already takes.

**Codes are strings, and the loader refuses a non-string rather than coercing it.** YAML reads an
unquoted `0006` as the integer `6`. `str(6)` is `"6"` — an identifier that looks plausible and
matches nothing, so the mistake would surface months later as a code that never resolves rather than
as an error at load. Both files quote every code, including Champions' where none currently has a
leading zero, so the rule is one rule rather than one per file.

**`canonical_type_id` is null on all 56 rows, deliberately.** The taxonomy it refers to
(`phase4.5-appendix-C-condition-taxonomy`) is **not in this repository**. The `AS-11`-style ids that
appear in `docs/rule-engine.md` and `docs/stage2-rule-classification.md` are **verification rule ids**
— a different vocabulary that happens to look alike, and mistaking one for the other would attach a
DTI rule's identity to a condition. Spec §LP-910 anticipates exactly this: leave them null and note
it. Stage 3 (LP-918) fills them.

**A re-run raises a status but never lowers one.** An `OBSERVED_UNMAPPED` row the seed can now explain
becomes `SEEDED`; a row a person has reviewed to `MAPPED` keeps it. Shipped data does not demote a
human decision. `times_seen`, `first_seen_at` and `last_seen_at` belong to the import path and are
left alone.

**The seed is not company-scoped, and this is the one place that is right.** `_lenders_for_key` reads
every active lender across every company that declares the key. The rows it writes are keyed
`(lender_id, code)` and so remain per-company by construction (ADR-407) — each company working with
UWM gets its own copy against its own lender.

### PyYAML is now a declared dependency — a STOP AND ASK, answered

`yaml` was already importable and **five existing loaders already used it**, but only because
`fastapi[standard]` happens to pull it in — `pyproject.toml` named it nowhere. Spec §9 makes a new
runtime dependency a STOP AND ASK, and first-party code resting on another package's dependency tree
breaks on an unrelated bump with an `ImportError` that names nothing about the cause.

Put to the product owner with three options; **answered 2026-09-23: declare it explicitly.**
`pyyaml>=6.0` is now in `dependencies` and `uv.lock` records it as a direct dependency. Already
resolved at 6.0.3, so this changed what is **declared**, not what is installed.

## Tests

`tests/conditions/test_lender_code_loader.py` — no database, because the question is whether the
shipped data is *valid*, not whether it is present.

| Test | What it pins |
|---|---|
| both maps parse, 28 rows each | LP-910's "every seeded code resolves" |
| **UWM codes keep their leading zeros** | the one that would cost months — asserts `"0006"` is present **and `"6"` is not**, because the failure produces a valid-looking code rather than a missing one |
| every enum value is real | the CHECK-tuple class of typo: `prior_to_doc` loads fine as a string, matches no `BucketKind`, and quietly downgrades every condition carrying that code |
| `canonical_type_id` is null throughout | pinned so Stage 3 filling them is a visible change rather than drift |
| a numeric code / missing label / unknown bucket / unknown hint is refused | four editing accidents a domain expert could plausibly make, each refused rather than absorbed |
| a null default is not confused with a typo | the distinction the enum resolver exists for, asserted in both directions |

## Verified

## NOT verified

**The seed has never run against a database.** No local Postgres — the same limit as LP-904's
migration. `seed_lender_codes(db)` is split from its CLI precisely so a test can drive it against a
session, and that test belongs with the import path in LP-909, where "an unknown code records as
`OBSERVED_UNMAPPED` rather than being dropped" becomes assertable end to end. What is verified here is
everything that does not need a database: the data parses, resolves and is refused when malformed.
