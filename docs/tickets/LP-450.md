# LP-450 — Step B: close the tag→field guard (extend it to MISMO, and prove derived/AI are already guarded)

## What this ticket is

A tag whose `data` reference points at a field that cannot exist resolves **silently to absent** — no load
error, no runtime warning — and its rule returns `couldnt_check` forever, looking like missing data. This is the
IH-1 shape: the value existed, the link was broken, nobody knew for months. Step D will write many tags against a
field surface that grew from 18 extractors to 109; this closes the guard first. **Code + tests only — no AI
calls** (Geet had ~$0.95 of API credit; nothing here re-extracts, reasons, or runs a live verification — the full
suite uses mocked/keyless stubs).

## D1 — the existing guard, and where it runs

The guard is `tests/verification/tag_materialization/test_parsed_declaration_fields.py` (LP-369). Its core:

```python
def _resolves(decl, doc_fields):
    field = _field_name(decl)                       # data with any ":suffix" stripped
    if decl.subject == "document":  return field in doc_fields      # extraction-model field names
    if decl.subject == "transaction": return field in _TXN_FIELDS
    return True  # borrower / loan — MISMO, not statically checkable (documented limitation)
```

It runs as a **CI test**, not a load-time check, because the authoritative field universe lives in
`app.ai.extraction.*` — a load-time check would force the deterministic tag loader (`declarations.py`) to import
the AI layer (a layering inversion).

**Load-time vs test — the argued answer:** load-time is preferable in principle (it cannot be skipped), and the
codebase already does it where the universe is *in-layer*: `declarations.validate_declarations` (called by the
projection loader) guards **derived** tags (`data` must be a key in `_RECIPES`) and **AI** tags (the group must
exist and *list* the tag). Those universes live in `declarations`' own layer, so no inversion. For the **parsed**
modes the universes are external (AI extraction models; the ORM + `mismo_section`), so the check stays a test —
LP-450 keeps parsed-field-legality unified in the one LP-369 test rather than splitting it. So field-legality is
now guarded for **every mode**: derived/AI at load, parsed field-existence in the test.

## D2 — the four universes

| mode | subject | `data` names | enumerable? | guarded where |
|---|---|---|---|---|
| parsed | document / transaction | an extraction field / `_TXN_FIELDS` key | ✅ | LP-369 test (already) |
| parsed | **loan / borrower** | a MISMO fact key / a `borrower.{n}.` suffix | ✅ **yes** (see below) | **LP-450 test (new)** |
| derived | any | a recipe key in `_RECIPES` | ✅ | `validate_declarations` (load) — **already** |
| ai | any | a group that lists the tag | ✅ | `validate_declarations` (load) — **already** |

**The ticket's premise that "every derived and AI tag are not guarded" is false** — they are guarded at load. The
real hole was **parsed loan/borrower**, which LP-369 explicitly skipped as "data-dependent, not statically
checkable." It IS statically enumerable: `build_mismo_section` emits the MISMO key space from a FIXED set of
`put(key, …)` calls, so the guard builds a fully-populated synthetic section (pure — transient
`SimpleNamespace` rows, no DB, no AI) and reads its keys. The measured universe: **28 loan-level keys**
(`loan.*`, `property.*`, file-level `liability.{n}.*` / `asset.{n}.*`) and **16 borrower suffixes** (`first_name`,
`citizenship`, `income.{n}.monthly_amount`, …).

**The residual (stated, not hidden):** `borrower.{n}.declaration.<slug>` slugs come from a borrower's free-form
declarations JSON — DATA-DEPENDENT. A `declaration.*` reference is accepted by prefix; its slug is not validated.
That is the one edge this guard cannot close.

## D4 — legality, not presence (expressible, asserted)

The guard checks whether a reference is a LEGAL member of the universe, never whether a value is PRESENT on a
given file. `middle_name` is a legal MISMO borrower field even for a borrower who has none (absent on that file →
the normal `couldnt_check` path) — and it PASSES the guard. `loan.refinance_type` is legal though absent on a
purchase file. Pinned by `test_legal_but_absent_mismo_field_does_not_fail__legality_not_presence`.

## D5 — the error (typo-obvious)

A failure names the tag, the bad reference, the universe, and the nearest legal matches (difflib). Example (a
constructed `maritalstatus` typo):

```
id.marital_status {subject: borrower, data: 'maritalstatus'} → 'maritalstatus' is not a legal MISMO borrower
field; nearest legal MISMO borrower fields: ['marital_status', ...]
```

## What was built

`tests/verification/tag_materialization/test_parsed_declaration_fields.py` — extended in place:
`_mismo_field_universe()` (the synthetic-section enumeration, index-normalised, `declaration.*` dropped);
`_resolves()` extended to check `loan` against the loan-key universe and `borrower` against the suffix universe
(with the `declaration.*` prefix residual); the main guard renamed
`test_every_parsed_declaration_names_a_real_field` and made mode-aware with nearest-match hints; new tests for a
bad loan ref, a bad borrower ref, the legality-not-presence case (D4), the `declaration.*` residual, the error
message (D5), and the universe's enumerability. **No broken tag was fixed** (there were none; a dead tag would be
reported, not silently fixed).

**Residual gap, stated:** `borrower.{n}.declaration.<slug>` slugs are not validated (data-dependent). No current
tag reads one.

## THE PROOF (reported, not predicted)

- **D3:** every mode checked; **0 broken tags** (table above).
- **A constructed bad reference fails per mode:** `loan.programme` / `property.purchse_price` (loan),
  `maritalstatus` / `citzenship` (borrower), `dob` / `ssn:hash` (document) — all rejected; the corrected forms
  (`loan.program`, `marital_status`, `date_of_birth`, `employee_ssn:hash`) resolve. Derived/AI: a bad recipe key
  / a group that doesn't list the tag raise `DeclarationError` at load (`validate_declarations`).
- **A legal-but-absent field passes** (`middle_name`, `loan.refinance_type`) — D4.
- **Equivalence:** ONLY a test file changed — no tag, rule, producer, prompt, or extractor was touched, so all 37
  live verdicts are byte-identical by construction; `ACTIVE_RULE_IDS` = 37; full suite green; ruff + mypy clean.
  Verified without any live verification run (the equivalence is structural).

## Assumptions / decisions

- The MISMO universe is enumerated from `build_mismo_section`'s own `put()` mapping (source of truth, can't
  drift) via a synthetic section — not a hand-copied key list.
- The guard stays a TEST (consistent with LP-369; the parsed universes are external to the loader). Derived/AI
  stay load-time (their universes are in-layer). Promoting the parsed check to load-time is a follow-up only if
  the layering is ever resolved.
- Collection indices (`borrower.{n}.`, `income.{m}.`, `liability.{k}.`) are normalised to `.{n}.` so a tag
  reading any index matches.

## NEW gaps / what remains

- The `declaration.<slug>` residual (data-dependent; unvalidatable). Reported.

## What step C and step D can now rely on

- **Step D** (writing many tags against the 109-extractor / MISMO surface) is now guarded on **all four modes**: a
  typo in a parsed document/transaction/loan/borrower field, a bad derived recipe key, or an AI group that
  doesn't list its tag all fail loudly (test or load) instead of resolving silently to `couldnt_check`. Only a
  `borrower.{n}.declaration.<slug>` slug is unguarded.
- **Step C** (the tag-coverage audit) can trust that no live tag points at a non-existent field today (D3).
