## What this ticket is

LP-400 landed `stmt.holder_name_variance` + `stmt.non_borrower_co_holder`, but two values were untestable:
`surname_differs` had **n=0** and `non_borrower_co_holder = yes` had **n=1** (N5 only). Building those scenarios
BEFORE Priya labels means ONE labeling round, not two (the LP-393 lesson). This adds three scenarios (N7, N8,
and the discriminating control N9) to LP-398's fixture and generates the blind worksheet for all three tags —
11 statements × 3 tags = **33 rows**.

- **D4 — row order.** GROUP BY TAG (all 11 match rows, then all 11 variance, then all 11 co-holder), so a
  scenario's three rows sit 11 apart and a labeler's answer on one tag can't reflexively bias the same
  scenario's next tag. Within each tag block, a deterministic statement order that does not cluster the
  positives (P1 at index 1, P2 at index 5).

**N9 is the key result:** a joint account of both borrowers returns co_holder `no`. The tag answers *"is a holder
a non-borrower?"* — NOT *"is this joint?"*. Without N9, the tag could have passed by conflating the two; it does
not. (Had N9 answered `yes`, that would have been a real semantic finding + an ADR — it did not.)

**The original 8 — unperturbed by the roster, with one flagged exception:**

yes/middle_absent/yes; P1 yes/middle_absent/no; P2 yes/nickname/no). **N2 moved again** (`no` → `yes`
"Roberta is a common feminine variant"). N2 has now flipped across all three runs — **LP-398 `unknown` →
LP-400 `no` → LP-401 `yes`** — and its reasoning cites *Robert* Chen, not Sarah. **This is N2's OWN inherent
ambiguity, NOT the roster:** it moved in LP-400 with no roster change, N9 proves the roster works, and the
other 7 are stable. **Finding + action:** N2 (Roberta vs Robert) is genuinely ambiguous, so it is
**RECLASSIFIED from clear-cut `no` to AMBIGUOUS** — Priya's label defines it. (The scenario itself is
unchanged; only its classification.)
