## The acceptance tests through the UI

The build prompt asks that both acceptance tests also run through the UI for the screens. What was
done:
- the harness (`scripts/visual-check/seed.py`, LP-934) builds each screen's state by calling the same
  services the acceptance tests call, in the same order;
- the builder shot every screen, and the reviewer re-shot and walked it in the browser;
- the Stage 3B fixes were re-shot on S3-07, S3-08, S3-09, S3-10 and S3-12.

What was **not** done: no test clicks through the UI end to end. The harness seeds the state through
services and the browser opens the result. The clicks themselves (Confirm plan, Mark as sent, Accept
anyway, Apply, Build package, Mark submitted) are covered by component tests against mocked hooks and by
the route tests. That gap is stated in the progress file's screen table rather than hidden under
"verified".
