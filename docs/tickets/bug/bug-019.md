# bug-019 — AS-12 refused to judge a deposit whose source it had already verified

- **Status:** Fixed
- **Date:** 2026-09-11
- **Found on:** staging `LF-XMB2`, reported by the processor: *"AS-12 text looks duplicate, only value
  and date are different"* — the duplication was bug-015; this is why there were four of them at all
- **Scope:** Backend — `rules/specs/AS-12.yaml` (one tag leaves `load_bearing_tags`)

## The report

Four of AS-12's seven findings on LF-XMB2 were `couldnt_check`, every one of them reading *"the deposit
category could not be read from the documents (it is present but unclear)"*. One was an **$8,000
deposit whose own tags say the source was found**:

```
txn.has_identified_source = yes
txn.source_strength       = verified      ("a matching own-account transfer of exactly $8,000.00
                                            posting on the same date")
txn.apparent_category     = unknown       ("Description only states 'DEPOSIT ID NUMBER 56195'")
```

AS-12 asks one question — could this money be **borrowed**? — and the file already answered it. The
rule abstained anyway, and told the processor nothing.

## The cause

A judgment rule's gate runs over its `load_bearing_tags` **before any AI call**, and abstains when any
of them reads "unknown" (`judgment.py`). AS-12 listed `txn.apparent_category` there.

That tag is the one the model can least often resolve — a bank line reading `DEPOSIT ID NUMBER 56194`
has no category to read — and the one AS-12 needs least: *borrowed or not* is answered by
`txn.has_identified_source`, which stays gated. So the least-resolvable input was given a veto over the
rule's whole question.

## The fix

`txn.apparent_category` leaves `load_bearing_tags` and stays everywhere else:

- in **`reasoned_over`**, so the model still sees it and the finding's provenance still carries it;
- in the activation bar's **`load_bearing_ai_tags`**, so the calibration gate still covers it;
- in **`exempt_when`**, untouched. That predicate clears a deposit only on a *definite* payroll or
  interest, and "unknown" is neither — the exemption still fails closed, and the model's answer can
  still only add a review, never remove one.

`txn.is_money_in` and `txn.has_identified_source` remain gated, so a deposit whose direction or source
genuinely cannot be read still abstains.

## What it does to LF-XMB2

The $8,000 deposit gets judged instead of abstaining. The $19,039.08 and $31,000 deposits — already open
under AS-1 — get a real AS-12 verdict rather than a second, contentless row. The cost is one AI call per
such deposit, and every AS-12 verdict is human-ratified regardless (`ships: ratify`).

## Tests

- an unknown category with a **verified** source reaches the model and returns a ratification-pending
  verdict (the LF-XMB2 $8,000 shape);
- an unknown category is **never exempted** — `exempt_when` needs a definite payroll/interest;
- a definite payroll **still clears by the guideline**, so LP-516 is untouched;
- an unknown **direction** still abstains, with no AI call;
- an unknown **source** still abstains, with no AI call.

**One existing assertion changed, deliberately.** `test_an_undetermined_category_never_exempts`
(LP-516) pinned both the invariant — an unknown category must never clear — and the route it took to
avoid clearing: `couldnt_check`, because the gate abstained before the model was asked. The invariant is
untouched and still asserted; the route is now "asked, then not cleared".

**And LP-516 decided that fork itself, in this direction** (established in review — the argument above
understated its own case). Its §A7 put the choice explicitly: *"scope-before-asking (cheaper, but
forfeits the guide's own escape hatch) or ask-then-suppress-a-no (costs an AI call per deposit, but
honours it)"*, and Phase B records the decision taken as **ask-then-suppress**. Gating the category
before asking IS scope-before-asking, applied to the one input the model can least often resolve. The
`| category unknown | couldnt_check |` row often cited for the opposite reading sits under "Phase C —
proof", which tabulates what the tests observed, not what was decided. So this change follows LP-516's
recorded decision rather than overturning it, and the cost in §2 below is a cost that ticket accepted in
writing. The full `tests/verification/` tree was run to find every such pin: this was the only one.

## Review — REVIEWED

Peer review of `280ee438` (second session). **The change is correct, and it is better supported than the
ticket argued** — LP-516 decided this exact fork in this exact direction. CI is green here too (2,708
passed, 0 failed). I corrected the argument, added the note the activation bar was asked for, and found
one processor-facing defect this change widens.

### The changed assertion: judged harshly, and it stands

Asked to attack it, and the attack fails — in the ticket's favour. LP-516 **§A7** posed the fork in as
many words: *"scope-before-asking (cheaper, but forfeits the guide's own escape hatch) or
ask-then-suppress-a-no (costs an AI call per deposit, but honours it)"*, and Phase B records
**ask-then-suppress** as the decision taken. Gating `txn.apparent_category` before asking IS
scope-before-asking, applied to the input the model can least often resolve. The
`| category unknown | couldnt_check |` row that looks like a contrary decision sits under "Phase C —
proof", which tabulates observed test verdicts.

So the test change is not an adjustment made to fit a new behaviour; it aligns the pin with the design
LP-516 chose. Both the ticket paragraph and the test docstring now cite §A7 instead of the file header.
And the cost question in the ticket's §2 is one LP-516 accepted in writing, per deposit, for this reason.

### Verified

- **Nothing else keyed on the gate.** `txn.apparent_category` is not in `distrusted_fields.yaml`, so the
  ADR-377 distrust guard loses nothing by the tag leaving the gate (it was worth checking: a distrusted
  value is caught in the gate, which is the step being removed). The tag's other roles are intact —
  `reasoned_over`, the bar's `load_bearing_ai_tags`, and both `exempt_when` predicates.
- **The exemption still fails closed**: it clears only `payroll` or `interest`, and "unknown" is neither.
- **Provenance and the subject label are unaffected.** A judgment finding's inline tags come from
  `reasoned_over`, not `load_bearing_tags` (the reason AS-12's findings never carried `txn.is_money_in`),
  so the amount and date that identify the row still reach it.
- **The activation bar did need the note** (question 3): its rationale read "both gates measured ->
  calibratable-now", which is now half true. Added, recording that the tag stays in the list because
  `reasoned_over` and the exempt path rest on it, so the calibration requirement is unchanged.

### Found: the finding a processor now reads can contradict itself

`guidance.action` keys on the MODEL'S VERDICT while `explain_by` keys on `txn.source_strength`, and
`judgment.py` renders the message as `action + "\n\n" + why`. For the LF-XMB2 $8,000 deposit — source
`verified`, category unreadable — any answer but "yes" produces:

> **Establish where the $8,000.00 deposit on 3/16 came from.**
>
> A matching withdrawal was found for this deposit, so its paper trail is complete; it is listed only
> because of its size.

with `how_to_fix` adding *"No further sourcing is needed if it is."* The row asks for what it
simultaneously says is already there. This is the failure the `none` case in that same block is
commented against: *"A sentence that contradicts the quote beside it reads as a system that cannot
read."*

It is **pre-existing** — a `transfer_own` deposit with a verified source and a model "no" renders the
same clash today — and **this ticket widens it** to every unknown-category deposit, which is exactly the
population being un-gated. Not fixed here on purpose: `action` cannot read the tag `explain` keys on, so
the repair is either a wording change to processor-facing prose or a structural change to the guidance
block, and both are the domain expert's call (LP-522/LP-527 territory, and this block's comments show it
has been iterated with her). Recorded here with the rendered text so it can be decided rather than
rediscovered.

Taken after the SSO login, and independently by both sessions in agreement. AS-12 on staging by outcome,
counting the abstentions this change converts into model calls (`message ilike '%category could not be
read%'`, which matches both the old "deposit category" wording and bug-015's "transaction category"):

| outcome | findings | files | category-caused |
|---|---:|---:|---:|
| no_longer_applies | 57 | 2 | 0 |
| needs_review | 29 | 7 | 0 |
| satisfied | 18 | 6 | 0 |
| **couldnt_check** | **12** | **4** | **4** |

So the entire cost across everything staging holds is **four additional AI calls** — the four LF-XMB2
deposits this ticket was written from. The worry was that a statement-heavy file would become many calls;
it does not. The other eight abstentions are caused by direction or source, which remain gated, so the
un-gating is as narrow in practice as it is in the spec — and LP-516 §A7 accepted this cost per deposit
in writing. Every AS-12 verdict stays human-ratified.
