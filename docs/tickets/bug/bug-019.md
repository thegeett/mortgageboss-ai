# bug-019 — AS-12 refused to judge a deposit whose source it had already verified

- **Status:** Fixed
- **Date:** 2026-09-11
- **Found on:** staging `LF-XMB2`, reported by the processor: *"AS-12 text looks duplicate, only value
  and date are different"* — the duplication was bug-015; this is why there were four of them at all
- **Scope:** Backend — `rules/specs/AS-12.yaml` (one tag leaves `load_bearing_tags`)

## The report

Four of AS-12's seven findings on LF-XMB2 were `couldnt_check`, every one of them reading *"the deposit
category could not be read from the documents (it is present but unclear)"*. One was an **$8,000
deposit whose own tags say the source was found**:

```
txn.has_identified_source = yes
txn.source_strength       = verified      ("a matching own-account transfer of exactly $8,000.00
                                            posting on the same date")
txn.apparent_category     = unknown       ("Description only states 'DEPOSIT ID NUMBER 56195'")
```

AS-12 asks one question — could this money be **borrowed**? — and the file already answered it. The
rule abstained anyway, and told the processor nothing.

## The cause

A judgment rule's gate runs over its `load_bearing_tags` **before any AI call**, and abstains when any
of them reads "unknown" (`judgment.py`). AS-12 listed `txn.apparent_category` there.

That tag is the one the model can least often resolve — a bank line reading `DEPOSIT ID NUMBER 56194`
has no category to read — and the one AS-12 needs least: *borrowed or not* is answered by
`txn.has_identified_source`, which stays gated. So the least-resolvable input was given a veto over the
rule's whole question.

## The fix

`txn.apparent_category` leaves `load_bearing_tags` and stays everywhere else:

- in **`reasoned_over`**, so the model still sees it and the finding's provenance still carries it;
- in the activation bar's **`load_bearing_ai_tags`**, so the calibration gate still covers it;
- in **`exempt_when`**, untouched. That predicate clears a deposit only on a *definite* payroll or
  interest, and "unknown" is neither — the exemption still fails closed, and the model's answer can
  still only add a review, never remove one.

`txn.is_money_in` and `txn.has_identified_source` remain gated, so a deposit whose direction or source
genuinely cannot be read still abstains.

## What it does to LF-XMB2

The $8,000 deposit gets judged instead of abstaining. The $19,039.08 and $31,000 deposits — already open
under AS-1 — get a real AS-12 verdict rather than a second, contentless row. The cost is one AI call per
such deposit, and every AS-12 verdict is human-ratified regardless (`ships: ratify`).

## Tests

- an unknown category with a **verified** source reaches the model and returns a ratification-pending
  verdict (the LF-XMB2 $8,000 shape);
- an unknown category is **never exempted** — `exempt_when` needs a definite payroll/interest;
- a definite payroll **still clears by the guideline**, so LP-516 is untouched;
- an unknown **direction** still abstains, with no AI call;
- an unknown **source** still abstains, with no AI call.

**One existing assertion changed, deliberately.** `test_an_undetermined_category_never_exempts`
(LP-516) pinned both the invariant — an unknown category must never clear — and the route it took to
avoid clearing: `couldnt_check`, because the gate abstained before the model was asked. The invariant is
untouched and still asserted; the route is now "asked, then not cleared", which is what LP-516's own
header describes ("the model is still consulted on every deposit; only a non-'yes' answer is
suppressed"). The full `tests/verification/` tree was run to find every such pin: this was the only one.
