# bug-020 — four untyped documents became five findings, and ID-5 asked for an ID the file already had

- **Status:** Fixed
- **Date:** 2026-09-11
- **Found on:** staging `LF-XMB2`
- **Scope:** Backend — `rules/specs.py` (a declared set), `rule_engine/applicability.py`
  (`undetermined_by_document_type`), `tag_materialization/derived.py` (ID-5's reason)

## The report

LF-XMB2 carries four documents the classifier could not identify — a driver's licence, an EAD card, a
third purchase agreement and a Chime statement. They produced **five** queue items, not one:

- the consolidated **UNIDENTIFIED-DOCUMENTS** finding, correctly naming all four; and
- four separate **LO-2** rows, one per document, each asking whether *this* file is a letter of
  explanation.

And **ID-5** told the processor to *"upload the borrower's unexpired government photo ID"* — while the
borrower's driver's licence sat in the file, unclassified.

## The cause

**LO-2 abstains on a proxy, and the consolidator only recognised the original.** LO-2's scope is eight
document types and the applicability DSL has only `eq`/`ne`, so it cannot scope itself on
`document.document_type` directly. It reads `loe.is_explanation_letter`, which a recipe computes from
the document type **alone**: "yes" for a letter type, "no" for anything else, "unknown" for an
unclassified document — fail-closed, so an untyped file is surfaced rather than silently declared "not a
letter".

`undetermined_by_document_type` (LP-640) decides whether an abstention folds into the consolidated
finding, and it ended `return cause == DOC_TYPE_TAG`. LO-2's cause is the proxy, so every untyped
document kept its own LO-2 row — the same question, about the same file, with the same remedy the
consolidated row already states.

**ID-5 filters to government-ID document types**, so an unclassified licence is skipped exactly as if it
were absent, and the reason said so: *"no driver's licence found for this borrower"*.

## The fix

1. **`DOC_TYPE_PROXY_TAGS`**, declared beside `DOC_TYPE_TAG`: tags whose value is derived from nothing
   but the document's own type, so abstaining on one *is* abstaining on the document type. Today that is
   `loe.is_explanation_letter` alone. The admission rule is written into the declaration: a tag belongs
   only if an unclassified document is the **sole** way it reads "unknown" — otherwise folding it in
   would send a processor after the wrong thing.
2. **`undetermined_by_document_type`** now also returns true when the cause is such a proxy *and* the
   subject's own document type is absent or "unknown" — the second half matters, because a proxy
   abstaining on a document whose type IS known is a different problem and must stay its own row.
3. **ID-5 says whether the file might already have it**: *"no driver's licence has been identified — 4
   document(s) in the file are not identified yet and may include it; identify those first"*. Counted
   file-wide, not per borrower, because an untyped document usually has no `belongs_to` either — scoping
   the count would hide the very documents being pointed at. The duplicated trailing *"for this
   borrower"* went with it; every branch of that recipe already opens *"this borrower:"*.

## Deliberately not in this ticket

**ID-3 and ID-8 carry the same shape** — ID-3 says only one document states the date of birth (the
licence would be a second), and ID-8 says work authorisation is not documented while the EAD card sits
untyped. Both are worth the same clause, but ID-3's message is built in `consistency.py` and ID-8's is
fixed spec wording, so each is a different edit in a different layer. They are bug-023.

### The admission rule: checked against the recipe, and it holds

The set's stated condition is that an unclassified document must be the SOLE way a member reads
"unknown". `_loe_is_explanation_letter` has exactly one path to `_UNKNOWN`:

```python
if doc_type is None or doc_type == _UNKNOWN_DOC_TYPE:   # the only "unknown" the recipe can return
```

Everything else returns `"yes"`, `"no"`, or `None` (declining a non-document subject, which materialises
no tag at all rather than an "unknown"). So the tag qualifies, and the LP-640 concern — folding a
different problem into "identify these documents" — does not arise for it.

Worth stating the limit of the second-half guard, since it is what protects the set from a future
mistake: it requires the SUBJECT's own type to be absent/unknown, which rejects a proxy that failed on a
TYPED document. It cannot distinguish a proxy that reads "unknown" for an unrelated reason *on an
untyped document*. For this tag that is moot (untyped is its only unknown), but a future member must be
read against the declaration, not waved in by the guard.

### Closed: the claim was asserted, not driven

The end-to-end test proved every LO-2 row carries `unidentified_document` — the INPUT to the collapse —
and stopped there, while the ticket says "four untyped documents produce one consolidated finding rather
than five rows". LP-640's suite proves the mechanism generically (22 rules × 3 documents → one finding)
over hand-built evaluations, so what was uncovered is precisely this ticket's sentence: that the new
proxy path reaches it. Added — real spec, real evaluator, real consolidator — asserting the four LO-2
rows leave the queue, the one row that replaces them is loan-level and still `couldnt_check`, it links
all four documents in order, and its text counts "4 documents"/"4 checks".

### Investigated and cleared: the two "unclassified" checks are both right

The commit lands two different-looking definitions, which is the shape that has been a real defect
repeatedly in this series — so it was worth running down. `undetermined_by_document_type` treats
`("", "unknown", None)` as unclassified; ID-5's count treats `(None, "unknown")`. They read DIFFERENT
sources and each is correct for its own: the predicate reads the DOC_TYPE_TAG *tag*, which
`enumerators._doc_type_tag` builds as `entry.document_type or "unknown"` — so its value is never `""`
and `doc_type is None` covers the tag being absent, leaving the `""` branch unreachable but harmless.
ID-5 reads `entry.document_type` off the entry, where `None` genuinely is the absent shape. No change
made; a "fix" here would have been churn.

### The other questions

- **The file-wide ID-5 count: endorsed.** A borrower-scoped count would read 0 in exactly the case that
  matters, because an untyped document usually carries no `belongs_to` — so scoping it would hide the
  documents the sentence exists to point at. That borrower A's row may cite what turns out to be
  borrower B's licence is acceptable because the remedy is identical and the wording says "may include
  it" rather than asserting ownership. It is honest about its own uncertainty, which is the property
  that matters.
- **The unclassified shapes and `documents.absent`: correct** (question 4). `(() if
  snapshot.documents.absent else ...)` means a degraded documents section counts zero untyped documents
  and ID-5 falls to the plain "no driver's licence found" — the right degradation: it declines to claim
  the file might already hold the licence when it cannot see the file at all.
- **Deferring ID-3 and ID-8 to bug-023: endorsed.** They are the same species in two other layers
  (`consistency.py`'s built message and fixed spec wording), and bug-015 is the precedent that layered
  text changes go wrong when rushed together — each wants its own diff and its own reading.
