# bug-018 — IN-4 asked for employment dates the application already carried

- **Status:** Fixed
- **Date:** 2026-09-11
- **Found on:** staging `LF-XMB2`
- **Scope:** Backend — `tag_materialization/derived.py` (`_income_max_employment_gap`)

## The report

IN-4 abstained on LF-XMB2 with:

> **Upload employment documentation with start and end dates for each position covering the two-year
> history…** The file has fewer than two dated employment records, so employment continuity cannot be
> verified.

The application on that file states, for one borrower, PNC ending **2026-03-03** and First National Bank
starting **2026-03-09** — two dated positions and a six-day gap, sitting in plain sight. The processor
was asked to upload dates the file already had.

## The cause

`income.max_employment_gap_days` is built from the document tags `income.employment_start` and
`income.employment_end`, and those are read from **VOE fields only** (`tag_production.yaml`). A file with
no VOE therefore has zero dated records, whatever the 1003 says.

The 1003's employment records have been in the snapshot since LP-624 —
`borrower.{n}.employer.{m}.start_date` / `.end_date`, beside the `is_current` flag bug-016 now reads —
and nothing consumed them.

## The fix

The recipe now merges the application's employer records into the **same per-borrower groups** the
document records use (`frozenset({borrower_id})` is exactly the key a `belongs_to`-attributed document
produces), so a VOE end can pair with a stated start rather than the two sources forming rival
timelines. Three properties are kept deliberately:

- **Never across borrowers.** A stated record whose borrower the application does not link to an id is
  skipped rather than grouped under the unattributed bucket — pooling it there could manufacture a gap
  between two different people, which is the one thing this recipe has always forbidden.
- **Only documents are named.** A date read from the application has no document behind it, so a gap
  measured from stated dates alone names nothing rather than pointing at a file that does not evidence
  it.
- **It runs with no documents at all.** The early return that skipped everything when the tags or
  documents section was absent now skips only the document half.

**And the abstention no longer says the wrong thing.** One sentence served two different absences:
genuinely fewer than two dated records, and records that exist but never pair (a single position, or
every start before every end). The second now says so.

## What it does to LF-XMB2

IN-4 moves from `couldnt_check` to **satisfied**: the borrower's gap is 6 days against IN-4's 30-day
window, so this removes a queue item rather than adding one. A gap beyond the window on some other file
would now fire where it previously abstained — which is the point.

## For the domain expert

**Is a gap computed from stated 1003 dates alone actionable?** IN-4's remedy is a letter of explanation,
and the guideline (B3-3.1-01/02) is about the borrower's actual history rather than about which document
evidences it — so acting on stated dates looks right. But a stated gap is unverified, and the rule will
now fire on one. If she wants a documented gap only, the fix is to require at least one document-backed
date in the pairing rather than to revert the merge.

## Tests

`test_employment_gap_mismo_bug018.py` — a stated prior position and a stated current one produce the
gap; a stated record merges with a document record for the same borrower; two borrowers' stated records
never pair with each other; a stated record with no borrower link is skipped; a gap from stated dates
alone names no document while a document-backed one still names its two; and the two abstentions now
read differently.
