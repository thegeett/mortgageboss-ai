# LP-511 — Fix the IN-3 regression introduced by LP-509-A3

**Status:** done
**Follows:** LP-509-A3 · **Blocks nothing** · **Blocked on:** LP-513 for the eventual per-borrower move

## What went wrong

LP-509-A3 did two things to IN-3. The first was right and stands; the second was wrong and is reverted.

1. **Fixed the arithmetic** — a cumulative YTD summed across pay stubs, a per-document documented monthly
   summed across documents, and a whole-month divisor. Together they reported a 62.6% income shortfall on
   a file that has none. **Kept.**
2. **Moved it from `loan` to `per_borrower`** to match IN-1. **Reverted.**

After the deploy, IN-3's finding on LF-WCHG was **not re-evaluated at all**:

```
rule    outcome  updated
IN-2    open     2026-08-16 13:44   <- today's run
RE-1    satisfied 2026-08-16 13:44
ID-6    satisfied 2026-08-16 13:44
IN-3    open     2026-08-14 21:50   <- two days old
```

and its stored reasoning was still the pre-fix text —
`YTD gross 78781.26 over 4 month(s) = 19695.32/mo vs documented 52615.42/mo`, `source_facts: ["loan"]`.

Two separate faults, both caused by the enumeration change:

**a. The rule now evaluates nothing.** `per_borrower` resolves subjects through documents' `belongs_to`
attribution, which on that file yields no borrower subjects at all — see LP-513. A live rule was
silently retired.

**b. Its previous finding was orphaned.** The old subject key is `"loan"`; the new enumeration produces
borrower keys. Nothing matches, so the finding is neither superseded nor marked `no_longer_applies` — it
simply persists, displaying pre-fix numbers in the Needs-attention tab. See LP-512.

## The fix

- **`subject_enumeration: loan`** again, with the corrected arithmetic intact. The de-duplication now
  happens over the document SET (`_distinct_documented_monthly` / `_latest_ytd`), which is
  scope-independent — only the enumeration reverted, and the per-borrower and loan-level callers share
  one implementation.
- **`{shortfall_percent}`** in the outcome template. The raw operand is a full-precision `Decimal`, so
  the finding read `falls short of documented by 0.6256740894589456855043635497`. Worse, on the
  read-only query path the identifier scrub matched the 9+ digit run and rewrote it to
  `0.[REDACTED-ID]` — the single number the sentence exists to convey was destroyed on the way to a
  reader. It now reads **"falls short of documented by 62.6%, beyond the 10.0% tolerance"**.
  The `_percent` companion is supplied by the evaluator for every Decimal operand
  (`deterministic._reason_fields`), additive so no existing template changes.

## Why not fix the attribution instead

That is the better end state and it is LP-513. Per-borrower genuinely is right for IN-3 — a loan-level
aggregate can mask one borrower's shortfall behind another's surplus (PIN #1). But a rule that silently
evaluates nothing is worse than one that aggregates, and the arithmetic fix is independent of the scope.

## Acceptance criteria

- [x] IN-3 is loan-scoped and evaluates on a file with documents
- [x] The three arithmetic fixes are unchanged (latest YTD, distinct documented, fractional elapsed)
- [x] The finding message renders a percentage, and survives the read-only scrub intact
- [x] The spec validator accepts `{name}_percent` and still rejects a genuinely unknown placeholder
- [ ] Re-run staging and confirm IN-3 re-evaluates (its `updated_at` moves)
