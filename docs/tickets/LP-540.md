# LP-540 — OC-2 corroborates the borrower's claim with the borrower's own claim

Deferred by the user on 2026-08-18. Not started. Found alongside [LP-539](LP-539.md).

## The defect

On LF-WCHG, `occupancy.consistent_with_signals` returned **`yes` at 95% confidence**,
concluding "All available occupancy signals align with the stated primary_residence
occupancy." Its three signals:

1. `declaration.intenttooccupytype = 'Yes'` — **the borrower's own claim.** OC-2's own
   system prompt forbids this: *"NEVER treat a stated value as self-proving (the
   borrower's claim is the thing under scrutiny, not the evidence)."*
2. `declaration.fhasecondaryresidenceindicator` absent — the model itself notes this is
   *"typical for non-FHA loans"*. A field that would not be present anyway, counted as
   support.
3. `property.financed_unit_count = 1` — equally consistent with a second home or an
   investment property. Not discriminating.

The one signal that could genuinely corroborate, `property.address_normalized_match`, is
**`unknown` — "no purchase contract states a property address."**

So the verdict is "the borrower said so and nothing contradicts it," presented as
corroboration.

## The structural half

LF-WCHG is a **refinance**. A refinance never has a purchase contract, so
`property.address_normalized_match` is `unknown` on **every refinance** — OC-2's only real
corroborating signal is permanently unavailable for an entire loan-purpose class.

Meanwhile `id.current_address_type` sits in OC-2's `reasoned_over` and was never used. On
a refinance, the borrower's current address against the subject property is exactly the
corroboration that IS available, and it is already in the rule's inputs.

## Scope

1. The `occupancy` tag prompt must not count the borrower's own declaration as
   corroboration of the borrower's own stated occupancy, nor count the absence of a field
   that would not appear on this loan type as support.
2. Use `id.current_address_type` / current-address-vs-subject on a refinance rather than
   treating the missing purchase contract as merely "one verification method unavailable."
3. Decide the honest verdict when the only support is the borrower's declaration. Probably
   `unknown` — which under OC-2 means couldnt_check, an honest gap rather than a
   corroboration that did not happen.

## Constraint

`occupancy.consistent_with_signals` is **shared with OC-1**, which AUTO-SHIPS on it
(activation_bars: OC-1's auto-ship is why that tag needed calibrating, where OC-2 did not
because it ratifies). Any prompt change here changes OC-1's behaviour too, and OC-1 has no
ratification standing between it and the file. Re-measure both.
