## D1–D4

- **D1 — the full edit list** is below (24 questions, 4 fields, 39 PII remaps).
- **D2 — is `ACCOUNT`'s last-4 mask right for all 14 kinds?** `ACCOUNT` masks to `****NNNN` (`pii.py`). For a
  passport / visa / I-94 / A-number this is the **standard document-number mask** — it protects all but the
  last four, exactly as SSN (`***-**-NNNN`) and an account number are masked. The goal here is **protection,
  not matching** (Geet's policy masks these identifiers), so last-4 is meaningful and not misleading. **No new
  mask strategy or `PiiKind` member is needed → no ADR.**
- **D3 — the redactor on key-value pairs.** LP-437's `redact` names row fields; `_list_row_fields` runs the
  shared `_DESC_REDACT` over each named field. `unmapped_key_value_pairs` rows carry `{label, value}`, so
  **`redact: ["value"]` scrubs the value of every pair** — the helper does exactly what Job 1D needs, no
  extension required.
- **D4 — any spec still blocked?** **None.** 0 blocking questions, 0 PII kinds outside the enum → 108/108.

## Assumptions / decisions

- Last-4 masking (`ACCOUNT`) is acceptable for document-number kinds (passport/visa/I-94) — protection, not
  matching; no new mask strategy (D2). NAME/PHONE/EMAIL unmasked, consistent with addresses and DOB.
- The four field additions are `rule_floor: true` where a future rule needs them (106) even though 106 serves
  no rule yet — that is exactly what `rule_floor` records.
