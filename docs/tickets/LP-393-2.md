# LP-393-2 — Scenario worksheet for Priya's blind labeling

## What this ticket is

LP-393-1 built the standalone income-scenario fixture and proved the blocked tags produce at n=11-13 (up from
2). This generates the labeling worksheet from `build_income_calibration_snapshot()` — reusing the existing
generator — so Priya can supply the goldens. It is **COMMITTABLE** (the scenario identities are invented — no
real PII), unlike the DB worksheet (LP-392, gitignored).

**Anti-anchoring is the ticket.** LP-393-1 already ran the real AI on these scenarios and REPORTED its answers,
and `CLEARCUT_EXPECTATIONS` holds B3-B8's expected values. **Neither may reach Priya's sheet** — if she sees
the AI's call (or our expectation), her label measures agreement-with-what-we-showed-her, not independent
judgment, and the ambiguous cases (B9-B13) are the entire point of this fixture.

## Acceptance criteria (met)

- A committable scenario worksheet with labelable rows for the 4 tags LP-393-1 unblocked; the thin /
  un-exercisable tags excluded (reported, not blank rows).
- NO prediction / confidence / AI reasoning / expected answer anywhere in the sheet — verified against
  LP-393-1's reported values and `CLEARCUT_EXPECTATIONS`.
- A neutral (non-leading) label prompt per tag; `source_document` present; plain ASCII; every golden cell
  empty.
- The LF-6T3N worksheets are byte-unchanged; no tag/rule/producer/snapshot change; `ACTIVE_RULE_IDS` unchanged
  (20); full suite green.

**The anti-anchoring proof (structural).** `build_worksheet` reads ONLY the snapshot (no AI call, no key) and
its signature is `(snapshot, document_filenames, only_tags, label_prompts)` — there is no path for a prediction
or `CLEARCUT_EXPECTATIONS` to enter, and `write_income_scenario_worksheet` never passes them (asserted by
source inspection). Every golden cell is empty; the prompt is UNIFORM across every row of a tag, so no per-row
answer can be smuggled into one row's context.

**The context column** shows the FACTS she reasons over and nothing else. Per-borrower income tags: that
borrower's income documents aggregated (`[w2] tax_year=…; employer_name=…; wages_tips_other_comp=… || [w2] …`)
— the same shape LP-379-B used. Asset rows: the account's `institution_name / account_type / total_value /
vested_balance / vesting_schedule`. Enough to judge; no hint of an answer.

**The scenario id column is OMITTED** — the subject_id (the borrower UUID / the asset content-id) already
identifies each row, and a descriptive label ("small 2% drop") would anchor. In doubt → omit (a bare id adds
nothing she needs).

## Phase 1 — what changed (generic; LF-6T3N-safe)

- **`worksheet.build_worksheet`** gained `only_tags` (restrict the sheet to a tag set) and `label_prompts`
  (override a tag's neutral question per id). Both default to None → **the LF-6T3N path is byte-unchanged**
  (the prompt is now appended in the borrower/document branches too, but only when non-empty — and only
  `has_identified_source` declares one).

  `write_income_scenario_worksheet(out_dir)` → `docs/calibration/income-scenario-labels.csv` (committable).

## The label prompts (quoted — neutral, not leading)

- `has_2yr_history`: "Do these income documents EVIDENCE this income across at least TWO consecutive years?
  yes / no / unknown"
- `is_declining`: "Comparing the documented income across the years shown, is there a year-over-year DECREASE?
  yes / no / unknown"
- `same_line_of_work`: "If the documents show an employer or role change, is the new role the SAME line of
  work? (one employer throughout = yes) yes / no / unknown"
- `asset.liquidation_terms`: "Per this statement's own terms, what portion of the account is usable?
  fully_liquid / vested_usable / restricted / unknown"

Each asks the OPEN question + offers `unknown` — never asserts an answer ("this looks like…", "confirm…").

  facts she reasons over, a uniform neutral prompt), so no scenario is mis-designed on that axis.

  (fixed-term only) and IN-12 is un-exercisable here (the LP-390-2a producer gap). They are NOT calibratable
  from this fixture; a future ticket needs fixed-term/other-income variety + `income.type` (IN-13) and a
  tax-return-reading producer (IN-12).
- **Committable, confirmed:** invented identities, no PII markers — unlike the DB worksheet (LP-392) this file
  is committed for Priya to open directly.
- **What LP-393-3/4 inherit:** 45 rows for the blind session (13/13/13 income + 6 asset), the goldens Priya
  fills becoming the definitions for the ambiguous cases; the clear-cut auto-check runs off
  `CLEARCUT_EXPECTATIONS` (in code, never the sheet).
