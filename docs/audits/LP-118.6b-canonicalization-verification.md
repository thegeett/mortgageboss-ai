# LP-118.6b — Category canonicalization mechanism: verification audit

**Type:** Read-only verification (no code changed) · **Date:** 2026-07-07
**Scope:** the canonicalization mechanism shipped with LP-118.6 (commit `3c37d7a`).
**Files audited:**
- `backend/app/verification/fact_namespace/canonicalize.py`
- `backend/app/verification/fact_namespace/canonicalization_map.json`
- `backend/app/verification/fact_namespace/builder.py`
- `backend/app/verification/fact_namespace/snapshot.py`
- `backend/app/verification/fact_namespace/__init__.py`
- `backend/tests/verification/test_fact_namespace.py`

**Headline:** The mechanism is **correctly built** and matches the intended
map → AI-fallback-seam → learn design. The critical guard (#3) holds: an unmapped
string is **never silently ignored** — it is recorded and marked `UNMAPPED`. No
faked AI (#4). Canonicalization runs at build time and is frozen (#6). No blocking
gaps; a few non-blocking notes are listed at the end.

---

## 1. Does it exist? — **PRESENT**

The mechanism is a real, self-contained module: `canonicalize.py`. The build-time
entry point is `Canonicalizer.canonicalize(field_name, raw)` (`canonicalize.py:91`).

It is applied to **all three** raw category fields, called from the fact-builder at
build time:
- `income_type` — `builder.py:127` (`income_type_canonical=canon.canonicalize("income_type", item.income_type)`)
- `liability_type` — `builder.py:183`
- `asset_type` — `builder.py:197`

The canonicalizer is instantiated once per run inside `assemble_fact_namespace`
(`builder.py:358` — `canon = canonicalizer or Canonicalizer()`) and threaded into
`_build_borrowers` / `_build_liabilities` / `_build_assets`. It is genuinely wired
into fact-building, not dead code.

**Verdict: present.**

---

## 2. Map first — **PRESENT**

A curated, version-controlled map exists as a config file (not scattered inline):
`canonicalization_map.json`. It is loaded once via `_load_maps()`
(`canonicalize.py:64`, path resolved at `canonicalize.py:35`), which strips
`_`-prefixed meta keys.

Structure is one entry per field, each with a `vocab` (allowed canonical values) and
a `map` (raw-variant → canonical):
- `income_type` — `canonicalization_map.json:6` (vocab at `:7`; ~35 variants at `:8`–`:45`, e.g. `base pay`, `w-2`, `1099`, `k1`, `social security` → `fixed`).
- `asset_type` — `canonicalization_map.json:47` (e.g. `401(k)` → `retirement`, `gift of cash` → `gift`).
- `liability_type` — `canonicalization_map.json:81` (e.g. `heloc` → `revolving`, `auto lease` → `lease`).

Lookup is normalized (lowercase / trim / collapse whitespace) before matching —
`_normalize` (`canonicalize.py:38`) used by `canonicalize` at `canonicalize.py:100`,
and the map's `_meta.normalization` documents this (`canonicalization_map.json:4`).
A map hit returns `Fact.present(mapped, source=CANONICAL_MAP)` (`canonicalize.py:104`).

**Verdict: present** — deterministic, curated, version-controlled, reviewable.

---

## 3. AI fallback for misses — **PRESENT (correct — no silent drop)**

This is the critical check. On a map miss, the code does **not** silently ignore or
default the string. The flow (`canonicalize.py:102`–`115`):

1. `mapped = self._lookup(...)` — miss returns `None` (`canonicalize.py:102`).
2. `answer = self.fallback.classify(field, raw, vocab)` — the miss is handed to the
   fallback **seam** (`canonicalize.py:106`).
3. If the seam answers → `Fact.present(..., source=CANONICAL_AI, confidence=...)` and
   the answer is learned (`canonicalize.py:107`–`111`).
4. If the seam returns `None` → the miss is **recorded** and marked:
   ```python
   self.misses.append((field_name, raw))            # canonicalize.py:114
   return Fact[str](value=None, source=FactSource.UNMAPPED)   # canonicalize.py:115
   ```

So an unmapped string becomes a first-class `UNMAPPED` fact **with the raw value
still available** on the item (`income_type_raw`, `builder.py:126`) — recorded in
`Canonicalizer.misses` (`canonicalize.py:77`) for the eval set. It is **not** dropped,
**not** defaulted to a bogus canonical value, **not** coerced to `"other"`.

Confirmed by test `test_canonicalization_map_and_unmapped_seam`
(`test_fact_namespace.py:215`–`227`): `"Moonlighting gig"` → `value is None`,
`source == UNMAPPED`, and `("income_type", "Moonlighting gig") in canon.misses`.

**Verdict: present and correct.** The brittle silent-ignore failure mode the design
exists to prevent is **not** present.

---

## 4. No faked AI — **PRESENT (seam, not fabrication)**

No live AI call is wired in this ticket. Instead there is a clearly-marked seam:
- `CanonicalizationFallback` Protocol (`canonicalize.py:51`–`54`) — the interface
  LP-120 fills (`classify(field, raw, vocab) -> FallbackAnswer | None`).
- The default `NoFallback` (`canonicalize.py:57`–`61`) returns `None` — it classifies
  nothing and forces the `UNMAPPED` path. It does **not** invent canonical values.

The default `assemble_fact_namespace` uses `NoFallback` (`builder.py:358`), so in the
live path today every map miss is honestly `UNMAPPED` (value `None`), never a
hallucinated category frozen into the snapshot.

The tests do **not** assert hallucinated values. The only `CANONICAL_AI` assertion
uses a **test-local** `StubFallback` the test itself defines and injects
(`test_fact_namespace.py:230`–`248`) — production code never fabricates. The stub's
canonical (`"other"`, conf `0.6`) is the *test's* injected value, exercising the seam
contract, not a production classification.

**Verdict: present.** Documented seam; no faked AI; `CANONICAL_AI` only appears when a
real fallback is injected.

## 5. Learn — **PRESENT (in-run only — by design)**

A fallback answer is recorded back so the same normalized key needs no second call
**within the run**:
```python
self._learned.setdefault(field_name, {})[key] = answer.canonical  # canonicalize.py:108
```
`_lookup` checks the curated map **and** `_learned` (`canonicalize.py:84`–`89`), so a
repeat string in the same run resolves from the learned cache.

Confirmed by `test_canonicalization_ai_fallback_seam_is_deterministic`
(`test_fact_namespace.py:230`–`248`): two calls with the same normalized key
(`"Moonlighting gig"` / `"moonlighting gig"`) hit the fallback **once**
(`stub.calls == 1`), the second served from the learned cache.

**Scope note (explicitly documented, not a defect):** learning is **in-run only** —
the `_learned` dict lives on the per-run `Canonicalizer` instance and is not written
back to `canonicalization_map.json` or a learned table. Persistent cross-run learning
is deferred to LP-120 (`canonicalize.py:17`–`19`, module docstring). So across runs
the same unknown re-hits the fallback until LP-120 persists it.

**Verdict: present (partial by design).** In-run learn works; cross-run persistence is
a declared LP-120 follow-up.

## 6. Frozen at build time (determinism) — **PRESENT**

Canonicalization runs only during fact-**building** and its result is stored as a
frozen `Fact[str]` in the snapshot:
- The only `canonicalize()` call sites are in `builder.py` (`:127`, `:183`, `:197`).
  A repo-wide grep found **no** `canonicalize(` / `.classify(` / `Canonicalizer(`
  call outside `builder.py` and the module itself — nothing at eval/projection time.
- The result is a typed field on the snapshot models: `IncomeItemFacts.income_type_canonical: Fact[str]`
  (`snapshot.py:100`), `LiabilityFacts.liability_type_canonical` (`snapshot.py:163`),
  `AssetFacts.asset_type_canonical` (`snapshot.py:175`).
- The snapshot round-trips losslessly: `save_fact_snapshot` uses `model_dump(mode="json")`
  (`__init__.py:36`) and `load_fact_snapshot` uses `FactNamespace.model_validate`
  (`__init__.py:43`), preserving `source` + `confidence` per fact.
- The rule-eval-facing projection (`projection.py`) reads frozen snapshot values and
  contains **no** canonicalize/classify call (grep confirmed; it only reads
  `doc.document_type` at `projection.py:62,127`).

There is **no** code path where canonicalization or an AI call happens at
rule-evaluation time.

**Verdict: present.** Deterministic: canonicalize once at build, freeze, read frozen.

## 7. Provenance / confidence — **PRESENT**

Map-hits, AI-guesses, and misses are distinguishable once frozen, via
`FactSource` (`snapshot.py:40`–`52`):
- `CANONICAL_MAP` (`snapshot.py:47`) — deterministic map hit.
- `CANONICAL_AI` (`snapshot.py:48`, commented "silent-misread risk") — fallback-classified.
- `UNMAPPED` (`snapshot.py:49`) — miss, no answer.

Confidence is a first-class field on `Fact` (`snapshot.py:71`, "Set for AI-canonicalized
values") and is set only on the AI path (`canonicalize.py:110`); map hits carry no
confidence (`canonicalize.py:104`). Plus `Canonicalizer.misses` (`canonicalize.py:77`)
collects `(field, raw)` pairs for a future eval set.

**Verdict: present.** A downstream reviewer can filter `source == CANONICAL_AI` (and
low confidence) for eval-set validation, and `UNMAPPED` for map-coverage gaps.

---

## 8. Scope / reuse — **PRESENT (one general mechanism; document_type correctly excluded)**

It is a **single** general mechanism parameterized by `field_name` + per-field `vocab`,
not hardcoded per field. `Canonicalizer.canonicalize(field_name, raw)`
(`canonicalize.py:91`) is field-agnostic; `_vocab`/`_lookup` key off `field_name`
(`canonicalize.py:79`,`:84`); income/asset/liability all call the *same* method
(`builder.py:127,183,197`). Extending to a new category is a new JSON vocabulary, no code.

`document_type` is **not** re-canonicalized here — it is passed through raw
(`builder.py:223` → `snapshot.py:118` `document_type: str | None`), correctly leaving
document classification to the existing document classifier. No duplication.

**Verdict: present.** General, reusable, and it avoided re-doing `document_type`.

## Summary — safe to commit

The category canonicalization mechanism is **correctly built and safe to commit** with
LP-118.6. All eight properties hold:

| # | Property | Verdict |
|---|----------|---------|
| 1 | Exists, applied to income/asset/liability, called at build | present |
| 2 | Map-first, version-controlled JSON | present |
| 3 | **Unmapped → seam, recorded UNMAPPED (never silent-ignore)** | **present (correct)** |
| 4 | No faked AI (documented seam; NoFallback default) | present |
| 5 | Learn (in-run; cross-run deferred to LP-120) | present (partial by design) |
| 6 | Frozen at build time; no eval-time AI | present |
| 7 | Provenance (`CANONICAL_MAP`/`CANONICAL_AI`/`UNMAPPED`) + confidence | present |

The single most important check (#3) is satisfied: a self-employment / gift string the
map misses is surfaced as `UNMAPPED` with its raw value retained and logged in
`misses`, not silently dropped or mis-defaulted.

### Non-blocking notes (for LP-120, not fixes-before-commit)

- **Live path has no AI today.** With the default `NoFallback` (`builder.py:358`),
  every map miss in production is `UNMAPPED` (value `None`) until LP-120 injects a real
  fallback. This is intended, honest, and non-silent — but until then a rule reading
  `*_canonical.value` gets `None` for any string not in the curated map. Map coverage +
  the LP-120 AI seam are what light up self-employment/gift branching for unseen strings.
- **`misses` is in-memory, not persisted into the snapshot.** The eval-set list lives on
  the transient `Canonicalizer` instance (`canonicalize.py:77`); it is not written to
  `fact_snapshot`. The signal is still recoverable from the frozen snapshot (each item
  keeps `*_raw` + `source == UNMAPPED`), but a caller wanting the tidy `misses` list must
  read it off the live object before discarding it. Consider surfacing misses in the
  snapshot when LP-121 wires the runner.
- **No runtime assertion that map values ⊆ vocab.** The JSON is curated correctly today
  (every map value is in its `vocab`), but nothing enforces it at load; a future edit
  could introduce an out-of-vocab canonical silently. A cheap `_load_maps` validation
  would harden the curated file. Cosmetic.
