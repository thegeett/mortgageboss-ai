01 — What's actually thereThe engineering is ahead of the interface

This is not a codebase in trouble. The rule engine distinguishes open from couldnt_check from pending_automation so a gap in evidence can never read as a pass. Findings carry their guideline citation from the spec rather than from the model's memory. Needs carry falsifiable source facts. Calculators show their arithmetic and let a processor override any input. The comments in rule-findings.ts argue about whether "violation" is a word processors actually use.

That is a rare amount of care about telling the truth to a human being. The interface does not yet carry it. Nine things stand between the two, found by reading rather than guessing.

02 — The directionLedger

The name is the structural idea, not decoration. A ledger has two columns that must reconcile, a rule between them, and a hand in the margin where they don't. That is literally what a loan file is, and it gives the system a shape that is specific to this product rather than borrowed from whatever dashboard shipped last week.

Six rules, enforceable in review

  1. Hairlines, not cards. One pixel of --line and a surface step do every job a border-radius-plus-shadow was doing. Shadows are reserved for things that genuinely float: menus, dialogs, tooltips. This alone removes about a third of the visual weight of the verification screen.
  2. Weight stops at 600. No 700 exists in the system. Hierarchy comes from size, colour and space. On a screen with forty labels, bold is not emphasis — it is noise with a reputation.
  3. One accent, spent only on primary action and active state. Not on links, not on headings, not on icons. Petrol #12545E because it sits far from red, amber and green in hue and therefore never argues with a status.
  4. Status is three channels: colour, glyph shape, word. Always all three. Remove the colour and the row still reads.
  5. AI state is a left rail and an icon, never a background fill. Fills stack badly — what does a hovered, focused, low-confidence, conflicting field look like? — and they cost contrast. A 2px rail scans vertically down a forty-field form and composes with everything.
  6. Every number that lines up in a column is tabular-nums. Money, rates, dates, ratios, file IDs. Non-negotiable.

Typeface

The current stack is -apple-system, BlinkMacSystemFont, "Segoe UI" — which is to say, no decision. IBM Plex Sans instead: engineered for product UI at 13px, real personality in the sheared terminals and the single-storey g, and it brings IBM Plex Mono for the thing this app does constantly — money, ratios, loan IDs, source citations, formulas. A third face, IBM Plex Serif, appears in exactly one place: quoted text lifted verbatim from a document. A serif in italic makes "this is the document speaking, not the app" legible without a label.

Why not Inter Inter is the default every AI-assisted redesign reaches for, and it would make this app look like every other B2B tool. Plex costs nothing extra and gives the product a face. It is also, not incidentally, a typeface commissioned for an institution that sells trust in systems.

The tokens

This replaces the :root block in app/globals.css wholesale. Two changes of principle: there are now two border tokens, because the hairline that is beautiful as a table rule fails WCAG 1.4.11 as an input border; and there is a separate AI hue that is not a status and never means "bad".

/* Ledger — light. Dark redefines only these values. */
:root {
  /* neutrals, biased faintly cool so they read as chosen */
  --background:       #FBFCFC;   --surface:      #FFFFFF;
  --surface-2:        #F3F5F5;   --surface-3:    #ECEFEF;
  --foreground:       #101617;   --foreground-2: #47514F;
  --muted-foreground: #6C7674;   /* 4.6:1 — the floor for 13px */

  /* two borders, deliberately */
  --border:           #E3E7E6;   /* decorative: rules, dividers */
  --border-strong:    #CDD3D2;
  --border-control:   #A9B1AF;   /* ≥3:1 — inputs, checkboxes, selects */

  /* one accent */
  --primary:          #12545E;   --primary-hover: #17707D;
  --primary-soft:     #E4EFF0;   --ring:          #12545E;

  /* status — always paired with a glyph and a word */
  --blocking:         #B23A2A;   --blocking-soft:  #FAEDEA;
  --attention:        #8F5D08;   --attention-soft: #FAF2E1;
  --verified:         #1B6E52;   --verified-soft:  #E6F2EC;

  /* provenance — NOT a status */
  --ai:               #5B4FA8;   --ai-soft:        #EEECF9;

  /* geometry: tool, not marketing site */
  --radius:           5px;       --radius-container: 8px;
  --row-compact:      28px;      --row-comfortable:  36px;
  --row-relaxed:      44px;

  /* shared with the backend's thresholds */
  --confidence-standard: 0.85;   --confidence-critical: 0.97;
}

Radius is the quiet one. shadcn ships 0.5rem and the app kept it; 5px for controls and 8px for containers is the difference between "product" and "landing page", and nobody will be able to say why the new one looks more serious.

The document reviewer, in detail

This is the one that does not exist yet and pays for itself fastest. Four decisions worth stating up front:

State lives on the left rail, not the background. A field that was extracted with high confidence and passes its rules gets no chrome at all — no yellow, no badge, nothing. Rossum-style products colour every freshly extracted field amber, which works for a twelve-field invoice and is useless for a loan file with 150 fields across fifteen documents, where everything is amber on load. Amber here means "a human needs to look at this", and it is rare enough to mean something.

Criticality overrides confidence. A 0.97-confidence loan amount, note rate, SSN or income figure still gets flagged. Two thresholds, both already expressible in the token block above: 0.85 for ordinary fields, 0.97 for the ones that move a decision.

Confidence is words and a location, never a decimal. "Matched to the paystub, page 2, YTD line" is worth more than "0.91", and "99.73%" is worse than both — false precision reads as a system that does not know what it does not know. The number belongs in a hover, next to the grounding excerpt.

An inferred value is badged as inferred. A figure the model carried over or derived, rather than read off a page, must not look identical to one it read. That is the difference between a defensible file and an audit finding, and the extraction shape already has the field to drive it.

One guardrail worth copying exactly When a field is selected and the processor clicks a different value on the document, navigate to that other field rather than overwriting the selected field's value. It is the single most common destructive misclick in this entire interaction pattern.

Keyboard

The review loop should be operable without the mouse, because the metric that matters is flagged fields per minute: Tab to the next field needing attention (skipping confident ones), Enter to accept, E to edit, R to reject, [ and ] between documents, ⌘Enter to mark reviewed and advance. Underneath it, the tables need the ARIA grid pattern with a roving tabindex — a 40-row, 9-column table must not be 360 tab stops, which is what tabIndex={0} on every row in file-table.tsx currently produces.

04 — SequenceFive phases, each shippable alone

Phase A~2 days

Fix what's broken, land the tokens

Add the missing danger colour or replace all twenty usages with destructive — the failure banner has been invisible for a while. Land the token block, the Plex faces, and the dark palette the config already promises. Collapse the six status maps into one StatusToken component taking a semantic state and rendering rail, glyph and word. Nothing visual ships yet except that the colours are now real.

Phase B~3 days

Shell and density

Drop max-w-6xl. Replace the sidebar with the shadcn sidebar block at collapsible="icon", cookie-persisted so it doesn't re-expand on every navigation. Add the context rail on file routes. Set table rows to 28px with a persisted per-person density preference. Delete the /loan-files stub. This is where the app starts feeling different.

Phase C~4 days

Verification, de-nested

Lift the outcome tabs to the top level of the page. Findings become rail-coded rows rather than cards. Calculator strip with the arithmetic shown. Group the six couldnt_check findings by the document they are missing so "request all four" is one action instead of six. No backend change — every field this needs is already on RuleFinding.

Two deliberate departures in the mockup: couldnt_check gets its own tab rather than sitting inside Needs attention (the batched request action in the context rail is what makes that safe — the gaps stay loud, they just stop crowding the real findings), and Needs gets its own route instead of living halfway down the Overview.

Phase D~2 weeks

The document reviewer

The real work, and the differentiator. Three resizable panes with the split persisted, container queries on the fields panel so it reflows to its own width rather than the window's, bidirectional field ↔ box linking, provenance chips, and the keyboard rhythm. Needs page images and box coordinates from the extraction pipeline — worth scoping against the backend before committing to the date.

Phase E~3 days

Accessibility pass

Contrast audit at 13px against every surface including zebra rows. :focus-visible rings at 2px with 2px offset, plus scroll-margin-block so focus never lands behind the sticky header. 24px minimum for icon buttons. Keyboard alternatives for column and pane resize. A colour-vision-deficiency simulation pass over every status state.

On Tailwind v4

Worth doing, and worth doing separately from the visual work so a regression has one obvious cause. The upgrade codemod handles most of it; five changes silently alter appearance and need a hand audit: default border colour becomes currentColor, ring width drops from 3px to 1px, shadow-sm becomes shadow-xs, outline-none becomes outline-hidden (and outline-none now genuinely removes the outline — an accessibility regression waiting in migrated code), and the important modifier moves to the end. Check the browser floor first: v4 needs Safari 16.4+, Chrome 111+, Firefox 128+, which matters if any of your processing companies run managed machines.

05 — Decisions I'd want from youFour forks

Petrol, or keep the blue?

The current #2563EB is Tailwind's default blue — the most common accent on the web. Petrol is a real choice and clears every status hue. Recommended: petrol. If there's brand equity in the blue I don't know about, the rest of the system works with it unchanged, minus a little separation from the "info" state.

Dark mode now, or later?

The tokens are written either way, so it costs one CSS block plus a toggle. Processors work in bright offices, so light stays the default. Recommended: ship both in Phase A — it is nearly free now and expensive to retrofit after 125 components pick up hard-coded greys.

Base UI or stay on Radix?

shadcn now initialises on Base UI and Radix is not deprecated; both ship for every component. With this much existing Radix surface, migrating during a visual redesign means two variables and one bug. Recommended: stay on Radix and revisit as its own project.

Does the extraction pipeline store box coordinates?

SourceLocation currently carries page and snippet. The reviewer's highlight needs a rectangle. If the coordinates aren't stored, Phase D starts in the backend, and a snippet-match fallback (find the snippet in the page's text layer, highlight it) is a decent interim. This is the one answer that changes the plan.
