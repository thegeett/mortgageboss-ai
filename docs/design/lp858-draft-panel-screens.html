The same pattern LP-851 uses for the append warning — quote their own line back at them.

Open — decision 3, and the one that matters A generated draft is linked to needs items, and LP-801 writes details.docs_requested on the finding — which makes the request button render as “Requested” and disabled. If deleting a draft does not unwind that, the file claims a request that exists nowhere, with the retry greyed out. My recommendation: it un-requests, reusing _clear_finding_markers, which already exists from the bounce path.

Three things the screens can't decide for you

  1. Row on click, or on first keystroke? Drawn as click, per your words. First keystroke is the one that survives a closed tab — recommended.
  2. What counts as “no detail”? Recommended: delete only when To, Subject and body are all empty. A typed recipient is work.
