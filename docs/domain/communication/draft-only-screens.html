Draft only — the screens

Ten screens and two research answers. Your five decisions are settled and built in; the two questions you asked back — the Gmail-grade toolbar, and whether we can open Gmail or Outlook directly — have answers that change the storage layer and add a settings screen.

Settled

✓

One open draft per party

“Create a second draft” does not exist. The dialog offers add to it, or I've sent it — mark sent and start fresh.

✓

The body_edited flag

Set the first time a saved body differs from the generated one. The dialog warns before an append rewrites a processor's words.

✓

The per-document note is gone

No more “Anything to add for the borrower?” form. The request runs on the click.

✓

A party draft is always named

Even when no dialog is needed. A draft the processor does not know exists is the failure you flagged about the buckets.

✓

No “Write to another party” button

Removed — which means the address has to be typed somewhere else, because 13 of 167 document types have nowhere to send. Screen 10.

Answer 1 — the toolbar, and what it costs

Gmail's compose bar, button for button, and what I would take. Then the part that is not free.

The part that is not free. The stored body is one plain string today, converted in and out by emailBodyToHtml / htmlToEmailBody. Underline, links, numbered lists, indent and quote cannot round-trip through that string — LP-849 chose the narrow schema precisely so the editor could not produce something the converter drops. Answering “make it like Gmail” therefore means storing HTML instead of a plain string, and that is the largest single item in this version.
1

Store HTML, not ProseMirror JSON

HTML is what the clipboard needs, what a future send provider needs, and what anything outside the editor can read. JSON would make the editor the only thing that can render a draft.

2

Resolve placeholders before the HTML exists, not after

finalise_draft_body substitutes into a plain string. Run it at generation time and convert once — a placeholder split across <strong> tags is a bug that only shows up on the one draft where someone bolded half a name.

3

Sanitise on the way in, server side

email-body.ts is safe today by construction — it escapes everything, then emits its own tags, so there is no passthrough to leave open. Storing author HTML ends that, and an allowlist on the server replaces it. This is the security consequence of the toolbar and it must be in the same ticket.

4

Derive the plain text, never store it twice

mailto: and every compose deep link need plain text. Strip it from the HTML on demand. Two stored copies of one message is the “one fact, two places” pattern that has bitten this codebase seven times.

Answer 2 — yes, we can open Gmail or Outlook. No, they cannot carry the formatting.

Every web compose route exists and takes to, subject and body. Every one of them takes the body as plain text.

RouteURLBody
Gmailmail.google.com/mail/?view=cm&fs=1&to=…&su=…&body=…plain
Outlook — workoutlook.office.com/mail/deeplink/compose?to=…&subject=…&body=…plain
Outlook — personaloutlook.live.com/mail/0/deeplink/compose?to=…&subject=…&body=…plain
Desktop defaultmailto:…?subject=…&body=…plain — RFC 6068
So the button does both things. It copies the rich body to the clipboard and opens the compose window with To and Subject filled and the body left empty, then says “Paste into the message — ⌘V”. One click, formatting intact. Filling the body with the plain-text version instead would hand the processor a stripped message that looks finished, which is worse than an empty one.
1

There is no way to detect which client they use

Nothing in the browser tells us. So it is a setting — asked once, on the first draft, and changeable afterwards. Screen 11.

2

Seed the default from their own address, never apply it silently

A processor signed in as @gmail.com or a Workspace domain gets Gmail pre-selected; an @outlook.com or Microsoft 365 tenant gets Outlook. It is a guess, so it pre-selects a radio button rather than deciding.

3

“Desktop default” stays and stays first

mailto: is the only route that works for someone on Apple Mail, Thunderbird, or a locally installed Outlook. It is the safe default when they skip the question.

4

The URL length ceiling applies to all four

mailto_max_chars already gates the mailto: route. Since the body is now empty in the URL, the ceiling stops being a problem — which is a second reason to leave it empty.

1

The party is a column, not a heading

This is the thing you caught about the buckets: a heading is a region that can be scrolled past, so a title-company draft ends up below the fold and the processor never learns it exists. A column is on every row and cannot be missed, and the list stays in one time order.

2

The dot means “since you last looked”, not “unread”

Nothing is received in this version, so “unread” would be a lie. It clears when the row is opened.

3

Status is a word, never a colour alone

Draft / Sent by Priya. And it is “Sent by Priya”, not “Sent” — a person claimed it; nothing observed it.

4

The row says what is inside without opening it

“4 documents” answers the count; the names answer “is this the one I need”. Both, because a list of four rows reading “A document request is being prepared” is the screenshot you sent me.

1

Three buttons and a quiet fourth — that is your answer

Copy & open Gmail is the whole send path in one click: it puts the rich body on the clipboard and opens the compose window with To and Subject filled. The label carries the chosen client — Copy & open Outlook, Copy & open mail app. Copy message stays for anyone doing it their own way. Mark as sent is the claim. Delete is quiet and on the far side, because it destroys the record.

2

No Send button, not even disabled

mail_transport is an interface with no provider behind it. A greyed Send is a promise this version cannot keep and the first thing a processor clicks.

3

“Where to get it” is the reason the email works

It comes from the catalog, indented under its own document as a nested list — not an indent, because the clipboard carries no stylesheet and Outlook renders with Word's engine. It is what lets a borrower act without phoning.

4

The polish button sits in the toolbar and is violet

Violet is the Ledger's provenance colour: it marks a model touched this, never a status. It is available on any draft, not only a free one.

5

“What it asks for” is read-only here

Documents join a draft through the request flow, not by typing in this box. A processor who wants one more opens the catalog, and the dialog on screen 3 brings it here.

It quotes the processor's own sentence back

Ticket 4 is the one to watch. Everything else on this page is UI work against existing endpoints. Changing the stored body from a plain string to HTML touches the templates, the placeholder pass, the clipboard, the mailto: derivation and the security model at once — and it exists only because the toolbar has to look like Gmail's. If that trade is not worth it, say so now: keeping bold, italic, bullets and links inside the current plain-string schema is a fraction of the work and covers most of what a document request needs.
