# Wiring backlog (LP-435) — hand-apply, not auto-applied

LP-435 generated the module + prompt + test for every spec that passed the validator, and placed them in the
live tree (`app/ai/extraction/`, `app/ai/prompts/extraction/`, `tests/ai/`). It **did not** wire any of them
into `EXTRACTORS` / `app/documents/catalog.py` / `app/ai/classification_prompt.py`. This file is the hand-apply
backlog for that wiring, plus the diff reports for the 18 shipping extractors.

## Why wiring was NOT auto-applied (Geet's decision, LP-435)

The extraction pipeline routes extraction **only to Tier-1 types** (`document_processing.py:196`), and a hard
invariant pins **exactly 18 Tier-1 types** (`tests/documents/test_catalog.py:test_eighteen_tier_1_types`) — the
18 shipping extractors. Making any generated module *live* therefore requires promoting its type to Tier-1 and
bumping that count test, which the ticket explicitly forbids editing. On top of that:

- **9 of the 13 passing specs are Tier-3 thin docs** (0–1 rules by their own `tier`), which should not be Tier-1
  extracted at all;
- **11 of the 13 are not in the catalog** — wiring them adds brand-new document types + classifier indicators
  (a taxonomy decision, not a mechanical promotion).

So the modules ship **generated and unregistered** (latent, `classified-only` per the pipeline), and wiring is a
deliberate per-type decision recorded below.

## To wire a generated module (per type)

1. `app/ai/extraction/__init__.py` — `from app.ai.extraction.<type> import extract_<type>` + an `EXTRACTORS` entry.
2. `app/documents/catalog.py` — the type must be **Tier-1** to route; add it (or flip an existing Tier-2 entry).
3. `app/ai/classification_prompt.py` — a recognition indicator (CI-enforced parity) **if not already cataloged**.
4. `tests/documents/test_catalog.py` — bump `test_eighteen_tier_1_types` (18 → 18+N) and the planned-Tier-1 list.
5. `tests/tasks/test_document_processing.py` — a routing assertion (the type now reaches its extractor).
